## Design Observations

### Concerns

- **Image and Volume mirrors re-assert the finalizer with no `DeletionTimestamp` guard** *(future)* [Claude Opus 5]. `applyContainer` reads the object first and skips the finalizer-only apply once `DeletionTimestamp` is set, with a comment saying that adding a finalizer to a deleting object is rejected (`sync_containers_containerd.go:232-243`). `applyImageMirror` applies `WithFinalizers(mirrorFinalizer)` unconditionally (`sync_images_containerd.go:161-164`). An `ImageUpdate` arriving between the finalizer strip and the delete completing would re-add one to a terminating object. Not a containerd regression: the moby path does the same at `sync_images.go:124` and `sync_volumes.go:100`, so a fix belongs in one pass across all four sites. Only the container path has the guard, and its comment reads as codebase policy, which is why I record it here.
- **One invariant is carried by four independent prune paths** *(in-scope, mitigated)* [Claude Opus 5]. `watcherEngine` is process-local, so the `previousEngine` arm never sees a backend switch that spans a daemon restart. Each backend's `fullSync` prunes what the other left, through `syncContainerNamespace`, `pruneVolumes` and the two `activeNames` sweeps. I traced all four and they cover the cases, but a single "sweep what the current backend did not produce" step at watcher start would collapse them.
- **User-visible mirror fields still diverge between the engines** *(future)* [Claude Opus 5, round 3]. Unchanged this round: `busybox:latest` under moby against `docker.io/library/busybox:latest` under containerd, `status.id` as config digest against manifest digest, and the two `status.size` definitions. Each is documented; together they mean a client keying on `repoTag` behaves differently per backend.

### Strengths

- Subscribing before `fullSync` is the right order, and containerd's `Exchange` neither filters by namespace nor drops while the snapshot runs [Claude Opus 5, Codex GPT 5.6 Sol].
- The `linuxSignals` table and the test pinning `SIGUSR1 == 10` rather than `syscall.SIGUSR1` close a bug class that would pass CI on Linux and ship broken on both supported hosts [Claude Opus 5, Codex GPT 5.6 Sol].
- `mirrorClient` centralizes the apply and finalizer semantics without pushing backend-specific concepts into a shared interface [Codex GPT 5.6 Sol, Gemini 3.5 Flash].
- The deferred exit sequence in `run` documents its LIFO order and gets it right, so the reconciler never sees `alive()==true` on a goroutine about to exit [Claude Opus 5].
- `supportsNamespaces` as `*bool` keeps the field absent until first write rather than materializing a zero-valued `false` [Codex GPT 5.6 Sol].
- Sorting map-derived status lists before applying them matches the moby path exactly, including the lexicographic port-name comparator [Codex GPT 5.6 Sol, Gemini 3.1 Pro].

## Review Process Notes

### Skill improvements

- Before accepting a finding that a `select`, wait, or blocking call ignores context cancellation, check whether any channel it already selects on is fed by a call that takes that same context. A client library that starts a goroutine around a cancellable RPC and forwards the error to the caller's channel unblocks the select without a `ctx.Done()` arm, so the missing arm changes which error is returned, not whether the code returns.
- When a finding contrasts the reviewed code with a sibling path ("the other backend does X", "the UI sorts this"), open the sibling and read the comparison rather than the code under review. The contrast is the whole finding: where the sibling turns out to behave identically, the code is matching an established convention, which is the opposite of a defect.
- A prior round's decline is evidence about the code as it stood then. When a later round changes the code the decline reasoned about, re-derive the decline rather than inheriting it, and say in the finding which clause of the stated reason no longer describes the code.

##### Design Observations

###### Strengths

- **Code Reusability**: The extraction of shared mirror operations into the `mirrorClient` struct (in `mirror_client.go`) cleanly avoids duplicate k8s API client plumbing for both `dockerWatcher` and `containerdWatcher`.
- **Safe State Transitions**: The `removeDockerContext()` method handles asynchronous probe cancellation and wait-group synchronization perfectly, ensuring that multiple back-to-back transitions or failed starts do not trigger races or file write conflicts.
- **Integer Overflow Protection**: The inclusion of `maxStopTimeoutSeconds` constant in `container_actions_containerd.go` prevents `time.Duration` wrapping on extremely large or unconstrained label inputs.

##### Acknowledged Limitations

- **Container Namespace Mirror Reconstruction (`sync_namespace_containerd.go:72-74`)**: A manually deleted `ContainerNamespace` mirror is not re-applied in steady-state. Since user edits do not generally target namespace mirrors directly, and full syncs re-apply them on startup, this minor limitation is acceptable.
- **Theoretical ID Collision Caveat (`sync_containers_containerd.go:42-44`)**: Valid RFC 1123 subdomain container IDs duplicated across distinct containerd namespaces could theoretically map to the same mirror resource. As both nerdctl and Kubernetes generate globally unique 64-hex IDs, this collision risk remains strictly theoretical.
