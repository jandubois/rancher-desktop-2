## Executive Summary

The PR implements containerd image pulls by running `client.Pull` in rdd and polling the content store. Four defects make the new path hang or fail. A stalled download never times out, Docker short names such as `hello-world:latest` fail to parse, pulls from a Windows host ask the guest for a `windows` snapshotter, and a request without `spec.namespace` fails. Each has a tested patch. A comment and the design doc still say containerd cannot pull, and the path is untested.

## Important Issues

I1. **A stalled download refreshes the request forever, so the pull timeout never fires** — `rdd/pkg/controllers/app/engine/controllers/containerd_watcher.go:353-355` [Codex GPT 6 Astra, Claude Opus 5.5]

```go
					if allTotal > 0 {
						onProgress(0, allProgress, allTotal, "bytes")
					}
```

Once any tracked download has appeared, the poller calls `onProgress` on every 500 ms tick, whether bytes moved or not. The reconciler's callback counts every call as a change (`image_pull_request_reconciler.go:383-387`), and the status write refreshes `LastUpdateTime` (line 362), so the stall check at line 186 never trips.

containerd's registry transport sets a 30 s response-header timeout and no body timeout (`core/remotes/docker/registry.go:254-268` in v2.4.2). So a registry that stops sending mid-layer leaves the request `Pulling` until rdd exits. The moby path calls `onProgress` only when dockerd sends a message, so its 60 s timeout fires.

```go repro
// harnessDiff applies a layer by waiting applyDelay, standing in for a
// slow unpack.
type harnessDiff struct {
	containerdclient.DiffService
	applyDelay time.Duration
}

func (h harnessDiff) Apply(ctx context.Context, desc ocispec.Descriptor, _ []mount.Mount, _ ...diff.ApplyOpt) (ocispec.Descriptor, error) {
	select {
	case <-time.After(h.applyDelay):
	case <-ctx.Done():
		return ocispec.Descriptor{}, ctx.Err()
	}
	return ocispec.Descriptor{MediaType: ocispec.MediaTypeImageLayer, Digest: desc.Digest, Size: desc.Size}, nil
}

type layerMode int

const (
	layerFast  layerMode = iota // the whole layer at once
	layerSlow                   // 1 MiB every 400 ms
	layerStall                  // half the layer, then nothing
)

// harnessRegistry serves one single-layer image, sending the 4 MiB layer
// blob as mode says.
func harnessRegistry(t *testing.T, mode layerMode) (ref string) {
	layer := []byte(strings.Repeat("rancher-desktop!", 4*64*1024)) // 4 MiB
	layerDigest := digest.FromBytes(layer)
	config, _ := json.Marshal(ocispec.Image{
		Platform: ocispec.Platform{OS: "linux", Architecture: runtime.GOARCH},
		RootFS:   ocispec.RootFS{Type: "layers", DiffIDs: []digest.Digest{layerDigest}},
	})
	configDigest := digest.FromBytes(config)
	manifest, _ := json.Marshal(ocispec.Manifest{
		MediaType: ocispec.MediaTypeImageManifest,
		Config:    ocispec.Descriptor{MediaType: ocispec.MediaTypeImageConfig, Digest: configDigest, Size: int64(len(config))},
		Layers:    []ocispec.Descriptor{{MediaType: ocispec.MediaTypeImageLayer, Digest: layerDigest, Size: int64(len(layer))}},
	})
	manifestDigest := fmt.Sprintf("sha256:%x", sha256.Sum256(manifest))
	srv := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		switch {
		case strings.HasPrefix(r.URL.Path, "/v2/probe/img/manifests/"):
			w.Header().Set("Content-Type", ocispec.MediaTypeImageManifest)
			w.Header().Set("Docker-Content-Digest", manifestDigest)
			w.Header().Set("Content-Length", fmt.Sprint(len(manifest)))
			if r.Method != http.MethodHead {
				_, _ = w.Write(manifest)
			}
		case r.URL.Path == "/v2/probe/img/blobs/"+configDigest.String():
			_, _ = w.Write(config)
		case r.URL.Path == "/v2/probe/img/blobs/"+layerDigest.String():
			w.Header().Set("Content-Length", fmt.Sprint(len(layer)))
			switch mode {
			case layerFast:
				_, _ = w.Write(layer)
			case layerSlow:
				for off := 0; off < len(layer); off += 1 << 20 {
					_, _ = w.Write(layer[off : off+1<<20])
					w.(http.Flusher).Flush()
					time.Sleep(400 * time.Millisecond)
				}
			case layerStall:
				_, _ = w.Write(layer[:len(layer)/2])
				w.(http.Flusher).Flush()
				<-r.Context().Done()
			}
		default:
			http.NotFound(w, r)
		}
	}))
	t.Cleanup(srv.Close)
	return strings.TrimPrefix(srv.URL, "http://") + "/probe/img:latest"
}

// pullFor runs pullImage until it completes or d passes, and reports
// whether it reached the layer download.
func pullFor(t *testing.T, w *containerdWatcher, namespace, ref string, d time.Duration) (downloaded bool, err error) {
	ctx, cancel := context.WithCancel(t.Context())
	defer cancel()
	var mu sync.Mutex
	done := make(chan error, 1)
	assert.NilError(t, w.pullImage(ctx, namespace, ref, func(_, _, _ int64, _ string) {
		mu.Lock()
		downloaded = true
		mu.Unlock()
	}, func(err error) { done <- err }))
	select {
	case err = <-done:
	case <-time.After(d):
		cancel()
		err = <-done
	}
	mu.Lock()
	defer mu.Unlock()
	return downloaded, err
}

// sent to Docker Hub. HTTPS_PROXY points at a local proxy that records the

func TestPullHarnessShortName(t *testing.T) {
	var mu sync.Mutex
	var connects []string
	proxy := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		mu.Lock()
		connects = append(connects, r.Method+" "+r.Host)
		mu.Unlock()

	}))
	t.Cleanup(proxy.Close)

		connects = nil
		mu.Unlock()
		w, _ := harnessWatcher(t, 0)

		mu.Lock()

		assert.Check(t, len(connects) > 0, "%s never reached a registry", ref)
		mu.Unlock()
	}

// harnessLastUpdates starts a pull through the reconciler and samples
// status.lastUpdateTime, which the pull timeout reads, at first and again
// 2.5 s later.
func harnessLastUpdates(t *testing.T, e engine, ref string, first time.Duration) (metav1.Time, metav1.Time) {
	req := &containersv1alpha1.ImagePullRequest{
		ObjectMeta: metav1.ObjectMeta{Name: "probe", Namespace: appv1alpha1.AppNamespace, UID: types.UID("probe-uid")},
		Spec:       containersv1alpha1.ImagePullRequestSpec{Namespace: "default", RepoTag: ref},
	}
	ctx, cancel := context.WithCancel(t.Context())
	defer cancel()
	r := &EngineReconciler{
		Client:                newEngineImagePullReconcilerTestClient(t, req),
		imagePullRequestState: map[types.UID]imagePullRequestState{},
		watcherCtx:            ctx,
	}
	_, err := r.reconcileSingleImagePullRequest(ctx, e, req)
	assert.NilError(t, err)
	sample := func() metav1.Time {
		var got containersv1alpha1.ImagePullRequest
		assert.NilError(t, r.Get(ctx, client.ObjectKeyFromObject(req), &got))
		c := apimeta.FindStatusCondition(got.Status.Conditions, containersv1alpha1.ImagePullRequestConditionSettled)
		assert.Assert(t, c != nil && c.Reason == "Pulling", "request settled early: %+v", got.Status)
		return got.Status.LastUpdateTime
	}
	time.Sleep(first)
	t1 := sample()
	time.Sleep(2500 * time.Millisecond)
	return t1, sample()
}

// TestPullHarnessStalledDownload: a download that stops sending bytes stops
// refreshing the request, so the pull timeout can fire; moby's pull stream
// is the comparison.
func TestPullHarnessStalledDownload(t *testing.T) {
	stalledMoby := &testEngine{pullImageHook: func(_ context.Context, _, _ string, onProgress func(int64, int64, int64, string), _ func(error)) {
		onProgress(0, 2<<20, 4<<20, "bytes")
	}}
	t1, t2 := harnessLastUpdates(t, stalledMoby, "registry.example/stalled:latest", 1500*time.Millisecond)
	t.Logf("moby-shaped engine, stalled:  lastUpdateTime %s -> %s", t1.Format(time.TimeOnly), t2.Format(time.TimeOnly))
	w, _ := harnessWatcher(t, 0)
	t1, t2 = harnessLastUpdates(t, w, harnessRegistry(t, layerStall), 1500*time.Millisecond)
	t.Logf("containerd pullImage, stalled: lastUpdateTime %s -> %s", t1.Format(time.TimeOnly), t2.Format(time.TimeOnly))
	assert.Check(t, t2.Equal(&t1), "a stalled download keeps refreshing lastUpdateTime")
}

// TestPullHarnessSlowUnpack: once the layers are down, a slow unpack keeps
// refreshing the request, so a large image does not time out while it
// unpacks.
func TestPullHarnessSlowUnpack(t *testing.T) {

	t.Logf("containerd pullImage, unpacking: lastUpdateTime %s -> %s", t1.Format(time.TimeOnly), t2.Format(time.TimeOnly))
	assert.Check(t, t2.After(t1.Time), "a slow unpack stops refreshing lastUpdateTime")
}
```

## Suggestions

S1. **A finished layer keeps its last sampled offset, so progress stops short of the total** — `rdd/pkg/controllers/app/engine/controllers/containerd_watcher.go:342-343` [Gemini 3.1 Pro, Gemini 3.5 Flash]

```go

					total[status.Ref] = status.Total
```

containerd drops a download's status when it commits, so a layer that finishes between two ticks keeps the offset sampled before. `content.Copy` writes in 1 MiB steps (`core/content/helpers.go:40`), so the stale value trails by up to a megabyte plus half a second of download per layer. The sum then stays below the total through the unpack, until the reconciler sets `current` to `total` on success (`image_pull_request_reconciler.go:441`).

Fix: When a tracked ref has a total but is missing from a tick's statuses, set its progress to its total. I1's patch already adds a check in the same loop for whether any download is active.

S2. **A registry 401 settles as `PullFailed`, not `Unauthorized`** — `rdd/pkg/controllers/app/engine/controllers/containerd_watcher.go:311-312` [Claude Opus 5.5, Codex GPT 6 Astra]

```go
		return err
```

The reconciler picks the `Unauthorized` reason through `cerrdefs.IsUnauthorized` (`image_pull_request_reconciler.go:506`). For a 401, containerd's resolver returns a `remoteerrors.ErrUnexpectedStatus`, and `cerrdefs.IsUnauthorized` returns false for it. Both reviewers' probes against a local registry that answers 401 showed this. This review didn't check which reason the moby path reports for the same response.

Fix: Wrap the error with `cerrdefs.ErrUnauthorized` when it is an `ErrUnexpectedStatus` with status 401, or matches `docker.ErrInvalidAuthorization`.

S3. **A nil `onProgress` or `onComplete` panics, where the moby path tolerates both** — `rdd/pkg/controllers/app/engine/controllers/containerd_watcher.go:354` [Gemini 3.1 Pro, Gemini 3.5 Flash]

## Design Observations

### Concerns

- **The pull runs in rdd on the host, not in the guest's containerd** (in-scope) [Claude Opus 5.5]. `client.Pull` resolves, downloads and drives the unpack from the calling process, and streams every blob into the guest through the content service. So the containerd daemon's own proxy environment doesn't apply to these pulls, and the client picks its defaults for the host OS, as I3 shows. containerd's transfer service (`cli.Transfer` with `registry.NewOCIRegistry` and `image.NewStore`, all in the pinned v2.4.2) runs the pull inside the guest daemon and reports its own progress, which would also replace the polling behind I1 and S1. Whether the guest's containerd enables the transfer plugin was not checked.

### Strengths

- **Progress counts only this pull's downloads** [Claude Opus 5.5, Gemini 3.5 Flash]. The image handler records each descriptor with `remotes.MakeRefKey`, the function that containerd's fetch handler uses to name the download (`core/remotes/handlers.go:142` in v2.4.2), so other pulls in the same namespace don't inflate the totals. The harness confirmed that the tracked refs match.
- **Every engine receives the namespace through the interface** [Codex GPT 6 Astra, Claude Opus 5.5]. The reconciler passes `Spec.Namespace`, `testEngine` and both watchers take it, and the moby watcher ignores it, because moby has a single namespace.

I2. **Completed layer progress sticks below 100% during unpack** — `rdd/pkg/controllers/app/engine/controllers/containerd_watcher.go:335-344` (important, gap)

```go
				for _, status := range statuses {
					trackingMu.Lock()
					if _, ok := tracking[status.Ref]; !ok {
						trackingMu.Unlock()
						continue // Skip untracked descriptors.
					}
					trackingMu.Unlock()
					progress[status.Ref] = status.Offset
					total[status.Ref] = status.Total
				}
```

Containerd's `ListStatuses` returns only *active* content transfers. When a layer completes, it disappears from the `statuses` list. Because this loop only updates `progress[status.Ref]` for active statuses, a layer's final progress stays at its last observed offset (which is often slightly less than `Total`). Since pulling blocks on the subsequent image unpack phase, the UI progress bar will hang at `< 100%` for a long time instead of completing. 

Fix: Track active references in each pass, and advance `progress[ref]` to the maximum (`Total`) for any transfer that is no longer active.

```go
				activeRefs := make(map[string]struct{})
				for _, status := range statuses {
					trackingMu.Lock()
					if _, ok := tracking[status.Ref]; !ok {
						trackingMu.Unlock()
						continue
					}
					trackingMu.Unlock()
					progress[status.Ref] = status.Offset
					total[status.Ref] = status.Total
					activeRefs[status.Ref] = struct{}{}
				}

				if len(total) > 0 {
					var allProgress, allTotal int64
					for ref, max := range total {
						if _, active := activeRefs[ref]; !active {
							progress[ref] = max
						}
						allProgress += progress[ref]
						allTotal += max
					}
					if allTotal > 0 && onProgress != nil {
						onProgress(0, allProgress, allTotal, "bytes")
					}
				}
```
