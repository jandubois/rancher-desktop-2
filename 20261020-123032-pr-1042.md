`doneHandler` does not check `this.stopped` after the list returns, so a `ListWatch` stopped while its first list is in flight still opens a watch, and nothing aborts it until the server ends the stream. ## Design Observations

### Concerns

- **(in-scope)** A re-created namespace takes the view back without the user asking. `selectedNamespace` keeps its value after the deletion, and the getter returns it again once it exists (`container-engine.ts:80`), so `nerdctl --namespace foo` can switch the lists to `foo` with no user action. If that is unintended, clear `selectedNamespace` when its namespace disappears. [Claude Opus 5.5]
- **(future)** Until the namespace list loads, `currentNamespace` is `undefined`, so the first list of containers, images or volumes goes out unfiltered and shows every namespace's rows until the plugin's rewatch replaces them. The merge-base kept those rows until the user picked a namespace, so this round shortens that window. [Gemini 3.1 Pro]
- **(future)** `BodyContainerEngine.vue` hardcodes its tabs, while `BodyVirtualMachine.vue` builds them from `preferencesNavItemsMap`, as round 1 noted. [Codex GPT 6 Astra, Claude Opus 5.5]
- **(future)** With browsing disabled (`Volumes.vue:149`), nothing in the UI reaches `/volumes/files/:name` (`entry/router.ts:44`), whose page still maps the removed `initialPreferences` field (`pages/volumes/files/_name.vue:167`). 'should browse volume files' (`e2e/volumes.e2e.spec.ts:72`) will fail once that suite leaves `fixme`. [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.5 Flash]

### Strengths

- Watching the getter, instead of rewatching in the setter, covers a pick, the list loading, an engine switch and a deletion alike. [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.1 Pro, Gemini 3.5 Flash]
- `rewatchResources` restarts only watches with a positive reference count (`rddConnection.ts:550`), and the plugin's filter leaves out the namespace watch, so a getter change never starts a watch that no page asked for. [Codex GPT 6 Astra]

## Review Process Notes

### Repo context updates

- [repo] The renderer's root store collects Vuex plugins from each module's exported `plugins` array (`pkg/rancher-desktop/entry/store.ts`). A test that installs a plugin by hand on its own store does not cover that registration, so when a fix depends on a module plugin, check that a test asserts the plugin is in the module's `plugins`.
- [repo] Unwatching a renderer resource (`unwatchResources` in `pkg/rancher-desktop/store/rddConnection.ts`) closes its watcher but keeps the last list in the store, so getters that read the list see stale data, not `null`, on pages that do not watch it.
- [repo] UPDATE the `errorManuallyStopped` entry's `doneHandler` clause, which reviewers read as a ban on any `stopped` finding there: "`doneHandler` in `pkg/rdd-client/cache.ts` dispatches ERROR callbacks before its `stopped` check, which gates only auto-restart, and that ordering is correct. A `stop()` that arrives while the initial list is awaited is a separate window; check whether `doneHandler` re-checks `stopped` before it opens the watch."
- [repo] UPDATE the entry saying `rewatchResources` is dispatched from exactly two places, once the getter-watching plugin is on the default branch: "`rewatchResources` is dispatched from a Vuex plugin in `store/container-engine.ts` that watches the `currentNamespace` getter, and from a plugin in `store/rddConnection.ts` that watches the Kubernetes namespace. A `fieldSelector` callback may read any state that the `currentNamespace` getter derives from; other state must change through something that rewatches, or the open watch keeps its stale selector."
