Design Observations ¶

Concerns ¶

  • The decode holds the LimaVM controller's only worker for about 30 s per creation (future) Claude Opus 5. With one worker, no other LimaVM reconciles meanwhile, so stopping or deleting another VM waits. This SHA's bats-lima logs show 28.5-34.7 s per decode on ubuntu-latest and macos-15-intel. The image holds 8 xz blocks (Claude, xz --list), so the block-parallel decoder planned as a follow-up would shorten the wait.

Strengths ¶

  • Skip-then-punch is the right design, and experiments bear it out (in-scope) Claude Opus 5. Without the punch, APFS allocated every interior gap Claude tried, up to 16 MiB; with it, the v0.2.8 arm64 image decodes to 908 MiB allocated, against 1015 MiB for xz -d (Claude, measured).
  • Cancellation reaches the decode (in-scope) Claude Opus 5. In this SHA's ubuntu bats-lima log, the service stop cancelled an in-flight decode 8.6 ms after the shutdown signal, and the controller deleted the half-made instance.
  • Go file-name suffixes pick the guest agent (in-scope) Claude Opus 5 Codex GPT 5.6 Sol Gemini 3.1 Pro Gemini 3.5 Flash. A build for another architecture can no longer embed a stale agent, and the Makefile needs no logic for it.
  • Round 1's Makefile fixes hold under GNU make 3.81 (in-scope) Claude Opus 5 Codex GPT 5.6 Sol. Both ran dry runs with GOARCH on the command line and in the environment; the downloader builds for the host, and every binary gets the target.

Acknowledged Limitations ¶

Declined in prior rounds

  • A first yarn install must fit the distro download into postinstall's ten minutes — declined Round 1: a comment at InstallTimeout gives the workaround, and Claude checked its claims against rdd.ts, the wait loop and Stage.
  • The embedded: branch ignores the location's arch and file name — declined Round 1: only a hand-written LimaVM template reaches it. The bats template this PR adds is one, and it matches, with no arch and the raw image, or the tarball on Windows Claude Opus 5 Codex GPT 5.6 Sol.
  • WSL2 cannot refetch a missing basedisk from an embedded: location — declined Round 1 with a comment on linkWSL2BaseDisk, which is accurate; limavm-wsl2-orphan.bats re-imported from the hardlinked basedisk on windows-latest at this SHA.
  • The round-1 testing and documentation gaps the author skipped: allocation tests (added with the fix), the embedded-before-xz ordering (no xz check remains), a Makefile guard, an external-manager bats setup, and rdd/NOTICE, left to the maintainers.

Author decisions and accepted costs

  • rdd never looks for a system xz, so an https .xz image needs xz on the host (api_lima.md:64). No code, test or doc still assumes the removed fallback Claude Opus 5.
  • The other controller binaries keep a previous target's build after an architecture switch; S1's stamp would cover them.
  • Lima's decompressLocal leaves an empty file on failure, an upstream bug.
  • bats no longer boots any VM from an image Lima downloads (4ab165a35).
  • The costs #708 accepted: the size of bin/rdd (413 MiB for mac amd64 in this SHA's Package log, per Claude), slower creation on hosts with xz, CI cache growth, and one VM restart after the upgrade.

Review Process Notes ¶

Skill improvements ¶

  • An agent can exit with empty output and a clean stderr because its last model turn came back empty. When the output is empty and stderr holds no error, read the agent's session log for a final turn with no output tokens, treat that as transient, and retry once, since the stderr checks in Step 4 find nothing to classify.
  • When code or its comments name a platform threshold (a gap size, a buffer length, a timeout), test inputs on both sides of it before accepting a boundary case as covered, because one measurement above the threshold says nothing about the values below it.

Repo context updates ¶

  • [repo] On APFS, a short run of zeros that a writer skips is allocated anyway, whether it lies between two writes or at the end of a file extended by truncate; 1 MiB and 16 MiB runs were allocated and a 64 MiB run stayed a hole (measured on macOS, 2026-09-14). Code that writes sparse images must punch holes over skipped runs, and its tests must use runs shorter than 16 MiB.
  • [repo] The rdd Makefile's binary rules depend on files, not on the build target, so a target switch whose staged files do not change leaves the previous build in place. Check a change to target handling against a switch of GOOS alone and of GOARCH alone.
  • [repo] UPDATE the entry on rdd/pkg/guestagent embedding lima-guestagent.gz: the embedded guest agent is rdd/pkg/guestagent/lima-guestagent.<arch>.gz, one file per architecture, and its make target is make pkg/guestagent/lima-guestagent.<arch>.gz; make, make test and make lint-rdd build the one for the target.
