Executive Summary ¶

Three issues survived verification. rddepman --regenerate against a legacy manifest erases Electron's recorded checksums; each regenerated sibling rewrites the whole file, re-serializing the skipped entry as empty. Credential-helper installation now succeeds silently when no asset matches, where the old code threw. Three of the new spec's validation tests never reach the validator they name. The asset schema itself is sound, and the two commits are cleanly split.

Codex found both production defects. Claude produced the only suggestions and the sharpest design analysis. Gemini found nothing and asserted, incorrectly, that the migration path is robust. The third finding came from consolidation: no agent caught it.

Design Observations ¶

Concerns

  • The whole-manifest rewrite can blank sibling assets during an ordinary bump, not just a regenerate (in-scope) Claude. updateManifest rebuilds the entire file from the in-memory model, so if checkDependencies ever runs against an un-migrated manifest, the resulting PR carries one dependency's real assets and assets: [] for every sibling. Post-merge the workflow always reads the migrated main, so the exposure is a manual workflow_dispatch branching off the old origin/main. This is the same mechanism as I1, reached through the bump path rather than --regenerate.

One correction to the original observation: it argued that a bad PR "fails its own postinstall (selectAsset 'found 0')". That holds for helm, dockerCLI, wix, and steve, but not for the credential helpers, which take the selectAssets path and pass — that is exactly I2.

  • selectAsset requires the caller to know a dependency's format multiplicity (future) Claude. distro ships four assets ({amd64,arm64} × {raw,tar}), so selectAsset without a format matches two and throws. The planned Go downloader must pass format; the contract deserves a note, since the TS side has no consumer yet.
  • Distro.getAssets downloads all four distro images concurrently just to hash them (future) [Consolidator]. Promise.all(cartesian(ARCHES, FORMATS)) fetches four compressed images to temp files on every guest bump. On a GitHub-hosted runner this is the most disk- and bandwidth-intensive step rddepman performs. Worth watching once the guest workflow runs on a real bump.

Strengths

  • The self-describing asset schema pairs an immutable, version-pinned url with its checksum, so install paths no longer re-derive URLs and the manifest is directly consumable by the planned Go downloader. Gemini Claude
  • serializeAsset fixes key order, keeping YAML diffs clean however the asset object was built. Claude
  • parseAsset validates platform, arch, and checksum at file-read time with per-field messages. Claude
  • regenerable = false isolates the one dependency whose version lives in package.json rather than the manifest. Claude
  • Storing the sha256: prefix documents the algorithm for readers while parseSha256Checksum normalizes case, so consumers compare hex with ===. I verified this end to end: hashFile emits lowercase, download() compares with ===, and the parser lowercases. Gemini

Testing Assessment ¶

The new spec covers the round-trip, header emission, legacy tolerance, and the full selectAsset/selectAssets/assetChecksum matrix. The suite runs and passes (13 tests) under the repo's ESM invocation.

Two agents overstated its strength. Gemini called the coverage "excellent" and Claude "solid", but the three parameterized validation cases are inert (I3), so parseAsset is untested in practice. Remaining gaps, in risk order:

  1. parseAsset platform / arch / checksum / format rejection — currently vacuous or absent (I3).
  2. selectAsset zero-match, the branch that distinguishes I2's silent path (S5).
  3. regenerateAssets skipping a non-regenerable dependency while preserving its entry — the mechanism I1 shows is broken. A test here would have caught I1.
  4. readDependencyManifest rejection of a missing version or a non-array assets.

Per-dependency getAssets methods reach the network and remain untested; that is pre-existing and reasonable.

Documentation Assessment ¶

Exported symbols carry good docstrings. Three comments contradict the code: the regenerateAssets comment (S2), the global.ts header (S3), and the manifest header's silence on the guest subcommand (S4).

More seriously, the readDependencyManifest docstring promises that the legacy tolerance lets rddepman --regenerate migrate an old manifest. I1 shows it does not; the docstring should either describe the limitation or the code should honor it.

Acknowledged Limitations ¶

  • Legacy-schema tolerance with a removal plan — scripts/lib/dependencies.ts:175-179 states the tolerance exists so --regenerate can migrate an old manifest, and should be removed once this lands. Both manifests ship migrated, so the tolerance is dead on merge. I1 is the finding that the advertised migration does not work; the removal plan itself is sound.
  • Electron is not regenerable — scripts/dependencies/electron.ts:35-37. Consistent with getAssets throwing on a version mismatch. I1 is the unhandled consequence.
  • Guest dependencies have no host install — distro.ts:28-30, nerdctl.ts:25-27 reject with "staged by the build, not by postinstall". Verified: neither class appears in postinstall.ts, so the rejection is an unreachable guard.
  • Buildx darwin has no upstream checksum — tools.ts:121-130 hashes darwin without upstream verification, citing the upstream bug. Unchanged behavior.
  • fetchUpstreamChecksums and downloadAndHash are out of scope — both predate this PR and this diff adds no lines to either. Their sidecar-parsing and basename-aliasing logic remains untested, but that is pre-existing.

Review Process Notes ¶

Skill improvements

  • [ ] When a review's changed files include a test file, run the test suite before consolidating, then verify that each new test fails when the behavior it names is broken. A test whose fixture aborts in an earlier validation layer passes while exercising nothing; a bare rejects.toThrow() or expect(fn).toThrow() with no message matcher cannot distinguish the intended error from an unintended one. Flag any new negative-path test that asserts only that something threw.
  • [ ] When one agent reports a defect in a code path and another agent reports the same code path as a strength, treat the disagreement as a finding to adjudicate against the code, not as a split verdict to report. Reproduce the mechanism directly before crediting either. Agents that scan a diff without executing it systematically over-trust migration and compatibility shims, whose failure modes appear only when the shim's output is fed back through the writer.
  • [ ] Before accepting a finding's "regression" label, confirm the cited construct exists at the merge-base. New subcommands, new flags, and new code paths cannot regress prior behavior; label them gaps. Conversely, a fail-loud to fail-silent change is a regression only if the prior code actually threw — read the removed error path, do not infer it from the diff's shape.
  • [ ] Treat Promise.all(xs.map(...)), for (const x of xs), and similar iteration over a collection returned by a lookup as a silent-success candidate whenever the lookup can return empty. Compare against sibling call sites: if one lookup helper throws on no-match and another returns an empty collection, every caller of the second needs an explicit arity check. This pattern hides best in refactors that replace per-item lookups with a single filtered query.

Repo context updates

  • [ ] [repo] Jest in this repo requires the ESM invocation: npx cross-env BROWSERSLIST_IGNORE_OLD_DATA=1 node --experimental-vm-modules node_modules/jest/bin/jest.js <path>. A bare npx jest fails with SyntaxError: Cannot use import statement outside a module on the octokit import, and specs under scripts/ additionally need the @jest-environment node docblock or they fail with ReferenceError: TextDecoder is not defined. Do not report either failure as a defect in the code under review.
  • [ ] [repo] Agent worktrees created for review have no node_modules, so agents cannot run the test suite or tsc. Run test-execution checks from the main checkout instead, and read any agent's claim about type-consistency or test outcomes as static tracing rather than verified execution.
  • [ ] [repo] scripts/dependencies/*.ts classes are registered in scripts/dependencies/global.ts (host) and in the configs map in scripts/rddepman.ts. A dependency class is only installed at postinstall if it also appears in the lists in scripts/postinstall.ts. When reviewing a new dependency class, check all three registries: absence from postinstall.ts is what makes a download() that rejects an unreachable guard rather than a bug.
