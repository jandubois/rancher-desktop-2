## Executive Summary

The rework fixes round 1's lifecycle defects. A spec update now reruns `up`, a spawn failure settles the request, a recreated object aborts the old process, macOS kill delivers SIGHUP, and a failed `down` falls back to deleting the containers. But deleting a project whose recorded member is gone never finishes. A rerun that cannot start keeps the old reap deadline, owned requests get reaped, Linux kill still needs kernel 6.9, and no test pins most of the round-1 fixes.

## Important Issues

I1. **Deletion never finishes when a recorded member's Container is already gone** — `rdd/pkg/controllers/containers/compose/compose_reconciler.go:242-246` [Codex GPT 6 Astra, Claude Opus 5.5]

```go

			if err == nil {
				err = r.Delete(ctx, &c)
			}
			errs = append(errs, client.IgnoreNotFound(err))
```

The reconciler updates `status.containers` only when it handles a Container event, so a member whose Container goes away unhandled stays listed. The only route found to that state is rdd exiting with the deletion still queued, which the engine's stop path makes possible by deleting every Container mirror at once (`watch_reconciler.go:421`). The probe sets up that state directly.

Deleting the project then never finishes. If `down` fails, this loop gets NotFound and deletes nothing, and line 263 requeues only for an empty list, so the project stalls. If `down` succeeds, line 287 drops the state and requeues after a second, and the next pass starts `down` again, indefinitely. Both contradict `api_containers.md:749-751`. The finalizer that holds the project is new in this PR.

Updating a settled request goes through `initiateUp` at line 84. When `docker compose up` cannot start, line 144 sets Settled from True to True, and `SetStatusCondition` keeps the old `LastTransitionTime` when the status does not change. So the reap at line 88 counts from the previous run. A request updated 9m30s after it settled is reaped 29 s after its new failure, although `api_containers.md:39-40` promises at least a minute and `:814-815` promise that an updated spec postpones reaping until its own `up` completes. I4. **Linux `kill` still fails with EINVAL on kernels before 6.9** — `rdd/pkg/controllers/containers/compose/command_linux.go:105-109` [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash]

```go
	err := process.WithHandle(func(handle uintptr) {
		innerErr = unix.PidfdSendSignal(int(handle), syscall.SIGTERM, nil, PidfdSignalProcessGroup)
		if innerErr != nil {
			return
		}
```

Round 1 raised this as I8; the code is unchanged. Before Linux 6.9, `pidfd_send_signal(2)` rejects any nonzero flags with EINVAL, so the SIGTERM call fails and `kill` returns without signalling anything. Deleting the object then leaves the process running, with the error logged only at V(1). A spec update cannot kill the running `up` either, so `initiateUp` fails with backoff until the old `up` exits. The comment at lines 20-22 says 6.9 covers every supported kernel, but rdd's Linux code runs on the desktop's own kernel, and Ubuntu 24.04 shipped with 6.8.

Unproven: no kernel older than 6.9 was available to run it on; the comment at line 21 states the same floor.

Fix: on EINVAL, signal the process group by negative PID for both signals, after checking `c.done`, since a PID-based kill loses the pidfd's guard against PID reuse; or document the kernel floor.

```go
if errors.Is(innerErr, unix.EINVAL) { // kernels before 6.9
	innerErr = unix.Kill(-process.Pid, syscall.SIGTERM)
}
```

### Concerns

- **The run key is half migrated** (in-scope). The ComposeUpRequest reconciler restarts by generation (`compose_up_request_reconciler.go:106`), while `run` still de-duplicates by resourceVersion (`compose_process.go:121-141`). ### Strengths

- **A spawn failure is a finished run.** Recording it in the tracker lets both reconcilers settle it through the same branch as a failed exit. [Claude Opus 5.5, Codex GPT 6 Astra]
- **The finalizer is part of `Create`** (`compose_reconciler.go:395`), which closes round 1's S3 window between creation and the finalizer. [Codex GPT 6 Astra, Gemini 3.5 Flash]

###### Design Observations

###### Concerns

- **Generation and resource-version responsibilities remain mixed — (in-scope).** `processTracker.run` still deduplicates by resourceVersion (`compose_process.go:121–125`), while the request reconciler now decides restart eligibility by generation. Current callers avoid restarting merely because status changed, so the original observable defect is fixed. Document those separate responsibilities or make the tracker accept an explicit run identity; otherwise a future caller can accidentally restart work on a status-only update.

- **Temporary-directory fallback remains triplicated — (in-scope).** Each OS performs its own retry and error classification. A shared working-directory selection helper would remove this divergence, while platform spawners retain responsibility for process setup. It must preserve genuine permission errors rather than treating every failure as a missing directory.

- **Executable discovery still depends on the daemon’s PATH — (future).** `compose_process.go:102` selects bare `docker`; `command.go:110` supplies the daemon’s inherited environment. Resolve the bundled executable through the instance’s binary location when discovery work lands.

- **nerdctl detection remains an independent gap — (future).** The dependency manifest still pins nerdctl 2.1.2 (`rdd/dependencies.yaml:62`), and membership still requires `config-hash` (`compose_reconciler.go:377–380`). The round-one conclusion remains consistent with those files. The pinned nerdctl label-writer source was not available in the permitted tree, so that producer-side claim was not independently re-executed or re-read here.

###### Strengths

- Finalizers are now attached atomically during ComposeProject creation.
- Process completion records the generation that actually ran.
- The fallback requests Container deletion and leaves engine cleanup to the Container finalizer; it does not strip another controller’s finalizer.
- Injectable commands make the important lifecycle cases testable without Docker, a VM, or envtest.

1. **UID Mismatch Loop**: `Abort` is called with the *new* `upReq.UID` instead of `processUID`. Since the UIDs don't match the tracker's record, `Abort` silently returns. The reconciler requeues, but the old process remains, looping forever. (Same bug in `compose_reconciler.go:121-125`).

I1. **Linux process termination fails with EINVAL on kernels prior to 6.9** — `rdd/pkg/controllers/containers/compose/command_linux.go:20-23,103-107` (important, regression)

```go
// PidfdSignalProcessGroup is the flag for [unix.PidfdSendSignal] to send the
// signal to the process group.  Introduced in Linux 6.9, released in (and EOLed
// in) 2024; that covers all kernels we want to support, include SLES 16 and WSL.
const PidfdSignalProcessGroup = 4
```

`unix.PidfdSendSignal` passes `PidfdSignalProcessGroup = 4` unconditionally at `command_linux.go:104,111`. Linux kernels before 6.9 reject any nonzero flags with `EINVAL`. Ubuntu 24.04 LTS shipped with GA kernel 6.8, and SLES 15 SP6 uses kernel 6.4. On these supported desktop hosts, `c.kill()` fails immediately with `EINVAL` without signalling the process group or process. Consequently, `r.procs.abort` at `compose_reconciler.go:110,121` and `compose_up_request_reconciler.go:56,71` logs at V(1) while the child process continues running unhindered.

Unproven: requires a Linux host running kernel 6.8 or earlier; verified against the `pidfd_send_signal(2)` kernel contract where `flags` must be 0 prior to Linux commit `e8b9013f43` (v6.9).

Fix: fallback to signalling the process directly with flag 0, or signal the process group via `syscall.Kill(-cmd.Process.Pid, ...)` (enabled by `Setpgid: true` at `command_linux.go:41`):

```diff
--- a/rdd/pkg/controllers/containers/compose/command_linux.go
+++ b/rdd/pkg/controllers/containers/compose/command_linux.go
@@ -102,3 +102,7 @@ func (c *concreteCommandExecutor) kill(ctx context.Context) error {
 	var innerErr error
 	err := process.WithHandle(func(handle uintptr) {
 		innerErr = unix.PidfdSendSignal(int(handle), syscall.SIGTERM, nil, PidfdSignalProcessGroup)
+		if errors.Is(innerErr, unix.EINVAL) {
+			innerErr = syscall.Kill(-c.Process.Pid, syscall.SIGTERM)
+		}
```
