## Important Issues

I1. **The spec doesn't pin the order of `hideSplash()`, the error box and `app.quit()`** — `pkg/rancher-desktop/window/__tests__/index.spec.ts:93-96` [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.5 Flash]

```ts
    expect(hideSplash).toHaveBeenCalled();
    expect(showErrorBox).toHaveBeenCalledTimes(1);
    expect(showErrorBox).toHaveBeenCalledWith(expect.stringContaining('Fatal Error'), expect.stringContaining('(ERR_UNEXPECTED)'));
    expect(quit).toHaveBeenCalled();
```

The failure test checks that each call happens. It doesn't check their order, so moving `hideSplash()` after the box, or `app.quit()` before it, in `failStartup()` (`window/index.ts:92-94`) leaves all 9 tests passing.

Both orders matter, and a mistake in either would show only on a rare error path that manual testing is unlikely to reach. A late `hideSplash()` leaves the spinner beside the box. #1341's round 1 fixed that defect for the "Incompatible RDD Service" box, and `rdd-ctl.spec.ts:100` pins its order.

An early `app.quit()` runs the `before-quit` handlers, and one of them destroys a FirstRun window (`window/index.ts:860-864`). That window's `closed` listener then closes the splash, the last window, so on macOS the dock icon hides and the box opens behind the frontmost app (reasoned from the measured `window-all-closed` behaviour, not run).

## Suggestions

S1. **The failure path's quit now logs "User triggered quit during first-run"** — `background.ts:153` [Claude Opus 5.5]

```ts
  if (lifetimeState === LifetimeState.ShuttingDown) {
    console.log('User triggered quit during first-run');

    return;
  }
```

When a hidden FirstRun window fails to load, `failStartup()` calls `app.quit()`. The `before-quit` handler (`background.ts:252-272`) sets `ShuttingDown` and emits `mainEvents` `before-quit`, whose listener destroys the FirstRun window (`window/index.ts:860-864`).

The window's `closed` event resolves `openFirstRunDialog()` (`window/index.ts:692-694`), and `initUI()` then logs that the user quit. But the error box caused the quit, and the startup timing line in the same `background.log` names `first-window-failed`. So the log contradicts itself for anyone diagnosing the failure.

Fix: drop the cause from the message, for example `console.log('Quitting during first-run');`.

S2. **The spec doesn't assert the `reportStartup()` call that the failure path now makes** — `pkg/rancher-desktop/window/__tests__/index.spec.ts:38` [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.1 Pro, Gemini 3.5 Flash]

```ts
  '@pkg/utils/startupTiming': { markStartup, reportStartup: jest.fn() },
```

This commit moves `reportStartup()` into `recordStartupEnd()` (`window/index.ts:73`), so the failure path writes the timing line before the box blocks. The spec mocks the function inline and never asserts it, and deleting the call leaves all 9 tests passing.

The test is optional, because the `will-quit` handler (`background.ts:274-278`) still writes the line, only later. The failure path and the success path now share that one call. So an assertion in the failure test also catches a deletion on the success path, the gap that #1341's round-2 S1 lists.

Fix: hoist the mock into `const reportStartup = jest.fn()`, clear it in `beforeEach`, and assert it in the failure test.

## Design Observations

### Concerns

- **(in-scope)** Showing only the error description in the box is an open question. Both measured failures arrive as `ERR_UNEXPECTED`, so every user sees "(ERR_UNEXPECTED)", which they can't act on or usefully attach to a report. The URL and the code reach only the log. Naming the log directory in the box, as `fatalError.showLogsErrorDetail` does, would point the user at the line that names the URL. [Claude Opus 5.5, Gemini 3.5 Flash]
- **(future)** Skipping -3 changes one case that the app can't reach today. For a visible first window, an aborted load used to end startup and close the splash; now the splash stays until `did-finish-load` or `closed`. The app never stops a load itself, so only a page that aborts its own load would hit this. [Claude Opus 5.5]

### Strengths

- **(in-scope)** English is enough for this box. The main process changes its locale only when a renderer sends `i18n/locale-change` (`main/i18n.ts:137-144`, sent only from `store/i18n.ts:239`). When the first window fails, the app hasn't run a renderer yet, so `t()` renders the title and the message in en-us whatever the user's language. [Claude Opus 5.5]
- **(in-scope)** Moving the listener out of the visible-only branch also covers the DenyRoot and UnmetPrerequisites dialogs. `openDialog()` creates both hidden, before `initMainI18n()` runs. `t()` works there, because en-us loads with the module (`main/i18n.ts:22`). [Claude Opus 5.5]
- **(in-scope)** `recordStartupEnd()` sets `startupFinished` and writes the timing line before the box blocks. So a queued `did-fail-load` can't open a second box, and the timing line reaches the log even if the user never dismisses the box. [Claude Opus 5.5, Gemini 3.5 Flash]
- **(in-scope)** Hiding the splash keeps the box in front on macOS, where closing it would deactivate the app, as #1341's round 1 measured. [Codex GPT 6 Astra, Gemini 3.1 Pro, Gemini 3.5 Flash]

##### Design Observations

**Concerns**

- **Choice 6, what the box shows (in-scope, open question).** By the author's own probe, both measured failures (a missing page file, a refused dev server) reach the window as `ERR_UNEXPECTED`. The box therefore always says "…could not load its user interface (ERR_UNEXPECTED) and will quit." A user can't act on that and can't attach anything useful to a report. The URL and code go only to `window_browser.log`. An alternative is to name the log directory in the box (`paths.logs`), as `fatalError.showLogsErrorDetail` already does elsewhere. That would point the user at the line that names the URL. This is a question, not a defect.
- **Choice 2, translations (observation, supports the choice).** The main process changes locale only when a renderer sends `i18n/locale-change` (`main/i18n.ts:137-144`; the only sender is `store/i18n.ts:239`). When the first window fails to load, no app renderer has run (the splash is a sandboxed data URL), so `t()` always renders this box in en-us. Translating `windowLoadFailed` into other locales would change nothing in this path, so keeping it in en-us only costs nothing.
- **Choice 3, skipping -3 (observation).** I agree with skipping `ERR_ABORTED`; nothing in the app calls `webContents.stop()`. One trade-off, unreachable today: for a visible first window, -3 used to end startup through `finishStartup('first-window-failed')`. Now it leaves the splash up until `did-finish-load` or `closed` arrives. If a page ever aborted its own load (`window.stop()`) without a later `did-finish-load`, the splash would stay up over the main window. No such page exists.
- **Choice 4, the `startupFinished` guard (observation).** For a hidden first window, the guard flips on `show`, not on `did-finish-load`. A main-frame failure between a successful load and `dialog/ready` would still show the box. The hash-routed dialogs can't produce one, and a `will-navigate` cancel arrives as -3, which is skipped. No concern.

**Strengths**

- Moving the listener out of the `else` branch covers every hidden first window: FirstRun, and also DenyRoot (`checkForRootPrivs`) and UnmetPrerequisites (`checkPrerequisites`). The last two open before `initMainI18n()`. `t()` still works there, because `main/i18n.ts:22` loads en-us when the module loads.
- `recordStartupEnd()` sets `startupFinished` before the blocking box. A re-entrant or queued `did-fail-load` therefore cannot open a second box. And because the timing report is written before the box blocks, it reaches the log even if the user never dismisses the box.
