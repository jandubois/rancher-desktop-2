## Executive Summary

This round replaces the hand-built flag parser with kubectl's own command tree and limits the recursion guard to the probe. Both changes hold, and each round-2 fix to the resolver's behavior has a test that fails without it. But two client-only paths still reach the resolver. `kubectl kuberc` runs in a downloaded kubectl that predates the command, and TAB completion of `config` commands probes the cluster. And no test pins the Password clearing that keeps the probe off stdin.

I1. **`rdd kubectl kuberc` runs in a downloaded kubectl that lacks the command** — `rdd/pkg/kuberlr/resolver.go:239-246` [Codex GPT 6 Astra, Claude Opus 5.5]


`clientOnlySubcommands` omits `kuberc`, so `kuberc view` and `kuberc set` probe the cluster like any cluster-bound command. At the merge-base, the embedded kubectl ran it, and `cmd_other.md` still promises that client-only commands run the embedded kubectl.

## Suggestions

S1. **Plugin arguments are read as kubectl connection flags** — `rdd/docs/design/cmd_other.md:21` [Claude Opus 5.5, Codex GPT 6 Astra]

```markdown
The probe parses the command line through kubectl's own command tree, so it contacts the cluster that kubectl will contact and applies the user's kuberc, both its defaults and its credential plugin policy. A separate flag parser in rdd would get attached shorthand values such as `-ojson` wrong and would not see kuberc. In exchange, `rdd kubectl` stops on a kuberc that the embedded kubectl rejects, even when the kubectl it would run is older and ignores kuberc.
```

For a kubectl plugin, `parseCommandLine` parses the plugin's own arguments with the root command's flags (`resolver.go:213-218`), so a plugin flag that matches a kubectl flag sets the probe's target. For example, `myplugin -ojson` sets the server to `on`. kubectl itself does not contact a cluster for a plugin; the plugin decides. The probe then usually fails and the embedded kubectl runs, as at the merge-base, so the harm is small. But this sentence and the commit message promise "the cluster that kubectl will contact", and the `parseCommandLine` comment does not mention plugin arguments.

Fix: say "the cluster that kubectl's flags and kuberc select", and name plugin arguments beside the alias limitation in the `parseCommandLine` comment.

S2. **No test pins `Exec`'s exit code on Windows** — `rdd/pkg/kuberlr/exec_windows.go:30-32` [Gemini 3.5 Flash]

```go
	if exitErr := cliexit.ChildExit(err); exitErr != nil {
		return exitErr
	}
```

Round 2 moved this conversion into `cliexit.ChildExit`, and no test covers the exit code that `Exec` returns: `pkg/cli/exit` has no test file, and the fake kubectl in `7-kubectl-cache.bats` always exits 0. Without the conversion, every failing kubectl on Windows would exit 1 behind a `running …: exit status N` message, so a script could no longer tell `kubectl diff`'s exit 1 (differences found) from its exit 2 (an error). The message names the cause, so the test is optional. The Windows `test-rdd` job runs this package's unit tests, so a Windows-only test that runs `cmd /c exit 3` through `Exec` does not need new setup.

Fix: add that test, asserting a `*cliexit.Error` with code 3.

## Design Observations

### Concerns

- **A cluster-bound completion can download a kubectl out of sight** `(in-scope)` [Claude Opus 5.5] — With I2's patch, `kubectl get pods <TAB>` still probes, which is right, because the matching kubectl completes it. But against a skewed cluster with an empty cache, that TAB starts the 50 MB download, and cobra's bash and zsh scripts discard its stderr (`2>/dev/null`), so the shell hangs with no notice for as long as the download takes. Completion could use only the cache, and fall back to the embedded kubectl on a miss.
- **A credential plugin that calls kubectl runs once more per call** `(future)` [Claude Opus 5.5] — This round stopped passing the recursion guard to the cached kubectl's children, as round 2 asked. So when the cached kubectl runs a kubelogin plugin (`kubectl oidc-login get-token`), that call re-enters `rdd kubectl`, finds `oidc-login` unknown, probes, and runs the plugin a third time. It adds to the declined double-run item below.

### Strengths

- **Parsing through kubectl's own command tree** `(in-scope)` [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.1 Pro, Gemini 3.5 Flash] — attached shorthand values, kuberc defaults, alias options and the credential plugin policy all come from kubectl itself. Building the tree costs a few milliseconds per call (1–6 ms measured cold on an M1).
- **The recursion guard covers the probe and nothing else** `(in-scope)` [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.1 Pro, Gemini 3.5 Flash] — the deferred `Unsetenv` clears it on every return path before `Exec` or the in-process kubectl runs, and `TestResolveSetsRecursionGuardWhileProbing` fails when either the set or the unset is removed.
- **Separate deadlines for the marker and the download** `(in-scope)` [Codex GPT 6 Astra, Gemini 3.5 Flash] — `markerTimeout` bounds the lookup that runs on every cache miss, while the 50 MB transfer keeps its 5-minute limit.

###### Highest-Risk Surface: `parseCommandLine` and `probeServerVersion`

###### 1. Process-Global Effects of Constructing the Command Tree

- **Kuberc parsing & exit**: `NewKubectlCommand` calls `pref.Apply(cmds, kubeConfigFlags, o.Arguments, o.IOStreams.ErrOut)` (`k8s.io/kubectl@v0.36.4/pkg/cmd/cmd.go:375`). If kuberc fails to load or validate, it calls `os.Exit(1)` after writing to `ErrOut` (`os.Stderr`). Non-fatal warnings (e.g. strict decoding errors, or command override warnings in `pkg/kuberc/kuberc.go:121`) are printed to `ErrOut`. When `Resolve` falls through to the embedded kubectl, `NewDefaultKubectlCommand` is constructed again, causing non-fatal kuberc warnings to be printed to stderr twice.
- **Package globals**: `utilcomp.SetFactoryForCompletion(f)` in `k8s.io/kubectl/pkg/util/completion/completion.go:50` mutates package-level variable `factory = f`. When `NewDefaultKubectlCommand` runs later, it cleanly overwrites `factory`. No other package globals are modified.
- **Deprecated flag output**: Cobra captures pflag deprecation notices inside `cmd.flagErrorBuf` and prints them via `c.Print()` (`command.go:1885`), which writes to `c.OutOrStdout()`. Because `parseCommandLine` calls `root.SetOut(io.Discard)` on line 209, Cobra suppresses deprecation notices during resolution, preventing double printing.

###### 2. Network, Plugin, and Stdin Safety

- **Plugins**: Neither tree construction, `root.Find`, nor `ParseFlags` executes plugins. `PluginHandler` is `nil` in `parseCommandLine`'s `KubectlOptions`, and plugin execution is confined to `HandlePluginCommand` in `NewDefaultKubectlCommandWithArgs`. `root.Find` is string matching on command nodes.
- **Stdin**: Does not read stdin. Line 225 clears `cf.Username, cf.Password = nil, nil`. In `k8s.io/cli-runtime/pkg/genericclioptions/config_flags.go:250`, `f.Password == nil` selects `NewNonInteractiveDeferredLoadingClientConfig`, preventing interactive stdin prompts.
- **Network**: Does not contact the network. Command factory setup and flag parsing are purely in-memory.

###### 3. Per-Invocation Construction Overhead

Measured on macOS ARM64 (Apple M1, Go 1.27):
- `parseCommandLine` for standard commands (`kubectl get pods -n default`): **3.84 ms/op**, 1.36 MB/op, 10,330 allocs/op (or **2.58 ms/op** with `KUBERC=off`).
- `parseCommandLine` for shell completion (`kubectl __complete get pods`): **7.44 ms/op**, 1.39 MB/op, 10,836 allocs/op.

###### 4. Subcommand Dispatch and Target Cluster

- **`__complete` / `__completeNoDesc`**: Cobra adds these commands dynamically in `ExecuteC()`. `root.Find` returns `findErr != nil`, but flags parse cleanly because `UnknownFlags = true`. Line 231 returns `clientOnly = false, cf, nil`. The probe targets the cluster specified in flags or current-context, executing a remote discovery request during tab completion (see issue I1).
- **`kubectl plugin list`**: `plugin` is a registered subcommand and is present in `clientOnlySubcommands` (`resolver.go:244`). Returns `clientOnly = true`, targeting no cluster.
- **`kubectl <plugin> --context other`**: `root.Find` returns `findErr != nil`. Line 219 switches to `root`, which parses persistent flag `--context other` into `*cf.Context = "other"`. Line 231 returns `clientOnly = false, cf, nil`. The probe targets cluster `"other"`, precisely matching the cluster kubectl will contact.

###### 5. Recursion Guard Environment Mutation

- `probeServerVersion` (`resolver.go:121-127`) calls `os.Setenv(envSkipResolver, "1")` and registers `defer os.Unsetenv(envSkipResolver)`. On every return path, the variable is unset before `Exec` runs and before embedded kubectl runs.
- Subprocesses spawned during `ServerVersion()` (specifically exec credential plugins) inherit `os.Environ()` and see `RDD_KUBECTL_RESOLVED=1`.
- `TestResolveSetsRecursionGuardWhileProbing` fails if the variable is set in the child environment instead: the test's mock credential plugin checks `${RDD_KUBECTL_RESOLVED}` during the probe and writes it to a file; without process-level inheritance during the probe, `assert.Equal(t, string(got), "1")` fails.

###### 6. Kuberc Sequence Parity

- **Applied**: Kuberc preference decoding, `credentialPluginPolicy` via `WithWrapConfigFn`, and default flag values on aliased commands.
- **Omitted**: Prepended and appended arguments on aliases (kuberc hands rewritten arguments to `cmd.Execute`, which `parseCommandLine` never executes). Aliases to client-only subcommands are treated as cluster-bound because the alias name is not in `clientOnlySubcommands`.

###### 7. Cli-Runtime Password Prompting

- Confirmed in `k8s.io/cli-runtime/pkg/genericclioptions/config_flags.go:250-254`: `f.Password != nil` constructs `NewInteractiveDeferredLoadingClientConfig` with `os.Stdin`, which prompts when authentication requires a password.
- Setting `cf.Username, cf.Password = nil, nil` does not alter cluster or user selection: clusters are selected via `f.ClusterName`/`f.Context`, and users via `f.AuthInfoName`/`f.Context` (`config_flags.go:200-205`). Clearing username and password only suppresses basic authentication overrides.

###### Concerns

1. **Full Command Tree Construction on Every Invocation** `(in-scope)`
