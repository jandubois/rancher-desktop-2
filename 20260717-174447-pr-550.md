## Important Issues

I1. **Deletion guard is bypassable by an unguarded update** — `rdd/pkg/controllers/app/k3sversions/controller.go:89-93` [Codex GPT 5.5]

```go
		ObjectSelector: metav1apply.LabelSelector().
			WithMatchLabels(controllers.DesiredLabels()),
		Operations: []admissionregistrationv1.OperationType{
			admissionregistrationv1.Delete,
		},
```

The webhook filters deletes through an `ObjectSelector` on the managed labels and registers only for `Delete`; `ValidateUpdate` (`k3s_versions_validator.go:65`) allows every update. Since no webhook guards updates, a client can first strip a managed label or the App owner reference, then delete — the selector no longer matches, or `getApp` returns nil for a missing owner, so the delete is admitted. That defeats the "not deletable while App exists" contract asserted at `k3s-versions.bats:57`. The sibling Lima `ConfigMapValidator` guards this exact case: it registers Create/Update/Delete and rejects removing its routing label (`limavm/controller.go:296`). The reconciler restores the labels, owner reference, and data on the next reconcile, so on a single-user control plane the practical risk is a race, not a security hole — but the guard is not deterministic.

Fix: register the webhook for `Update` and reject removal of the labels or owner reference while the App exists, mirroring the Lima validator.

```diff
 		Operations: []admissionregistrationv1.OperationType{
+			admissionregistrationv1.Update,
 			admissionregistrationv1.Delete,
 		},
```

## Suggestions

S1. **`GetVersions` returns shared cached maps** — `rdd/pkg/controllers/app/k3sversions/controllers/k3s_versions.go:94` [Gemini 3.1 Pro]

```go
func GetVersions() (K3sVersions, error) {
	return k3sVersions()
}
```

`k3sVersions()` is cached with `sync.OnceValues`, and `K3sVersions` holds two maps. `GetVersions` copies the struct but shares the underlying maps; the App defaulter and validator then hold those maps for the process lifetime. No caller mutates them today — the admission paths only read (`app_defaulter.go:70`, `app_webhook.go:60`) — so this is a latent footgun, not a live bug, the same class Round 1 fixed for `DesiredLabels`. Gemini rated it Important; checking the callers downgrades it, since corruption would need a mutation that does not exist.

Fix: return `maps.Clone` copies of `Versions` and `Channels`, matching the `DesiredLabels` fix.

S2. **BATS: command substitution swallows the exit status** — `rdd/bats/tests/32-app-controllers/k3s-versions.bats:49-50` [Gemini 3.1 Pro, Gemini 3.5 Flash]

```bash
    channels=$(jq_output '.data.channels')
    versions=$(jq_output '.data.versions')
```

`jq_output` wraps `run jq`, so command substitution discards its exit status: a failed query leaves `channels` empty and surfaces later as an opaque error in the following `run -0 jq`. The repo's BATS convention (bats-style memory) is `run -0` for capture, not `$(...)`. The direct `jq_raw '.data.hello'` call at line 83 shares the pattern.

Fix: capture with `run -0`, then read `${output}`.

```diff
-    channels=$(jq_output '.data.channels')
-    versions=$(jq_output '.data.versions')
+    run -0 jq_output '.data.channels'
+    channels=${output}
+    run -0 jq_output '.data.versions'
+    versions=${output}
```

## Design Observations

### Concerns

- **The reconciler races the App controller's namespace creation** `(future)` [orchestrator verification] — the k3s reconciler creates the ConfigMap in `app.Spec.Namespace`, but the App controller creates that namespace on the same App-create event (`app_controller.go:289`). If the reconciler runs first, `CreateOrUpdate` fails with "namespace not found," returns a wrapped error, and requeues with backoff — logging an ERROR each attempt until the namespace appears. It self-heals, and the reconciler already returns a quiet result when `app.Spec.Namespace` is empty (`k3s_versions_reconciler.go:68`); it could treat a not-found namespace the same way to keep startup logs clean.
- **Lexical version sort on duplicate builds** `(future)` [Gemini 3.5 Flash] — `slices.Sorted` orders k3s builds lexically, so `+k3s10` sorts before `+k3s2`. If the embedded JSON ever held two builds of one bare version, the lexically-last would win and could pick the older build. The static list has no duplicates, so this cannot fire today.

### Strengths

- **App-scoped, App-owned ConfigMap fits the no-GC control plane** `(in-scope)` [Codex GPT 5.5, Gemini 3.1 Pro, Gemini 3.5 Flash] — moving the ConfigMap into `App.spec.namespace` and tying cleanup to App ownership (via `DeleteOwnedResources`) resolves the Round 1 immortal-ConfigMap and cross-namespace concerns; deletion now cascades correctly. The App is cluster-scoped, so the owner reference on a namespaced ConfigMap is valid, not a cross-namespace violation.
- **The reconciler self-heals deterministically** `(in-scope)` [Gemini 3.5 Flash] — it owns and watches the ConfigMap and restores data, labels, and owner reference on drift, and it skips recreation while the App is being deleted, so it does not fight cleanup.
- **Custom webhook paths fix a real collision** `(in-scope)` [Gemini 3.5 Flash] — name-based `/{validating|mutating}-<name>` paths let multiple ConfigMap validators coexist on one port; verified safe when only a validator or only a defaulter is present, since the nil side registers no configuration.
- **Reused parsed version data keeps admission off the control plane** `(in-scope)` [Codex GPT 5.5, Gemini 3.5 Flash] — the defaulter, validator, and reconciler share the embedded `K3sVersions` rather than reading the ConfigMap back through the API server.

## Review Process Notes

### Skill improvements

- When an admission webhook filters its targets through an `ObjectSelector` on mutable labels, or gates its decision on mutable metadata such as owner references, and registers for only some operations (commonly Delete but not Update), check whether an unguarded operation can remove the selector metadata. A client that strips the routing label or owner reference through an unguarded Update, then performs the "guarded" operation, bypasses the webhook — the API server never routes the request to it. Flag such a guard as non-deterministic unless the Update path is also registered and rejects removal of the routing metadata while the guard should hold. A reconciler that restores the metadata narrows the window to a race but does not close it.

### Repo context updates

- [repo] The reference implementation for a deletion-guard webhook keyed on a label `ObjectSelector` is the Lima `ConfigMapValidator` (`pkg/controllers/lima/limavm/controller.go`): it registers Create, Update, and Delete, and its `ValidateUpdate` rejects removing the routing label while the resource is owned. A new label-selected guard that registers only Delete and allows all updates is bypassable — compare any such guard against this pattern.
- [repo] The `App` resource is cluster-scoped (`+kubebuilder:resource:scope=Cluster`), and its `spec.namespace` names the namespace holding its namespaced children (the k3s-versions ConfigMap, LimaVM). An App owner reference on a namespaced resource is therefore valid, not a cross-namespace ownership violation; `base.DeleteOwnedResources` resolves the target namespace through the `ResourceNamespace` interface (`GetResourceNamespace`). Do not flag an App-owned namespaced resource as a cross-namespace owner reference.

#### Critical Issues

**C1. App webhook rename breaks BATS suite** — `rdd/pkg/controllers/app/app/controller.go:127-129` (critical, regression)

```go
	config := base.WebhookConfig[*v1alpha1.App]{
		Name:        ControllerName,
		WebhookName: "app-webhook.app.rancherdesktop.io",
```

By consolidating the previously separate `appValidatorConfigName` (`"app-validator"`) and `appDefaulterConfigName` (`"app-defaulter"`) into a single `WebhookConfig` named `ControllerName` (`"app"`), the Kubernetes `ValidatingWebhookConfiguration` object is now named `"app"` rather than `"app-validator"`, and its target webhook is now `"app-webhook.app.rancherdesktop.io"`.

The BATS suite in `rdd/bats/tests/32-app-controllers/app.bats` still hard-codes the old names and will fail on a timeout and an assertion mismatch:
`rdd ctl wait --for=create ValidatingWebhookConfiguration app-validator --timeout=60s`

Fix: Update the assertions in `rdd/bats/tests/32-app-controllers/app.bats` to expect the new configuration and webhook names:
```bash
APP_VALIDATOR_CONFIG="app"
...
    assert_output "app-webhook.app.rancherdesktop.io"
```

#### Important Issues

**I1. `GetVersions()` exposes a shared mutable map** — `rdd/pkg/controllers/app/k3sversions/controllers/k3s_versions.go:94-96` (important, regression)

```go
// GetVersions returns the supported Kubernetes versions and channels.
func GetVersions() (K3sVersions, error) {
	return k3sVersions()
}
```

The underlying `k3sVersions()` is cached via `sync.OnceValues`. `K3sVersions` is a struct containing map fields (`Versions` and `Channels`). When `GetVersions()` is called, it returns a value-copy of the struct, but the map fields themselves are references to the shared underlying maps. Any caller that mutates the returned maps will silently mutate the global singleton, creating race conditions across controllers.

This is the exact same class of issue correctly fixed in the previous round for `DesiredLabels()`. 

Fix: Deep-clone the maps before returning them across package boundaries:
```go
func GetVersions() (K3sVersions, error) {
	versions, err := k3sVersions()
	if err != nil {
		return K3sVersions{}, err
	}
	return K3sVersions{
		Versions: maps.Clone(versions.Versions),
		Channels: maps.Clone(versions.Channels),
	}, nil
}
```

#### Suggestions

**S1. BATS: Command substitution swallows exit status** — `rdd/bats/tests/32-app-controllers/k3s-versions.bats:49-50` (suggestion, enhancement)

```bash
    channels=$(jq_output '.data.channels')
    versions=$(jq_output '.data.versions')
```

Following the project's BATS conventions, command substitution `$(...)` swallows non-zero exit codes. If `jq_output` fails (e.g. because the JSON path yields `null`), the test will not fail at the extraction point. The variables will just be empty, and the subsequent `run -0 jq` will fail with an opaque error rather than properly surfacing the upstream extraction failure. (This also applies to `jq_raw` at line 80).

Fix: Capture using `run -0` to surface failures immediately:
```bash
    run -0 jq_output '.data.channels'
    channels="${output}"
    run -0 jq_output '.data.versions'
    versions="${output}"
```

##### S2. Command substitution swallows non-zero exits in BATS tests — `rdd/bats/tests/32-app-controllers/k3s-versions.bats:49-50`

### Design Observations

#### Strengths

- **Lifecycle Consistency**: Aligning the `ConfigMap`'s namespace and lifecycle with the `App` resource's own target namespace resolves cross-namespace ownership and allows proper garbage collection when the `App` is deleted.
- **Robust Self-Healing**: Setting a controller reference on the `ConfigMap` and watching it ensures any manual modifications or accidental deletions are automatically and immediately reverted.
- **Conflict Prevention**: Moving to named custom paths in `GenerateWebhookPath` elegantly prevents endpoint collisions for shared resource types (such as multiple `ConfigMap` validator webhooks) on the same port.
