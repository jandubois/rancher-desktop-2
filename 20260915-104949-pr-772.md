## Executive Summary

This PR mirrors a containerd namespace whose name is not a valid object name as `cns-<sha256>`, as #651 specifies. But #651 pairs that name with `status.name`, which `ContainerNamespace` still lacks, so a hashed mirror records nothing that names its namespace (I1). One BATS test and nine doc statements still say such a namespace gets no mirror (I2, I3), and the test still passes because its mirror assertion cannot fail.

All four reviewers found I1, at three different severities. Claude, Codex and Gemini 3.1 Pro found the stale test, and Claude and Codex the stale docs. Claude also raised the two suggestions nobody else did (S1, S4). I proved each Important finding with a probe run at the merge-base and the PR head, and checked a patch for each; the BATS patch passes lint but needs a VM to run.

## Important Issues

I1. **Hashed `ContainerNamespace` mirror records nothing that names its containerd namespace** — `rdd/pkg/controllers/app/engine/controllers/sync_namespace_containerd.go:74-76` [Claude Opus 5, Codex GPT 5.6 Sol, Gemini 3.1 Pro, Gemini 3.5 Flash]

```go
	applyConfig := containersv1alpha1apply.ContainerNamespace(
		containerdNamespaceMirrorName(ns),
		w.apiNamespace)
```

#651's spec pairs the `cns-<sha256>` name with `status.name`, the engine's name for the namespace (`rdd/docs/design/api_containers.md:142-145`), and every `status.namespace` field joins on it (lines 210-211, 431-432). This PR adopts the name only.

`ContainerNamespace` has only `ObjectMeta` (`rdd/pkg/apis/containers/v1alpha1/container_namespace_types.go:20-27`). Until now each mirror's name was the engine's name. Now a client holding `Container.status.namespace: Not_Valid` can find the mirror only by recomputing the hash.

`Volume` pairs a hashed name with a selectable `status.name` (`rdd/pkg/apis/containers/v1alpha1/volume_types.go:56-58`).

Gemini 3.1 Pro rated this Critical, and Codex a Suggestion because the merge-base lacked the field too. Nothing breaks today, since the renderer hides namespaces while `supportsNamespaces()` returns `false`. It is still Important. The PR claims #651 and creates the first mirrors whose name differs from the engine's.

## Suggestions

S1. **`containerdNamespaceMirrorName` has no doc comment and no unit test, unlike its siblings** — `rdd/pkg/controllers/app/engine/controllers/sync_namespace_containerd.go:91-97` [Claude Opus 5]

```go
func containerdNamespaceMirrorName(ns string) string {
	if len(validation.IsDNS1123Subdomain(ns)) == 0 {
		return ns
	}
	hash := sha256.Sum256([]byte(ns))
	return fmt.Sprintf("cns-%x", hash[:])
}
```

Its siblings `containerdMirrorName` and `containerdImageMirrorName` document their naming rule, and unit tests pin them (`rdd/pkg/controllers/app/engine/controllers/sync_containers_containerd_test.go:20-65`). This helper defines a name clients now compute, and it has neither.

It also shares the container helper's collision caveat. `cns-90fc85…e8` is itself a legal containerd namespace name (containerd v2.3.5 accepts alphanumeric runs joined by `.`, `_` or `-`, up to 76 characters), and it maps to the same mirror as `Not_A_Valid_Kubernetes_Namespace`. Removing either namespace deletes the shared mirror until the next event or full sync re-applies it. The control plane is single-user, so the risk is low.

Fix: add a doc comment that states the rule and the collision, and a table test that pins `k8s.io` unchanged and `Not_A_Valid_Kubernetes_Namespace` to `cns-90fc85ba911fb94cb359ad53ab3e07257f4f8d395615ad1908e57d39478e09e8`.

```go
// containerdNamespaceMirrorName returns the ContainerNamespace mirror name for
// a containerd namespace. That is the name itself when it is a valid object
// name, and "cns-" plus the hex SHA-256 of the name otherwise. A namespace
// literally named like another's hash shares that mirror; nobody picks such
// names, so the collision stays theoretical.
```

S2. **No test covers how the full sync keys hashed mirrors** — `rdd/pkg/controllers/app/engine/controllers/sync_namespace_containerd.go:43` [Codex GPT 5.6 Sol, Claude Opus 5]


Reverting this line to `activeNames[ns] = true` makes every full sync apply a hashed mirror and prune it in the same pass, and no test fails. No unit test reaches `syncNamespaces`, which needs a containerd client, and the new BATS test exercises only the namespace create and delete events.

The VM restart tests (`rdd/bats/tests/32-app-controllers/engine-containerd.bats:509-531`) run after both invalid-name namespaces are gone (lines 251 and 467). Nobody ran the mutation, since it needs a VM.

Fix: in "VM start recreates the ContainerNamespace mirror after cleanup", keep an invalid-name namespace across the restart and `rdd ctl get` its mirror once `ContainerEngineReady` is `True`; a `wait --for=create` would also pass on the apply that precedes the prune.

## Design Observations

### Concerns

- **Keep the mirror's object name out of the client contract** `(in-scope)` [Claude Opus 5]. Clients can reach a mirror only by recomputing `cns-` plus SHA-256. The new BATS test does; the webhook and the renderer do not (S4). A selectable `status.name`, as `Volume` has, lets every consumer query by the engine's name and leaves the naming rule free to change (I1).
- **The commit message overstates the change** `(in-scope)` [Claude Opus 5]. "Matches the new API where we hash invalid names" covers the naming half of #651's `ContainerNamespace` contract, not `status.name` or `status.labels`. "Fix containerd namespace mirroring" presents a reversal of documented behavior, from skip to hash, as a bug fix, and the doc, field comments and test that described the skip stay in place (I2, I3).

### Strengths

- **One helper names the mirror everywhere** `(in-scope)` [Claude Opus 5, Codex GPT 5.6 Sol]. Apply, remove and the full-sync keying all call `containerdNamespaceMirrorName` (`rdd/pkg/controllers/app/engine/controllers/sync_namespace_containerd.go:43`, 75, 88), so apply and prune agree on every name, and `removeNamespace` drops its validity guard.
- **A name kept verbatim is always admissible** `(in-scope)` [Claude Opus 5]. The check is the one the API server applies to custom-resource names (`NameIsDNSSubdomain` in apiextensions-apiserver v0.36.4), and a hashed name is 68 characters.
- **The new test proves the mirror exists before waiting for its deletion** `(in-scope)` [Claude Opus 5], which avoids the vacuous `wait --for=delete` the neighbouring test's comment warns about.

S1. **Portability Issues with `shasum --algorithm 256`** — `rdd/bats/tests/32-app-controllers/engine-containerd.bats:246` (suggestion, regression)

```bash
    encoded_name=cns-$(printf "%s" "${namespace_name}" | shasum --algorithm 256 | cut -d ' ' -f1)
```

The new test in `engine-containerd.bats` uses `shasum --algorithm 256`. While standard on macOS, the `shasum` command (part of optional Perl utilities) is often absent from minimal Linux environments, where `sha256sum` (part of GNU coreutils) is standard. Sibling tests in `engine-docker.bats:796-801` already handle this portably by checking for `sha256sum`.

Fix: Use a portable shell snippet to compute the SHA-256 hash.

```diff
-    encoded_name=cns-$(printf "%s" "${namespace_name}" | shasum --algorithm 256 | cut -d ' ' -f1)
+    local hash
+    if command -v sha256sum &>/dev/null; then
+        hash=$(printf '%s' "${namespace_name}" | sha256sum | awk '{print $1}')
+    else
+        hash=$(printf '%s' "${namespace_name}" | shasum -a 256 | awk '{print $1}')
+    fi
+    encoded_name="cns-${hash}"
```

### Design Observations

#### Concerns
- **Missing Raw Name Mapping in Client API (in-scope):** As raised in I2, mapping a hashed name `cns-xxx` back to the raw name is impossible for any client unless they replicate the SHA-256 hashing and naming algorithm. Storing the raw namespace in annotations is the most straightforward out-of-band mechanism to allow UI and CLI components to map hashed Kubernetes resource names back to their original engine representations.

#### Strengths
- **Safe and Non-Destructive Hashing Approach:** Using `crypto/sha256` to format names into standard DNS-1123 subdomains ensures that containerd namespaces containing spaces, uppercase characters, or special symbols can be safely mirrored without crashing the API server or triggering validation rejections.
