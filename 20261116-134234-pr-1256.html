Executive Summary ¶

Since round 1 the author amended fixes into the first commit and added three. The picker shows the pending pick, Apply switches the language itself, an Object.prototype name falls back to English, specs use Node's structuredClone, and Escape reattaches Preferences to the main window. Those changes work. But the picker's fallback for an untranslated App locale is untested, and with that fallback deleted the picker goes blank while every spec passes. The patch adds that test.

Design Observations ¶

Concerns ¶

  • Two functions named closePreferences treat unsaved changes in opposite ways (in-scope) Claude Opus 5.5. The new export in window/preferences.ts:121 lets the page ask before it discards anything. The page's own closePreferences in pages/Preferences.vue:32 clears the changes and closes without asking. The page's function predates the PR, but the PR adds the second name, and Cancel, Discard and Apply all call the page's version. A name such as discardAndClose for the page's function would tell a reader which of the two asks.

Strengths ¶

  • The round-2 delta holds up (in-scope) Claude Opus 5.5 Codex GPT 6 Astra Gemini 3.5 Flash. closePreferences() returns early when getWindow returns null, and it does for a destroyed window, since it goes through BrowserWindow.fromId. For a Preferences window opened without a main window, the reattach sets the null parent that the window already has. A mutation that puts the Escape handler back to a bare close() fails the window spec.
  • Escape and the main window's close request go through one function (in-scope) Claude Opus 5.5 Codex GPT 6 Astra, so the macOS reattach is in one place.
  • Specs now clone the way the app does (in-scope) Claude Opus 5.5 Codex GPT 6 Astra Gemini 3.1 Pro Gemini 3.5 Flash. Probes in the jsdom environment found that Node's structuredClone throws DataCloneError on a Vue reactive() proxy and on a value holding a function, and that toStrictEqual still passes on its copies.

  • A picked language takes effect only on Apply, with no preview.
  • Reattaching after close() is the fix for the macOS detach. Do not re-suggest making Preferences modal: true.
  • A Cancel keeps Preferences open against preferences-close.   • Escape during an Apply's round trip asks about changes already sent.
  • switchTo can throw after a successful commit, and it can run twice when the App arrives inside the one-second wait.
  • The apply-fails test lacks a positive preferences/commit assertion; three sibling tests catch an apply that never runs.
  • The main process learns App state only from renderer relays (#1260), and it starts in English until a window sends the locale (#1204).

The channel's other callers do not catch it, and a rejection leaves Preferences open with its changes, so the next close asks again.

Review Process Notes ¶

Skill improvements ¶

  • When a prior-round fix adds more than one branch, ask each agent for the test that fails when each branch is deleted, not only when the whole fix is reverted. An agent that reverts the whole fix finds a failing test and credits it, while a guard added beside the main change stays untested.

Repo context updates ¶

  • [repo] In the jsdom Jest environment, values that Node creates, such as an fs error or a structuredClone copy, belong to Node's realm, so instanceof checks and expect.any(Error) fail on them inside a test. A review patch that asserts on such a value should match its properties, for example with expect.anything() or expect.objectContaining().
