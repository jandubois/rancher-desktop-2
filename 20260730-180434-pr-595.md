I2. **`kebabCase('WSL')` is `w-s-l`, against three sites that already spell it `wsl`** — `pkg/rancher-desktop/utils/string-utils.ts:56-61` [Claude Opus 5, Codex GPT 5.6 Sol, Gemini 3.1 Pro, Gemini 3.5 Flash]

```ts
export function kebabCase<T extends string>(input: T): KebabCase<T> {
  return input
    .trim()
    .replace(/./ug, (c, i) => (i > 0 && /[A-Z]/.test(c) ? '-' : '') + c.toLowerCase())
    .replace(/[\s-_]+/g, '-') as KebabCase<T>;
}
```

The implementation inserts a dash before every uppercase letter, so an acronym becomes one letter per segment. Measured: `kebabCase('WSL')` returns `'w-s-l'` where the lodash version it replaces returns `'wsl'`.

The breakage is latent: `pkg/rancher-desktop/window/preferenceConstants.ts:19-23` keeps the WSL entry commented out and both WSL e2e tests are `test.fixme`. Uncommenting that entry is the documented next migration step, and it yields `nav-w-s-l` and a 404 help URL.

Fix: give each `prefItemData` entry an explicit slug (`{ name: 'WSL', slug: 'wsl' }`) and derive test IDs, state keys, and help routes from that field.

S1. **The string path returns `Infinity` where the number path throws** — `pkg/rancher-desktop/utils/parseQuantity.ts:51-57` [Gemini 3.1 Pro, Claude Opus 5]

```ts
  const parsedNumeral = parseFloat(numeral);

  if (Number.isNaN(parsedNumeral)) {

```

The new guard at lines 12-14 rejects a non-finite `number` argument, but the string path only tests for `NaN`. Measured: `parseQuantity(Infinity)` throws `Malformed quantity: Infinity`, while `parseQuantity('1e400')` returns `Infinity` and `parseQuantity('1e400Gi')` does too.
```diff
-  return parsedNumeral * scale;
+  const result = parsedNumeral * scale;
+
+  if (!Number.isFinite(result)) {
+    throw new Error(`Malformed quantity: ${ trimmed }`);
+  }
+
+  return result;
```

## Design Observations

### Concerns

- **Stable identifiers are derived from display text** `(in-scope)` [Codex GPT 5.6 Sol, Gemini 3.5 Flash] — I2 is the symptom, and the shared cause is that one human-readable label feeds store keys, help routes, and test selectors through a string transform. Any relabelling or new acronym repeats it. An explicit slug per `prefItemData` entry would also retire the recursive type-level parser, since the slug can be a literal.
- **A third case-conversion helper now lives in `utils/`** `(future)` [Claude Opus 5] — `pkg/rancher-desktop/utils/string.js` already exports `dasherize()`, and `typeUtils.ts:58-60` exports `UpperSnakeCase()`, whose body is the same `replace(/./g, (c, i) => …)` shape as the new `kebabCase`. The new file also sits beside `string.js` under a name that differs only by suffix. Putting `kebabCase`/`KebabCase` next to `UpperSnakeCase` in `typeUtils.ts`, which `string-utils.ts` already imports `Alpha` from, would keep the pair together.
- **The UI says GB and means GiB** `(future, pre-existing)` [Claude Opus 5] — `gigaScale = 2 ** 30`, `setMemory` appends `'Gi'`, the new comment on line 15 says GiB, and the prop is `memoryInGB` against a slider labelled `Memory (GB)`. This PR touched three of the four sites.

### Strengths

- **The type and the function are tested against one table** `(in-scope)` [all four reviewers] — `string-utils.spec.ts:29-54` drives both the runtime assertions and the `KebabCase<T>` type assertions from the same `cases` array, so the two cannot drift for ASCII input. Claude compiled the type block standalone under the pinned `typescript@6.0.3`; I ran the runtime half as part of the Jest suite.
- **The suffix lookup survives prototype-chain keys** `(in-scope)` [Gemini 3.1 Pro] — an object-literal lookup would return a function for `'toString'`, and the `typeof scale !== 'number'` check rejects it. `parseQuantity.spec.ts:79` pins the behavior.
- **Doubles keep exact precision to the scales that matter** `(in-scope)` [Gemini 3.1 Pro] — every binary suffix through `Pi` is a power of two, so the float rewrite loses nothing a VM memory value can hit.
- **`help.ts` sheds a cast** `(in-scope)` [Claude Opus 5] — the removed `as topKeys` meant a nav item whose kebab form had no matching preferences key cast silently. The inferred `KebabCase<T>` makes that a compile error.
- **`string | number` at the parser boundary matches the client surface** `(in-scope)` [Codex GPT 5.6 Sol] — the CRD marks the field `x-kubernetes-int-or-string`, so the generated model types it `any` and a JSON integer can arrive at runtime.

## Acknowledged Limitations

- **`E` and `Ei` now throw.** Commit `6106a2f9c`: *"We don't care about exabytes (that's not feasible memory for the machines we target)."* The rationale is loose, because a suffix names a scale and not a magnitude. I chased reachability with a Go probe against the pinned `k8s.io/apimachinery`: `0.00000001E` canonicalizes to `10G`, so a plausible memory value never keeps an `E` suffix through the typed `AppDefaulter` round-trip, and `1E` and `1Ei` do survive but the validator rejects them at `rdd/pkg/controllers/app/app/controllers/app_webhook.go:89`. Claude reached the same conclusion by brute-force sweep over `[2 GiB, 32 GiB]`. So no caller can reach the gap today. Note the ceiling check is skipped when `hostInfo.Memory` is `0`.
- **Malformed numerals such as `1..2` parse.** `parseQuantity.spec.ts:85-86`: *"We accept things like `1..2`; it's the responsibility of the controller to ensure valid values."* Confirmed in both directions: `parseQuantity('1..2')` returns `1` and `parseQuantity('1.5.5Gi')` returns `1.5Gi`, while apimachinery rejects `1..2` outright. The daemon is the only writer, so the rationale holds. The commit removed the `'1..2'` throw assertion that guarded this.
- **The type and the function agree on ASCII only.** `string-utils.ts:46-47` says so. Measured: `kebabCase('Ärger Test')` returns `'ärger-test'` while `KebabCase<'Ärger Test'>` keeps the `Ä`, since `IsUpperAlpha` only knows `A`-`Z`. `String.prototype.trim()` also strips U+00A0, which the type's `Whitespace` union omits. Every nav item name is ASCII.

## Review Process Notes

### Skill improvements

- When a change removes a normalization step (truncation, rounding, clamping, coercion, sorting), enumerate every value that flowed through it, not only the value the change targets. A fix aimed at one input silently changes every other input on that code path, and those other values usually reach a display or comparison the diff does not show. Trace each one to its consumer and state what it produced before and after.
- Before including a patch in a finding, check it against the assertions in the test files the PR touches. A patch that fails an existing test is either the wrong diagnosis or an incomplete one, and a patch quoted in a review carries the review's authority. When the patch cannot be checked, describe the fix in prose and say why no diff is offered.

### Repo context updates

- `[repo]` `hostinfo.Detect()` (`rdd/pkg/hostinfo/hostinfo.go`) returns the host's total RAM in raw bytes, and only macOS reports a figure that is an exact multiple of 2^30; Linux and Windows subtract reserved memory and report an arbitrary byte count. Renderer code converting that value to GiB for display or for a slider bound must floor or round it. No automated test can catch a failure to: the Playwright mock controller reports exactly 12 GiB, so every derived value is a whole number there, and the same conversion on a developer's Mac also produces whole numbers.
- `[repo]` Each preferences nav item's display name in `pkg/rancher-desktop/window/preferenceConstants.ts` feeds three derived identifiers through a kebab-case transform: the `data-testid` emitted by `components/Preferences/ModalNav.vue`, the tab-default keys in `preferenceConstants.ts`, and the help mapping keys in `config/help.ts`, whose values are published docs paths. When reviewing a change to a nav item name or to the transform, check the result against the selectors in `e2e/pages/preferences/*.ts` and the docs paths in `config/help.ts`. Acronym labels are where transforms disagree most.
- `[repo]` UPDATE the existing entry on renderer quantity parsing: the renderer converts App-spec quantities through `@pkg/utils/parseQuantity`, which returns a `number` and accepts `string | number`. `quantityToScalar` in `pkg/rdd-client/util.ts` now has no callers, so the entry's `BigInt(quantityToScalar(x))` framing points at a call site that no longer exists. The quantity facts in that entry still hold and I re-verified them against the pinned apimachinery: `2.5Gi` canonicalizes to `2560Mi`, `.5Gi` to `512Mi`, and `5.Gi` round-trips verbatim.

S2. **Hyphen in character class `[\s-_]` is non-portable and throws under unicode mode** — `pkg/rancher-desktop/utils/string-utils.ts:59` (suggestion, enhancement)


In the regular expression `.replace(/[\s-_]+/g, '-')`, the hyphen `-` is placed between `\s` and `_`. While V8 happens to parse this, placing a hyphen in the middle of a character class is non-portable and throws a `SyntaxError: Invalid character class` in strict engines or when the Unicode `/u` flag is enabled (e.g. `/[\s-_]/u`).

### Design Observations

#### Concerns

* **Simplification of `kebabCase` for general use** `(in-scope)`: The custom `kebabCase` implementation is a great step to unify type-level and runtime kebab-casing. However, because it matches only uppercase letters with hyphens, it deviates from the standard word-based boundary splitting used by standard libraries like Lodash (which splits acronyms like `"WSL"` gracefully). Although we can override `"WSL"`, future developers adding new acronyms to UI navigation labels or tab names might face silent compilation issues or test failures because their acronyms will similarly be hyphenated (e.g., `'API'` to `'a-p-i'`). A longer-term design choice would be to explicitly declare the snake/kebab keys in the navigation array structure rather than generating them via a string helper.

#### Strengths

* **Parity between Type System and Runtime**: The introduction of `KebabCase<T>` and matching it with the runtime `kebabCase(input)` function is a stellar architectural decision. It brings complete, compile-time type-safety to navigation tab defaults, preventing silent bugs where state properties and tab names might drift.
