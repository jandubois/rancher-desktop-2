Executive Summary ¶

The one-line emits declaration is the right root-cause fix. Without it the number input emits 5, NaN; with it, only 5. The problem is the test. Chromium writes 7 into the field before any app code runs, and the NaNGi corruption then aborts the Vue re-render instead of repainting the field, so toHaveValue('7') passes at the merge-base. Only the CPU assertion goes red.

All four reviewers converged on the string-vs-number emit payload type. Claude alone found the test defect and the unforwarded min/max.

S4. The commit message names the wrong mechanism Claude Opus 5¶

The body says "the change event emitted the actual event object instead of the value". updatedVal always emitted the value (line 56); the Event came from a second call. With change undeclared, onChange stayed in $attrs and Vue attached it as a native listener on the <fieldset> root that RdFieldset renders, where the input's bubbling change hit it.

Fix: say that the parent's @change was inherited as a native listener on the component's root element because change was not declared in emits. The precise wording is what lets the next reader recognise S2's siblings.

Design Observations ¶

Concerns ¶

  • SystemPreferences's validation layer is dead code (future) Claude Opus 5. hasError/hasWarning/threshold build user-facing strings and emit error/warning (lines 124, 133); nothing in the tree listens. Meanwhile the store has a working error channel. The dry-run patch at store/preferences.ts:289 sets errorStatus, and ModalFooter.vue:31 renders <preferences-alert> from it. Routing the component's validation there, or deleting it in favour of the CRD pattern and the webhook floor, would collapse two parallel validation paths and give I2 somewhere to surface.
  • A malformed quantity takes down the whole pane (future) Claude Opus 5. parseQuantity throws and VirtualMachineHardware.vue:16 calls it straight from a computed. On a fresh mount Vue swaps the component's output for a comment node, confirmed by mounting with NaNGi, which raises Error: Malformed quantity: NaNGi. That is the "dialog hangs" half of #616. A non-throwing variant would leave a corrupt stored value visible as a wrong number, and keep the pane up.

Strengths ¶

  • The fix is the minimal correct one, and the revert proves it (in-scope) Claude Opus 5 Codex GPT 5.6 Sol.
  • The alternatives a reader might reach for (inheritAttrs: false, a .self modifier, renaming the event) each break the id fallthrough the e2e page object depends on (e2e/pages/preferences/virtualMachine.ts:37-38) or hide the mechanism (in-scope) Claude Opus 5.
  • One component fix covers both the memory and CPU consumers without duplicating anything in the parent (in-scope) Codex GPT 5.6 Sol.

Review Process Notes ¶

Skill improvements ¶

  • When a test asserts a value that the browser or runtime sets natively (an input's own value after a synthetic key press, a default the framework fills in), verify the assertion can fail by reverting the fix and re-running it. A test that observes a value written before application code runs may pass against the unfixed code, and the diff renders a real guard and a vacuous one identically.
  • When a finding rests on what the UI displays after an error, distinguish a fresh mount from an update. A framework that aborts a re-render leaves the previous DOM in place, so the same corrupt state produces a broken pane on navigation and an apparently healthy one in an already-open view.
  • A finding whose subject is the commit message itself has no file to cite, so the citation lint reports it unresolved and no permalink anchors it. Cite the short SHA and leave the lint warning standing; inventing a file reference to satisfy the linter points the reader at code the finding is not about.

Repo context updates ¶

  • [repo] The renderer's unit suite runs from a worktree once node_modules is symlinked from the main checkout. Run BROWSERSLIST_IGNORE_OLD_DATA=1 node --experimental-vm-modules node_modules/jest/bin/jest.js <path>; the bare jest binary fails on ESM. The full suite is ~22s and components/__tests__/SystemPreferences.spec.js mounts the real slider stack, so an experiment settles component-level claims about the preferences dialog more cheaply than reading does.
  • [repo] Nothing type-checks Vue template expressions: lint:typescript runs ESLint only and vue-tsc is not a dependency. A type annotation on an emits declaration or a method signature is documentation, not an enforced contract, so a mismatch between a declared payload type and what a template actually passes will never fail CI.
  • [repo] vue/require-explicit-emits is disabled in eslint.config.mts under "Compatibility: disable lints during the ESLint transition". Undeclared emits whose names collide with native DOM events (click, change, input, focus, blur, paste) make the parent's listener fire twice, once with the payload and once with the bubbling DOM event. When reviewing a component that emits a native-sounding name, check for an emits declaration and whether the root is a single element.
