## Executive Summary

This round routes containerd Containers and moby Images through `api.MirrorName`, which now takes extra values to hash with the input, and fixes most round-1 findings. The code behaves correctly, and moby Image names come out byte-identical to before. But the new "extra arguments are separated" subtest never reaches the hashing branch, and the PR deleted the test that did. The rewritten Image naming rule is wrong for containerd, and the `MirrorName` doc comment misdescribes its output.

I3. **`MirrorName`'s doc comment misdescribes the output and the extras** — `rdd/pkg/util/api/mirror_name.go:18-26` [Codex GPT 6 Astra, Claude Opus 5.5]

```go

// given name is not a valid Kubernetes object name, or if it looks like the

// followed by the SHA-256 hash of the input, possibly followed by any extra
```

The comment makes two claims the code contradicts. First, it describes the result as the prefix and the hash "followed by any extra strings". For an input that needs encoding, different extras give different names, which the PR's own "extra arguments are incorporated" subtest asserts. ## Design Observations

### Concerns

- **containerd Images still use a separate always-hash helper** *(future)* [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash]. Round 1 noted that only two of five kinds used the shared algorithm; four do now. `containerdImageMirrorName` cannot route through `MirrorName` as it stands, because its hash puts the namespace first and a valid namespace would pass through unencoded. An always-hash sibling of `MirrorName` would let the doc state one rule for Images instead of two (I1).
- **The mock controller still uses a third naming scheme** *(future)* [Gemini 3.1 Pro, Codex GPT 6 Astra, Gemini 3.5 Flash]. `sanitizeKubernetesObjectName` (`mock/volume_reconciler.go:72`, `mock/image_reconciler.go:45`) replaces only `/` and `:`, so a mock Volume named `My_Vol_Ume` produces an invalid object name. This predates the PR and round 1 recorded it.
- **Tag separation depends on the image ID containing a colon** *(future)* [Gemini 3.1 Pro]. `imageMirrorNames` passes the tag as an extra, which `MirrorName` ignores for a valid input. Docker IDs always include the `sha256:` algorithm prefix, so this holds today.

### Strengths

- A pass-through name still can never equal a hashed one with extras present, since hashed output always matches `<prefix>-<64 hex>` and any input of that form is hashed [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash].
- Moby Image mirror names are byte-identical to the merge-base for dangling, single-tag and multi-tag images, so no existing Image mirror is renamed [Claude Opus 5.5, Codex GPT 6 Astra].
- Every containerd container call site (apply, prune, task-start, delete event, resolver scan) passes the namespace as the extra, which avoids the namespace loss round 1 warned a naive swap would cause [Claude Opus 5.5, Codex GPT 6 Astra].

#### Design Observations

##### Concerns

- **Asymmetry in image mirror naming between Docker and containerd** `(in-scope)`: Docker images hash `status.id` with `status.repoTag`, whereas containerd images hash `status.namespace` with `img.Name()` using a private helper `containerdImageMirrorName`. Consider harmonizing both backends around `api.MirrorName` so API clients and reconcilers share identical naming expectations across container engines.
- **Divergent naming schemes in mock controllers** `(future)`: Real controllers now route through `api.MirrorName` for volumes, containerd containers, Docker images, and containerd namespaces, but the mock controller in `volume_reconciler.go:72` and `image_reconciler.go:99` still uses `sanitizeKubernetesObjectName` (substituting dashes for non-alphanumerics). In the future, mock controllers should reuse `api.MirrorName` so Playwright and UI tests see names conforming to production.

##### Strengths

- **Bijective mapping guarantee preserved**: By re-encoding any input that already matches the `<prefix>-<64hex>` pattern, `MirrorName` prevents collisions between raw resources whose names happen to match encoded outputs and actual hashed resources. Because pass-through names never match that pattern and hashed names always match that pattern, pass-through and hashed sets remain strictly disjoint even with variadic `extras`.
- **Clean variadic extras design**: Extending `MirrorName` with variadic `extras ...string` separated by `\x00` accommodates container namespaces and image tags cleanly without requiring bespoke hashing implementations per mirror resource kind.
