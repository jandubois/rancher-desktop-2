## Executive Summary

The PR publishes each Windows tool as a forwarder, a hardlink to one user-owned forwarder copy in `~/.rd<n>/bin` beside a `.shim` file naming the real binary, and reconciles the directory in place on each bundle start. The Go side follows the issue #448 proposal, but nothing builds or packages `rdd-forwarder.exe`. So a Windows bundle no longer publishes any tool, and the required Windows `bats-others` check fails. Three doc comments still describe the old behaviour.

## Suggestions

S1. **The standalone prune deletes a forwarder on any stat error** — `rdd/pkg/binlinks/forwarders.go:174-177` [Codex GPT 6 Astra, Gemini 3.5 Flash, Claude Opus 5.5]

```go
		if _, err := os.Stat(target); err == nil {
			continue
		}
		dropForwarder(binDir, strings.TrimSuffix(name, shimSuffix)+".exe")
```

On a permission error, an unready drive or an offline share, rdd deletes the forwarder and its shim although the target still exists. A probe with an unreadable target directory lost both files.

The sibling `pruneDanglingLinks` keeps such an entry and warns (`rdd/pkg/binlinks/binlinks.go:183-188`). Codex and Gemini 3.5 Flash rated this Important. It stays a Suggestion because only a standalone start reaches it, and the next bundle start recreates every forwarder.

Fix: skip and warn unless `os.IsNotExist(err)`, as `pruneDanglingLinks` does.

S2. **Every start rewrites each shim in place** — `rdd/pkg/binlinks/forwarders.go:85-89` [Codex GPT 6 Astra, Claude Opus 5.5]

```go
	for tool, target := range want {
		if err := os.WriteFile(shimPath(binDir, tool), shimContent(target), 0o644); err != nil {
			klog.Warningf("Failed to write shim for %q, skipping: %v", tool, err)
			continue
		}
```

`os.WriteFile` truncates before it writes, so a forwarder starting during a service start can read an empty shim. The upstream shim opens its `.shim` with `GENERIC_READ, FILE_SHARE_READ` only (ScoopInstaller/Shim `cpp/shim.cpp:523`). So on Windows a forwarder can also fail to open the file while rdd writes it, and a forwarder holding it open makes rdd's write fail, which skips relinking that tool as well. Unverified on Windows.

Fix: write through `atomicfile.Write` (`rdd/pkg/util/atomicfile/atomicfile.go:70`), which skips identical content, so a start with an unchanged bundle writes nothing.

S3. **A fixed `.old` name can block the forwarder refresh** — `rdd/pkg/binlinks/forwarders.go:217-219` [Gemini 3.1 Pro, Gemini 3.5 Flash, Claude Opus 5.5]

```go
	aside := path + ".old"
	_ = os.Remove(aside)
	return os.Rename(path, aside)
```

While a process started from an earlier forwarder copy still runs, its `.old` name cannot be removed or replaced, because Go's `os.Rename` is `MoveFileEx(MOVEFILE_REPLACE_EXISTING)` and Windows refuses to replace a running image. For the master copy, `ensureForwarderCopy` then fails and `linkForwarders` returns before it writes any shim (`rdd/pkg/binlinks/forwarders.go:81-82`).

Reaching this takes a long-lived process, such as a `kubectl port-forward`, still running across two forwarder updates, and it clears once that process exits. So the Important both Geminis gave it drops to a Suggestion. Unverified on Windows.

Fix: give each aside file a unique name and match the new names in `sweepAside`.

S4. **A bundled file without a lower-case `.exe` gets a forwarder but loses its shim** — `rdd/pkg/binlinks/forwarders.go:147` [Claude Opus 5.5, Gemini 3.1 Pro, Gemini 3.5 Flash]

```go
		tool := strings.TrimSuffix(name, shimSuffix) + ".exe"
```

`shimPath` strips only `.exe`, but this line appends `.exe` to every shim name. A probe bundling `helper.ps1` ended with a `helper.ps1` forwarder and no `helper.ps1.shim`, because `removeStaleForwarders` deletes the shim line 86 just wrote. An upper-case `.EXE` also misses the upstream shim, which replaces the last three characters of its own name with `shim` (`cpp/shim.cpp:517`).

This is latent. `packaging/electron-builder.yml` filters archives and `.unsigned` files out of `resources/`, so a shipped bundle's bin directory holds only `.exe` files, and development builds run `rdd/bin/rdd.exe`, which takes the standalone path.

Fix: skip bundle entries whose extension is not `.exe`, compared case-insensitively.

S5. **An upgrade from the link layout keeps tools the bundle dropped** — `rdd/pkg/binlinks/forwarders.go:147-151` [Claude Opus 5.5]

```go
		tool := strings.TrimSuffix(name, shimSuffix) + ".exe"
		if _, ok := want[tool]; ok {
			continue
		}
		dropForwarder(binDir, tool)
```

`removeStaleForwarders` walks only `.shim` files, and the links the merge-base layout wrote have none. A probe that published the merge-base layout, dropped `helm.exe` from the bundle and ran `linkForwarders` kept the old `helm.exe` hardlink, which still shadows PATH. The merge-base `RemoveAll` cleared it, and the #448 proposal asks to delete every tool the bundle no longer ships.

Fix: in bundle mode rdd owns the directory, so drop any entry that is not a wanted tool, the master copy, or a wanted tool's shim.

S6. **The master copy is on PATH and outlives an uninstall** — `rdd/pkg/binlinks/forwarders.go:80-83` [Claude Opus 5.5, Gemini 3.1 Pro, Gemini 3.5 Flash]

```go
	master := filepath.Join(binDir, forwarderName)
	if err := ensureForwarderCopy(forwarderSrc, master); err != nil {
		return fmt.Errorf("stage forwarder %q: %w", master, err)
	}
```

`rdd-forwarder.exe` is in the bin directory, so typing `rdd-forwarder` runs a forwarder without a shim. `pruneDanglingForwarders` walks only `.shim` files, so after an uninstall the standalone prune keeps the master. That path also never calls `sweepAside`, so a forwarder it renamed aside stays behind as `.old`.

Fix: keep the master in `instance.ShortDir()`, one level above the bin directory and off PATH; a hardlink needs only the same volume, and `rdd svc delete` removes that directory. Sweep `.old` files in `ensureSelfLinks` too.

S7. **`dropForwarder` logs the wrong error** — `rdd/pkg/binlinks/forwarders.go:203-206` [Gemini 3.5 Flash]

```go
	if err := os.Remove(forwarder); err != nil && !os.IsNotExist(err) {
		if asideErr := renameAside(forwarder); asideErr != nil {
			klog.Warningf("Failed to remove forwarder %q: %v", tool, err)
		}
```

When both the removal and the rename aside fail, the warning prints the removal error and discards `asideErr`, the one that says why the forwarder is still on PATH.

Fix: log `asideErr`, or both errors.

## Design Observations

### Concerns

- **The MSI still puts the bundle's bin directory on PATH** (future) [Codex GPT 6 Astra]: `build/wix/main.wxs:91` and `:116` add `resources\windows\bin` to the user and system PATH. The #448 proposal removes both, so the bundled tools reach PATH only through `~/.rd2/bin` and the `addPath` position applies to them. That is a later part of the issue's plan.

### Strengths

- **The contract with the forwarder is written down** (in-scope) [Claude Opus 5.5]: `forwarders.go:23-31` names the three invariants the fork must keep, including the `argv[0]` passthrough that rdd's multicall dispatch reads (`rdd/cmd/rdd/multicall.go:24`).
- **Reconciling in place keeps working hardlinks** (in-scope) [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash]: the byte comparison and the `os.SameFile` check skip unchanged entries, and the PR's `RDD Unit tests (windows-latest)` job passed, so the hardlink identity checks hold on NTFS.
- **The Go side matches the #448 proposal** (in-scope) [Claude Opus 5.5, Codex GPT 6 Astra]: the `.shim` format, `kubectl.shim` naming `rdd.exe`, forwarders whether or not symlinks work, one master copy with a hardlink per tool, no `RemoveAll`, busy forwarders renamed aside, dangling forwarders pruned, and a standalone rdd linking only `rdd` and `kubectl`. S5 is the one divergence.
- **The daemon outlives the `rdd.exe` forwarder** (in-scope) [Claude Opus 5.5]: the upstream shim's job object sets `JOB_OBJECT_LIMIT_SILENT_BREAKAWAY_OK` (`cpp/shim.cpp:812`), so the `rdd svc serve` that `rdd svc start` spawns leaves the job and keeps running after the forwarder exits.

## Acknowledged Limitations

- **`.old` files can outlive a start.** `sweepAside` skips aside files that are still in use, and the next start removes them.
- **rdd owns the bin directory.** One reviewer asked the standalone prune to protect a standalone `rdd.exe` a user copied into `~/.rd<n>/bin`. rdd rewrites that directory on every bundle start, so a future reviewer should not re-suggest guarding user-placed binaries there.
- **`shimTarget` reads only what rdd writes.** Every `.shim` in the bin directory comes from `shimContent`, which writes a single `path = ` line, so a key such as `path_args` never reaches the parser. Do not re-suggest a general key-value parser unless the shims gain more keys.

## Review Process Notes

### Skill improvements

- When a change alters what a code path requires (a file it must find, a precondition, a branch one platform takes), find the tests outside the diff that reach that path on every leg of the CI matrix, and check that their fixtures still meet the new requirement. I1. **`renameAside` fails if the `.old` file is still open by a prior process** — `rdd/pkg/binlinks/forwarders.go:220-222` (important, regression)

```go
	aside := path + ".old"
	_ = os.Remove(aside)
	return os.Rename(path, aside)
```

`_ = os.Remove(aside)` assumes the folklore that Windows `os.Rename` cannot overwrite existing destinations. On Windows, `os.Rename` uses `MoveFileEx(MOVEFILE_REPLACE_EXISTING)`, which atomically replaces existing files. However, when an earlier forwarder process is still running, `aside` (`path.old`) is held open; `os.Remove(aside)` fails silently and `os.Rename(path, aside)` fails with a sharing violation (`ERROR_SHARING_VIOLATION` / `ERROR_ACCESS_DENIED`). Using a static `.old` filename causes all subsequent rename-aside attempts to fail until the earlier process terminates. When called from `ensureForwarderCopy` (line 114), this aborts the entire bundle linking operation.

Fix: Generate a unique destination (e.g., using PID or a timestamp) or fall back to a distinct name when replacement fails:

```diff
-	aside := path + ".old"
-	_ = os.Remove(aside)
-	return os.Rename(path, aside)
+	aside := fmt.Sprintf("%s.%d.old", path, os.Getpid())
+	return os.Rename(path, aside)
```
