## Suggestions

S1. **`StartAggregation` does nothing with nil options** — `rdd/pkg/steve/steve.go:78` [Codex GPT 6 Astra, Claude Opus 5.5]

```go
	s.StartAggregation(ctx)
```

`server.New(ctx, restConfig, nil)` leaves the aggregation secret's namespace and name empty, and steve v0.9.23's `aggregation.Watch` returns at once when either is empty (`pkg/aggregation/watch.go:14-16` in the module). The fork made the same dead call. A reader has to trace into steve to learn that the line does nothing.

Fix: delete line 78.

S2. **The help text and doc comments promise the dashboard in API-only builds** — `rdd/cmd/rdd/steve.go:19` [Claude Opus 5.5]

```go
		Short: "Serve the steve API and the Cluster Explorer dashboard",
```

Every build of this PR serves only the API, and the PR's own demo shows `--help` printing this line right after stderr says the binary does not embed the dashboard. After #1185, packaged builds embed it, but BATS, lint and Node-less `make build-rdd` builds still won't.

The package comment (`rdd/pkg/steve/steve.go:5-6`) and the doc comment on `Run` (`rdd/pkg/steve/steve.go:36`) make the same unconditional claim.

Fix: "Serve the steve API, and the Cluster Explorer dashboard in builds that embed it", with the same change in both comments.

S3. **rdd's default log level drops the info lines that the fork wrote to steve.log** — `rdd/pkg/steve/steve.go:76` [Claude Opus 5.5]

```go
	os.Stdout = os.Stderr
	logrus.Infof("Steve is listening on port %d", port)
```

The fork left logrus at its default `info` level, because its `debug.SetupDebug` changes the level only under `--debug`. `rdd steve` inherits the root command's `setLogOptions` (`rdd/cmd/rdd/main.go:99-104`), which picks `warn`, or `debug` in developer mode. So once `steve.ts` spawns `rdd steve`, a packaged app's steve.log loses steve's info lines, line 76 included, and a developer checkout gets steve's debug output instead.

Fix: decide which level steve should log at. For the fork's behaviour, set `logrus.InfoLevel` in `Run` when neither `--log-level` nor `RDD_LOG_LEVEL` is given. Otherwise drop line 76, since `steve.ts` already logs the port at debug level.

S4. **Reloads on the shell's other top-level routes still reach steve's 404** — `rdd/pkg/steve/dashboard.go:46-47` [Claude Opus 5.5, Gemini 3.5 Flash]

```go
	mux.Handle("/fail-whale", rewriter)
	mux.Handle("/home", rewriter)
```

The shell's router (`config/router/routes.js` in the dashboard source) also declares `/about`, `/prefs`, `/account`, `/diagnostic`, `/clusters` and `/auth/{login,logout,setup,verify}`. A probe against `newHandler` sent `/prefs`, `/about`, `/auth/login`, `/diagnostic`, `/home/` and `/fail-whale/` to the API handler. The fork served only `/c/`, so this is not a regression.

Not every route is reachable. The only link to `/prefs` is the header's user menu, which the shell hides when `rancherEnv` is `desktop`. This review did not check whether a desktop build shows the top-level menu, whose footer links to `/about`.

Fix: register each route that the RD build can reach, as these two are. Register the trailing-slash form of every one of them too, `/home/` and `/fail-whale/` included. Keep `/v3/` with steve, because the dashboard's `/v3/settings` probes rely on its 404s (`rdd/pkg/steve/steve.go:46`).

S5. **The shutdown `context.Background()` does not say why it is there** — `rdd/pkg/steve/steve.go:85` [Gemini 3.1 Pro, Gemini 3.5 Flash]

```go
		timeoutCtx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
```

The use is correct. `ctx` is already cancelled once `<-ctx.Done()` on line 84 returns, and `Shutdown` needs a live context to drain connections for up to five seconds. The review convention for rdd accepts `context.Background()` in cleanup that must outlive a cancelled parent, and asks for a comment that says so, because elsewhere it means a caller's context was dropped.

Fix: add a one-line comment, or derive the timeout from `context.WithoutCancel(ctx)`, which states the intent in code.

S6. **The port leaves out the fork's `isNotModified` test cases** — `rdd/pkg/steve/dashboard_test.go:56-58`

```go
		{name: "matching tag", path: "/c/local/explorer", ifNoneMatch: `W/"` + checksum + `"`, wantStatus: http.StatusNotModified},
		{name: "star", path: "/c/local/explorer", ifNoneMatch: "*", wantStatus: http.StatusNotModified},
		{name: "different tag", path: "/js/app.js", ifNoneMatch: `W/"other"`, wantStatus: http.StatusOK, wantBody: `fetch("https://127.0.0.1:12345/v1")`},
```

Raised by the consolidator. `isNotModified` is copied from the fork, whose `TestIsNotModified` also covered a strong tag, surrounding whitespace, a tag list with and without a match, and misplaced whitespace. This PR tests only these three header values. A mutation that stopped splitting the header on commas, stopped trimming whitespace and rejected strong tags left `go test ./pkg/steve/` passing. But browsers send back the single weak tag that they received, so a user would not notice such a regression. That makes the test optional (Testing check 3).

Fix: copy the fork's `TestIsNotModified` table into `dashboard_test.go`.

## Acknowledged Limitations

- **Closing stdout frees fd 1.** After `os.Stdout.Close()` the next socket can take fd 1. A probe confirmed the reuse, and also that a write through the old `*os.File` fails with "file already closed". Only a raw write to fd 1 would reach the socket, and nothing under `github.com/rancher` in the module cache makes one. The fork closes stdout the same way, and `steve.ts` depends on the EOF. Do not re-suggest unless a raw fd-1 writer turns up.
- **Windows does not get a graceful shutdown.** Electron stops steve with `kill('SIGINT')` (`pkg/rancher-desktop/backend/steve.ts:239`), which terminates the process on Windows, as it did the fork. Steve does not keep state on disk here, since the SQL cache is off, so the drain matters only for open connections. Do not re-suggest.
- **`Run` leaves goroutines behind when `Serve` fails.** Its only caller returns the error to `main`, which exits through `logrus.Fatal`, so nothing outlives the process. Do not re-suggest a derived cancel context.
- **The rewriter matches `://127.0.0.1:6120/` only with the trailing slash.** All 18 occurrences in the real dashboard build have the slash, and dropping it would also match ports such as 61200. Do not re-suggest.
- **`EMBEDDED_SOURCES` does not list dashboard files.** This PR does not add a Makefile rule for the tag; the build wiring and its prerequisites belong to #1191.
- `rdd/pkg/steve/steve.go:8-12` records that steve v0.9.23 does not compile against k8s 0.37. Not checked here, since this PR does not change a k8s version.

## Review Process Notes

**Skill improvements**

- When a change re-implements code from another repository, compare the source's tests with the new ones and report each test case that did not come along, together with the mutation that the dropped case would have caught. Ported code keeps its edge cases, but a rewritten test table loses the ones that the author did not think of.
- When the run stages a Go module cache, have the agent launcher export `GOMODCACHE`, `GOCACHE`, `GOPROXY=off` and `GOFLAGS` pointing at the staged copies into each agent's environment. Prompt text that names the variables does not bind a `go` command that the agent types without them, and such a command downloads into the user's module cache.

**Repo context updates**

- [repo] Every `rdd` subcommand inherits the root `PersistentPreRunE`, which sets logrus to `warn`, or `debug` in developer mode, unless `--log-level` or `RDD_LOG_LEVEL` says otherwise. Flag info-level logging in a subcommand whose stderr an operator reads, such as one that the app spawns and logs, because it never prints in a packaged app.

### [Gemini 3.1 Pro]

###### Executive Summary

This PR links upstream steve into the RDD daemon, allowing `rdd steve` to serve the API and optionally embed the Cluster Explorer dashboard. The headline finding is that closing `os.Stdout` frees file descriptor 1, allowing it to be claimed by incoming HTTP sockets, which exposes them to data corruption from any subsequent native writes to stdout.

###### Critical Issues

None.

###### Important Issues

I1. **`os.Stdout.Close()` frees file descriptor 1, risking socket corruption** — `rdd/pkg/steve/steve.go:72-74` (important, regression)

```go
	if err := os.Stdout.Close(); err != nil {
		return err
	}
```

Closing `os.Stdout` frees file descriptor 1 on Unix. The next opened file or socket (such as an incoming HTTP connection to the API) will claim fd 1. While `os.Stdout = os.Stderr` prevents Go's `fmt` from writing to it, any native C library (via cgo) or raw fd write will inadvertently send output to the HTTP client, potentially causing data corruption or information disclosure.

Fix: Do not close `os.Stdout`. Instead, update the frontend consumer (`pkg/rancher-desktop/backend/steve.ts`) to resolve the port immediately upon parsing the newline, removing the need for an EOF. Alternatively, safely sink fd 1 by duplicating `/dev/null` over it using `syscall.Dup2` (noting that `Dup2` requires platform-specific builds, as it is unavailable in `syscall` on Windows).

I2. **Graceful shutdown is unreachable on Windows** — `rdd/cmd/rdd/steve.go:21-23` (important, gap)

```go
		RunE: func(*cobra.Command, []string) error {
			return steve.Run(genericapiserver.SetupSignalContext(), opts)
		},
```

The `steve` command relies on `genericapiserver.SetupSignalContext()` for graceful shutdown, which listens for POSIX signals. On Windows, the Electron app stops it using `kill('SIGINT')`, which terminates the process abruptly without sending a catchable signal. The graceful shutdown logic in `steve.Run` is therefore dead code on Windows.

Fix: If graceful shutdown is required on Windows, register a named interrupt event via `process.RegisterInterruptHandler` (e.g., `ServeInterruptKey` or a new key) and update the Electron app to signal it via `process.Interrupt`. If abrupt termination is acceptable because the server holds no persistent state, document this limitation.

I3. **Dashboard files missing from Makefile `EMBEDDED_SOURCES`** — `rdd/pkg/steve/dashboard_embed.go:14-15` (important, regression)

```go
//go:embed dashboard/*
var embeddedDashboard embed.FS
```

The `//go:embed dashboard/*` directive embeds HTML, JS, and CSS files, but `rdd/Makefile`'s `EMBEDDED_SOURCES` only tracks `*.yaml` and `*.json`. Editing the dashboard files will leave a stale `bin/rdd` binary because the Makefile will not rebuild it on changes to these files.

Fix: Extend `EMBEDDED_SOURCES` in `rdd/Makefile` to track the dashboard files (e.g., `*.html`, `*.js`, `*.css`), or add a dedicated dependency target for the dashboard directory.

	srv := &http.Server{Handler: handler}
