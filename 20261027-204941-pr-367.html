kubectl runs kubectl create foo as the plugin kubectl-create-foo and does not contact a cluster for it, as with a top-level plugin. But Find resolves the line to create, so parseCommandLine counts it as cluster-bound and Resolve probes. The plugin then waits for the probe, and against a skewed cluster with nothing cached, for a kubectl download that serves only to dispatch it. Against a server at 1.28 or older, the plugin fails unless a 1.29 kubectl is cached, because kubectl releases before 1.29 do not run plugins under create by default. RD2 supports only Kubernetes 1.32 and newer.

Design Observations ¶

Concerns ¶

  • The probe could read the command line that a kuberc alias expands to (future) Claude Opus 5.5 — kuberc's Preferences.Apply returns the rewritten arguments, which NewKubectlCommand discards (kubectl v0.36.4 pkg/cmd/cmd.go:375), and each alias command records its target in the kubectl.kubernetes.io/original-command annotation. If parseCommandLine ran Apply itself and classified an alias by its target, two documented limitations would go away. The probe would see an alias's added arguments, and an alias of a client-only command would stop probing. The parseCommandLine comment describes kubectl correctly today, so this is an option for later.

Strengths ¶

  • The probe is skipped exactly where kubectl's own Find fails (in-scope) Claude Opus 5.5 Codex GPT 6 Astra Gemini 3.1 Pro Gemini 3.5 Flash — kubectl's NewDefaultKubectlCommandWithArgs uses the same Find on the same tree to decide when to look for a plugin. The only flags that rdd's tree lacks are the ones component-base adds at run time, --v, --vmodule and --log-flush-frequency; all three take values, so cobra's stripFlags skips them just as kubectl's Find does.
  • Reverting any round-3 behavior fix fails a test (in-scope) Claude Opus 5.5 — see the Testing Assessment.

Acknowledged Limitations ¶

Each entry below was declined in an earlier round of this PR, except the $(winpath …) entry, which PR #348 declined. Codex confirmed each of this PR's entries against a file and line, and Claude confirmed each as well. The delta does not touch the code they rest on.

  • The cache root is classic Rancher Desktop's directory — declined round 2: the location belongs to a broader cache design, and rdd svc paths and RDD_CACHE_DIR hide it from callers.
  • kube-context.bats downloads a kubectl from dl.k8s.io — commented round 2, beside K3S_VERSION.
  • Ctrl+C during a download leaks the .kubectl-* temp file — commented round 2 in TODO(eviction).
  • No test pins the embedded-first step, and no unit test calls SkipResolver — declined round 2 as optional.
  • winpath duplicates host_path — declined round 2: 5-paths.bats needs cygpath -w's backslashes.
  • $(winpath …) captures instead of run -0 — declined in PR #348 round 8: a winpath failure is pathological, and the rewrite adds noise for little safety. Do not re-suggest.
  • The probe and a cached kubectl both run exec credential plugins — declined round 2 as a cost.
  • Pre-GA servers warn on every call, and downloads are not retried — declined round 2 as future work.
  • No test pins Exec's exit code on Windows — declined round 3: a lost exit code still prints an error naming the child's exit status.
  • TestResolveHonorsKubercPluginPolicy lacks a positive control — declined round 3: the recursion-guard test proves that the same fixture runs its plugin.
  • No test pins the MSYS2 RDD_CACHE_DIR conversion — declined round 3: Windows BATS only, and its comment says why it exists.
  • An exec credential plugin gets a terminal stdin during the probe — declined round 3: it reaches stdin only when stdin is a terminal, where the user can answer it.

Carried from earlier rounds and unchanged: the Windows os.Rename cache-publish race, CacheRoot panicking when os.UserCacheDir fails, no test for concurrent first-time downloads, the probe overriding --request-timeout (commented), the dependabot entry for fake-kube (commented), TODO(eviction), TODO(offline), truncation reported as a checksum mismatch, the Windows Exec hard-kill on context cancel, and local_teardown_file in 7-kubectl-cache.bats.

Documented in code (resolver.go:187-209): the probe does not see an alias's prepended and appended args and counts every alias as cluster-bound, kuberc warnings print twice, and a kuberc that the embedded kubectl rejects stops rdd kubectl.

Tracked in pending-work: cmd_service.md still lists an rdd.sqlite3 data store and a config map copy.
