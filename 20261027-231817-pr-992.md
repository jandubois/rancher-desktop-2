S1. **`remove` corrupts a file whose value or comment lines are dedented** — `src/go/i18n-report/report_remove.go:263` [Codex GPT 6 Astra, Claude Opus 5.5]

```go
	end := keyIdx
	for j := keyIdx + 1; j < len(lines); j++ {
		if strings.TrimSpace(lines[j]) == "" {
			continue
		}
		if lineIndent(lines[j]) <= indent {
			break
		}
		end = j
	}
```

`markKeyLines` ends a key's value at the first line indented no deeper than the key. yaml.v3 accepts layouts that break that rule. When a quoted scalar continues at the key's indentation, `remove` writes a file that does not parse. With a column-0 comment inside a pruned parent, `remove` exits 0, the removed key reappears at the root, and the next top-level key is lost. The merge-base reserialized the whole tree and handled both. No locale file has such a layout (an awk scan of all ten found none), and `serializeYAMLNode` writes each head comment at its key's indentation.
