## Suggestions

S1. **A plugin under `create` still probes, unlike a top-level plugin** — `rdd/pkg/kuberlr/resolver.go:220-229` [Claude Opus 5.5]

```go
	cmd, rest, err := root.Find(args)
	if err != nil {
		// The tree lacks shell-completion requests (`__complete`),
		// top-level kubectl plugins and unknown commands, including any
		// top-level command that only a newer kubectl has. kubectl does
		// not contact a cluster for a plugin or an unknown command.
		// Skipping the probe for completion spares every TAB the probe
		// and any download, whose progress the shell would hide.

	}
```

kubectl runs `kubectl create foo` as the plugin kubectl-create-foo and does not contact a cluster for it, as with a top-level plugin. But `Find` resolves the line to `create`, so `parseCommandLine` counts it as cluster-bound and `Resolve` probes. The plugin then waits for the probe, and against a skewed cluster with nothing cached, for a kubectl download that serves only to dispatch it. Against a server at 1.28 or older, the plugin fails unless a 1.29 kubectl is cached, because kubectl releases before 1.29 do not run plugins under `create` by default. RD2 supports only Kubernetes 1.32 and newer.

## Design Observations

### Concerns

- **The probe could read the command line that a kuberc alias expands to** `(future)` [Claude Opus 5.5] — kuberc's `Preferences.Apply` returns the rewritten arguments, which `NewKubectlCommand` discards (kubectl v0.36.4 `pkg/cmd/cmd.go:375`), and each alias command records its target in the `kubectl.kubernetes.io/original-command` annotation. If `parseCommandLine` ran `Apply` itself and classified an alias by its target, two documented limitations would go away. The probe would see an alias's added arguments, and an alias of a client-only command would stop probing. The `parseCommandLine` comment describes kubectl correctly today, so this is an option for later.

### Strengths

- **The probe is skipped exactly where kubectl's own `Find` fails** `(in-scope)` [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.1 Pro, Gemini 3.5 Flash] — kubectl's `NewDefaultKubectlCommandWithArgs` uses the same `Find` on the same tree to decide when to look for a plugin. The only flags that rdd's tree lacks are the ones component-base adds at run time, `--v`, `--vmodule` and `--log-flush-frequency`; all three take values, so cobra's `stripFlags` skips them just as kubectl's `Find` does.
- **Reverting any round-3 behavior fix fails a test** `(in-scope)` [Claude Opus 5.5] — see the Testing Assessment.

  An executed probe built the root with `Arguments: []string{"kubectl"}`, which skips kubectl's internal `Apply`, and then called `kuberc.NewPreferences().Apply(root, cf, args, errOut)` itself:

  Classifying an alias by the first word of that annotation, and parsing the returned args, would remove two documented limitations: an alias counts as cluster-bound, and its added args are not seen. ###### Suggestions

S1. **Avoid command substitution in BATS test assertion setup** — `rdd/bats/tests/10-cli/5-paths.bats:42` (suggestion, enhancement)

```bash
@test 'rdd svc paths honors RDD_CACHE_DIR override' {
    cache_override=$(winpath "${BATS_TEST_TMPDIR}/cache-override")
```

Line 42 uses `cache_override=$(winpath ...)` command substitution. Under BATS `set -e`, a bare command substitution failure surfaces only the line number rather than the exit status and command output. Following repository BATS conventions, capturing via `run -0` and reading `${output}` provides clearer failure diagnostics.

```diff
-    cache_override=$(winpath "${BATS_TEST_TMPDIR}/cache-override")
+    run -0 winpath "${BATS_TEST_TMPDIR}/cache-override"
+    cache_override="${output}"
```

Fix: capture `winpath` output via `run -0` into `cache_override`.

S2. **Ensure read end of pipe fixture is closed in test cleanup** — `rdd/pkg/kuberlr/resolver_test.go:694-699` (suggestion, enhancement)

```go
	r, w, err := os.Pipe()
	assert.NilError(t, err)
	_, err = w.WriteString(manifest)
	assert.NilError(t, err)
	assert.NilError(t, w.Close())
	origStdin := os.Stdin
	os.Stdin = r
	t.Cleanup(func() { os.Stdin = origStdin })
```

In `TestResolveLeavesStdinAlone`, the write end `w` of the pipe is closed at line 695, but the read end `r` is never explicitly closed. Registering `r.Close()` in `t.Cleanup` ensures the file descriptor is released promptly upon test completion.

```diff
 	origStdin := os.Stdin
 	os.Stdin = r
-	t.Cleanup(func() { os.Stdin = origStdin })
+	t.Cleanup(func() {
+		_ = r.Close()
+		os.Stdin = origStdin
+	})
```

Fix: close `r` inside the `t.Cleanup` closure.

###### Design Observations

###### Strengths

- **Graceful unrecognized command resolution**: Returning `clientOnly: true` when `root.Find(args)` returns an error (`resolver.go:220-229`) elegantly addresses completion commands (`__complete`, `__completeNoDesc`) and top-level plugins without brittle string-splitting or specialized flag parsers.
- **Probe safety and credential isolation**: Clearing deprecated username and password fields (`cf.Username, cf.Password = nil, nil` at `resolver.go:240`) before constructing the REST config prevents interactive prompts on `os.Stdin`, ensuring manifests piped into `kubectl apply -f -` remain untouched.
- **Recursion protection**: Setting `RDD_KUBECTL_RESOLVED=1` during the server version probe breaks potential execution loops from nested credential plugins while keeping parent process environments clean.

###### Acknowledged Limitations

- **Cache directory location** (`rdd/pkg/kuberlr/cache.go:33`): The shared cache root defaults to `os.UserCacheDir()/rancher-desktop`, aligning with classic Rancher Desktop conventions and overridable via `RDD_CACHE_DIR`.
- **Pre-GA servers and offline fallback** (`rdd/pkg/kuberlr/downloader.go:34-40`, `resolver.go:111-115`): Pre-GA clusters without version markers warn on every invocation and fall back to the embedded kubectl; downloads are not retried per `TODO(offline)`.
- **Interrupted download temp file retention** (`rdd/pkg/kuberlr/cache.go:37-40`): In-flight `.kubectl-*` temporary files may persist if the process is killed abruptly; noted under `TODO(eviction)`.
- **Windows process execution** (`rdd/pkg/kuberlr/exec_windows.go:19-25`): Windows runs kubectl via `exec.CommandContext`, which terminates the child on context cancellation; noted in in-code comments.
- **Probe timeout override** (`rdd/pkg/kuberlr/resolver.go:167-170`): The server probe caps timeouts at 2 seconds (`serverProbeTimeout`), overriding any user-supplied `--request-timeout` for the probe phase.
- **Truncation reported as checksum mismatch** (`rdd/pkg/kuberlr/downloader.go:150-154`): Downloads truncated at `maxKubectlBytes` fail with checksum mismatch rather than explicit truncation errors.
- **`kube-context.bats` CI downloads** (`rdd/bats/tests/32-app-controllers/kube-context.bats:13-19`): Running k3s 1.32 triggers a download from `dl.k8s.io` on clean CI runners; annotated in test comments.
- **`winpath` helper** (`rdd/bats/helpers/paths.bash:32-42`): `winpath` specifically emits backslashes for native Windows executables, complementing `host_path`.
- **Kuberc alias probe limitations** (`rdd/pkg/kuberlr/resolver.go:183-195`): Probes cannot evaluate prepended/appended alias arguments, treating aliases as cluster-bound; kuberc warnings may print twice.
- **Service data store in design doc** (`rdd/docs/design/cmd_service.md:15, 46`): Mentions of `rdd.sqlite3` and `config` map predate this PR and are tracked independently.
