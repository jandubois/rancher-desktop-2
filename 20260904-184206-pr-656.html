RequeueAfter is a time.Duration, so the untyped 1 is one nanosecond. Requeue: true rate-limited the requeue; RequeueAfter > 0 calls Queue.Forget(req) and re-adds with no throttle. In isolation the queue delay across eight passes falls from 645 ms to 1 ms.

Against a live control plane the cost is one extra reconcile about 1 ms later, and the same doubling appears with the requeue removed altogether. So this is a clarity defect, not a performance one. Nobody means one nanosecond, and the value leaves no bound if the cache ever converges slowly.

// drive replays controller-runtime's own requeue dispatch -- the
// `case result.RequeueAfter > 0` and `case result.Requeue` arms of
// pkg/internal/controller/controller.go:495-506 -- against its real priority
// queue, and reports the delay the queue adds before each redelivery.
func drive(t *testing.T, label string, result reconcile.Result, iterations int) {
	t.Helper()
	q := priorityqueue.New("probe", func(o *priorityqueue.Opts[string]) {
		o.RateLimiter = workqueue.NewTypedItemExponentialFailureRateLimiter[string](5*time.Millisecond, 1000*time.Second)
	})
	defer q.ShutDown()

	const req = "app"
	q.Add(req)
	prev := time.Now()
	var total time.Duration
	for i := range iterations {
		item, shutdown := q.Get()
		if shutdown {
			t.Fatal("queue shut down")
		}
		gap := time.Since(prev)
		total += gap
		prev = time.Now()
		t.Logf("%-26s delivery %d after %v", label, i+1, gap.Round(time.Microsecond))
		q.Done(item)
		switch {
		case result.RequeueAfter > 0:
			q.Forget(req)
			q.AddWithOpts(priorityqueue.AddOpts{After: result.RequeueAfter}, req)
		case result.Requeue: //nolint:staticcheck // reproducing the merge-base behaviour is the point
			q.AddWithOpts(priorityqueue.AddOpts{RateLimited: true}, req)
		}
	}
	t.Logf("%-26s TOTAL delay over %d requeues: %v", label, iterations, total.Round(time.Millisecond))
}

  • Promoted-field literals erase the metadata/payload boundary on Kubernetes objects (in-scope) Claude Opus 5. Flattening ObjectMeta: metav1.ObjectMeta{Name: …} to a bare Name: is the language feature this PR exists to adopt, and the rewrite is complete and correct. It also diverges from every Kubernetes example, from the generated files in pkg/apis/, and from what reviewers of this repo read daily. It reads worst where an object has a single promoted field, since HostInfo{Name: …} scans as a status field, and where two metadata fields share a line with the type's own (kube_reconciler_test.go:94, pathmanagement/controllers/reconciler_test.go:50).   • Generated output is toolchain-version-dependent (future) Claude Opus 5. make verify-generate compares committed apply-configurations against whatever the local go prints comments as. Results are consistent only because go 1.27.0 forces the toolchain and CI resolves go-version-file: rdd/go.mod. The next minor bump can produce the same whitespace-only churn.

Review Process Notes ¶

Skill improvements ¶

  • [ ] When a change replaces a deprecated API with a literal constant, verify the constant's units against its declared type before accepting the migration as mechanical. A deprecation fix reads as textual, so reviewers skim it; a bare integer assigned to a typed duration, size, or timeout is the case where that skim costs a behavior change. Report the effective value in the unit the type declares, not as written.
  • [ ] The retro table's Downgraded cell hard-codes the direction as I→S, so it misreports any other severity move (Critical to Important, or a finding reclassified as a design observation). Either accept a direction string in metadata.json or render the count alone, and let the Reconciliation paragraph carry the direction.
  • [ ] When judging whether a proposed fix is correct, check it against the constraint that forced the change under review. A fix that reinstates the exact construct a linter or deprecation rejected cannot merge, however well it restores the original behavior, and reviewers reach for the pre-change form because it is known-good.

S2 cites a commit SHA rather than a file, so beautify --lint reports it as unresolved. The finding is about a commit message, which lives in history and not in the tree; the citation is correct as written.

Repo context updates ¶

  • [ ] [repo] make verify-generate compares committed output against whatever go is on PATH, because scripts/generate-deepcopy.sh runs go tool controller-gen, whose comment printing varies by Go version. CI is immune, since every setup-go step uses go-version-file: rdd/go.mod with GOTOOLCHAIN=local, but a developer on a newer toolchain than the go directive sees whitespace-only drift in the containers applyconfiguration files. Check the local go version against the directive before reporting such a diff as stale generated output.
  • [ ] [repo] rdd/go.mod lists development tools (golangci-lint, controller-gen, ltag, shfmt) in a tool directive inside the production module, so a tool upgrade can raise the selected version of a package the daemon links. When a PR bumps a linter or generator, check whether the resulting go.mod changes touch modules that are runtime-reachable, using go mod why from a non-test package.
  • [ ] [repo] rdd/pkg/util/nxadmtail/ is a vendored copy of github.com/nxadm/tail with Pulumi's unmerged race fixes applied, and its convention is to preserve upstream text exactly and suppress lint with //nolint instead of editing.
