## Design Observations

### Concerns

- **The parser accepts whitespace the format it targets rejects** `(future)` [Claude Opus 5] — `parseQuantity.spec.ts:52-54` pins `'  10  Mi'` and `'5 Gi'` as valid, because line 26 trims the suffix. My apimachinery probe rejects both. That is harmless for a display converter and wrong for a validator, and this round tightened `'1..2'` in the name of conformance while leaving this laxity pinned by a test. A one-line comment saying the function is not a validator would stop a later caller reusing it as one.
- **A second quantity parser is still in the tree** `(in-scope)` [Codex GPT 5.6 Sol] — `quantityToScalar` at `pkg/rdd-client/util.ts` duplicates this grammar, no longer has callers, and does not handle fractional binary quantities. Deleting it would remove the drift risk.
- **The type and the function diverge outside ASCII** `(future)` [Claude Opus 5] — `String.prototype.trim()` and `\s` cover U+00A0 while the `Whitespace` union at `string-utils.ts:3` does not, so `kebabCase('a b')` returns `'a-b'` while the type keeps the U+00A0. The `@note` on line 46 already scopes the guarantee to ASCII, and every nav name is ASCII.

### Strengths

- **The suffix map matches apimachinery element for element** `(in-scope)` [Claude Opus 5, Gemini 3.1 Pro] — my Go probe against the pinned `k8s.io/apimachinery` agrees with the parser on all 21 inputs I tried, including the `E` and `Ei` suffixes this round restored. The `typeof scale !== 'number'` check also rejects prototype-chain keys; `'1toString'` throws.
- **Kebab enforcement moved from runtime to compile time** `(in-scope)` [all four reviewers] — `EnforceKebabNames` constrains each `name` to `KebabCase<N>`, so the acronym question disappears instead of being answered. Nav names are now literal slugs (`virtual-machine`, `wsl`) with a separate `labelKey` for display, which is the explicit-slug fix round 1 recommended, carried further.
- **`help.ts` sheds a third ad-hoc transform** `(in-scope)` [Claude Opus 5] — the removed `top.toLowerCase().replace(/ /g, '-')` and its `as topKeys` cast are genuinely redundant now that `top` is already a slug. I confirmed the mapping keys match the e2e selectors: `nav-wsl`, `nav-container-engine`, `nav-virtual-machine`.
- **The type assertions are a real gate** `(in-scope)` [Claude Opus 5] — the `Failures`/`AssertNoFailures` construct at `string-utils.spec.ts:49-54` fails compilation on a corrupted row rather than passing silently.

## Review Process Notes

### Skill improvements

- When a round's context injection names what the current round changed, derive that list from the merge-base of the SHA under review, not from a diff against the previous round's base. On a rebased branch those differ, and code the new base brought in reads as the author's work, sending every agent to verify something the PR never touched.
- When a finding proposes rounding, clamping, or reformatting a value bound to a UI control, check the control's own step, min, and max before repeating the patch. A value the control cannot represent produces a different defect than the one the finding named, and the control's constraints usually sit in a component the diff does not touch.

### Repo context updates

- `[repo]` `pkg/rancher-desktop/utils/testUtils/mockModules.ts` wraps `jest.unstable_mockModule`, which only intercepts modules imported *after* it runs. Specs must call `mockModules(...)` before pulling the component in, and reach it with a top-level `await import('@pkg/...')` rather than a static `import` (see `components/__tests__/StatusBar.spec.ts`). A spec that statically imports the component first still passes, because the mock silently does nothing. Passing `{}` for a key rather than `undefined` also discards the built-in default stub for that module.
- `[repo]` The memory slider in `components/SystemPreferences.vue` passes no `:interval` to `RdSlider`, whose prop defaults to `1`, while the CPU slider sets `:interval="1"` explicitly. Any change that gives the memory slider a fractional value must set an interval to match, or the value cannot be reached by dragging.
- `[repo]` Preferences nav items in `window/preferenceConstants.ts` carry a kebab-case `name` used as the identifier and a separate `labelKey` resolved through i18n for display. The `EnforceKebabNames` type rejects a non-kebab `name` at compile time. When reviewing a nav change, check the `name` against the `data-testid` selectors in `e2e/pages/preferences/*.ts` and the docs paths in `config/help.ts`, and check that the `labelKey` exists in `assets/translations/en-us.yaml`.
- `[repo]` UPDATE the entry on renderer quantity parsing: `@pkg/utils/parseQuantity` now accepts the `E` and `Ei` suffixes (inexactly, past `2 ** 53`), rejects repeated dots such as `1..2`, and rejects an exponent combined with a unit such as `1e3Ki`, all matching the pinned apimachinery. It still accepts internal whitespace (`'5 Gi'`) and returns `Infinity` for `'1e400'`, where apimachinery rejects the first and accepts the second.

## Design Observations

### Concerns

- **The parser is deliberately more permissive than the format it now claims to conform to** *(future)*. `parseQuantity.spec.ts:53-54` pins `'  10  Mi'` and `'5 Gi'` as valid, but apimachinery v0.36.3 rejects both (measured: `quantities must match the regular expression '^([+-]?[0-9.]+)([eEinumkKMGTP]*[-+]?[0-9]*)$'`). Same for `'1 '`, `' 1Gi'`, `'1Gi '`. That is fine for a display converter and wrong for a validator — the risk is a future caller reusing it as an input check. A one-line comment on the function saying "accepts more whitespace than Kubernetes; not a validator" would foreclose that.

- **Type-level and runtime kebab-casing diverge outside ASCII** *(future)*. Measured with `tsc 6.0.2`: `KebabCase<'a\u00A0b'>` is `'a\u00A0b'` while `kebabCase('a\u00A0b')` returns `'a-b'`, because `String.prototype.trim()` and the regex `\s` cover U+00A0 while the `Whitespace`/`Separator` unions at `string-utils.ts:3-4` do not. The `@note` at line 46-47 already scopes the guarantee to ASCII, so this is only worth noting if anything ever feeds the pair non-ASCII input.

### Strengths

- The suffix table at `parseQuantity.ts:31-48` matches apimachinery v0.36.3's `newSuffixer()` exactly, and the `typeof scale !== 'number'` check at line 51 (replacing the old `suffix in scaleMapping`) closes the prototype-chain hole — verified: `'1toString'`, `'1constructor'`, `'1__proto__'` all throw `Unknown units`.
- Accepting `string | number` (line 7) is the right call: the generated client types the field as `'memory'?: any` (`pkg/rdd-client/gen/models/IoRancherdesktopAppV1alpha1AppSpecVirtualMachine.ts:26`) because the CRD marks it `x-kubernetes-int-or-string`, so a JSON integer genuinely arrives at runtime.
- Moving kebab enforcement from a runtime transform to a compile-time constraint is a strictly better design than either lodash or the hand-rolled function: it removes the acronym question entirely rather than answering it. Verified — introducing `name: 'virtualMachine'` into `prefItemData` produces `TS2322: Type '"virtualMachine"' is not assignable to type '"virtual-machine"'`, and the same for a tab key (`'badHardware'` → `'bad-hardware'`).
- The `Failures`/`AssertNoFailures` construct at `string-utils.spec.ts:49-54` is a real gate, not decoration: ts-jest 29.4.11 runs with diagnostics on, and a deliberately broken row produces `TS2344: Type 'TypeFailure<"word", "word", "wrong">' does not satisfy the constraint 'never'`.
