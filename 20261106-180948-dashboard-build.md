## Suggestions

S1. **`bin/rdd` is not rebuilt when the dashboard's presence changes** — `rdd/Makefile:254` [Codex GPT 6 Astra, Claude Opus 5.5]

```make
bin/rdd$(EXE): $(GOLANG_SOURCES) $(EMBEDDED_SOURCES) $(GUESTAGENT_GZ) $(DISTRO_IMAGE) $(DASHBOARD_INDEX)
```

The rule watches the mtime of `index.html`, but the tag depends on whether the file exists. Deleting the staged directory leaves the old `with_dashboard` binary up to date. Staging an `index.html` that is older than `bin/rdd` does the reverse and leaves a binary built without the tag up to date. Unzipping the CI `dashboard` artifact produces such a file, and so does copying with `cp -p`, `rsync -a` or `tar x`. `make --directory=dashboard` writes fresh mtimes, so its own output always triggers a rebuild.

Fix: make `bin/rdd` depend on a stamp file that a `FORCE` rule rewrites only when `$(if $(DASHBOARD_INDEX),with_dashboard)` changes. Adding `FORCE` to `bin/rdd` itself also works, but then every `make build-rdd`, including the one that `yarn install` runs, invokes `go build` and re-signs the binary; I did not measure that cost.

**Outcome:** fixed in `e73fc574a`. `bin/rdd` depends on a `bin/.dashboard-tag` stamp that a `FORCE` rule rewrites only when the tag changes.

S2. **A release build without the dashboard still passes** — `rdd/Makefile:250` [Claude Opus 5.5]

```make
DASHBOARD_INDEX := $(wildcard pkg/steve/dashboard/index.html)
```

Choosing the tag by file presence suits dev and test builds, as the comment above it says, but the Package job falls back the same way. If the artifact path in `package.yaml` (lines 57 and 109), `STAGED` in `dashboard/Makefile:24` and this wildcard drift apart, the release builds without the dashboard and every check passes. `upgrade-generate.yaml` already packages without a dashboard job, which is probably fine for upgrade-test data.

Fix: have the Package job check `go version -m` on the built rdd for `with_dashboard`, or fail `make` when the index is missing and a `REQUIRE_DASHBOARD` variable is set.

**Outcome:** fixed in `e73fc574a`. The Package job's new step, "Check that rdd embeds the dashboard", checks `go version -m` on the built rdd for `with_dashboard`.

S3. **The pin-bump comment leaves out the checksum** — `dashboard/Makefile:10-17` [Claude Opus 5.5]

```make
# This commit on rancher-sandbox/dashboard's i18n-fixes-2.15 branch is
# RANCHER_TAG plus our shell fixes. We pin the commit because a branch archive
# does not have a stable checksum. yarn.lock holds a hash of this shell, so
# `yarn install --immutable` fails on a new commit. After `make` stops there,

```

With only `SHELL_COMMIT` changed, `make` stops at the `shasum --check` on line 31, before it reaches the `yarn install --immutable` that the comment tells the reader to expect.

Fix: add that a new pin also needs `RANCHER_SHA256` set to the new archive's checksum.

**Outcome:** fixed in `3f8ed042b`. The comment says a new pin also needs `RANCHER_SHA256` set to the new archive's checksum.
