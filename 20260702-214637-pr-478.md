## Important Issues

I1. **Mock-controller exit assertion is swallowed by its own catch** — `e2e/utils/TestUtils.ts:178-196` [Claude Opus 4.8, Codex GPT 5.5]

```ts
      const { exitCode: exit, signalCode: signal } = mockController;
      expect({ exit, signal }, 'mock controller exited').toEqual({ exit: 0, signal: null });
    }
  } catch (ex) {
    if (!ex || typeof ex !== 'object' || !('code' in ex) || ex.code !== 'ESRCH') {
      console.error(`Failed to clean up mock controller: ${ ex }`); // never re-throws
    }
  }
```

The assertion the delta commit added to surface a bad exit sits inside the same `try` as the kill, and the catch only logs — it never re-throws. A Playwright matcher error is not `code === 'ESRCH'`, so a crashed or signal-killed controller (`{exit: null, signal: 'SIGKILL'}`) reaches `console.error` and the test stays green. The `ESRCH` branch is itself dead: the old `process.kill(pid)` threw `ESRCH`, but `ChildProcess.kill()` does not. A mid-run crash is still caught indirectly — the app never settles, so `waitForAppSettled` times out — but a non-zero exit after the UI assertions pass goes unreported.

Fix: move the assertion out of the `try`, or re-throw everything except `ESRCH`.

```ts
} catch (ex) {
  if (ex && typeof ex === 'object' && 'code' in ex && ex.code === 'ESRCH') return;
  throw ex;
}
```

I2. **Stale-controller kill guard can never fire** — `e2e/utils/TestUtils.ts:320-322, 355-359` [Claude Opus 4.8, Gemini 3.1 Pro]

```ts
currentTest = {                                  // line 320: fresh object, no mockController
  file: testInfo.file, options, startTime: Date.now(),
};
// ...
if (typeof currentTest.mockController?.exitCode !== 'number') { // always undefined here
  currentTest.mockController?.kill();                           // no-op
}
```

`startRancherDesktop` replaces `currentTest` with a fresh object at line 320, then the guard at line 356 reads `currentTest.mockController` from that fresh object — always `undefined`. The guard, meant to kill a controller a prior run left behind, is dead code and never calls `kill()`. Today the trigger is narrow: `workers: 1` runs every file in one worker, teardown now reliably kills the controller (the Round 2 undefined-`app` fix), and only `.fixme` suites re-enter `startRancherDesktop` without a teardown between. The defect is real regardless of the current blast radius.

Fix: capture the previous handle before reassigning `currentTest`.

```ts
const previousController = currentTest?.mockController;
currentTest = { file: testInfo.file, options, startTime: Date.now() };
// ...
if (previousController && typeof previousController.exitCode !== 'number') {
  previousController.kill();
}
```

## Suggestions

S1. **Teardown can hang on an already-exited or unresponsive controller** — `e2e/utils/TestUtils.ts:181-186` [Claude Opus 4.8, Gemini 3.1 Pro]

```ts
if (typeof mockController?.exitCode !== 'number') {
  const promise = new Promise<void>((resolve) => {
    mockController.once('exit', () => resolve());
  });
  mockController.kill();
  await promise;
}
```

Two paths leave `await promise` waiting forever. If the controller already exited on a signal, `exitCode` is `null` (`typeof null === 'object'`), the guard treats it as running, and `once('exit')` waits for an event that already fired. If `kill()` (SIGTERM) fails to terminate the process, `'exit'` never fires. Either way teardown stalls to Playwright's hook timeout. The normal path is safe — `rdd service delete` earlier in teardown drops the control plane and the controller self-exits 0 before this block — so the risk stays confined to abnormal exits. Gemini rated this Important; the abnormal-only trigger puts it at Suggestion.

Fix: guard on both fields (`exitCode === null && signalCode === null`) and bound the wait with a timer that escalates to `SIGKILL`.

S2. **`Main App Test` runs without `.serial` despite order-dependent shared state** — `e2e/main.e2e.spec.ts:10` [Claude Opus 4.8]

```ts
test.describe('Main App Test', () => {
```

The suite shares one app across its tests and depends on order: `application should have been created` asserts `running === true`, then `progress should return when application not settled` sets `running=false`. Its sibling `screenshots/screenshots.e2e.spec.ts:29` runs the same "Main App Test" as `test.describe.serial`, and `preferences`, `quit-on-close`, and `start-in-background` follow that convention. Under `workers: 1` with `fullyParallel` off the happy path runs in order regardless, so this is no correctness break. It matters on failure: a plain `describe` runs the remaining tests after one fails, and on CI (`retries: 2`) retries a single test against already-mutated state instead of re-running the whole group from `beforeAll`.

Fix: use `test.describe.serial` to match the sibling suite and the repo convention.

## Review Process Notes

**Skill improvements**

- Add a review dimension for assertions placed inside error-swallowing handlers. When a test or cleanup routine puts an `expect`/`assert` inside a `try` whose `catch` only logs or returns, or inside a detached event callback, verify the assertion can still fail the test. A matcher throws an ordinary error; a catch that swallows or logs it turns a real failure into a false-green. Recognize the pattern as an assertion whose nearest enclosing `catch` does not re-throw, and flag it.
- Add a review dimension for cleanup or a guard that reads a resource handle from mutable shared state (a module variable or an object field). Trace the read back to the last write in the same scope: if an earlier statement reassigned or reset that state before the read, the guard operates on the new value and silently no-ops. Flag a teardown or safety-net check that reads state a preceding line in the same function already cleared.

**Repo context updates**

- `[repo]` The `rdd service` verbs are idempotent: `delete` returns nil when `!service.Exists()`, `create` returns nil when the instance already exists, and `start`/`stop` return nil when the plane is already in the target state (`rdd/cmd/rdd/service.go`). Do not flag an un-`.catch()`'d `rdd service delete`/`create` at the start of a test helper as "aborts setup on a clean environment" — the command exits 0 when there is nothing to do.
- `[repo]` `rdd svc config` blocks for readiness rather than reading a file: it routes through `ensureServiceRunning`, which waits up to `startWaitTimeout` (90 s) for the API server and a fresh discovery ConfigMap (`rdd/cmd/rdd/service.go`). An external controller that fetches its kubeconfig via `base.GetKubeConfigFromRDD` therefore blocks for readiness and does not fast-fail, even when the daemon was launched with `service start --wait=false`. Reviewers have twice flagged a nonexistent "controller starts before kubeconfig is written" race; the wait forecloses it.
- `[repo]` E2E suites that share one app or page across their tests and depend on test order use `test.describe.serial` (see `screenshots/screenshots.e2e.spec.ts`, `preferences`, `quit-on-close`, `start-in-background`). The e2e config runs `workers: 1` with `fullyParallel` off, so a plain `describe` still runs in order, but `.serial` additionally skips the remainder on a failure and retries the whole group from `beforeAll` rather than one test against mutated state. Flag an order-dependent, shared-state suite enabled as a plain `describe`.

### [Gemini] — Gemini 3.1 Pro

### Executive Summary

This delta commit migrates the mock controller lifecycle from per-test attachments to module-level state and removes flaky `beforeExit` polling. However, the new setup introduces a critical startup blocker where `rdd service delete` failure aborts the entire suite, and the teardown logic will hang indefinitely if the mock controller crashes.

### Findings

#### Critical Issues

**C1. `rdd service delete` failure aborts setup** — `e2e/utils/TestUtils.ts:348`

```typescript
    await spawnFile(
      path.join(topSrcDir, 'rdd', 'bin', exeName('rdd')),
      ['service', 'delete'],
      { env, stdio: ['ignore', rddLogs, rddLogs] });
```
`rdd service delete` exits non-zero if the service is not currently running. The `spawnFile` helper wrapper throws (rejects the promise) on non-zero exits. Because this call lacks a `.catch()` block, a failure here propagates out, skipping `rdd service start` and completely breaking the E2E setup in clean environments where the daemon isn't running yet.

Fix: Catch and swallow errors from the delete command so setup can proceed.
```diff
-    await spawnFile(
-      path.join(topSrcDir, 'rdd', 'bin', exeName('rdd')),
-      ['service', 'delete'],
-      { env, stdio: ['ignore', rddLogs, rddLogs] });
+    await spawnFile(
+      path.join(topSrcDir, 'rdd', 'bin', exeName('rdd')),
+      ['service', 'delete'],
+      { env, stdio: ['ignore', rddLogs, rddLogs] }).catch(() => {});
```

#### Important Issues

**I1. Teardown hangs indefinitely if the mock controller is killed by a signal** — `e2e/utils/TestUtils.ts:182` (regression)

```typescript
        if (typeof mockController?.exitCode !== 'number') {
          const promise = new Promise<void>((resolve) => {
            mockController.once('exit', () => resolve());
          });
          mockController.kill();
          await promise;
        }
```
If the mock controller crashes or is terminated by the OS, Node.js sets `exitCode` to `null` and `signalCode` to the signal name (e.g. `'SIGKILL'`). Because `typeof null` is `'object'`, the condition `typeof ... !== 'number'` evaluates to `true`. The teardown will attach an `'exit'` listener to a process that has already exited and `await` it forever, stalling the Playwright teardown until it hits a hard timeout.

Fix: Check both properties to reliably determine if the process is still running.
```diff
-        if (typeof mockController?.exitCode !== 'number') {
+        if (mockController.exitCode === null && mockController.signalCode === null) {
```

**I2. Stale controller cleanup uses overwritten `currentTest`** — `e2e/utils/TestUtils.ts:360` (regression)

```typescript
  currentTest = {
    file: testInfo.file, options, startTime: Date.now(),
  };
  // ...
  try {
    if (typeof currentTest.mockController?.exitCode !== 'number') {
      currentTest.mockController?.kill();
    }
  } catch { /* Ignore errors killing stale controllers */ }
```
`currentTest` is completely replaced at the start of `startRancherDesktop`. By the time the `try` block executes, `currentTest.mockController` is `undefined`. The stale controller cleanup is effectively dead code and cannot catch controllers leaked from earlier suite failures.

Fix: Capture the old `currentTest` before reassigning it.
```diff
+  const staleController = currentTest?.mockController;
   currentTest = {
     file: testInfo.file, options, startTime: Date.now(),
   };
   // ...
   try {
-    if (typeof currentTest.mockController?.exitCode !== 'number') {
-      currentTest.mockController?.kill();
+    if (staleController && staleController.exitCode === null && staleController.signalCode === null) {
+      staleController.kill();
     }
```

**I3. `teardown` file open outside `try` block bypasses cleanup if missing** — `e2e/utils/TestUtils.ts:165` (regression)

```typescript
  const logsDir = reportAsset(testInfo, 'log');
  const rddLogs = (await fs.promises.open(path.join(logsDir, 'rdd-exec.log'), 'a')).createWriteStream();
  try {
    const rddExe = path.join(import.meta.dirname, '..', '..', 'rdd', 'bin', exeName('rdd'));
// ...
```
If `startRancherDesktop` fails exceptionally early (or isn't called due to a fatal error), `logsDir` may not exist. Because `fs.promises.open` is outside the `try` block, it throws an unhandled `ENOENT` that crashes `teardown()`. This skips the `mockController.kill()` step entirely, leaking the background process.

Fix: Move directory creation and file opening into the `try` block.
```diff
   const logsDir = reportAsset(testInfo, 'log');
-  const rddLogs = (await fs.promises.open(path.join(logsDir, 'rdd-exec.log'), 'a')).createWriteStream();
+  let rddLogs: fs.WriteStream | undefined;
   try {
+    await fs.promises.mkdir(logsDir, { recursive: true });
+    rddLogs = (await fs.promises.open(path.join(logsDir, 'rdd-exec.log'), 'a')).createWriteStream();
     const rddExe = path.join(import.meta.dirname, '..', '..', 'rdd', 'bin', exeName('rdd'));
     await spawnFile(rddExe, ['service', 'delete'], { stdio: ['ignore', rddLogs, rddLogs] });
   } catch (ex) {
     console.error(`Failed to clean up RDD: ${ ex }`);
   } finally {
-    await expect(util.promisify(rddLogs.close.bind(rddLogs))(), 'failed to close RDD logs')
-      .resolves.toBeUndefined();
+    if (rddLogs) {
+      await expect(util.promisify(rddLogs.close.bind(rddLogs))(), 'failed to close RDD logs')
+        .resolves.toBeUndefined();
+    }
   }
```
