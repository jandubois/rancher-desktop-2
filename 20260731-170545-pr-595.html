My apimachinery probe rejects both. That is harmless for a display converter and wrong for a validator, and this round tightened '1..2' in the name of conformance while leaving this laxity pinned by a test. Review Process Notes ¶

Skill improvements ¶

  • When a round's context injection names what the current round changed, derive that list from the merge-base of the SHA under review, not from a diff against the previous round's base. On a rebased branch those differ, and code the new base brought in reads as the author's work, sending every agent to verify something the PR never touched.
  • When a finding proposes rounding, clamping, or reformatting a value bound to a UI control, check the control's own step, min, and max before repeating the patch. A value the control cannot represent produces a different defect than the one the finding named, and the control's constraints usually sit in a component the diff does not touch.

Repo context updates ¶

  • [repo] pkg/rancher-desktop/utils/testUtils/mockModules.ts wraps jest.unstable_mockModule, which only intercepts modules imported after it runs. Specs must call mockModules(...) before pulling the component in, and reach it with a top-level await import('@pkg/...') rather than a static import (see components/__tests__/StatusBar.spec.ts). A spec that statically imports the component first still passes, because the mock silently does nothing. Passing {} for a key rather than undefined also discards the built-in default stub for that module.
  • [repo] The memory slider in components/SystemPreferences.vue passes no :interval to RdSlider, whose prop defaults to 1, while the CPU slider sets :interval="1" explicitly. Any change that gives the memory slider a fractional value must set an interval to match, or the value cannot be reached by dragging.
  • [repo] Preferences nav items in window/preferenceConstants.ts carry a kebab-case name used as the identifier and a separate labelKey resolved through i18n for display. The EnforceKebabNames type rejects a non-kebab name at compile time. When reviewing a nav change, check the name against the data-testid selectors in e2e/pages/preferences/*.ts and the docs paths in config/help.ts, and check that the labelKey exists in assets/translations/en-us.yaml.
  • [repo] UPDATE the entry on renderer quantity parsing: @pkg/utils/parseQuantity now accepts the E and Ei suffixes (inexactly, past 2 ** 53), rejects repeated dots such as 1..2, and rejects an exponent combined with a unit such as 1e3Ki, all matching the pinned apimachinery. It still accepts internal whitespace ('5 Gi') and returns Infinity for '1e400', where apimachinery rejects the first and accepts the second.
