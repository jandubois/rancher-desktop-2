# Leave the App missing, or create it with the given addPath ("unset" omits

prepare_app() {
    "${rdd}" ctl delete app app --ignore-not-found >/dev/null
    "${rdd}" ctl wait --for=delete app/app --timeout=30s 2>/dev/null || true

    fi

}
addpath() {
    "${rdd}" ctl get app app -o jsonpath='{.spec.application.addPath}' 2>/dev/null || echo "(no App)"
}

Suggestions ¶

S1. cmd_app.md still says rdd stop behaves like rdd set running=false Codex GPT 6 Astra¶
rdd/docs/design/cmd_app.md

Start Rancher Desktop by setting `running=true` on the App singleton, creating the App with default settings if it does not yet exist. This is shorthand for `rdd set running=true`, sharing its `--wait`, `--timeout`, and exit-code behavior.

## `rdd stop`

Stop Rancher Desktop by setting `running=false` on the App singleton. `rdd stop` returns successfully without creating or starting anything when the instance or the App does not exist, or when the control plane is stopped. On a stopped control plane the App keeps its `running` value, so the next control-plane start resumes it. Otherwise it behaves like `rdd set running=false`, sharing the same `--wait` and `--timeout` flags.


## `rdd delete`

Delete the `App` and all owned objects, like the `LimaVM` and the `K3sVersions`, etc.

Round 3 made the pin depend on the caller, so the two commands now differ for an App that is still unset. rdd set running=false stores manual there, and rdd stop keeps unset (I1's probe, the unset rows). The statement held at the merge-base.

Skill improvements ¶

  • When the PR's linked issue names a follow-up issue that finishes the feature, fetch the follow-up's body and inline it beside the linked issue. External agents cannot fetch GitHub, so without it they report as gaps the doc and test changes that the follow-up already plans.
  • When a prior round left a design choice to the maintainers and the next revision takes one option, look for a maintainer's ruling before writing a finding or a test that assumes the choice. When none exists, raise the choice in the report as an open question. A test written to the author's pick otherwise locks in a behaviour that nobody with the authority to decide has approved.
