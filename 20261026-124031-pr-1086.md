## Executive Summary

The round-1 fixes hold. Quitting with the dialog open now exits, OK waits for the App, and the e2e harness creates the App before launch. Six defects remain. ## Important Issues

I1. **A failed OK does not tell the user why** — `pkg/rancher-desktop/pages/FirstRun.vue:85-88` [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.1 Pro, Gemini 3.5 Flash]

```ts
  } else {
    // If we're not closing the window, let the user try clicking again.
    processing.value = false;
  }
```

Round 1's I2 fix keeps the dialog open when OK's commit fails, but nothing says why. `preferences/commit` stores the API server's reason in `state.preferences.errorStatus` (`store/preferences.ts:212-229`), and the dialog renders nothing from it, so OK re-enables and the user learns nothing. Closing the window then drops the choices. The comment at lines 79-81 expects the main window to show the error, but that window builds its own store and never sees this one.

A failed App create looks the same: `ensureAppExists` returns `false` (`store/rdd.ts:110-113`), `FirstRun.vue:97` ignores it, and OK stays disabled with no message.

I2. **Eight locales show a literal `&hellip;` while the versions load** — `pkg/rancher-desktop/assets/translations/de.yaml:874` [Claude Opus 5.5, Codex GPT 6 Astra]

```yaml
    unavailable: Lade Versionen&hellip;
```

`KubernetesVersionSelector.vue:55` renders this key with `{{ }}` inside an `<option>`, and the `i18n/t` getter returns the raw string, so Vue escapes the entity. On a fresh install, the version list stays empty until the App exists and rdd writes the `k3s-versions` ConfigMap. Users of every non-English locale therefore see `Lade Versionen&hellip;` or its equivalent on the dialog's first screen. I3. **The first-run e2e spec never tears down its app or its rdd instance** — `e2e/first-run.e2e.spec.ts:14-17` [Claude Opus 5.5, Codex GPT 6 Astra]

```ts
  test.beforeAll(async({ colorScheme }, testInfo) => {
    electronApp = await startRancherDesktop(testInfo, { firstRun: true });
    firstRunPage = new FirstRunPage(await electronApp.firstWindow());
  });
```

Every other e2e spec calls `teardown`; this one does not. `startRancherDesktop` gives each spec its own instance, and only `teardown` (`e2e/utils/TestUtils.ts:157-180`) saves the trace, closes the app and runs `rdd service delete`. In the PR head's CI run, the first-run spec's control plane was never deleted and its trace was never saved. Its app's last log line, at 01:32:47.571, came after the last lines of the main and preferences specs. Locally, the control plane stays until the next run of this spec deletes it at startup.

```bash repro
#!/usr/bin/env bash
# Save as probe-e2e-teardown.sh; run: bash probe-e2e-teardown.sh [run-id]
# Needs gh. Downloads the log artifact of the PR head's e2e run and, for each
# spec, prints whether teardown deleted its control plane, whether its
# Playwright trace was saved, and the time of its app's last log line.
set -u
run=${1:-40049818904}
dir=$(mktemp -d)
gh run download "${run}" --repo rancher-sandbox/rancher-desktop-2 \
    --name failure-reports.zip --dir "${dir}" >/dev/null
for spec in first-run main preferences; do
    deleted=$(grep -c 'control plane has been deleted' "${dir}/${spec}-logs/rdd-exec.log")
    trace=$([[ -f ${dir}/${spec}-pw-trace.zip ]] && echo yes || echo no)
    last=$(tail -n 1 "${dir}/${spec}-logs/background.log" | cut -c1-24)
    echo "${spec}: deleted=${deleted} trace=${trace} last app log line ${last}"
done
rm -r "${dir:?}"
```

## Design Observations

### Concerns

- **Open question: should the first-run gate key on the App existing?** (in-scope) [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.1 Pro, Gemini 3.5 Flash]: The dialog creates the App when it opens, because its settings patch the App and rdd writes the version list only after the App exists; the code bears that out. It does not follow that the gate must key on the App existing. `c8543e759` on main (#1081) defaults `spec.application.addPath` to `unset`, forbids returning to it, and has `rdd set` write `manual` for a new App so CLI-created instances skip the dialog. After a rebase, keying the gate on `addPath == unset`, with OK writing the field, would reopen the dialog after a quit or kill mid-dialog. What OK should write before the path-management selector exists is part of the same choice. This is a maintainer call, and no finding or test here assumes either answer.
- **The first-run check spawns the `rdd` CLI** (in-scope) [Claude Opus 5.5]: `isFirstRunNeeded` runs `rdd service status` and `rdd ctl get app` before any window opens. The main process already caches the kubeconfig in `fetchConfig()`, so a GET of the App over the kube API answers the same question. Its only spawn is `rdd service config`, which the app runs anyway, and it fits the README's statement that the GUI reaches rdd through its kube API (S2).
- **Outside the first-run spec, e2e no longer exercises the GUI's own App creation** (future) [Claude Opus 5.5]: every other spec now creates its App with `rdd set` before launch, so `ensureAppExists` always finds one.

### Strengths

- Destroying the FirstRun window from the `before-quit` pipeline fixes round 1's hidden process without touching the renderer; Electron probes by two agents confirmed the quit [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash].
- Disabling the dialog's inputs and OK until preferences load closes round 1's early-OK path [Gemini 3.5 Flash, Codex GPT 6 Astra].
- `rdd-ctl.spec.ts` now runs without a built `rdd`, and its outcome assertions pin the spawns: a constant `isFirstRunNeeded` fails 2 of its 4 tests [Codex GPT 6 Astra, Claude Opus 5.5].
- `cliflag.EnumValue`, the `LifetimeState` enum and the shared selectors still stand, as round 1 credited them [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash].

### Repo context updates

- [repo] Translations reach Vue through the `i18n/t` getter, which returns the raw string. A value rendered with `{{ }}` or bound to an attribute shows an HTML entity such as `&hellip;` as typed; only `<t raw>` and `v-clean-html` decode it. Flag an entity in a translation whose render site is a text sink, in every locale.
- [repo] Every e2e spec that calls `startRancherDesktop` must call `teardown(electronApp, testInfo)`, from `test.afterAll` when its tests share one app. Each spec gets its own rdd instance, and only `teardown` closes the app, saves the trace and deletes the instance before the spec's next run, so a spec without it leaks a control plane and loses its diagnostics while every test still passes.

Flag client code that polls for a CRD after such a command; only the e2e harness, whose mock controller registers CRDs after the annotation, needs that wait.

###### Design Observations

**Concerns**

- **(in-scope) Do the first-run check over the kube API, not by spawning `rdd`.**
  - The main process already caches the kubeconfig in `fetchConfig()`, which the dialog and main window call anyway. `isFirstRunNeeded` could `await fetchConfig()` and `GET` the App by name; a 404 means first run.
  - That drops `rdd service status`, the `api-resources` loop (S1) and `rdd ctl get app`, and it keeps the README's kube-API-only contract (I4).
  - The cost is unchanged: `rdd service config` creates and starts the service exactly as the dialog's own `fetchConfig` would.
- **(in-scope) Open question from round-1 I4: should the gate key on App existence?** The author says the App must exist "to have settings to work with". The code supports that much:
  - The preferences store validates and patches against the App (`patchApp`).
  - The k3s-versions ConfigMap only appears once the App exists.

  It does not follow that the *gate* must key on existence. `upstream/main`'s `c8543e759` adds `spec.application.addPath: unset` as the default, forbids returning to `unset` with a CEL rule, and has `rdd set` write `manual` for a new App, explicitly so CLI-created instances skip the dialog. After a rebase, gating on `addPath === 'unset'` would reopen the dialog after a quit or kill mid-dialog while still creating the App up front. Whether that should replace the existence check is a maintainer call.
- **(future) Every e2e App now comes from `rdd set`, not from the GUI.** On `main`, `rdd set` also pins `addPath=manual`, so the e2e suite no longer exercises the GUI's own App creation outside the first-run spec.

**Strengths**

- `LifetimeState` makes `activate` and `second-instance` behaviour explicit per phase. This round's move of `ShuttingDown` above the emit closes the quit hole without touching the renderer.
- Destroying the FirstRun window from `mainEvents` `before-quit` reuses the existing quit pipeline instead of a second quit pass.
- `cliflag.EnumValue` moves format validation into pflag; tests pass with `-race`.
- `KubernetesVersionSelector` and the self-contained `EngineSelector` remove duplicated selection logic. This round undoes none of the round-1 strengths.

###### Design Observations

###### Concerns

1. **First-run gate keys on App existence; killed process skips dialog permanently** `(in-scope)`
   When `FirstRun.vue` mounts, line 100 runs `store.dispatch('rdd/ensureAppExists')`, which creates the `App` object with `spec.running: false` and default settings. If the process terminates abnormally (SIGKILL, crash, power loss) while the dialog is open, the `App` object already exists in etcd/kine. On the next application launch, `isFirstRunNeeded()` checks `rdd ctl get app` (line 165), sees the existing `App`, and returns `false`. The dialog is never shown again, and `ensureAppStarted()` launches the VM with default settings without user consent.
   *Alternative approach:* As designed in #1051 and enabled by commit `c8543e759` (#1081 on main, which defaults `spec.application.addPath: unset`), the first-run gate should check whether `spec.application.addPath` is `unset` rather than whether the `App` resource exists. When the user accepts the dialog, `addPath` is set (e.g. to `front` or `manual`). Until accepted, `addPath` remains `unset`, guaranteeing that subsequent runs still open the first-run dialog if interrupted.

###### Strengths

1. **Reliable window termination during quit:** In `window/index.ts:753-757`, destroying the FirstRun window synchronously upon `mainEvents.on('before-quit')` prevents the `beforeunload` listener from calling `event.preventDefault()` and hanging the quit process.

3. **Dedicated flag enumerations:** `cliflag.EnumValue` (`3e487be48`) provides clean, reusable Cobra/pflag enum handling for both `service paths` and `service status`.
