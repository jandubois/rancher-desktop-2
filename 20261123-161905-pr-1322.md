The guest's transfer service reports extraction under each layer's download name, with progress up to the layer's size (`core/transfer/local/progress.go:143-164`, containerd v2.4.2). ## Design Observations

### Concerns

- **A cancelled pull keeps running in the guest, and its lease pins the content for a day** (in-scope). After a timed-out `rust:1-alpine` pull, the guest stored the image 10 s after the request settled as `PullTimeout`, and two timed-out pulls left two leases behind. `Client.Transfer` creates a lease that expires after 24 h and deletes it with the pull's own context (`client/transfer.go:29-33`, `client/lease.go:37-42` in v2.4.2). The timeout has already cancelled that context, so the lease outlives the pull. A user sees a timeout, and the image appears anyway.
- **A slow final disk flush doesn't report progress, even with I1's patch** (future). With the guest's containerd writes limited to 8 MB/s, the patched build still timed out, after quiet stretches of 44 s and 60 s. Extraction progress counts the compressed bytes read, and the flush after the last read doesn't report progress. Only a heartbeat sent while the transfer runs would cover that flush, but a heartbeat would also keep a hung unpack from ever timing out.
- **A namespace label can turn off the unpack without an error** (in-scope) [Claude Opus 5.5]. `getSnapshotter` honours the namespace's `containerd.io/defaults/snapshotter` label. When that names a snapshotter missing from the daemon's unpack configuration, the daemon logs "Unpack configuration not supported, skipping" and the pull succeeds without unpacking the image (`core/transfer/local/pull.go:212`).
- **CI never selects containerd** (future) [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash]. Neither the `bats-app` job nor `bats-docker` sets `RDD_CONTAINER_ENGINE=containerd`, and the matrix leaves out `bats-nerdctl`, so I1 through I4 passed CI. One containerd job running `image-docker.bats` would cover the pull path.

### Strengths

- **The pull now runs in the guest** [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.5 Flash]. Moving to the transfer service fixed round 1's stall, host snapshotter and tagged-short-name findings. On a live guest, `image-docker.bats` passed under containerd, and requests without `spec.namespace` pulled into `default`.
- **`WithDefaultNamespace` is safe for the rest of the watcher** [Claude Opus 5.5]. Its other calls set a namespace or don't need one, and the events service doesn't scope a subscription by the namespace header (`plugins/services/events/service.go:101-105`).

## Review Process Notes

### Skill improvements

- Check free disk space before launching agents and again while they run. Agents that build write their own build caches into their worktrees, and several of them can fill a nearly full disk partway through a review.
- When a PR changes tests for a configuration that no CI job selects, such as another engine, platform or feature flag, run the changed tests in that configuration before consolidating. A green CI run never reached those branches.

##### Design Observations

**Concerns**

- **(in-scope)** `getSnapshotter` honours the namespace's `containerd.io/defaults/snapshotter` label. If that label names a snapshotter missing from the daemon's transfer `unpack_config`, the daemon logs "Unpack configuration not supported, skipping" and the pull succeeds unpacked (`core/transfer/local/pull.go:189-203`). Passing `""` would let the daemon choose its configured default. Alternatively, keep the label and say in a comment that the pull still succeeds when the label names an unsupported snapshotter, just without unpacking.
- **(future)** CI never runs containerd: `bats-nerdctl` and the containerd variants of `tests/32`/`34` are not in the `rdd-bats.yaml` matrix. Each of I1–I5 escaped for that reason. One containerd job running `image-docker.bats` and `tests/40-docker/` would cover this PR's surface.

**Strengths**

- Moving the pull into the guest daemon removes round 1's host-side unpack into the host snapshotter. Daemon-side pulls also go through containerd's allowed-images `HTTPS_PROXY` drop-in (`rdd/overlay/root/usr/local/lib/systemd/system/containerd.service.d/allowed-images.conf`), the same mechanism dockerd uses.
- `WithDefaultNamespace` is safe for the rest of the watcher. Every other call either sets a namespace (`container_actions_containerd.go:103,506,541`, the `sync_*_containerd.go` sites) or rejects an empty one. The events service ignores the injected namespace header (`plugins/services/events/service.go:101-105`).

I2. **Remote registry HTTP 401/403 status is lost across gRPC, preventing `Unauthorized` classification** — `rdd/pkg/controllers/app/engine/controllers/containerd_watcher.go:367-372` (important, new-feature)

```go
		// Convert unexpected status errors as needed.
		if unexpectedErr, ok := errors.AsType[remoteerrors.ErrUnexpectedStatus](err); ok {
			switch unexpectedErr.StatusCode {
			case http.StatusUnauthorized, http.StatusForbidden:
				return fmt.Errorf("%w: %w", cerrdefs.ErrUnauthenticated, err)
			}
		}
```

Because `w.cli.Transfer` executes over gRPC (`client/transfer.go:34`), daemon errors are encoded with `errgrpc.ToGRPC` (`plugins/services/transfer/service.go:122`). `remoteerrors.ErrUnexpectedStatus` does not implement `errdefs` interfaces, so `errgrpc.ToGRPC` serializes it as an unmapped `codes.Unknown` status. On the client, `errgrpc.ToNative` (`core/transfer/proxy/transfer.go:155`) returns an opaque `errdefs.customMessage`. `errors.AsType[remoteerrors.ErrUnexpectedStatus](err)` is therefore always `false` on gRPC returns, and 401/403 registry errors still settle with reason `PullFailed` instead of `Unauthorized` (`image_pull_request_reconciler.go:506`).

```go repro
)

func main() {
	origErr := remoteerrors.ErrUnexpectedStatus{StatusCode: 401}
	nativeErr := errgrpc.ToNative(errgrpc.ToGRPC(origErr))
	if _, ok := errors.AsType[remoteerrors.ErrUnexpectedStatus](nativeErr); !ok {
		panic("ErrUnexpectedStatus lost across gRPC error mapping")
	}
}
```

```text repro-output
panic: ErrUnexpectedStatus lost across gRPC error mapping
```

Fix: Check the returned gRPC error message for unauthorized/forbidden HTTP status indicators:

```diff
-		if unexpectedErr, ok := errors.AsType[remoteerrors.ErrUnexpectedStatus](err); ok {
-			switch unexpectedErr.StatusCode {
-			case http.StatusUnauthorized, http.StatusForbidden:
-				return fmt.Errorf("%w: %w", cerrdefs.ErrUnauthenticated, err)
-			}
-		}
+		if strings.Contains(err.Error(), "401 Unauthorized") || strings.Contains(err.Error(), "403 Forbidden") {
+			return fmt.Errorf("%w: %w", cerrdefs.ErrUnauthenticated, err)
+		}
```

I3. **Progress updates halt during layer unpacking, risking premature timeout on large images** — `rdd/pkg/controllers/app/engine/controllers/containerd_watcher.go:357-360, 394-396` (important, gap)

