S1. **No test pins `build -f .`, the case behind round 1's I2** — `rdd/pkg/nerdctlstub/translate_test.go:369-373` [Gemini 3.5 Flash]

```go

		{"k.pem:.", "/mnt/c/w/k.pem:.", "/mnt/c/w/k.pem:."},
```

No test hands the stub a bare `.`. The new `TestTranslateCommandLinePathForms` cases pass `C:\ctx\.` and `D:\.`, and `TestKeepDirSuffix` covers only drive forms and a key file.

The `slashed == "."` clause of `keepDirSuffix` (`rdd/pkg/nerdctlstub/translate.go:150`) is what makes `build -f .` reach nerdctl as `<dir>/.`, which nerdctl reads as `./Dockerfile`. Deleting that clause leaves `go test ./pkg/nerdctlstub/ ./pkg/guestexec/` green, so round 1's I2 regression could come back unnoticed. With the case below, the same mutation fails `TestKeepDirSuffix` with `/mnt/c/w (string) != /mnt/c/w/. (tc.want string)`, and the reviewed code passes it.

Fix: add a bare `.` case to `TestKeepDirSuffix`.

```diff
 		{"d:", "/mnt/d/", "/mnt/d/."},
+		{".", "/mnt/c/w", "/mnt/c/w/."},
```

**Outcome:** fixed as proposed in `d35b3f180`. The row fails with the `slashed == "."` clause deleted.

S2. **The doc blames the stub for a comma limit that nerdctl and buildctl impose too** — `rdd/docs/design/nerdctl.md:65-66` [Claude Opus 5.5]

```markdown

stub splits those values at every comma. The stub expands a relative path to
```

nerdctl v2.1.2's `ProcessFlagMount` splits a `--mount` value at every comma (upstream `pkg/mountutil/mountutil_linux.go:295`), and buildctl v0.21.1's `ParseSSH` splits the paths of an `--ssh` value the same way (upstream `cmd/buildctl/build/ssh.go:18`). So an absolute path with a comma fails in the guest whatever the stub does. The paragraph goes on to say that quoting works in the builder CSV values, which suggests the stub could lift the limit for `--mount` and `--ssh` as well. Only the relative-path case comes from the stub. Round 1's I3 patch wrote this sentence.

```markdown

comma, so a path inside one cannot contain a comma. The stub expands a
relative path to an absolute one, so a relative path in them fails the same
way when the working directory has a comma, such as `OneDrive - Acme, Inc`.
```

**Outcome:** fixed in `d35b3f180`, worded as "nerdctl splits a `--mount` value at every comma, and buildctl splits the paths in an `--ssh` value the same way", with "a relative path in either" in the next sentence.

S3. **The commit message leaves out how far the directory-form change reaches, and the new dependency** — `1e6f43bfc` [Claude Opus 5.5]

The message describes the build options alone. But `keepDirSuffix` runs inside the shared `filePathArgHandler`, so it changes every path that the stub rewrites through that handler. This commit merges after #974, so its message is where a reader of the log learns that #974's handlers changed. The message also omits that `github.com/tonistiigi/go-csvvalue` becomes a direct dependency.

Fix: add a sentence on each, saying that every rewritten path keeps its directory form and that buildctl's own CSV parser, go-csvvalue, now reads the builder CSV values.

**Outcome:** fixed in `d35b3f180`. The message says that most rewritten paths keep their directory form, since the `-v` source, `--ssh` and `--build-context` handlers call `TranslateHostPath` directly and skip `keepDirSuffix`.

S4. **The `!ok` test never changes what `builderOutputArgHandler` returns** — `rdd/pkg/nerdctlstub/translate.go:332-336` [Claude Opus 5.5]

```go
	trimmed, ok := strings.CutPrefix(result, wrapper)
	if !ok || strings.Contains(trimmed, "type=") {
		return result, nil
	}
	return trimmed, nil
```

`result` lacks the wrapper prefix only when `writeCSVRecord` quoted the `dest=` field, and its first field is then still the unquoted `type=local`. So `strings.Contains(trimmed, "type=")` holds whenever `!ok` does. Deleting `!ok` leaves the package suite green, while deleting the `type=` test fails `TestBuilderOutputAndSecret`. The comment names two reasons to keep the wrapper, but only the second one decides.

The doc's claim that a relative path works from a working directory with a comma (`rdd/docs/design/nerdctl.md:70-71`) holds. From a directory named `a,b`, `-o out`, `--secret id=s,src=s.txt` and `--cache-to type=local,dest=c` each come out with the path field quoted, and buildctl's parser reads back the intended fields. No test covers that case.

Fix: drop `!ok` and say in the comment that a quoted `dest=` field leaves `type=local` in the value, or keep it and add a `t.Chdir` case for a directory named `a,b` beside the existing `type=x` case.

**Outcome:** fixed by the second option in `d35b3f180`. `!ok` stays, and `TestBuilderOutputAndSecret` runs `-o out` and `--secret id=s,src=s.txt` from a working directory named `a,b` and expects both path fields quoted.

###### Caller Audit for `filePathArgHandler`, `outputPathArgHandler`, and `fileOrURLOrStdinArgHandler`

`keepDirSuffix` (`translate.go:145–164`) is invoked inside `filePathArgHandler`, which is also called by `outputPathArgHandler` and `fileOrURLOrStdinArgHandler`. Every consumer was evaluated against nerdctl v2.1.2 and buildctl v0.21.1 semantics:

1. **`build --file` / `-f` (`fileOrURLOrStdinArgHandler`)**: In `pkg/cmd/builder/build.go:281`, nerdctl uses `filepath.Split(options.File)`. Preserving `/` or `/.` yields `file == ""` or `file == "."`, which `buildkitutil.BuildKitFile` defaults to `DefaultDockerfileName` ("Dockerfile"). Cleaning the path would strip the trailing slash and treat the directory name as the Dockerfile file name, failing the build.
2. **`compose --file` / `-f` (`fileOrURLOrStdinArgHandler`)**: Compose expects either a file or a directory containing `compose.yaml`/`docker-compose.yaml`. Keeping `/` or `/.` preserves directory semantics identically.

###### Acknowledged Limitations

- **Commas in `--mount` and `--ssh` values**: Documented at `nerdctl.md:65–68`. Neither flag uses CSV quoting; paths containing commas fail if expanded against host directories with commas.
- **BATS test backslash handling**: `engine-containerd.bats:672` runs `cygpath -w` behind `skip_on_unix`. Windows BATS runs under MSYS2, so lack of a WSL branch is expected and consistent with existing test patterns.
- **Case-sensitive `raw=` matching in `--ssh`**: Implemented at `translate.go:351` (`strings.HasPrefix(p, "raw=")`) to strictly follow buildctl v0.23.0+ key matching.
- **Trailing line breaks stripped in `--output`**: `csvvalue.Fields` treats trailing `\r\n` as record termination (`translate.go:204`); Windows file paths do not end in newlines.
- **Leaked temporary directory with `-f -` on malformed `--build-context`**: Passing `--build-context` values without `=` to nerdctl causes nerdctl's `pkg/cmd/builder/build.go:293–296` to fail after creating the temporary Dockerfile directory without running deferred cleanup. Acknowledged as upstream nerdctl error handling behavior.
