I1. **A short-option bunch that fails at a command is parsed again at its parent** — `rdd/pkg/nerdctlstub/parse_args.go:131-133` [Claude Opus 5.5]

```go

```

`parseShortOptions` (called at line 103) already looks up each letter of a bunch at every enclosing level. When it fails, some letter is unknown at every level, so the retry at line 132 can succeed only by reading an earlier letter differently. The root's `-a` is the value flag `--address`, while `images` has a boolean `-a`. At the merge-base, the line reached nerdctl unchanged.

I2. **A comma-separated list of files is translated as one path** — `rdd/pkg/nerdctlstub/overlay.go:43-44` [Codex GPT 6 Astra]

```go

		"--label-file": filePathArg,
```

nerdctl v2.1.2 declares these flags, `exec`'s `--env-file` and the `--key` of `image encrypt` and `image decrypt`, as pflag `StringSlice`s, which split a value at commas (`container_run.go:248,261`, `container_exec.go:52`, `image_cryptutil.go:79`). `filePathArgHandler` translates the whole list as one path (`translate.go:124`), so a second drive path stays untranslated and fails in the guest. I3. **Splitting an attached value hides the subcommand from cobra** — `rdd/pkg/nerdctlstub/parse_args.go:128` [Codex GPT 6 Astra, Claude Opus 5.5]

```go
		return []string{option, converted}, consumed, nil
```

Line 128 splits an attached value from its option for every known option, whether or not the value changed. So `--hosts-dir=--certs ps` reaches nerdctl as `--hosts-dir --certs ps`. nerdctl's root sets cobra's `TraverseChildren` (`main.go:212`), so cobra's `Traverse` reads the separate `--certs` as a new flag, takes `ps` as its value and runs the root command instead of `ps`. The trigger needs a value that starts with a dash, on an option before a subcommand, and no root or compose option takes such a value in practice. But the original line worked at the merge-base, and the rewrite does not.

## Review Process Notes

### Skill improvements

- When a change rewrites a command line for a program that parses it in more than one stage, such as cobra's subcommand traversal before pflag's flag parse, compare the rewrite under each stage, not only the final one. The stages read the same tokens differently, so a rewrite that the flag parser accepts can still send the earlier stage to another command.

### Repo context updates

- [repo] UPDATE the pending nerdctl-stub parity rule: also check a rewrite against cobra's `TraverseChildren` on nerdctl's root and `compose`, where cobra takes a separate value that starts with `-` for a flag, and check each translated option's declared pflag type, since a `StringSlice` (`run --env-file`, `--label-file`, `image encrypt --key`) splits the value at commas after the stub rewrote it as one path. A short-option bunch that fails at a command must reach nerdctl unchanged, not be parsed again at an enclosing command.
