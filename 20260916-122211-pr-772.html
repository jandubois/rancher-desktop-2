Executive Summary ¶

Round 1's I1 asked for a selectable status.name written by one shared helper. The field is there; the marker and the helper are not. A real apiserver rejects status.name as a field selector (I1), so the ImagePullRequest webhook re-derives the hash as a second, untested copy of the naming rule (I2). The new IsNotFound guard cannot fire (I3), and the new BATS test races the two-step status write (I4).

The author amended the single commit in place; the merge-base is unchanged, so the round-2 delta is the whole fix. Claude raised every Important finding and four of the six suggestions; Codex found I3, which Claude and Flash both got backwards. I proved each Important finding with a probe run against the reviewed tree, one of them against a real kube-apiserver, and verified a patch for each.

Review Process Notes ¶

Skill improvements ¶

  • When a finding rests on how a client library classifies an error, read the server or store that produces the error, not only the client's conversion path. A proxy that maps a transport code faithfully proves nothing about whether the code is ever sent, Trace only the client half and you get a wrong verdict with a full citation chain behind it, which is the hardest kind to catch in consolidation.
  • When a PR adds a status field whose purpose is to let clients find an object by a name other than its own, check whether the field is declared selectable in the generated schema. A status field that consumers cannot filter on forces every consumer to re-derive the object's name, which is how one naming rule acquires a second implementation.

Repo context updates ¶

  • [repo] A CRD status field is only queryable when its Go type has +kubebuilder:selectablefield:JSONPath=.status.<field> and the generated crd.yaml shows a matching selectableFields entry. Without it the apiserver rejects the selector with field label not supported. Flag any change that documents a join on a status field, or adds a status field so a consumer can look the object up, and omits the marker. The limit is 8 selectable fields per version and +optional fields are eligible.
  • [repo] The renderer's namespace picker is dead code. supportsNamespaces() in pkg/rancher-desktop/store/container-engine.ts returns a hardcoded false and the dropdown is behind v-if="supportsNamespaces". Rate renderer-side namespace defects as latent until that getter reads the backend.
  • [repo] pkg/rdd-client/gen/ is regenerated in its own commit by convention (RDA: rdd-client: regenerate), and no CI job checks it against the CRDs. A new CRD field missing from the generated TypeScript is expected follow-up work, so do not report it against the PR that added the field.
  • [repo] containerd's namespace store reports a namespace it does not hold as an empty label map with a nil error, never NotFound (core/metadata/namespaces.go, Labels). Reject any error handling that treats a NotFound from NamespaceService() as the signal that a namespace was deleted.
