## Executive Summary

Round 1's I1 asked for a selectable `status.name` written by one shared helper. The field is there; the marker and the helper are not. A real apiserver rejects `status.name` as a field selector (I1), so the `ImagePullRequest` webhook re-derives the hash as a second, untested copy of the naming rule (I2). The new `IsNotFound` guard cannot fire (I3), and the new BATS test races the two-step status write (I4).

## Important Issues

I1. **`ContainerNamespace.status.name` is not a selectable field, so no client can resolve a mirror from the engine's name** — `rdd/pkg/apis/containers/v1alpha1/container_namespace_types.go:29` [Claude Opus 5]

```go
// +kubebuilder:object:root=true
// +kubebuilder:ac:generate=true
// +kubebuilder:subresource:status
// +kubebuilder:resource:shortName=cns,categories="all"
```

`Volume`, the resource round 1 named as the model, pairs its hashed `metadata.name` with `+kubebuilder:selectablefield:JSONPath=.status.name` (`rdd/pkg/apis/containers/v1alpha1/volume_types.go:57-58`). `ContainerNamespace` got the status field without the marker, so a client holding `Not_Valid` must list every mirror or recompute the hash. That is why I2 exists.

The commit writes the join into the API: `ContainerStatus.Namespace` now says "a `ContainerNamespace` object in the same Kubernetes namespace exists where its `status.name` matches this value" (`rdd/pkg/apis/containers/v1alpha1/container_types.go:140-142`). Nothing can perform that match server-side. `selectableFields` does not require `+required`, so `+optional` is no obstacle.

containerd's namespace store answers an absent namespace with an empty label map and a nil error, never `NotFound`. The service's `Get` forwards that verbatim (`plugins/services/namespaces/local.go:78-93` at v2.3.5) and the client proxy returns it unwrapped, so the guard is dead and the race it names is unhandled. That is harmless today, since the queued `NamespaceDelete` removes the mirror either way.

Two neighbouring statements are also false. Take "the object will be deleted on next reconcile". No reconcile deletes a `ContainerNamespace`; `fullSync` runs only from `newContainerdWatcher` (`containerd_watcher.go:94`). And line 72's caller list omits `NamespaceUpdate`, a fourth caller this commit added (`containerd_watcher.go:256-258`).

## Design Observations

### Concerns

- **The mirror-name rule is a documented contract with no owner** `(in-scope)` [Claude Opus 5, Codex GPT 5.6 Sol]. `rdd/docs/design/api_containers.md:140-142` states the rule normatively, the code holds it in two places, and the type that defines the resource holds it in neither. I2's patch moves it beside `ContainerNamespaceKind`, which is where a new consumer looks; with I1's marker a consumer then gets a choice between deriving the name and selecting on the real one.
- **The two-step apply publishes a half-written mirror** `(future)` [Codex GPT 5.6 Sol, Claude Opus 5]. Every consumer must tolerate a mirror that exists with no status. Splitting the write is right for a status subresource, and it also makes "the object exists" a weaker signal than a reader expects. I4 is the first thing to trip on it, and it will not be the last.
- **`applyNamespace` runs on every container and image create** `(future)` [Claude Opus 5]. Each call is now a create-or-update, a containerd round trip, and a status apply, for labels that rarely change. The engine reconciler watches `ContainerNamespace`, so each status write also wakes a reconcile; the workqueue coalesces them, so nothing is broken today.

### Strengths

- **Fetching labels rather than trusting the event payload** `(in-scope)` [Claude Opus 5]. containerd's `Update` applies a field mask and republishes only the requested keys, so `NamespaceUpdate.Labels` is a delta. Reading them back from `NamespaceService()` is the correct call.
- **`activeNames` is now recorded outside the apply's error branch** `(in-scope)` [Claude Opus 5] (`sync_namespace_containerd.go:42-45`), so one failed apply no longer also prunes the mirror it failed to refresh.
- **The replacement BATS test covers the whole round trip** `(in-scope)` [Codex GPT 5.6 Sol, Gemini 3.1 Pro]: the encoded name, the status, a label update through the new `NamespaceUpdate` path, the container inside the namespace, and the reaping. It replaces a test whose central assertion could not fail.

## Review Process Notes

### Skill improvements

- When a finding rests on how a client library classifies an error, read the server or store that produces the error, not only the client's conversion path. A proxy that maps a transport code faithfully proves nothing about whether the code is ever sent, Trace only the client half and you get a wrong verdict with a full citation chain behind it, which is the hardest kind to catch in consolidation.
- When a PR adds a status field whose purpose is to let clients find an object by a name other than its own, check whether the field is declared selectable in the generated schema. A status field that consumers cannot filter on forces every consumer to re-derive the object's name, which is how one naming rule acquires a second implementation.

### Repo context updates

- `[repo]` A CRD status field is only queryable when its Go type has `+kubebuilder:selectablefield:JSONPath=.status.<field>` and the generated `crd.yaml` shows a matching `selectableFields` entry. Without it the apiserver rejects the selector with `field label not supported`. Flag any change that documents a join on a status field, or adds a status field so a consumer can look the object up, and omits the marker. The limit is 8 selectable fields per version and `+optional` fields are eligible.
- `[repo]` The renderer's namespace picker is dead code. `supportsNamespaces()` in `pkg/rancher-desktop/store/container-engine.ts` returns a hardcoded `false` and the dropdown is behind `v-if="supportsNamespaces"`. Rate renderer-side namespace defects as latent until that getter reads the backend.
- `[repo]` `pkg/rdd-client/gen/` is regenerated in its own commit by convention (`RDA: rdd-client: regenerate`), and no CI job checks it against the CRDs. A new CRD field missing from the generated TypeScript is expected follow-up work, so do not report it against the PR that added the field.
- `[repo]` containerd's namespace store reports a namespace it does not hold as an empty label map with a nil error, never `NotFound` (`core/metadata/namespaces.go`, `Labels`). Reject any error handling that treats a `NotFound` from `NamespaceService()` as the signal that a namespace was deleted.

## Design Observations

**Concerns**

- **The mirror-name rule is a public contract with no single owner** *(in-scope)*. `api_containers.md:140-142` states the rule normatively, yet the code has it in two places and the type that defines the resource has it in neither. Putting `ContainerNamespaceMirrorName` in `pkg/apis/containers/v1alpha1`, next to `ContainerNamespaceKind`, makes the API package the one place a new consumer looks — the engine watcher, the webhook, the mock, and any future `ComposeProject` work from #651 all reach it without a layering inversion into `pkg/controllers/app/engine`. Combined with I1's selectable field, a consumer gets a choice: derive the name, or select on the real one. Today it gets neither cleanly.

- **The status write is a second round-trip that the mirror apply could carry** *(future)*. `applyNamespace` issues a create-or-update, a containerd RPC, and a status apply per call, and it runs on every container and image create event, not just namespace events. The engine reconciler watches `ContainerNamespace` (`engine_reconciler.go:265`), so each status write also wakes a reconcile. The workqueue coalesces those into one pass, so nothing is broken; but if namespace counts grow, a cheap guard — skip the label fetch when the cached mirror's `status.name` already matches and the event was not a namespace event — would remove both the RPC and the wake-up from the hot path.

**Strengths**

- Fetching labels from `NamespaceService().Labels` rather than trusting `NamespaceUpdate.Labels` is the correct call: containerd's `Update` handler applies a field mask (`plugins/services/namespaces/local.go:157-168`) and republishes only the requested keys, so the event payload is a delta, not the full set.
- Subscribing before `fullSync` (`containerd_watcher.go:84-91`) is what makes the new two-step apply safe: a namespace that vanishes between the create and the label fetch is cleaned up by the `NamespaceDelete` event already sitting in the queue.
- Recording `activeNames` outside the apply's error branch (`sync_namespace_containerd.go:42-45`) means one failed apply no longer also prunes the mirror it failed to refresh.

### Executive Summary

PR #772 fixes a critical gap in containerd namespace mirroring where invalid, non-DNS-compliant namespace names were silently skipped. By hashing and encoding unsupported namespace names, registering a status subresource to track raw names and labels, and updating webhooks to compute corresponding hashes on lookup, all namespaces are now cleanly mapped and verified. All prior-round findings are fully resolved, and unit tests and linters pass with zero issues.

#### Suggestions

##### S1. **Avoid redundant `local` declarations inside `@test` blocks** — `rdd/bats/tests/32-app-controllers/engine-containerd.bats:241` (suggestion, style)

```bash
@test "unsupported namespace names are encoded" {
    local namespace_name=Not_A_Valid_Kubernetes_Namespace encoded_name
```

RDD BATS conventions state that `local` should not be used inside `@test` blocks because each `@test` block executes inside its own isolated subshell, making all variables implicitly scoped. 

Fix: Remove the `local` keyword and declare the variables directly.

```diff
-   local namespace_name=Not_A_Valid_Kubernetes_Namespace encoded_name
+   namespace_name=Not_A_Valid_Kubernetes_Namespace
+   encoded_name=
```

### Design Observations

#### Strengths
- **Symmetric Two-Step Apply Re-verification:** Applying the main metadata configuration and subsequently calling the `.Status().Apply(...)` subresource in `sync_namespace_containerd.go` is implemented cleanly and is highly idiomatic.

### Acknowledged Limitations

The following items are confirmed as intentional and structurally correct under the current system design:

1. **K8s-Side Delete Staying Gone:**
   - *Code Comment:* `rdd/pkg/controllers/app/engine/controllers/sync_namespace_containerd.go:71`:
     ```go
     // A K8s-side delete therefore stays gone. Only fullSync and the container,
     // image and namespace create events call this, so nothing re-applies the
     // mirror until one of those fires again or the watcher restarts.
     ```
   - *Status:* **Confirmed**. The containerd watcher responds exclusively to VM-side container/namespace events. It does not watch or reconcile K8s-side deletions back to the host, which is an accepted design limitation.
2. **Skipping Failed Per-Namespace Applies:**
   - *Code Comment:* `rdd/pkg/controllers/app/engine/controllers/sync_namespace_containerd.go:37`:
     ```go
     // Log and skip per-item Apply failures. A single permanently-broken
     // Apply must not pin ContainerEngineReady at ConnectFailed.
     ```
   - *Status:* **Confirmed**. Keeping failed applies localized prevents a single un-admittable namespace mirror from failing overall engine readiness sync, which is correct.
3. **Disappearing Namespaces During Watch Update:**
   - *Code Comment:* `rdd/pkg/controllers/app/engine/controllers/sync_namespace_containerd.go:88`:
     ```go
     // If the namespace is not found, skip updating the status; the object will
     // be deleted on next reconcile.
     ```
   - *Status:* **Confirmed**. The two-step apply safely intercepts `NotFound` errors when a namespace disappears between the update event and the label fetch, preventing race conditions from bubbling up as false errors.
