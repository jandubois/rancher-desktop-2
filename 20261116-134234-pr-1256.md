## Design Observations

### Concerns

- **Two functions named `closePreferences` treat unsaved changes in opposite ways** (in-scope) [Claude Opus 5.5]. The new export in `window/preferences.ts:121` lets the page ask before it discards anything. The page's own `closePreferences` in `pages/Preferences.vue:32` clears the changes and closes without asking. The page's function predates the PR, but the PR adds the second name, and Cancel, Discard and Apply all call the page's version. A name such as `discardAndClose` for the page's function would tell a reader which of the two asks.

### Strengths

- **The round-2 delta holds up** (in-scope) [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash]. `closePreferences()` returns early when `getWindow` returns null, and it does for a destroyed window, since it goes through `BrowserWindow.fromId`. For a Preferences window opened without a main window, the reattach sets the null parent that the window already has. A mutation that puts the Escape handler back to a bare `close()` fails the window spec.
- **Escape and the main window's close request go through one function** (in-scope) [Claude Opus 5.5, Codex GPT 6 Astra], so the macOS reattach is in one place.
- **Specs now clone the way the app does** (in-scope) [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.1 Pro, Gemini 3.5 Flash]. Probes in the jsdom environment found that Node's `structuredClone` throws `DataCloneError` on a Vue `reactive()` proxy and on a value holding a function, and that `toStrictEqual` still passes on its copies.

## Review Process Notes

### Skill improvements

- When a prior-round fix adds more than one branch, ask each agent for the test that fails when each branch is deleted, not only when the whole fix is reverted. An agent that reverts the whole fix finds a failing test and credits it, while a guard added beside the main change stays untested.

### Repo context updates

- [repo] In the jsdom Jest environment, values that Node creates, such as an `fs` error or a `structuredClone` copy, belong to Node's realm, so `instanceof` checks and `expect.any(Error)` fail on them inside a test. A review patch that asserts on such a value should match its properties, for example with `expect.anything()` or `expect.objectContaining()`.

###### Design Observations

###### Strengths

- **Renderer-driven discard lifecycle**: Shifting the discard confirmation from synchronous main-process `dialog.showMessageBoxSync` to the renderer's `beforeunload` event with asynchronous `ipcRenderer.invoke('show-message-box', ..., true)` eliminates main-process blocking and centralizes dirty-state management in the Vuex store (`isDirty`).
- **Clean window parenting recovery**: Handling macOS's `BrowserWindow.close()` parent detachment quirk directly within `closePreferences()` ensures modal window ordering is preserved without introducing global state flags or tight coupling across window managers.
- **Decoupled locale store watchers**: Switching the store plugin in `store/i18n.ts:249` to watch `preferences/committed` rather than `preferences/preferences` decouples uncommitted UI selection previews from app-wide locale updates.

###### Acknowledged Limitations

- **Dropped changes on quit or main window close**: Closing the main window or quitting the application drops unsaved changes without confirmation (`pkg/rancher-desktop/window/preferences.ts:14-20,35-37`). This is intentional to prevent `beforeunload` from aborting application shutdown after background services (Steve) have already stopped.
- **Language takes effect on Apply**: Selecting a language in Preferences does not provide an immediate live preview across the app; changes apply only when clicking "Apply" (maintainer consensus).
- **Modal attachment disparity between IPC channels**: `show-message-box` attaches modally to the calling window (`background.ts:358`), whereas `show-message-box-rd` attaches to the main window (`background.ts:362`). Tracked for future alignment.
- **Reattachment vs. Modal Window**: Window re-attachment via `setParentWindow` in `closePreferences` was intentionally chosen over making Preferences a native modal (`modal: true`).
- **Unexercised `asking` guard**: No unit test specifically exercises the re-entrancy `asking` flag in `pages/Preferences.vue:54-66`.
- **`Shortcuts.isRegistered` setup**: `openPreferences` re-adds its `ipc-message` handler outside `Shortcuts.isRegistered` (`pkg/rancher-desktop/window/preferences.ts:106-110`). Tracked for a separate PR (#1207).
- **Electron-level unload / IPC test harness**: The repository lacks an Electron-level test harness to execute the native side of window unload and `preferences-close` IPC under mocks.
- **Cancel preserves window against `preferences-close` IPC**: Cancelling the discard prompt keeps Preferences open even when closed via `preferences-close` IPC from the main window.
- **Shutdown paths skipping `before-quit`**: System-level termination paths that bypass Electron's `before-quit` event could trigger the discard prompt.
- **Escape during in-flight commit**: Pressing Escape while an Apply commit is actively in-flight prompts about discarding changes already submitted.
- **Potential double `switchTo` execution**: `switchTo` can run twice if the updated `App` custom resource arrives within the 1-second timeout before Preferences closes.
- **Main process App state reflection**: The main process relies on renderer relays (`backend/app-status-changed` and `i18n/locale-change`) rather than watching the `App` custom resource directly (#1260).
- **Main process startup locale**: Initializing the main process in the user's stored locale at launch is tracked under #1204.
- **Synthetic double Escape invocations**: `utils/shortcuts.ts` dispatches on both key-down and key-up events, resulting in dual `closePreferences()` calls merged by Chromium.
- **Native Cmd-W and Close button detachment immunity**: Cmd-W and the window's close button do not call `BrowserWindow.close()` and do not suffer from macOS parent detachment.
