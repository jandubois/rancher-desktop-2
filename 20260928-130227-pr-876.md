## Review Process Notes

### Skill improvements

- Reconcile the two stale-comment severity rules. `instructions.md` rates a comment the code contradicts IMPORTANT, while `dimensions.md` rates a comment naming a removed symbol SUGGESTION. State the boundary: a comment that names something no longer there is a dangling reference (SUGGESTION), but a comment that a deletion leaves next to other code, where it now makes a false claim about that code, is a contradiction (IMPORTANT). Reviewers split on this case.
- When a change deletes files or a feature, list what existed only to serve them and check that each goes too. The usual ones are build and loader rules, package dependencies, spell-check dictionaries and excludes, attributes entries, and comments that describe or cite them. Search for each deleted path and for words or identifiers that only the deleted content used, comparing the merge-base with the head. Leftovers are cheap to miss because nothing breaks.

### Repo context updates

- [repo] The CI spelling job in `.github/workflows/lint.yaml` is commented out, so nothing in CI reads `.github/actions/spelling/`. A change that deletes files must prune their `excludes.txt` entries, any comment attached to those entries, and the `expect/*.txt` words only the deleted files used; review is the only check that catches the leftovers.

S3 cites commit `9e718b63f`, and `beautify --lint` warns about it because a commit is not a file. The warning is expected.
