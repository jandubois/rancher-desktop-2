## Design Observations

### Concerns

- **Dates and sizes in the tables follow the OS locale** (future) [Claude Opus 5.5, Gemini 3.5 Flash]. `formatDate` (`pages/volumes/files/_name.vue:415-416`) calls `toLocaleString()`, and `Images.vue:207` passes `undefined` as the locale to `Intl.NumberFormat`. The English fallback `'Failed to list files'` inside the translated `volumes.files.listError` (`_name.vue:335`) is on #1205's list.

### Strengths

- **Headers built in `computed` reach every place where the table shows a label** (in-scope) [Claude Opus 5.5]. `SortableTable` also accepts `labelKey`, but only `labelFor` translates it (`SortableTable/index.vue:814-821`). - **A switch keeps the user's sort** (in-scope) [Claude Opus 5.5]. Only `changeSort` (`SortableTable/sorting.js:103-105`) writes `sortBy` and `descending`, so recomputing the headers leaves both alone.
- **Stored messages keep their translation key and arguments** (in-scope) [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.1 Pro, Gemini 3.5 Flash]. They are translated when shown, so they follow a switch without a watcher.
- **The rebase keeps #1254's regression test able to fail** (in-scope) [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.1 Pro, Gemini 3.5 Flash]. `mountPage` leaves `isLoading` alone, and putting the loading indicator back above the error banner fails #1254's test.

## Review Process Notes

### Skill improvements

- When a PR body says users see a change on a page, a dialog or a table, trace that page's entry point in the reviewed build. Find the nav entry or link that opens it, the handler that answers the message that it waits on, and the site that mounts the component. Flag a claim about a page that users cannot reach, because readers of the body take it at its word.

### Repo context updates

- [repo] Many renderer pages and components that RD2 inherited from RD1 don't have a live entry point yet, and each has a "Restore feature:" issue. `window/constants.ts` comments out the main window's Port Forwarding, Snapshots, Troubleshooting, Diagnostics and Extensions nav entries. Other pages open but wait on a main-process handler that the app never registers, or on a store action that does not exist, and some components are commented out where they would mount. Before rating a finding in such code above Suggestion, or accepting a claim that users see a change there, follow the entry point. Check the nav entry or link, the `ipcMain` handler for the message that the page waits on, and the mount site.

I1. **Latent gap: `SnapshotsDialog` properties from `dialog/options` and `dialog/error` do not follow the locale switch** — `pkg/rancher-desktop/pages/snapshots/dialog.vue:49-51` (and `61-64`) (important, gap)

```vue

      this.error = args.error;
      this.errorTitle = args.errorTitle;
      this.errorDescription = args.errorDescription;
      this.errorButton = args.errorButton;

```

The PR adds `infoKey` to the snapshot dialog so the lock-file notification updates on locale switch, fulfilling the PR's claim for info messages. However, it leaves `dialog/options` (`header`, `message`, `info`) and `dialog/error` (`errorTitle`, `errorDescription`, `errorButton`) as plain string assignments. Fix: Extend the `dialog/options` and `dialog/error` formats to pass translation keys and arguments instead of translated strings, and add matching computed properties in `dialog.vue` (e.g. `errorTitleText`), similar to `infoText`.

###### Suggestions

S1. **Type error: `errorSources.find()` returns a possibly null/undefined value assigned to `Record<string, string>`** — `pkg/rancher-desktop/pages/volumes/files/_name.vue:277` (suggestion, gap)

```typescript
        console.error('Error listing files:', error);
        this.error = { key: 'volumes.files.listError', args: { error: errorSources.find(msg => msg) } };
        this.isLoading = false;
```

In strict TypeScript, `Array.prototype.find` returns `T | undefined` (here `string | null | undefined`). The `errorMessage.args` type requires `Record<string, string>`, so assigning this result directly is a type error. Although it is safe at runtime (the array's last element is a non-null string fallback, guaranteeing a match), `tsc` in strict mode rejects it, which would surface if the file were fully type-checked in CI.

Fix: Cast or provide a fallback to ensure the assigned value is strictly typed as a string.

```diff
-        this.error = { key: 'volumes.files.listError', args: { error: errorSources.find(msg => msg) } };
+        this.error = { key: 'volumes.files.listError', args: { error: errorSources.find(msg => msg) as string } };
```
