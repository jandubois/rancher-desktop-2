## Executive Summary

This PR stores the engine's container ID in a required `status.id` and uses it for containerd actions and deletes, which replaces the reverse-hash scan. It routes containerd Image names through `MirrorName` without changing them and fixes most documentation findings from the #787 review. The design is sound. But the required field breaks the e2e test that writes Container status, `make check` now fails on any uncommitted edit, and two new design-doc sentences misstate containerd. Generated files were not reviewed.

I3. **Two new design-doc sentences misstate containerd** — `rdd/docs/design/api_containers.md:456` [Claude Opus 5.5, Gemini 3.5 Flash, Codex GPT 6 Astra]

```markdown
  - When using containerd, the input is the image namespace, followed by a null
    byte, followed by the image name; there is no extra value.  This is
    necessary as the delete event does not include the container id; the null
    byte is used to force the name to become encoded.
```

This rule covers Images, and containerd's `ImageDelete` event has only the image `Name` field, so "container id" should read "image id".

The Container bullet at lines 224-226 justifies ignoring cross-namespace duplicates with "container IDs are supposed to be globally unique". But containerd keys containers per namespace and accepts one ID in two namespaces. A valid ID such as `test` then passes through `MirrorName` unchanged in both, since extras only affect encoded names, so the two containers share one mirror. Ignoring that case is reasonable, because only a hand-picked ID reaches it; the reason the doc gives is wrong.

## Design Observations

### Concerns

- **The docker backend still addresses Docker by mirror name** *(future)* [Claude Opus 5.5, Gemini 3.1 Pro]. `docker_watcher.go:330` and `:504` pass `c.Name` to Docker, while containerd now reads `status.id`. That works today because moby mirror names are the raw ID. Gemini 3.1 Pro rated it Important, since a user-created Container named after a Docker container can act on that container. The code predates this PR, though, and anyone who can write Container objects can already reach Docker. Reading `status.id` on both paths would give one rule.
- **containerd Image names force encoding with a NUL in the input** *(future)* [Gemini 3.5 Flash]. `containerdImageMirrorName` joins namespace and record name with `\x00` so that `MirrorName` never passes the input through unchanged. An always-hash helper would state that intent; the #787 review raised the same point.

### Strengths

- `status.id` removes the reverse-hash scan, and with it the #787 review's S1, where a direct `LoadContainer(mirrorName)` hit could reach the wrong container [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.1 Pro, Gemini 3.5 Flash].
- containerd Image mirror names are byte-identical to before, because `MirrorName` hashes the same namespace, NUL and record-name bytes that the old `img-%x` formula did [Claude Opus 5.5, Codex GPT 6 Astra].

### Design Observations

#### Concerns

1. **`containerdImageMirrorName` manual null-byte injection** `(in-scope)`: Because `api.MirrorName` checks `len(validation.IsDNS1123Subdomain(input)) == 0` and immediately returns `input` when valid (ignoring `extras`), passing namespace `ns` as `input` would return `"default"` unencoded. `containerdImageMirrorName` works around this by formatting `fmt.Sprintf("%s\x00%s", ns, name)` into `input` solely to make DNS-1123 validation fail. An explicit helper like `api.HashName(prefix, parts...)` that unconditionally hashes without a subdomain bypass would make this call site idiomatic.
2. **Container ID resolution across client and daemon** `(future)`: Introducing `status.id` resolves container lookup inside the daemon, but UI components (`Containers.vue`, `ContainerInfo.vue`) and main-process modules (`containerStats.ts`) still assume `metadata.name` equals the container ID. When an encoded container name (`ctr-<hash>`) is present, CLI subprocesses running `docker stats` or `nerdctl stats` fail. Components should consistently fall back to `status.id`.

#### Strengths

1. Replacing the `resolveContainer` containerd namespace container scan with direct `status.id` lookup eliminates an O(N) scan per container action and delete, preventing wrong-target actions on container ID collisions.
2. Normalizing mirror prefix constants to `*MirrorPrefix` across controllers and documenting `volumeMirrorPrefix` improves codebase consistency.
