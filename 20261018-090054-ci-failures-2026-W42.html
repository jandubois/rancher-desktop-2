Assessment ¶

68 jobs failed against 84 the week before, but only 4,572 jobs ran against 6,175, so the failure rate barely moved (1.5% against 1.4%, and 2.1% over four weeks). Lost runners made up the largest group on main, 9 of the 11 BATS jobs (10 on Windows, 1 on macOS) that died with GitHub's "hosted runner lost communication with the server" annotation and didn't leave a log; 6 of them passed on a re-run of the same commit. This is the failure to root-cause, and that's hard, because a runner that dies never uploads the data that would show whether it was starved. Of the other 12 main failures, 8 were Dependabot hitting the same two standing breaks every day from Tuesday to Friday (the /rdd k8s.io/kubernetes 1.37 bump and the npm @yarnpkg/core got-patch scan), 4 were single hits of known flakes, and none was a regression. Among the known flakes, windows-ssh-keygen-timeout led with 4 jobs, all on PR branches, and it has fired every week since it first appeared in W39 (4, 2, 3, 4), so it's the next flake to fix. On PR branches, 25 of the 47 failures came from the gvisor-tap-vsock 0.9.0 Dependabot bump, which broke the build of lima's pkg/networks/usernet/gvproxy.go; lima-vm/lima#5616 adapted that file on 2026-10-15, so the bump builds only together with a lima pin that includes it.

How this report is built

ci-sweep weekly --week 2026-W42 over sweep.db, one row per failed job — a run can fail on one matrix leg out of many, so the job is the unit.

  • Known flake — a job whose log matched a matchers.yaml pattern. Pattern matching only, no LLM.
  • One flake per job — when several matchers fire, the job counts under the one whose surface appears earliest in the log, because the first failure is the root and what follows is fallout: a suite killed at its wall-clock cap logs a failed wait on the way out. The others are recorded but not counted, and only a true tie is left uncounted.
  • Proven flake — the identical job passed on a re-run of the same commit, so the code cannot be at fault.
  • Unrecognized — no matcher fired. On main it earns analysis; on a PR branch it earns only a count, because PR failures are dev breakage, not CI health.
  • No log — the log expired or was never uploaded, so the sweep could not classify the failure. A data gap, not a clean bill.
  • What failed — for a known flake, the matcher's summary; otherwise the failing test and command, or the job error for a failure that never reached its tests. --fetch names the rest, at one download each.
  • Counts cover only jobs the sweep recorded. A period never swept reads as zero failures.
