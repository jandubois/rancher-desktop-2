const metadata = "#!/bin/sh\necho '{\"SchemaVersion\":\"0.1.0\",\"Vendor\":\"probe\",\"Version\":\"1\"}'\n"

func addCompose(dir string) {
	_ = os.MkdirAll(dir, 0o755)
	_ = os.WriteFile(filepath.Join(dir, "docker-compose"), []byte(metadata), 0o755)
}

func main() {
	root := os.Args[1]
	config.SetDir(filepath.Join(root, ".docker"))

	userDir := filepath.Join(config.Dir(), "cli-plugins") // ~/.docker/cli-plugins

// acquirePathLock takes the shared PATH lock and returns a function that
// releases it. It blocks up to pathManagementLockTimeout; a stuck holder surfaces
// as an error so the reconcile requeues rather than hanging.
func acquirePathLock(ctx context.Context) (func(), error) {
	dir, err := sharedDataDir()
	if err != nil {
		return nil, fmt.Errorf("locate PATH lock directory: %w", err)
	}
	if err := os.MkdirAll(dir, 0o700); err != nil {
		return nil, fmt.Errorf("create PATH lock directory: %w", err)
	}
	fl := flock.New(filepath.Join(dir, pathManagementLockFile))

	lockCtx, cancel := context.WithTimeout(ctx, pathManagementLockTimeout)
	defer cancel()
	locked, err := fl.TryLockContext(lockCtx, 50*time.Millisecond)
	if err != nil {
		return nil, fmt.Errorf("acquire PATH lock: %w", err)
	}
	if !locked {
		return nil, fmt.Errorf("acquire PATH lock: timed out after %s", pathManagementLockTimeout)
	}
	return func() { _ = fl.Unlock() }, nil
}

// sharedDataDir returns the per-user data root that every instance shares (the
// parent of instance.Dir()). The PATH lock lives here rather than under a single
// instance's directory, so all of a user's daemons serialize on the same file.
// It mirrors instance.Dir()'s layout but drops the instance-specific leaf, and
// avoids instance.Dir()'s memoization so it tracks HOME in tests.
func sharedDataDir() (string, error) {
	home, err := os.UserHomeDir()
	if err != nil {
		return "", err
	}
	switch runtime.GOOS {
	case "windows":
		return filepath.Join(home, "AppData", "Local"), nil
	case "linux":
		return filepath.Join(home, ".local", "share"), nil
	case "darwin":
		return filepath.Join(home, "Library", "Application Support"), nil
	default:
		return "", fmt.Errorf("platform %s not supported", runtime.GOOS)
	}
}

Design Observations ¶

Concerns ¶

  • (in-scope) App users cannot reach the plugin registration. It depends on addPath, and no app code writes application.addPath; the Settings dialog and first-run page write RD1's pathManagementStrategy, which nothing passes to rdd. #499, now closed, listed application.addPath among the Alpha 2 settings. With the default manual, docker compose stays broken for app users (#899), and I1 makes standalone docker-compose worse on Windows. Either add the Settings control or register the plugin directory under a default that does not edit PATH. Claude Opus 5.5
  • (future) rdd svc delete unwinds with the CLI's DOCKER_CONFIG, not the daemon's. An entry that the daemon wrote under a different DOCKER_CONFIG remains after deletion. Docker skips a directory it cannot read, so the leftover is clutter. Claude Opus 5.5
  • (future) The shutdown clear can outlast the manager's grace period. lockTimeout is 30 s, while GracefulShutdownTimeout is 10 s (service/controllers/manager.go:153), so a config.json lock held for more than about 7 s abandons the clear. Holders keep the lock for milliseconds. Codex GPT 6 Astra Claude Opus 5.5

Strengths ¶

  • (in-scope) Reverting any of round 1's four code fixes through a go test -overlay fails the test that pins it. Claude Opus 5.5
  • (in-scope) The marker is still written before the config.json edit and cleared only after it succeeds, and the new early return fires only when no marker exists, so an interrupted front still leaves a marker for manual to act on. Codex GPT 6 Astra Claude Opus 5.5 Gemini 3.5 Flash
  • (in-scope) pruneDanglingForwarders acts only on .shim pairs, so round 1's I3 fix leaves the macOS and Linux symlinks and any user file alone; docker skips dangling symlinks by itself. Codex GPT 6 Astra Claude Opus 5.5

Acknowledged Limitations ¶

  • docker/cli's ConfigFile drops unknown top-level keys on save. docker_context_test.go:183-184 pins that, and docker context use behaves the same way.
  • docker login, docker context use and other docker commands write config.json without Rancher Desktop's lock. The dockerconfig package doc names Rancher Desktop's writers before it promises anything, so it does not claim coordination with docker's own writes; round 1's S7 overstated it.
  • #918's "To discuss" items stay open. With two instances at front, the last writer wins docker compose, and an uninstall that keeps ~/.rd2 leaves the cliPluginsExtraDirs entry behind.
  • apply holds the PATH lock while it waits for the config.json lock. Both controllers take the locks in the same order, and lockTimeout bounds the wait. Do not re-suggest releasing the PATH lock before the plugin edit.
  • The plugin marker's location derives from BinDir's parent, as the Windows Path marker's does (pathmanagement_windows.go:53), and both production call sites put BinDir and PluginDir in the instance directory. Do not re-suggest deriving it from PluginDir.

Review Process Notes ¶

Skill improvements ¶

  • Replacement reachable only by opt-in: when a change removes a working delivery path (a PATH entry, an installer step, a default) and replaces it with a mechanism that the user must opt into, check that the default configuration and every UI surface can reach that opt-in. A replacement that only some users can enable is a regression for the rest, and reviewing the replacement's correctness does not show it.

Repo context updates ¶

  • [repo] No app code writes spec.application.addPath (as of 2026-10-16), so app installs run with the default manual. Before crediting a feature that addPath=front|back enables, grep pkg/rancher-desktop for a writer of application.addPath; when none exists, the feature is unreachable for app users, and removing an older path to the same capability is a regression for them.
  • [repo] UPDATE the pending round-1 rule about the path-management reconciler under manual: permanentPathError decides the reason, and only causes that it recognizes map to the non-gating Malformed. Flag any new file that reconcile parses unless its parse failures are classified permanent, even when the step has work to do, since a marker can keep the step running under manual. Classify I/O failures as repairable, as unreadable startup files are. Note that fmt.Errorf with two %w operands yields Unwrap() []error, which permanentPathError reads as independent causes.
