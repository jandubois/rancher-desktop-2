## Important Issues

I1. **The backslash rule rests on a false claim about container paths** — `rdd/pkg/nerdctlstub/translate_test.go:324-325` [Codex GPT 6 Astra]

```go
			// A compose service name may be one letter, but a container path
			// never has a backslash.
```

The commit body gives the same reason, and the comment at `command_handlers.go:61-64` draws the same conclusion from "A container path is a Linux path". But a Linux file name may contain a backslash, and nerdctl v2.1.2's `parseCpFileSpec` reads `a:\file` as container `a`, path `\file`.

The rule is sound as a convention, since a Linux file name rarely starts with a backslash, but a later reader would take the stated reason for a guarantee. The probe asserts the claim, which `a:/file` satisfies and `a:\file` breaks. The fix changes only the comments, so the probe still fails afterwards.

import (

	"path/filepath"

	"testing"

var errFileSpecDoesntMatchFormat = errors.New("filespec must match the canonical format: [container:]file/path")

// parseCpFileSpec and copyFileSpec are nerdctl v2.1.2's, copied from
// cmd/nerdctl/container/container_cp_linux.go.
func parseCpFileSpec(arg string) (*copyFileSpec, error) {
	i := strings.Index(arg, ":")

	// filespec starting with a semicolon is invalid
	if i == 0 {
		return nil, errFileSpecDoesntMatchFormat
	}

	if filepath.IsAbs(arg) {
		// Explicit local absolute path, e.g., `C:\foo` or `/foo`.
		return &copyFileSpec{
			Container: nil,
			Path:      arg,
		}, nil
	}

	parts := strings.SplitN(arg, ":", 2)

	if len(parts) == 1 || strings.HasPrefix(parts[0], ".") {
		// Either there's no `:` in the arg
		// OR it's an explicit local relative path like `./file:name.txt`.
		return &copyFileSpec{
			Path: arg,
		}, nil
	}

	return &copyFileSpec{
		Container: &parts[0],
		Path:      parts[1],
	}, nil
}

type copyFileSpec struct {
	Container *string
	Path      string
}

func TestProbeBackslashContainerPath(t *testing.T) {
	// A Linux file name may start with a backslash.
	assert.NilError(t, os.WriteFile(filepath.Join(t.TempDir(), `\file`), nil, 0o600))
	kinds := map[copySpecKind]string{copySpecHost: "host", copySpecAmbiguous: "ambiguous", copySpecContainer: "container"}
	for _, spec := range []string{`a:/file`, `a:\file`} {
		s, err := parseCpFileSpec(spec)
		assert.NilError(t, err)
		t.Logf("%s: nerdctl reads container %q, path %q; the stub classifies it as %s",
			spec, *s.Container, s.Path, kinds[classifyCopySpec(spec)])
		// The claim in translate_test.go and the commit message.
		assert.Check(t, !strings.Contains(s.Path, `\`), "container path %q has a backslash", s.Path)
	}
}

## Suggestions

S1. **The backslash rule looks only at the character after the colon** — `rdd/pkg/nerdctlstub/command_handlers.go:60` [Claude Opus 5.5]

```go
	case colon == 1 && len(p) > 2 && p[2] == '\\' && isASCIILetter(p[0]):
```

A path with mixed separators, such as `C:/src\f`, stays ambiguous. A script produces one when it appends `\f` to the output of `git rev-parse --show-toplevel`, which uses forward slashes on Windows. Opposite a one-letter service, `compose cp C:/src\f a:/dst` reaches nerdctl unchanged and fails with "copying between services is not supported". The error is loud and the input uncommon.

## Design Observations

### Concerns

- (future) In `container cp`, a one-letter spec can name a container only as an ID prefix from `a` to `f`. nerdctl v2.1.2 requires names of at least two characters (`pkg/identifiers/validate.go:27-29`) and matches lowercase hex IDs with the case-sensitive filter `id~=^%s.*$` (`pkg/idutil/containerwalker/containerwalker.go:53`). So `C:/src` and `g:/x` can only be drives there, and only `compose cp` needs the full ambiguity. A rule per command would settle more pairs, but the classifier would then depend on the command, and the pairs that it leaves unsettled already fail loudly. [Claude Opus 5.5] **Outcome:** Declined for now and kept as future work.

### Strengths

- The pass-through contract holds across every class of pair. A cross product of 18 spec classes, run against Go models of nerdctl's `parseCpFileSpec` and compose's `splitCpArg`, did not find an accepted command whose container side or direction changed, or an accepted command that the stub turns into an error. (in-scope) [Claude Opus 5.5, Codex GPT 6 Astra]
- The fixes from #974's review rounds still hold. A wrong argument count, `cp --help`, two container specs and a leading `:` reach nerdctl unchanged, and a user's `--` stays in front of the handler's arguments. (in-scope) [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.1 Pro]
- A pair that the stub cannot settle reaches nerdctl unchanged, so nerdctl's own error describes it. (in-scope) [Gemini 3.1 Pro, Gemini 3.5 Flash]

## Review Process Notes

### Skill improvements

- When a comment or commit message justifies a heuristic with an absolute claim about another system's input ("a container path never has X", "an ID cannot start with Y"), test the claim against that system's grammar and the platform's naming rules, not against the heuristic. A heuristic is often sound as a convention while its stated reason is false, and later readers take the reason for a guarantee.

### Repo context updates

- [repo] `rdd nerdctl` rewrites host paths only on Windows, so the Linux and macOS BATS jobs run the stub's tests with no translation, and only the Windows jobs test it. The guest also runs in the translated working directory, so on Windows a test that passes a relative path succeeds without any rewrite. When judging whether a stub test can fail, ask what the guest nerdctl does with the untranslated argument.
- [repo] nerdctl requires container names of at least two characters (`identifiers.ValidateDockerCompat`) and matches an ID prefix with a case-sensitive regex over lowercase hex IDs, so a one-letter `container cp` spec can only be an ID prefix from `a` to `f`. A compose service name can be any single letter.
