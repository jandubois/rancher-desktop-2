## Executive Summary

Round 2 removes `unset` from the App API, adds the PATH selector to the first-run dialog, and translates the new strings. Most round-1 fixes are in, and every check passes. But a PATH click in first-run before the App exists enables OK with nothing to commit to. `rdd run --help` still promises the removed `unset` pinning, the descriptions don't say "user Path" or "shell profile", and the `path_marker` doc is wrong outside Windows. Removing `unset` needs a maintainer ruling.

I1. **A PATH click in first-run before the App exists enables OK** — `pkg/rancher-desktop/pages/FirstRun.vue:27` [Codex GPT 6 Astra, Claude Opus 5.5]


S1. **Every `binDir` start value is the e2e override's value, so the Environment-tab e2e test passes with `get-paths` broken** — `pkg/rancher-desktop/layouts/preferences.vue:9` [Claude Opus 5.5, Gemini 3.5 Flash, Codex GPT 6 Astra]

## Design Observations

### Concerns

- (in-scope) **Removing `unset` needs a maintainer ruling.** Item 1 asked the GUI to check Manual while the stored value is `unset`; the PR removes the value from the API instead, and no PR comment approves that. `unset` was the maintainer's design for "nobody has chosen yet", and #1081 settled which commands pin it. The removal is complete in code. It covers every `setAction` caller, the generated enum and both CRDs. `unset` shipped in no release, so only development Apps can still hold it. [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash]
- (in-scope) **The first-run dialog preselects Manual, while #1051 specifies `front`.** `rdd/ensureAppExists` creates the App with only `running: false` (`store/rdd.ts:93-103`), so the selector shows the new CRD default. #1051, which this PR does not close, asks for a dialog that "defaults to `front`" and opens while `addPath` is `unset`. With `unset` gone, its trigger and its default both need a decision.
- (in-scope) **The translations overlap #1108.** The maintainer asked to leave the locales to #1108; `88b4ccee6` translates all nine, `vi` included. Spot checks of de, it, ja, zh-hans and vi matched their `# @source`, and `i18n-report check --locale=all` passes. I3's fix removes two of those keys again, so #1108's scope needs updating. [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash]
- (future) **Every dialog now calls `get-paths`.** The fetch in `layouts/dialog.vue` runs for SudoPrompt, UnmetPrerequisites, KubernetesError and DenyRoot as well, though only FirstRun shows the path. [Claude Opus 5.5]

### Strengths

- The handler returns a plain object built from `pathKeys`, so round 1's structured-clone failure on the error Proxy is gone, and the e2e override no longer reaches main-process code. [Claude Opus 5.5, Codex GPT 6 Astra]
- Escaping before `t` and rendering through `v-clean-html` shows a path containing `&` as typed; a mounted probe confirmed it. [Claude Opus 5.5, Codex GPT 6 Astra]
- `RadioButton` no longer nests a `<label>` in a `<label>`, and each `aria-describedby` names an `id` that exists. [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash]
- The selector writes through `preferences/modify`, so Apply and Cancel still work in Preferences. [Codex GPT 6 Astra]

### Skill improvements

- When a PR removes or renames an API value, enum member or field, search the repository's open issues for that identifier and inline every issue that specifies behaviour around it. A removal can invalidate a plan that the PR body never mentions, and agents cannot fetch issues themselves.
- Have each external agent's liveness monitor also scan that agent's stderr for a quota error and report it at once. A CLI that runs out of quota sleeps until the reset, so the stall window of 15 minutes passes with nothing to show.

##### Design Observations

###### Concerns

- **Unruled removal of `unset` strategy (in-scope)**: In round 1, maintainer S1 requested that the UI display "Manual" as checked when `spec.application.addPath` is `unset`, without mutating the spec. The author instead eliminated `unset` across the API, CRD, and reconcilers, making `manual` the CRD default. While this simplifies the API and removes the need for `pinUnset` transitions, it drops the control plane's ability to distinguish an unconfigured first-run instance from an explicit choice of `manual`. Maintainers should explicitly confirm whether eliminating `unset` is acceptable.
- **Translation duplication with Issue #1108 (in-scope)**: Issue #1108 was opened specifically by the maintainer to translate `pathManagement` strings after this PR merged. Commit `88b4ccee6` translated them prematurely without the requested platform-branching descriptions (I2), necessitating another translation pass once I2 is addressed.

###### Strengths

- **ARIA compatibility in `RadioButton.vue`**: Replacing the inner nested `<label>` with `<span class="radio-label">` and connecting `aria-describedby` to the description container resolves invalid HTML nesting and improves accessibility without breaking label click delegation.
- **Centralized `binDir` injection**: Providing `binDir` via `binDirInjectionKey` in layouts (`preferences.vue`, `dialog.vue`) avoids redundant per-component IPC calls while allowing clean mock injection in unit tests.
