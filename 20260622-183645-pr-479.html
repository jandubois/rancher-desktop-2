Executive Summary ¶

This Windows-only PR heals orphaned WSL2 distro registrations (re-import on start) and prevents new ones (unregister on svc delete). The mechanism is sound and matches Lima's WSL2 driver. One Important defect: instanceDistroNames enumerates every directory under LimaHome, so Lima's reserved _config/_disks dirs become phantom lima-_config distros that emit a spurious warning on every Windows delete — and a unit test masks it by creating _config as a file.

Two cloud reviewers ran (Codex, Claude); Gemini dropped on an authentication error. Both reviewers independently raised the enumeration bug. They split on the start-time heal path: Codex rated the missing terminate-before-unregister step Important, Claude rated it a Suggestion. This report adjudicates it as a Suggestion — the triggering state (a diskless distro still running) is unlikely, but the one-line fix restores parity with the two sibling cleanup sites.

instanceDistroNames returns a lima-<name> distro for every directory under LimaHome, checking only entry.IsDir(). LimaHome also holds Lima's reserved directories — _config, _disks, _networks — and Lima creates _config (the shared SSH key) as soon as any instance exists (ssh_keys_windows.go:21-26). So unregisterInstanceDistros runs wsl --unregister lima-_config, which fails and logs at warn (service.go:605): "Failed to unregister WSL2 distro; a stale registration may remain." On the CLI path (logrus, default level warn) this false alarm reaches the user's terminal on every Windows delete. Lima's own store.Instances() skips ./_-prefixed entries (store.go:67); this hand-rolled copy dropped that filter.

The heal path calls unregisterWSL2Distro without first calling terminateWSL2Distro. Both sibling cleanup sites terminate first — removeStaleInstance (limavm_lifecycle.go:844-845) and unregisterInstanceDistros (service.go:591-592) — because wsl --unregister can deadlock on a distro that still holds kernel state (documented at limavm_lifecycle.go:841-843; recovery needs taskkill /F /IM wslservice.exe). The 30s context timeout bounds the wsl.exe call, not the underlying wslservice deadlock.

rdd/pkg/controllers/lima/limavm/controllers/limavm_lifecycle.go
// a previous service run whose cleanup failed. On Windows, the WSL2 distro is
// terminated and then unregistered (removing its ext4.vhdx and releasing any
// file locks) before the remaining Lima metadata directory is deleted; the WSL2
// calls are no-ops on other platforms, where the directory is removed directly.
func removeStaleInstance(ctx context.Context, logger logr.Logger, instName, instanceDir string) error {
	// Terminate the distro before unregistering it: wsl.exe --unregister can
	// deadlock on a distro that still holds kernel state, the same hazard
	// forceStopForDeletion guards against. Both calls are no-ops off Windows.
	terminateWSL2Distro(ctx, logger, instName)
	unregisterWSL2Distro(ctx, logger, instName)
	return os.RemoveAll(instanceDir)
}

Design Observations ¶

Concerns ¶

  • (future) unregisterInstanceDistros (service.go) and terminateWSL2Distro/unregisterWSL2Distro (limavm_lifecycle.go) are two independent implementations of the same terminate-then-unregister cleanup — differing in logger (logrus vs logr), log level, and instance-enumeration discipline. The TODO at service.go:580-583 flags this pending the #319 stop/delete hook. The duplication is the structural reason I1 exists: the CLI copy lost the reserved-name filter that Lima's store.Instances() encodes. One shared helper taking an explicit limaHome would foreclose the class. Claude

Strengths ¶

  • (in-scope) wsl2RegistrationIsOrphaned reads both live signals at one reconcile — inst.Status (from wsl --list) and an os.Stat of the disk — so no staleness creeps between proxy and ground truth. The StatusUninitialized and VMType != WSL2 short-circuits keep it a correct no-op for fresh imports and off Windows. Claude
  • (in-scope) The heal runs before the hostagent launches — the right lifecycle point, since Lima's WSL2 driver re-imports only a distro absent from wsl --list. Codex
  • (in-scope) The fix targets the root cause (Lima's re-import gating) rather than the symptom, and covers both recovery and prevention. Claude

Testing Assessment ¶

  • The reserved-directory exclusion is untested for its real shape: the test creates _config as a file, so the directory case that produces the spurious warning never runs (I1). Recreating _config/_disks as directories makes the test fail until I1 is fixed. Codex Claude
  • No test covers the terminate/unregister sequencing or the orphan re-import end-to-end. The unit tests exercise only the wsl2RegistrationIsOrphaned predicate and the name mapping; no Windows BATS case exercises orphaned-distro recovery. Codex Claude
  • The os.Stat non-ENOENT error path in wsl2RegistrationIsOrphaned is untested: a permission or I/O error returns false (not orphaned) and boots. The conservative default is reasonable but uncovered. Claude

The predicate tests themselves are correct — missing-disk, present-disk, uninitialized, and non-WSL2 cases all hold.

Documentation Assessment ¶

  • rdd/docs/design/cmd_service.md:111-115 describes svc delete as directory removal only. Add one Windows sentence: WSL2 distro registrations are unregistered before the Lima home is removed. Codex
  • The comment at service_test.go:21 calls _config "a stray file"; it is a directory. Fix alongside I1. Claude
  • New docstrings are accurate. wsl2RegistrationIsOrphaned's "Always false off Windows, where VMType is never WSL2" holds, and the service.go TODO and unregisterInstanceDistros docstring describe the duplication and best-effort behavior correctly. Claude

Commit Structure ¶

Clean. Two commits split along the recovery/prevention seam — c684b5ff9 (heal on start) and 491188217 (prevent on delete) — each self-contained with its own tests. Both messages state the root cause and the mechanism. No fixup commits. Claude

Acknowledged Limitations ¶

  • service.go:580-583 (TODO): the service-layer cleanup reimplements the lima controller's, because svc delete stops the daemon before reaching it; routing through the controller awaits #319. I1 is a concrete bug in that temporary code, not the duplication itself. Codex Claude
  • service.go:598-600 (comment): a never-imported distro name fails the unregister harmlessly. This covers instance directories whose distro was never imported; it does not cover Lima's reserved _config/_disks directories (I1), which are not instances. Claude
  • service.go:575-577 (docstring): cleanup is best-effort and time-bounded, since wsl.exe can hang on a degraded WSL subsystem — so the PR reduces, but does not guarantee, stale-registration cleanup. Codex
