## Executive Summary

The PR moves the current-context takeover to the reconcile that turns `KubernetesReady` True and makes the switch compare inside the write. Both work, and the new tests guard them. But the reachability probe still calls some live clusters dead. It drops `tls-server-name`, a regression from the merge-base, and ignores environment proxies. It also calls an https server dead when it completes the TLS handshake but fails the request, though #1150 and the PR's own comments count that as alive.

## Important Issues

I1. **The probe's transport drops `tls-server-name` and environment proxies, which kubectl uses** — `rdd/pkg/controllers/app/kubernetes/controllers/kube_reconciler.go:446-448` [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.1 Pro, Gemini 3.5 Flash]

```go
			Proxy: cfg.Proxy,
			//nolint:gosec // G402: the probe sends no credentials and only tests reachability.
			TLSClientConfig:   &tls.Config{InsecureSkipVerify: true},
```

At the merge-base the probe used `newProbeHTTPClient`, which sets `ServerName: cfg.ServerName`. `reachabilityHTTPClient` leaves it out. So a cluster behind an SNI router, addressed by IP with `tls-server-name` set, now fails the handshake and loses current-context. That part is a regression, since the merge-base probe reached it.

The proxy part predates the PR. Without `proxy-url`, `cfg.Proxy` is nil, and an `http.Transport` with a nil `Proxy` dials directly. client-go v0.36.4 falls back to `http.ProxyFromEnvironment` instead (`transport/cache.go:142-145`), so a cluster that kubectl reaches through `HTTPS_PROXY` looks dead to the probe.

The reproducer runs client-go and the probe on the same kubeconfig. Without `tls-server-name`, neither one reaches the SNI router.

#1150 counts a cluster alive when its address "completes a TLS handshake or returns any HTTP status", and the comments at lines 541 and 596 say the same. The code returns false on any error from `Do`, even one after the handshake. A server that demands a client certificate rejects the credential-free probe after a TLS 1.3 handshake, and a server that answers after `kubeProbeTimeout` (3s) times out. Both are live, and both lose current-context when `KubernetesReady` turns True.
