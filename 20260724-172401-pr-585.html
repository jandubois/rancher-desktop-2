Executive Summary ¶

Round 2 answers the round-1 memory crash with a hand-written Kubernetes Quantity parser. The parser fixes 2.5Gi but still throws on other API-valid numerals. rdd set virtualMachine.memory=5.Gi stores a value the CRD accepts and the API server preserves verbatim; the renderer cannot parse it, so Preferences crashes. A non-string memory value throws too. Both reopen the failure class the round set out to close.

All four reviewers converged on the grammar gap, each reaching it through a different input. Codex and Claude both reproduced it by running the real parser, and Codex confirmed the value survives a Go round-trip. I verified the reachable case independently: the CRD pattern accepts a trailing dot, and resource.ParseQuantity("5.Gi") returns 5.Gi unchanged rather than canonicalizing it as it does 2.5Gi and .5Gi. Gemini 3.1 Pro alone noticed that the new files use BigInt literals their directory's tsconfig forbids. The display truncation both Gemini reviewers raised is deliberate, per Jan's PR comment, and moves to Acknowledged Limitations.

Design Observations ¶

Concerns

  • BigInt is not needed for this field (in-scope) [Orchestrator] — Number.MAX_SAFE_INTEGER is a little over 8 PiB expressed in bytes, and this field holds host RAM, which tops out in the low terabytes. Every value it can carry is therefore exactly representable as a number. Returning number would keep the arithmetic exact, drop the mixed bigint/number handling at the call site, and make I3 moot, because the ES2018 target rejects only the literal syntax and not the BigInt type. That is a larger change than the I1 regex fix, so it belongs in its own pass rather than folded into this round.
  • Truncation compounds twice on the display path (future) Claude Opus 5 — parseQuantity truncates toward zero, then memoryInGB truncates again at Number(bytes / gigaScale). Kubernetes' own Quantity.Value() rounds away from zero, so both layers disagree with the source of truth in the same direction: 1500m gives 1n here and 2 there. Measured against the shipped defaulter, every host whose reported RAM is under 24 GiB and not a multiple of 4 GiB gets a fractional default that displays low: 10 GiB gives 2560Mi shown as 2, and 18 GiB gives 4608Mi shown as 4. Review Process Notes ¶

Skill improvements

  • Before stating that a defect breaks a named CI job, build step, or release gate, read that job's status at the review SHA and report what you found. A defect can be real while the consequence attached to it is wrong, and a severity built on an unchecked consequence inflates the finding. When the job is green, the finding still stands on its own terms; describe the cost that does apply, such as editor diagnostics or a check that runs only locally.
  • When reporting that unusual or malformed input breaks a code path, choose an example that clears every validation layer between the entry point and that code: schema patterns, admission webhooks, minimum and range checks, and any canonicalization the storage layer applies on write. State which layers the example passes. A defect class can be real while the specific input named for it is rejected upstream, and the reader will test the input you gave them.
  • When a change hand-implements a grammar, wire format, or encoding that a dependency already in the tree parses, compare the two accepted languages in both directions: inputs the reference accepts and the new code rejects, and inputs the new code accepts and the reference rejects. Run the reference implementation to establish ground truth instead of reading its documentation. Then check whether the accompanying tests assert any divergence as correct, because a test that pins wrong behavior converts a bug into a contract.
  • When a change introduces syntax or language features new to a directory, check the compiler or language-level setting that governs that directory rather than the repository root. Toolchains resolve the nearest configuration file, and a nested one often sets a lower level than the root, so new syntax can be valid at the root and rejected where the code actually lives. Report which config governs the file and what it sets.
