## Executive Summary

PR 644 adds the Extension CRD, its admission webhook, and a reconciler that pulls, extracts and starts RDX extensions through moby. Installing an extension from a registry fails at the download step. The controller's ImagePullRequest names a container namespace that doesn't exist under moby, so the webhook rejects it; the Windows BATS job's rdd log shows 30 rejections. Deleting an extension whose install failed leaves it in Terminating for good. Only three Critical or Important findings lack a tested patch.

The pull reconciler settles a successful pull with reason `ImagePulled` and `Failed=False` (`image_pull_request_reconciler.go:58`). rdd never sets `Finished`. So when the request settles before the Image mirror appears, or the lookup misses the mirror (I2), the code falls through to line 316 and sets Installed to `Failed`. ## Review Process Notes

### Skill improvements

- [ ] When code compares another component's condition reason, status value or string format, find the producer and confirm it emits that exact value. A test fixture that types the expected value in passes whether or not the producer agrees, so a passing test doesn't settle it.

### Repo context updates

- [ ] [repo] An Image mirror's `status.repoTag` is the engine's own string. The moby mirror stores Docker's `RepoTags`, which moby renders in familiar form (`foo/bar:latest`, with `docker.io/` and `library/` dropped), while containerd stores the full reference. Code that looks up an Image by a normalized reference must try both forms, and a digest reference needs `status.repoDigests`.
- [ ] [repo] Under moby the only ContainerNamespace is `moby`, and the Docker watcher prunes every other one. The ImagePullRequest webhook rejects any other `spec.namespace`, so a controller that creates pull requests must take the namespace from the running engine.
- [ ] [repo] An ImagePullRequest settles with `Settled=True` and reason `ImagePulled` or `Errored`, plus `Failed=False` or `True`. The reason constants are unexported in the engine package, so consumers should read the `Failed` condition.
- [ ] [repo] controller-runtime's fake client ignores a cancelled context and doesn't run admission webhooks. A status write on a context that the code itself cancels, or a child object a webhook would reject, passes unit tests and fails against the API server; ask for an interceptor that honours `ctx.Err()` or the envtest harness.

When an extension image defines `manifest.VM.ComposeFile` at the root of the image (e.g. `"/compose.yaml"` or `"/docker-compose.yaml"`), `path.Dir(manifest.VM.ComposeFile)` returns `"/"`.

In `dockerEngine.export` (`extension_engine_docker.go:146-150`), `path.Clean("/")` produces `"/"`, and `strings.TrimPrefix("/", "/")` produces `""`. With `prefix == ""`, `strings.HasPrefix(relPath, prefix+"/")` checks for leading `"/"`, which fails for clean tar paths. Every file and directory in the container image (`/bin`, `/usr`, `/etc`, etc.) is extracted into `<installDir>/compose`. If `ComposeFile` is a bare name without a slash (`"compose.yaml"`), `path.Dir` returns `"."`, causing Docker `CopyFromContainer` to fail.

Fix: Check if `path.Dir(manifest.VM.ComposeFile)` is `"/"` or `"."`. If so, export the compose file as a single file entry rather than exporting the directory.

```diff

+			isDir := sourcePath != "/" && sourcePath != "."
+			if !isDir {

-						sourcePath:  path.Dir(manifest.VM.ComposeFile),
```

I6. **Updating `spec.image` fails to recreate or restart running Compose containers** — `rdd/pkg/controllers/extensions/extension/controllers/extension_installed_reconciler.go:97-105`, `rdd/pkg/controllers/extensions/extension/controllers/extension_started_reconciler.go:50-84` (important, regression)

```go
	case installed.ObservedGeneration < ext.Generation:
		return r.setInstalledCondition(ctx, ext,
			metav1.ConditionFalse, v1alpha1.ExtensionInstalledReasonResolving,
			"Resolving extension image reference")
```

When an extension's `spec.image` tag is updated, `reconcileInstalled` correctly resets `Installed` condition to `Resolving` and re-extracts the new image files. However, the existing `ComposeProject` is never torn down or recreated.

When `reconcileStarted` runs after re-installation, line 51 checks `r.Get(ctx, composeKeyForExtension(ext), &compose)`. Because `composeKeyForExtension` is fixed to `"rdx-" + ext.GetName()`, the old `ComposeProject` from the previous image version is found immediately. Line 80 unconditionally marks `Started=True` without triggering `ComposeUpRequest`. The extension continues executing the outdated container workload indefinitely.

Fix: On generation increment, or when `status.image` changes, trigger `reconcileDeleteStarted` to terminate the running compose workload and remove the stale `ComposeUpRequest` before marking `Installed`.

###### Suggestions

S1. **`ExtensionValidator` does not enforce the App namespace** — `rdd/pkg/controllers/extensions/extension/controllers/extension_validator.go:42-68` (suggestion, gap)

`api_extensions.md:48` specifies that `metadata.namespace` must be `rancher-desktop`. `ExtensionValidator.validate` lists extensions in `obj.Namespace` but never asserts `obj.Namespace == appv1alpha1.AppNamespace`. Extensions created in other namespaces will fail when creating child resources like `ImagePullRequest`. Add `if obj.Namespace != appv1alpha1.AppNamespace { return nil, fmt.Errorf("extension must be created in namespace %q", appv1alpha1.AppNamespace) }`.

S2. **`ControllersFlagUsage` omits `extensions` API group** — `rdd/pkg/service/controllers/options.go:17` (suggestion, regression)

`ControllersFlagUsage` lists `"Groups: rdd, app, containers, lima."`. Because `extensions` is now a registered controller group, update the help text to include `extensions`.

S3. **`reconcileExtracted` returns `nil` instead of requeuing on finalizer addition** — `rdd/pkg/controllers/extensions/extension/controllers/extension_extracted_reconciler.go:36-38` (suggestion, regression)

In `reconcileExtracted`:
```go
	if !controllerutil.ContainsFinalizer(ext, extractedFinalizer) {
		return base.AddFinalizerWithRetry(ctx, r.extractor, ext, extractedFinalizer)
	}
```
Unlike `reconcileInstalled:79-84` which returns `requeueError(0)` upon adding its finalizer, `reconcileExtracted` returns `nil`. This allows `r.reconcile` to fall through into `reconcileStarted` and `reconcileReady` on the same reconcile pass before extraction has begun. Return `requeueError(0)` after adding the finalizer.

S4. **`runScript` leaks completed `scriptState` in memory indefinitely** — `rdd/pkg/controllers/extensions/extension/controllers/extension_installed_reconciler.go:633-649` (suggestion, regression)

`runScript` stores `scriptState` in `r.scripts`. When the post-install script completes successfully, `r.scripts.Delete(ext.GetUID())` is never called (unlike `reconcileDeleteInstalled:513`). The `*exec.Cmd` and process handles remain in memory for all installed extensions across the lifetime of the daemon. Delete the entry once `completed == true` is observed in `reconcileInstalled:126`.

S5. **`readyConditionFor` maps `Stopped` to `Starting`** — `rdd/pkg/controllers/extensions/extension/controllers/extension_ready_reconciler.go:50-54` (suggestion, regression)

When an extension's `Started` condition has `Reason: Stopped`, `readyConditionFor` hits `default`, returning `Status: ConditionFalse, Reason: Starting, Message: "Extension is being started"`. Add an explicit case for `startedReason == v1alpha1.ExtensionStartedReasonStopped` that returns `Reason: Stopping` or a dedicated stopped reason.

S6. **Doc comment in `extension_types.go` contradicts post-install error handling** — `rdd/pkg/apis/extensions/v1alpha1/extension_types.go:90` (suggestion, regression)

`ExtensionManifest.Host.InstallScript`'s doc comment says `"Errors will be ignored"`. In `extension_installed_reconciler.go:119-123`, post-install script failure is fatal and transitions `Installed` condition to `Failed`. Update the comment to clarify that post-install script failures are fatal, whereas pre-uninstall script failures are ignored.

###### Design Observations

###### Concerns

1. **Monolithic state machine across separate reconciler files** `(in-scope)`
   `reconcileInstalled`, `reconcileExtracted`, `reconcileStarted`, and `reconcileReady` are split across multiple files but mutate the same status conditions, return synthetic `requeueError` values to drive transitions, and share in-memory state maps. A linear step executor that returns explicit next-action directives would eliminate the cascade of synthetic requeue errors and prevent out-of-order execution.

2. **Absence of containerd support for extensions** `(future)`
   Extensions currently mandate Docker (`moby`), rejecting containerd with an error. When containerd support is introduced, containerd's content store and image unpacking API can extract files directly without spawning temporary export containers or running tar-over-HTTP copies.

###### Strengths

1. **Deterministic naming and compose integration**: Leveraging `api.MirrorName` for `ComposeProject` and linking `ComposeUpRequest` with ownership tracking cleanly ties extension lifecycles into the existing containers controller architecture.
2. **Atomic in-memory synchronization**: `AtomicMap` provides clean, thread-safe state tracking for async extraction operations without ad-hoc mutex nesting.

###### Testing Assessment

- **C1, C2 (Required; check: how would a user see it)**: A user pulling an extension from a remote registry fails immediately with a webhook rejection or false download failure. The test suite bypassed this because `extension-lifecycle.bats:29` pre-builds the image locally rather than testing registry pulls.
- **C3 (Required; check: how would a user see it)**: Any extension that enters `Failed` state cannot be deleted and hangs in `Terminating`. No unit or BATS test exercises deleting an extension whose `Installed` condition reason is `Failed`.
- **I1 (Required; check: how would a user see it)**: Deletion logs error spam and triggers backoff on every step. No test asserts that deletion proceeds without reconciler errors.
- **I2 (Required; check: how would a user see it)**: Normal uninstall leaves orphaned `ImagePullRequest`s in sqlite. No test inspects `ImagePullRequestList` after extension deletion.
- **I6 (Required; check: does an existing test catch it)**: Updating `spec.image` does not update running compose containers. No test updates an existing `Extension` spec.

###### Documentation Assessment

`rdd/docs/design/api_extensions.md` line 48 specifies that extensions must be created in `rancher-desktop`, but `ExtensionValidator` does not validate this. `rdd/pkg/service/controllers/options.go` needs updating to document `extensions` in `--controllers` help text.

###### Commit Structure

The 15 commits follow a logical bottom-up progression (APIs -> stubs -> engine abstraction -> extractor -> status reconcilers -> BATS). Messages are concise and accurately describe the changes. No fixup or squashing issues observed.

###### Acknowledged Limitations

- `rdd/pkg/controllers/extensions/extension/controllers/extension_utils.go:27`: `// TODO: support namespaces, in containerd.` — Acknowledges that containerd namespaces are not yet supported for extensions.
- `rdd/pkg/controllers/extensions/extension/controllers/extension_installed_reconciler.go:158`: `// TODO: Pick the best tag.` — Acknowledges that tagless image references currently default to TagNameOnly rather than semver resolution.
