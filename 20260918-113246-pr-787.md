## Executive Summary

The PR closes S1 from the merged predecessor: `MirrorName` now re-encodes an input already shaped like its own output, and the volume helper folds into it. The encoding is injective and the new test rows pin it. The documentation shipped alongside contradicts it in four separate ways, and renaming every volume mirror makes an upgrade strip a pending deletion's finalizer without forwarding the delete to Docker.

## Important Issues

I1. **An upgrade discards a volume deletion the user already requested** — `rdd/pkg/controllers/app/engine/controllers/sync_volumes.go:47` [Codex GPT 5.6 Sol]

```go
		mirrorName := api.MirrorName(volumeMirrorPrefix, v.Name)
		activeNames[mirrorName] = true
```

This commit renames every valid-named volume's mirror, from `vol-<sha256>` to the Docker name. A mirror the user has deleted keeps the mirror finalizer until `processVolumeFinalizers` forwards the delete to Docker, and that pass retries for as long as the engine refuses (`watch_reconciler.go:746-751`), so an in-use volume can wait there indefinitely. After the rename the old object is absent from `activeNames`, so the prune at line 61 calls `removeMirrorResource` on it, which strips the finalizer and forwards nothing; its own comment says it is for objects the engine has already deleted (`mirror_client.go:28-30`). The Docker volume is still there, and a fresh mirror replaces the deleted one.

// field returns the value of "  <key>:" nested under "<section>:", or of
// "<key>:" at top level when section is empty.
func field(block, section, key string) string {
	in := section == ""
	for _, line := range strings.Split(block, "\n") {
		switch {
		case line == section+":":
			in = true
		case in && strings.HasPrefix(line, "  "+key+":"):
			return strings.TrimSpace(strings.TrimPrefix(line, "  "+key+":"))
		case in && section != "" && line != "" && !strings.HasPrefix(line, " "):
			in = false
		case in && section == "" && strings.HasPrefix(line, key+":"):
			return strings.TrimSpace(strings.TrimPrefix(line, key+":"))
		}
	}
	return ""
}

func containerdMirrorName(ns, id string) string {
	if len(validation.IsDNS1123Subdomain(id)) == 0 {
		return id
	}
	sum := sha256.Sum256([]byte(ns + "/" + id))

## Design Observations

### Concerns

- **The "one shared algorithm" framing holds for two of five kinds** *(future)* [Claude Opus 5]. The new section opens "Where we mention encoding names into a `foo-0000...` form below, we use the following algorithm", but only `ContainerNamespace` and `Volume` route through `api.MirrorName`. Containers use `containerdMirrorName`, Images use `imageMirrorNames` and `containerdImageMirrorName`, and `ComposeProject` has no code. The two image helpers already agree with the shared algorithm by accident, since every input they hash contains a `\x00` or a `:` and can never be a valid object name, so `api.MirrorName("img", id+"\x00"+tag)` returns the same bytes today. Converting them is mechanical and would delete two helpers.
- **The mock controller ships a third naming scheme** *(future)* [Claude Opus 5]. `sanitizeKubernetesObjectName` at `pkg/controllers/mock/image_reconciler.go:45-47` replaces `/` and `:` and nothing else, so a mock volume or image name with an underscore or an upper-case letter produces an invalid object name and the apply fails. The mock's namespace reconciler already calls `api.MirrorName`; its Volume and Image reconcilers do not. Pre-existing, found while tracing call sites.

### Strengths

- The escape rule is the smallest change that makes the mapping injective, and it does make it so. A pass-through result can never equal a hashed result, because any string matching `<prefix>-<64 hex>` takes the hashing arm by construction [Claude Opus 5, Gemini 3.5 Flash].
- The exact prefix, length, and lower-case-hex checks avoid over-encoding a name that merely has a different prefix or a trailing suffix, and the three added test rows pick exactly those discriminating cases [Codex GPT 5.6 Sol, Gemini 3.1 Pro].
- Folding `volumeMirrorName` into `api.MirrorName` removes a duplicate implementation rather than adding a second guard beside it, and `ce5e7e271` updated the destroy path in the same commit, so apply and remove cannot drift [Claude Opus 5, Codex GPT 5.6 Sol].
