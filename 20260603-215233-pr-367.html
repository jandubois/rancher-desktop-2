Executive Summary ¶

The PR adds a kuberlr-style resolver under pkg/kuberlr/: it probes the cluster's version and, when the embedded kubectl is more than ±1 minor out of skew, downloads an sha512-verified match from dl.k8s.io and execs it. The implementation is careful, well-commented, and well-tested. The one user-facing gap is that a cache-miss download runs silently at the default warn log level, so the command appears to hang.

Claude carried the review with the only Important finding and the sharpest design observations; Codex contributed one unique real finding and shared another; Gemini produced two "Critical" findings that were both hallucinations against code that reads correctly — verified and dropped. The remaining findings are four low-risk suggestions. No correctness defect blocks the merge.

S1. Resolver discards known-flag parse errors and probes the default cluster Codex¶
pkg/kuberlr/resolver.go
// affects the resolver's probe, which falls through silently to the
// embedded kubectl on probe failure either way.
//
// parseKubeConfigFlags exists as a separate helper so unit tests can
// verify the binding without reaching for a real cluster.
func parseKubeConfigFlags(args []string) *genericclioptions.ConfigFlags {
	fs := pflag.NewFlagSet("rdd-kubectl", pflag.ContinueOnError)
	fs.ParseErrorsAllowlist.UnknownFlags = true
	fs.SetOutput(io.Discard)
	fs.Usage = func() {}
	cf := genericclioptions.NewConfigFlags(true)
	cf.AddFlags(fs)
	_ = fs.Parse(args)
	return cf
}

// clientOnlySubcommands lists kubectl subcommands that never contact
// a cluster. config and completion manipulate local state only;
// kustomize renders local manifests; plugin lists local plugins on
// PATH; options prints kubectl's global flags; help prints help text.

parseKubeConfigFlags ignores fs.Parse's error, so a malformed known flag — rdd kubectl get pods --kubeconfig with no value — leaves the connection overrides unset. loadClientConfig (resolver.go:154) then builds a client from the default kubeconfig and probes that cluster; if it is reachable and out of skew, the resolver downloads a kubectl for a cluster the user never named, before kubectl reports the flag error.

The trigger is narrow (a typo plus a reachable, out-of-skew default cluster) and self-correcting, so this consolidates to a Suggestion rather than the Important Codex assigned. The fix also aligns this path with isClientOnly, which already treats a parse failure conservatively.

Fix: return fs.Parse's error from parseKubeConfigFlags; serverVersion already falls through on any loadClientConfig error.

Design Observations ¶

Concerns ¶

  • Exact-patch download can 404 for vendor clusters (future) Claude — Resolve passes the server's exact parsed version to ensureCached, so a server reporting v1.32.7-gke.500 downloads kubectl-v1.32.7 (downloader.go:99). Skew compatibility is a minor-level guarantee, yet the resolver pins the patch. A vendor build whose patch number is not published on dl.k8s.io would hard-fail every kubectl call against that cluster, per the loud-error policy. Upstream patches usually exist, so this is rare; resolving the latest published patch of the server's minor would remove the risk. TODO(offline) already flags follow-up nearby.
  • Hand-rolled kuberlr reimplementation owns upstream's maintenance tail (future) Claude — the package reimplements flavio/kuberlr inline because its logic lives under internal/. The right call given the constraint; flagged so the ownership of dl.k8s.io URL drift, checksum-format variants, and cache eviction (TODO(eviction)) is explicit and revisited if upstream ever exports the resolver.

Strengths ¶

  • rdd ctl skips the probe (in-scope) Codex Claude — ctlAction calls SkipResolver() before kubectlAction, keeping the embedded-control-plane path off the network; the embedded apiserver and kubectl share a module entry and cannot drift.
  • Hardened download path (in-scope) Codex Claude Gemini — streaming sha512 verification with body-size caps, an atomic temp-file-then-rename publish, and a per-request 5-minute timeout.
  • Probe reuses kubectl's genericclioptions.ConfigFlags loader (in-scope) Claude — the probe targets the same cluster the kubectl child will contact, with correct KUBECONFIG/--kubeconfig precedence, avoiding the config-file-only-default class of bug.
  • Unbound basic-auth flags (in-scope) Gemini — leaving --username/--password unbound stops ToRawKubeConfigLoader from launching an interactive stdin prompt during the background probe.
  • compatible casts to int64 before subtracting (in-scope) Claude — avoids unsigned-minor underflow when the client minor is below the server minor.

Testing Assessment ¶

Coverage is strong. resolver_test.go exercises the skew rule (with EKS/GKE/AKS suffixes), the full ConfigFlags binding surface, client-only detection across many flag forms, the dev-build fall-through, and the recursion guard. 7-kubectl-cache.bats covers download-on-miss, skip-on-hit, mirror-404, sha-mismatch, and apiserver-500 fall-through end to end. Gaps, by risk:

  1. No test asserts any user-visible signal during a cache-miss download (I1); the suite runs at debug, so it would miss a regression that drops the notice entirely.
  2. No integration test drives a within-skew server to prove the resolver returns "" and the embedded kubectl runs without contacting the mirror. compatible is unit-tested; the wiring through Resolve to the embedded path is not.
  3. The concurrent first-time download race (Acknowledged Limitations) is untested on any platform.

Codex ran go test ./pkg/kuberlr (passed). go test ./cmd/rdd could not type-check in the worktree because the generated lima-guestagent.gz embed artifact is absent outside the Makefile build path — an environment limitation, not a PR defect.

Acknowledged Limitations ¶

Declined in prior rounds (PR #348, carried forward in the repo-context file):

  • Windows os.Rename cache-publish race (downloader.go:128) — two concurrent first-time downloads of the same version can both reach os.Rename; on Windows the second fails. Declined rounds 1–8. This PR adds a second CacheRoot/CacheDir consumer (rdd svc paths), but that path never downloads, so the race surface is unchanged.
  • CacheRoot panics if os.UserCacheDir fails (cache.go:52) — declined rounds 1, 2, 3, 5, 7, 8. service_paths.go:33 adds a call site reached by rdd svc paths, which the BATS harness sources on every test, so a failure would now also crash the test bootstrap. Likelihood stays near zero (it needs $HOME/$XDG_CACHE_HOME/%LocalAppData% all unset), so per the decline history this stays noted, not re-raised.

Documented in code as intended follow-ups:

  • Cache eviction and leaked .kubectl-* temp files on SIGKILL (cache.go:33).
  • Offline fallback when a download fails against a reachable out-of-skew cluster (resolver.go:64).
  • maxKubectlBytes truncation surfacing as a checksum mismatch if kubectl ever exceeds 256 MiB (downloader.go:138).
  • Windows child-process exec hard-killing on context cancel (exec_windows.go:27); the cobra context is never canceled today.
  • local_teardown_file() in 7-kubectl-cache.bats deviates from the no-teardown convention; the author documents the exception (an ephemeral-port HTTP server leaks ports if left running). Reasonable.

Review Process Notes ¶

Skill improvements ¶

  • When one agent raises a Critical or Important finding in a file that every other agent's Coverage Summary marks "Reviewed, no issues," treat the lone finding as a false-positive candidate and read the raw file bytes before consolidating it. Cross-agent disagreement on a severe finding is a strong false-positive signal: a real blocker in changed code is usually caught by more than one reviewer, so a lone severe claim against code others read as clean more often reflects a hallucination than a unique catch. This complements the existing "distrust findings that require the file to be malformed" gate by adding a prioritization cue for which findings to verify against bytes first.

Repo context updates ¶

  • [repo] The BATS harness runs rdd in developer mode: it executes bin/rdd from the source tree, and developer.Mode() returns true when ../cmd/rdd/main.go exists beside the executable, which sets the default log level to debug. A user-facing message logged at info or below is therefore visible in tests but hidden for end users, whose packaged binary defaults to warn. When reviewing user-facing output or progress messages, check the level the code logs at against cmd/rdd/main.go's defaults — a defect visible only at production verbosity is invisible to the test suite.
