The PR splits status.name and status.labels across two field managers, so a failed label fetch can no longer erase stored labels. The split works, and an empty label set from containerd still clears them. Nothing pins that behavior. Revert the fix and the package suite stays green. A mirror written by the merge-base build still loses its labels once, but only on code that merged today and has shipped in no release.

func TestOwnerSplit(t *testing.T) {
	env := &envtest.Environment{CRDDirectoryPaths: []string{".probecrds"}}
	cfg, err := env.Start()
	assert.NilError(t, err)
	t.Cleanup(func() { _ = env.Stop() })
	assert.NilError(t, containersv1alpha1.AddToScheme(scheme.Scheme))
	c, err := client.New(cfg, client.Options{Scheme: scheme.Scheme})
	assert.NilError(t, err)

	const nameOwner = "engine-controller"
	const labelOwner = "engine-controller-labels"

	// manager carrying both name and labels.
	oldApply := func(t *testing.T, n string, labels map[string]string) {
		t.Helper()
		ac := containersv1alpha1apply.ContainerNamespace(n, "default")
		assert.NilError(t, c.Apply(t.Context(), ac, client.ForceOwnership, client.FieldOwner(nameOwner)))

		assert.NilError(t, c.Status().Apply(t.Context(), ac, client.ForceOwnership, client.FieldOwner(nameOwner)))
	}

	// label-fetch failure: return before the second status apply.
	newApply := func(t *testing.T, n string, labels map[string]string, labelsOK bool) {
		t.Helper()
		ac := containersv1alpha1apply.ContainerNamespace(n, "default")
		assert.NilError(t, c.Apply(t.Context(), ac, client.ForceOwnership, client.FieldOwner(nameOwner)))
		ac.WithStatus(containersv1alpha1apply.ContainerNamespaceStatus().WithName(n))
		assert.NilError(t, c.Status().Apply(t.Context(), ac, client.ForceOwnership, client.FieldOwner(nameOwner)))
		if !labelsOK {
			return
		}
		ac.WithStatus(containersv1alpha1apply.ContainerNamespaceStatus().WithLabels(labels))
		assert.NilError(t, c.Status().Apply(t.Context(), ac, client.ForceOwnership, client.FieldOwner(labelOwner)))
	}

	read := func(t *testing.T, n string) containersv1alpha1.ContainerNamespaceStatus {
		t.Helper()
		var got containersv1alpha1.ContainerNamespace
		assert.NilError(t, c.Get(t.Context(), client.ObjectKey{Namespace: "default", Name: n}, &got))
		return got.Status
	}

	// controller name onto its own manager, so no manager ever relinquishes

		assert.NilError(t, c.Apply(t.Context(), ac, client.ForceOwnership, client.FieldOwner(nameOwner)))
		ac.WithStatus(containersv1alpha1apply.ContainerNamespaceStatus().WithName(n))
		assert.NilError(t, c.Status().Apply(t.Context(), ac, client.ForceOwnership, client.FieldOwner(nameOwner+"-name")))

		}

	fixedApply(t, "fixed-clear", map[string]string{}, true)

	assert.Equal(t, m.Labels["hello"], "world", "migrated labels survived when the fetch worked")
	assert.Equal(t, len(f.Labels), 0, "migrated labels were erased when the fetch failed")
	assert.Equal(t, len(cl.Labels), 0, "labels were cleared when containerd reported none")
	assert.Equal(t, pf.Labels["hello"], "world", "FIX: migrated labels survived the failed fetch")
	assert.Equal(t, pf.Name, "fixed-fail", "FIX: the name was still updated")
	assert.Equal(t, len(fc.Labels), 0, "FIX: labels still clear when containerd reports none")
	assert.Equal(t, len(sp.Labels), 1, "PR drops the stale legacy key")
	assert.Equal(t, len(sf.Labels), 2, "FIX leaves the stale legacy key behind")

Design Observations ¶

Concerns ¶

  • applyNamespace now costs three API round trips instead of two, and it runs on every ContainerCreate and ImageCreate event, not only during a full sync (containerd_watcher.go:197 and :236). Each is a no-op apply after the first, so the extra cost is one request per event over the local socket, but it scales with image pulls into k8s.io. (future) Claude Opus 5 Gemini 3.5 Flash
  • Only the containerd path writes engine-controller-labels. The Docker path's syncContainerNamespace still applies status.name under engine-controller alone (sync_namespace.go:32-38), so nothing there would clear containerd-era labels off a moby mirror. cleanupMirrorResources deletes every mirror on an engine change within one process, which covers it today. (future) Claude Opus 5

Strengths ¶

  • Applying status.name before the labels fetch, rather than after, keeps the selectable field fresh even when the fetch fails. That ordering is deliberate and any fix for S1 should preserve it. (in-scope) Claude Opus 5
  • The len(entries) > 0 guard in WithLabels that caused the original bug now works in the PR's favor: an empty map produces a status:{} body, which removes exactly the keys that owner wrote. Scenario 4 of the S1 probe confirms it. (in-scope) Codex GPT 5.6 Sol Gemini 3.1 Pro Claude Opus 5
  • The PR drops stale label keys from a migrated mirror correctly, which the simpler alternative fix does not. Scenario 7 of the S1 probe shows both. (in-scope)

Review Process Notes ¶

Repo context updates

  • REMOVE the entry stating that supportsNamespaces() in the container-engine store returns a hardcoded false and that the namespace picker is dead code. The getter now reads app?.status?.supportsNamespaces ?? false (pkg/rancher-desktop/store/container-engine.ts:61-65), so the guidance to rate renderer-side namespace defects as latent is wrong and will suppress real findings.
  • REMOVE the entry stating that a containerd namespace is mirrored only when its name is a valid DNS1123 subdomain and that no hashed cns--prefixed object is ever created. api.MirrorName (rdd/pkg/util/api/mirror_name.go) returns cns-<sha256> for a name K8s would reject, and a BATS case covers exactly that.
  • ADD: Controllers persist their mirrors in the embedded kine/sqlite store, which outlives a daemon restart; db/state.db is removed only by rdd svc delete. cleanupMirrorResources sweeps mirrors when the App stops or the engine changes within one process, but a daemon restart with the App still running goes straight to startWatcherAndSync without a sweep. When judging whether stored state from an older build can reach new code, check for a sweep on the specific path rather than assuming a restart clears it.
  • ADD: A server-side apply that omits a field the same field manager previously owned deletes that field. When a change splits one manager's writes across two managers, or moves a field between managers, check what happens to objects an earlier build wrote under the old ownership, and check it in both directions: the field the new owner fails to claim, and the stale key the old owner never relinquishes.

Skill improvements

  • When a PR's remedy rests on a claim about how an external system merges concurrent writers, and the repository offers a harness that runs the real system, require the consolidator to reproduce the claim against that harness rather than the project's test doubles. A double that implements the same merge library confirms the library, not the deployment.
  • When a finding proposes a fix, run the reproducer against the fix from the opposite direction as well. Check the state the fix newly fails to clean up, not only the state it newly preserves. A fix that turns the supplied reproducer green can introduce the mirror-image defect, and the author will take a verified-looking patch at face value.
  • When judging how severe a state-migration defect is, establish whether the code that produced the old state has ever shipped. Check the tags containing the merge-base before rating it. An unreleased predecessor bounds the affected population to developer machines and usually moves the finding a full severity level.
