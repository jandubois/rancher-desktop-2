Executive Summary ¶

The head commit translates Windows host paths in nerdctl build and builder debug, and its handlers match nerdctl v2.1.2 and buildctl v0.21.1 for every unquoted form. Three things need fixing. Two new BATS tests fail the required Ubuntu bats-app job, because buildctl cannot set file owners on the guest's host mount. A --file that names a directory, sub/ or ., loses its trailing slash. A quoted type= field turns stdout or an env secret's name into a path.

buildctl v0.21.1 decodes the values of --output, --secret, --import-cache and --export-cache as CSV (csvvalue.Fields in cmd/buildctl/build/). The stub splits at commas and keeps the quote in the key, so it never finds the type in "type=tar",dest=-. streamsToStdout then reports a file, and dest=- becomes a file named - in the working directory. In "type=env",id=s,src=MY_TOKEN the variable name becomes a path. Before this commit both values passed through, and buildctl streamed the tar to stdout and read the variable. Nobody needs to quote a type= field, so the trigger is rare. But decoding the CSV also lets a quoted path keep its comma, which nerdctl.md lists as unsupported. The probe runs on macOS, so its relative paths resolve against the probe's directory.

Design Observations ¶

Concerns ¶

  • (future) An env-type --secret, --ssh default and a value-less --build-arg NAME read buildctl's environment, and buildctl runs in the guest under sudo with no host variables forwarded. The stub passes them through correctly, but they resolve against the guest's environment on every OS. Forwarding the named variables would take rdd nerdctl sending them and sudo --preserve-env. This is reasoned from limaVMGuestExec, not run. Claude Opus 5.5
  • (future) On Linux, rdd nerdctl build --output type=local,dest=... into the home directory fails for users the same way as I1's tests, because the QEMU guest's 9p mount refuses lchown by root. The stub translates paths only on Windows, so the limitation predates this PR. Exporting into a directory outside the mount avoids it, and so should a tar export, which buildctl writes with os.Create and no owner change (cmd/buildctl/build/output.go:97-106; not run). #1129 tracks it.

Strengths ¶

  • (in-scope) The CSV handlers follow buildctl's parser: keys match in any case, the last type= wins, tar= falls back to true when ParseBool fails, and an env secret's src= stays a variable name. Claude Opus 5.5 Codex GPT 6 Astra Gemini 3.5 Flash
  • (in-scope) builderOutputArgHandler translates a bare value inside nerdctl's own type=local,dest= wrapper, so a comma in it splits into the same fields that buildctl sees. Claude Opus 5.5 Gemini 3.1 Pro
  • (in-scope) The eleven BATS tests run each translated option through a real build. Gemini 3.5 Flash

Acknowledged Limitations ¶

  • A path inside a --mount or --ssh value cannot contain a comma, as nerdctl.md:62-66 documents. The I3 patch changes only the builder CSV handler, so the limit stays for both.
  • The new backslash-path test calls cygpath -w under skip_on_unix, like #974's tests at lines 540 and 557 and the guest_path helper at line 43. Windows BATS runs under MSYS2 (.github/workflows/rdd-bats.yaml:159), so do not re-suggest a WSL branch for it in this PR; a change belongs with #974's tests.
  • Do not re-suggest matching raw= in --ssh case-insensitively: buildctl v0.29.0 compares key == "raw" exactly.
