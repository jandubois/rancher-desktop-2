Executive Summary ¶

Both kube probes now get their TLS settings from client-go, so the current-context probe honors insecure-skip-tls-verify and reads a relative certificate-authority path from the kubeconfig's directory. The code matches client-go v0.36.4, and dropping ResolveLocalPaths or AnonymousClientConfig turns a test red. This round converged. The suggestions that remain are optional. A doc comment misses some cases where the probe keeps current-context, and a proxy subtest also passes before the fix.

Design Observations ¶

Concerns ¶

  • The probe validates credentials that it never sends (future) Claude Opus 5.5. ClientConfig() checks the context's user stanza, so a broken credential config, such as a client certificate file deleted along with its cluster, keeps a dead context current (S1). Building the REST config from a copy of the context with an empty AuthInfo would validate only the cluster settings, and rdd could then switch away from such a context. The maintainer's ruling covered TLS settings that client-go refuses. Earlier rounds treated a missing client-certificate file as the same case without asking for a separate ruling. Whether broken credential settings belong in that case is still the maintainer's question, and the findings and tests in this report do not assume either answer.

Strengths ¶

  • One transport builder for both probes (in-scope) Claude Opus 5.5 Codex GPT 6 Astra Gemini 3.5 Flash. probeTransport replaces two hand-built tls.Configs with rest.TLSConfigFor, so CA file and data, insecure-skip-tls-verify and tls-server-name follow kubectl's rules in both probes.
  • rest.AnonymousClientConfig before TLSConfigFor (in-scope) Claude Opus 5.5 Gemini 3.5 Flash. It drops client certificates, tokens and the exec and auth-provider settings, so the reachability check never builds an authenticator. The subtest "the probe does not send a client certificate" confirms that the server does not receive one.
  • fakeK3sServer demands a client certificate (in-scope) Claude Opus 5.5 Codex GPT 6 Astra. A k3s probe that stops presenting the kubeconfig's certificate now fails Test_Reconcile_KubernetesReady_Ready.

Repo context updates ¶

  • [repo] The current-context reachability probe (probeCurrentKubeContext) leaves current-context alone whenever it cannot judge the cluster: the kubeconfig fails to load, client-go refuses its TLS settings, or a certificate check fails, including one at an https proxy. The bias is deliberate, because a wrong switch takes a live context away from the user, so do not flag a dead context kept current in these cases as a defect.
