Review Process Notes ¶

Skill improvements ¶

  • When the target's prior round has a maintainer review that triages the findings, declaring some important and the rest cosmetic, treat that triage as the resolution table the target lacks. Re-raising what the maintainer called cosmetic spends the round relitigating a decision already made, and the items that remain belong in Acknowledged Limitations, not the findings list.
  • Cross-check an agent's prior-round status table against the tree before repeating any row. A table marking an unfixed item "Fixed" is more damaging than a missed finding, because a later reader takes it for verification and stops asking; the rows are cheap to spot-check and an optimistic one predicts more.
  • When a prior round records that a verification was impossible for an environmental reason, run the trivial command that tests the excuse before inheriting it. A misdiagnosed toolchain is the cheapest thing in a review to check and the most expensive to keep, since each later round skips the same verification for the same wrong reason.
  • When a finding rests on a platform configuration the project does not support, say so in the severity, not in the prose alone. The mechanism can be entirely real while the severity is not, and a finding that states the mechanism without saying the configuration is unsupported looks blocking.

Repo context updates ¶

  • [repo] The repository has two independent Windows-detection idioms, and which one is correct depends on the file. Makefiles use $(shell sh -c 'command -v winver.exe') to set EXE; shell scripts use uname -s against MSYS*|MINGW* (rdd/bats/helpers/os.bash, scripts/spelling.sh, scripts/install-latest-ci.sh). A new probe that matches neither, command -v cygpath.exe for instance, agrees with both under MSYS2 and diverges under WSL. Flag a new detector that does not reuse one of the two, and check it against the Makefile that produces any binary the script then executes.
  • [repo] Shell scripts under scripts/ are linted by the root Makefile's lint-shell target (shellcheck --enable=all plus shfmt --indent=4), but SHELL_FILES lists specific files instead of a glob, and no CI job runs the target. Check whether a changed .sh file is in that list before treating it as covered, and note that a passing local make lint-shell proves nothing about what CI enforces.
  • [repo] rdd/bats/helpers/paths.bash defines host_path() (cygpath -m under Windows, no-op elsewhere) and rdd/bats/helpers/load.bash exports MSYS_NO_PATHCONV=1, together the repo's settled answer to MSYS2 rewriting argv paths when a bash process execs a native Windows binary. Flag new code that passes host paths to docker, wsl.exe or another native executable without reusing that pair, and reject a proposed remedy that invents a third approach.
  • [repo] make generate, generate-typescript and verify-generate are in rdd/Makefile, not the root one. A remedy string or doc line naming them must say make -C rdd ... or state the directory; bare make generate fails at the repo root.
  • [repo] REMOVE the containers-API bullet claiming "The design doc's the status.name of a ContainerNamespace names a field the type does not have." ContainerNamespaceStatus.Name is declared with json:"name,omitempty" in rdd/pkg/apis/containers/v1alpha1/container_namespace_types.go, which also has a +kubebuilder:selectablefield:JSONPath=.status.name marker. The entry leads agents to flag correct generated descriptions; round 1 filed the same removal and it has not been applied.
