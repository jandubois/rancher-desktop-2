## Design Observations

### Concerns

- **(in-scope) Any `config.json` that rdd can't read or parse holds Settled at `False` under `front` and `back`.** Round 3 raised the parse case. I2's probe shows the I/O case too. An unreadable `config.json` sets `Failed` while the startup block is written, and `app_controller.go:721-722` gates on it. At the merge-base `front` never read the file, so `rdd set --wait` now waits on a plugin registration the user may not need. Options: give the plugin edit its own reason, or stop gating Settled on plugin-edit failures. [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash]
- **(in-scope) App users still can't reach the plugin registration.** No code under `pkg/rancher-desktop` writes `application.addPath`, so app installs run `manual`. [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.5 Flash]
- **(future) `rdd svc delete` unwinds with the CLI's `DOCKER_CONFIG`, not the daemon's.** [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.5 Flash]
- **(future) The shutdown clear can outlast the manager's 10 s grace period**, since `lockTimeout` is 30 s (`pkg/service/controllers/manager.go:153`, `dockerconfig.go:29`). [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.5 Flash]

### Strengths

- **(in-scope)** `Edit` holds the lock from load through save. A two-process probe showed one writer timing out while another process held the lock, and a later writer adding the plugin directory without losing `currentContext`. [Codex GPT 6 Astra]
- **(in-scope)** `apply` runs the PATH and plugin edits independently and joins their errors, so a broken dotfile can't block the `config.json` cleanup; `TestUnwindRemovesPluginEntryDespiteMalformedBlock` pins it. [Claude Opus 5.5]

###### Design Observations

###### Concerns

- **(in-scope) Minor `config.json` parse warnings permanently block Settled under `front` and `back`**: `docker/cli`'s `config.Load` fails on invalid `auths` entries (e.g. invalid base64). `dockerconfig.Edit` classifies all non-I/O errors as `ErrMalformed`, prompting `PathManagementReconciler` to report `PathManagementReasonMalformed`. In `app_controller.go:711-722`, `Malformed` is exempted from gating `Settled` only under `manual`. Under `front` and `back`, `Settled` remains permanently `False` until the user manually cleans up the credentials, even if Docker CLI itself would have functioned or printed a warning.
- **(in-scope) Unreachable plugin registration from the Electron application**: No code in `pkg/rancher-desktop` writes `spec.application.addPath`, so application installs default to `manual`. On macOS and Linux, bundled Docker CLI plugins remain undiscoverable by `docker` unless the user explicitly switches `addPath` to `front` or `back` via the CLI (`rdd set application.addPath=front`).
- **(future) CLI `DOCKER_CONFIG` environment drift during deletion**: `rdd svc delete` invokes `pathmanagement.Unwind` from the CLI process, which resolves `dockerconfig.Dir()` using the CLI environment's `DOCKER_CONFIG` or `HOME`, rather than the daemon's runtime configuration.
- **(future) Lock acquisition timeout during daemon shutdown**: The shutdown cleanup in `removeDockerContext` bounds lock acquisition by `dockerconfig.lockTimeout` (30 s), which can exceed the controller manager's 10-second shutdown grace period (`pkg/service/controllers/manager.go:153`).

###### Strengths

- Using cross-process file locking via `flock` in `pkg/dockerconfig` cleanly serializes `config.json` modifications between concurrent daemons and internal controllers without risking lost updates.
- The fast-path exit in `applyDockerPlugins` skips reading or loading `config.json` entirely when running under `manual` without a marker, ensuring corrupted Docker configuration files cannot fail default daemon reconciliations.

- Engine probe lock wait: `manageDockerContext` passes `r.watcherCtx` to `setCurrentDockerContext` (`rdd/pkg/controllers/app/engine/controllers/watch_reconciler.go:313`), so `removeDockerContext` cancelling `probeCtx` cannot abort the lock wait.
