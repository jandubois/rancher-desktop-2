## Executive Summary

Round 3 points the namespace lookup at the `cns-` names #772 now creates, reads
through the uncached reader before the cache starts, and stops re-checking the
filesystem on unrelated updates. All three fixes work, but no test pins any of
them, and reverting each one leaves the suite green. The design doc still describes
`spec.workingDir` as relative to where RDD runs, while the validator rejects
every relative path. Both problems have small fixes, each with a tested patch.

## Suggestions

S1. **After startup the lookup reads the cache; the sibling webhook reads uncached, as the repo convention asks** — `rdd/pkg/controllers/containers/compose/compose_webhooks.go:55-58` [Codex GPT 5.6 Sol, Gemini 3.1 Pro, Claude Opus 5, Gemini 3.5 Flash]

```go
		err := v.Client.Get(ctx, key, &namespace)
		if _, isErrCacheNotStarted := errors.AsType[*cache.ErrCacheNotStarted](err); isErrCacheNotStarted {
			err = v.Reader.Get(ctx, key, &namespace)
		}
```

The fallback works as wired: an envtest probe with the manager stopped admitted
an existing mirror and rejected a missing one. After the cache starts, the
lookup lags a newly created mirror. With the manager running, a validation
issued immediately after creating a `ContainerNamespace` rejected 2 of 200
requests, and none of 200 once one API round trip separated the two. A real
request passes through the API server first, so users should rarely hit it;
Codex and Gemini 3.1 Pro rated it Important, and the measurement does not
support that.

The sibling holds one `client.Reader` from `mgr.GetAPIReader()`
(`image_pull_request_webhooks.go:23-25`), as the repo convention asks. Embedding
both interfaces also makes `Get` and `List` ambiguous and hands the validator
write methods it never uses.

Fix: hold one named `reader client.Reader` and drop the fallback; I1's fallback
subtest goes with it.

S2. **`composeMirrorName` reimplements `api.MirrorName`** — `rdd/pkg/controllers/containers/compose/compose_utils.go:23-29` [Claude Opus 5]

```go
func composeMirrorName(namespace, name string) string {
	candidateName := namespace + "." + name
	if len(validation.IsDNS1123Subdomain(candidateName)) == 0 {
		return candidateName
	}
	return fmt.Sprintf("cmp-%x", sha256.Sum256([]byte(candidateName)))
}
```

`api.MirrorName("cmp", namespace+"."+name)` computes the same value: the same
DNS-1123 test and the same `prefix-%x` SHA-256 form (`mirror_name.go:18-23`).
The webhook already imports `api` for the `cns` lookup, and the engine, the mock
and the `ImagePullRequest` webhook already call it for namespace mirrors.

Fix: return `api.MirrorName("cmp", namespace+"."+name)` and drop the local
hashing.

S3. **The compose-go import adds 1.41 MB for a rule one regexp expresses** — `rdd/pkg/controllers/containers/compose/compose_webhooks.go:66-68` [Claude Opus 5]

```go
	if request.Spec.Name == "" || loader.NormalizeProjectName(request.Spec.Name) != request.Spec.Name {
		errs = append(errs, loader.InvalidProjectNameErr(request.Spec.Name))
	}
```

`loader` pulls 16 compose-go packages into `cmd/rdd` and the containers
controller. Rewriting the check as a regexp shrank the stripped darwin/arm64
`containers-controller` from 56,909,074 to 55,503,298 bytes, measured at the
review SHA. The check holds exactly when the name matches
`^[a-z0-9][a-z0-9_-]*$`, since `NormalizeProjectName` lowercases, drops characters
outside `[a-z0-9_-]`, and trims leading `_` and `-` (compose-go v2.15.0
`loader.go:767-772`). Round 2 credited the import for tracking upstream's rule;
this is the price of that coupling. Keep it if the reconciler will load compose
files through compose-go anyway.

Fix: put the pattern on `ComposeUpRequestSpec.Name` as a
`+kubebuilder:validation:Pattern`, which also publishes it in the CRD, and
delete the check.

S4. **Three rejection messages mislead** — `rdd/pkg/controllers/containers/compose/compose_webhooks.go:59-60` [Claude Opus 5, Codex GPT 5.6 Sol, Gemini 3.5 Flash]

```go

An absolute config path inside `workingDir` gets `statat …: path escapes from

`configs: ["", ""]` produces two identical lines, still without the index round

S5. **Comments still describe a create-only, naming-only webhook** — `rdd/pkg/controllers/containers/compose/compose_controller.go:73-74` [Claude Opus 5, Codex GPT 5.6 Sol, Gemini 3.1 Pro, Gemini 3.5 Flash]

```

Round 2's S1 is partly fixed. The webhook also runs on UPDATE, the default at

S6. **A FIFO as `workingDir` parks the admission handler until the daemon exits** — `rdd/pkg/controllers/containers/compose/compose_webhooks.go:114` [Claude Opus 5]

```go
	} else if root, err := os.OpenRoot(request.Spec.WorkingDir); err != nil {
```

`os.OpenRoot` blocks on a FIFO until a writer appears. A probe on macOS was
still blocked after 3 s, while a directory and a regular file returned at once.
The API server gives up at its webhook timeout and rejects the request, but the
handler goroutine stays in `open(2)`, and `validateSpec` ignores its context,
so each such request leaks one goroutine. Unlikely on a single-user desktop,
and cheap to close.

Fix: `os.Stat` the path and require `IsDir()` before `os.OpenRoot`.

## Design Observations

### Concerns

- **Two mechanisms now cancel work that outlives a `Reconcile`** (future) [Claude Opus 5, Gemini 3.1 Pro]. The engine derives `watcherCtx` from `context.Background()` and cancels it from a `manager.RunnableFunc` when the manager begins stopping (`engine_reconciler.go:215-225`). The new `RegisterWithManager` context cancels when `mgr.Start` returns, up to `GracefulShutdownTimeout` later, but also on registration and webhook-setup failures the runnable never sees. When the compose reconciler lands, pick one or document the difference. Gemini 3.1 Pro asked to revert the parameter; round 2 credited it for covering those failure paths, and that still holds.
- **`status.configs` is documented as relative, but compose-go makes compose file paths absolute** (future) [Claude Opus 5]. `ResolveRelativePaths` in compose-go `loader/paths.go` turns `ComposeFiles` absolute. If the reconciler fills `status.configs` from the `config_files` label docker compose writes, those paths will be absolute (the label format itself is unverified; docker/compose is not in the module cache). Either relativize them or change the doc.

### Strengths

- **Round 3's fixes behave as intended** (in-scope) [Claude Opus 5, Codex GPT 5.6 Sol, Gemini 3.5 Flash]. The `cns` key matches both producers (`sync_namespace_containerd.go:77`, and `sync_namespace.go:27` for `moby`), the fallback admits through the API reader with the cache stopped (envtest), and the UPDATE gate compares exactly the two fields `validateSpec` reads.
- **`os.Root` enforces the documented confinement** (in-scope) [Claude Opus 5, Codex GPT 5.6 Sol, Gemini 3.1 Pro]. It refuses `..` escapes and symlinks that resolve outside `workingDir`, and admits `sub/../compose.yaml` and symlinks that stay inside.

### Design Observations

**Concerns**

- **(in-scope) `ComposeUpRequest` reports success differently from every other `*Request` kind.**
  - ImagePullRequest reports success as `Failed=False, Reason=Succeeded` (`api_containers.md:490-491`), and the push, scan and volume-create examples show `Failed: False`.
  - `ComposeUpRequest` instead removes `Failed` on success (`api_containers.md:787-788`, `compose_types.go:65-66`), so absent `Failed` means "running" in one state and "succeeded" in another.
  - A generic request tracker in the GUI would need a per-kind branch.
  - The code comment justifies the choice only as "per the design doc", which the same PR edited. Keeping the sibling shape costs one constant (`ComposeUpRequestFailedReasonSucceeded = "Succeeded"`) and gives one consumer rule for every kind.
- **(future) Two mechanisms now exist for work that outlives a `Reconcile`.**
  - The engine derives `watcherCtx` from `context.Background()` and cancels it from a `manager.RunnableFunc` (`engine_reconciler.go:215-225`). That context cancels as soon as the manager's stop procedure begins.
  - The new `RegisterWithManager` context (`manager.go:212-213`) cancels only when `mgr.Start` returns. controller-runtime runs its stop procedure inside a defer of `Start` (`internal.go:379-383`), so after a runnable fails, that is up to `GracefulShutdownTimeout` (10 s, `manager.go:152`) later.
  - In exchange, the new context also cancels when registration or webhook setup fails, where the engine's hook never runs.
  - When the compose reconciler lands, pick one mechanism and migrate the other, or document the difference.
- **(future) `status.configs` is documented as relative, but compose stores absolute paths.** The field is documented "relative to WorkingDir" (`compose_types.go:99-100`, `api_containers.md:677-679`). compose-go makes `project.ComposeFiles` absolute (`loader/paths.go:33-37`). docker compose writes those paths into the `config_files` label, which is where the reconciler will populate `status.configs` from; I could not check that last step because docker/compose is not in the module cache. Either the reconciler relativizes the paths, or the doc should say they are absolute.

**Strengths**

- The name derivation cannot collide. Project names cannot contain dots (`NormalizeProjectName` strips them), so the last dot splits namespace from name unambiguously, and hashed names contain no dot.
- The UPDATE gate compares exactly the two fields `validateSpec` reads. A metadata-only update on a vanished directory is admitted.
- Moving `mgrCtx` above registration cancels it on every exit from `Start`, and the mock drops its `context.Background()`.
- `os.Root` enforces the documented confinement: `..` escapes and symlinks that resolve outside `workingDir` are refused, while `sub/../compose.yaml` and symlinks that stay inside pass.

##### S1. Simplify Validator client to use Uncached Reader Directly `(suggestion, enhancement)` — `rdd/pkg/controllers/containers/compose/compose_webhooks.go:55-58`

```go
		err := v.Client.Get(ctx, key, &namespace)
		if _, isErrCacheNotStarted := errors.AsType[*cache.ErrCacheNotStarted](err); isErrCacheNotStarted {
			err = v.Reader.Get(ctx, key, &namespace)
		}
```

By querying the cached client and falling back to the uncached reader on `ErrCacheNotStarted`, the code handles startup races but still remains vulnerable to watch-delay cache lag (where a freshly created namespace is not yet visible to the cache). Using `v.Reader.Get` (directly utilizing `mgr.GetAPIReader()`) for all namespace validation would bypass the cache entirely, prevent any lag-related spurious rejections, and simplify the validator by removing dual-client fields and `errors.AsType` checks, matching the pattern used by the sibling `ImagePullRequest` webhook.

```diff
-type composeUpRequestValidator struct {
-	client.Client
-	client.Reader
-}
+type composeUpRequestValidator struct {
+	reader client.Reader
+}
```

### Design Observations

#### Concerns

- **Admission Gated on Mirror Existence `(in-scope)`**:
  The webhook validates that the requested containerd namespace matches an existing `ContainerNamespace` mirror in Kubernetes. Because these mirrors are transient and only exist when the engine watcher is connected, requests to bring up Compose projects will be rejected during early VM boot or when the engine is temporarily stopped. This is a known and accepted trade-off also present in the `ImagePullRequest` webhook, but worth documenting for developers.

#### Strengths

- **Optimized Spec-Change-Only Updates**:
  The `changed` gate in `ValidateUpdate` is elegantly constrained to mutable fields. This ensures that unrelated metadata, label, or status updates to a `ComposeUpRequest` can proceed smoothly even if the original project files on the host filesystem have since been moved or deleted.
