## Executive Summary

The PR converts the `Containers` e2e suite off `docker` onto the mock controller's baked-in fixtures, adds four label-selected log-writer modes to the mock WebSocket passthrough, and runs Playwright under `tsx` so `@rdd-client` imports resolve. Only Claude produced findings; the other three reviewers returned one suggestion between them. This report checks each finding against the lead worktree and measures the location regression on both sides of the merge-base.

## Important Issues

I1. **Playwright reports every e2e test at `file:1:<offset>` instead of its source line** — `scripts/e2e.ts:71` [Claude Opus 5]

```ts
      // Run playwright under tsx, so it goes through the same TypeScript
      // compilation pipeline as the main app.  Otherwise, we encounter errors
      // importing files without using the `.js` suffix.
      'node_modules/tsx/dist/cli.mjs',
```

Running Playwright under `tsx` with `PW_DISABLE_TS_ESM=1` bypasses Playwright's own transpiler, so its location extractor reads the transpiled file. I measured the same spec file on both sides: job 91215737194 at `9a8ba657c` reports `e2e/main.e2e.spec.ts:21:3`, and job 91220529854 at the review SHA reports `e2e/main.e2e.spec.ts:1:418`. This hits all 127 collected tests, not only the files this PR touches, and the `list` reporter output is the primary artifact for diagnosing an e2e failure.

The `delete` at `e2e/config/playwright-config.ts:29` restores correct frames in failure stack traces. The author states that mitigation in the `fcc491f69` commit message, but it does not restore the reported location.

Fix: confirm the trade is acceptable, and track `microsoft/playwright#41402` (named in the code comment) so the workaround can be dropped once upstream resolves ESM TS imports.

## Suggestions

S1. **Global dispatcher restore is not `finally`-guarded** — `e2e/containers.e2e.spec.ts:42` [Claude Opus 5]

```ts
    await teardown(electronApp, testInfo);
    rddConfigCleanup();
```

`getRDDConfig` swaps the process-wide undici dispatcher and returns a restore closure (`e2e/utils/TestUtils.ts:423-425`). `teardown` has several throwing paths, including `context.tracing.stop()` and the `expect(...).resolves.toBeUndefined()` on the log-stream close, so a throw skips the restore. With `workers: 1` the worker process is reused across spec files, so later suites keep the CA-injected agent.

The practical harm is small: the replacement agent adds CAs on top of `rootCertificates`, so normal TLS still verifies. The leaked keep-alive socket pool and the unrestored global are the real cost, and the agent is never `close()`d even on the happy path.

Fix: wrap the teardown in `try`/`finally` so the restore always runs, and have the cleanup `close()` the agent it created.

S2. **`spec.image` and `spec.args` are silently pruned by the API server** — `e2e/containers.e2e.spec.ts:296` [Claude Opus 5]

```ts
          spec:       {
            image: 'alpine',
            args:  ['sleep', 'infinity'],
          },
```

`ContainerSpec` is an empty struct (`rdd/pkg/apis/containers/v1alpha1/container_types.go:129`) and the CRD renders `spec` as a bare `type: object` with no properties, so structural pruning drops both keys on create. The generated client types `spec` as `any`, so nothing catches it at compile time. The test reads as though the fixture carries an image and a command, but the values that matter are set by the status patch below it.

Fix: use `spec: {}` and note that Container has no desired-state fields, since actions go through the `containers.rancherdesktop.io/action` annotation.

S3. **Fixture declares a container namespace the mock never creates** — `e2e/containers.e2e.spec.ts:308` [Claude Opus 5]

```ts
            namespace: 'k8s.io',
```

`status.namespace` refers to a `ContainerNamespace` in the same Kubernetes namespace, and the mock only ever creates `buildkit` (`rdd/pkg/controllers/mock/mock_controller.go:33`). The row is visible today only because `supportsNamespaces()` is hardcoded `false` (`pkg/rancher-desktop/store/container-engine.ts:60-62`). Flip that to `true` and the store's field selector adds `status.namespace=<current>`, which would hide this container and break both the visibility assertion and the row-count assertion.

Fix: use `namespace: 'buildkit'` so the fixture matches the `ContainerNamespace` the mock actually creates.

S4. **The screenshots config did not get the stack-trace fix** — `e2e/config/playwright-config.ts:29` [Claude Opus 5]

```ts
delete (Error as any).prepareStackTrace;
```

`scripts/e2e.ts` is shared: `test:e2e:screenshots` appends `--config=screenshots/playwright-config.ts` to the same hardcoded arg list, and I confirmed by experiment that Playwright's last `--config` wins. So screenshot runs now go through tsx too, but `screenshots/playwright-config.ts` has no equivalent line and its failures will report transpiled frames.

Fix: move the `delete` into a small shared module imported by both configs.

S5. **`getAnyContainer`'s docstring disclaims the stability two tests rely on** — `e2e/containers.e2e.spec.ts:67` [Claude Opus 5]

```ts
    return containers.items[0];
```

`should display test container` navigates to `items[0]` and leaves the page there. `should show container information` then issues a second, independent LIST and asserts the page title matches `items[0]` of that call. They agree only because the API server returns items in key order, which the helper's own "some unspecified container" comment tells callers not to rely on.

Fix: memoise the first result, or have the second test reuse `getContainerByLogsWriter('labels')`, which resolves to the same container.

S6. **`apps.items[0]` is dereferenced without a length check** — `e2e/containers.e2e.spec.ts:37` [Claude Opus 5]

```ts
    namespace = apps.items[0].spec!.namespace!;
```

An empty list produces `TypeError: Cannot read properties of undefined (reading 'spec')` inside `beforeAll`, which tells the reader nothing about what went wrong. `getAnyContainer` already models the right pattern with an explicit `expect(...).toBeGreaterThan(0)`.

Fix: assert `apps.items` is non-empty, with a message, before indexing.

S7. **Silent fallback hides a mistyped writer name** — `rdd/pkg/controllers/mock/logs_passthrough.go:113` [Claude Opus 5]

```go
	logWriter, ok := logWriterMap[container.Status.Labels[logWriterLabel]]
	if !ok {
		logWriter = c.writeLogsLabels
	}
```

A container labelled `hundered` gets the labels writer, and the e2e failure surfaces as a Playwright timeout waiting for `[Line 100]` rather than a message naming the bad value. The writer vocabulary is spelled out in three places (Go constants, the JSON fixture, and four call sites in the spec), so a typo in the fixture is realistic.

Fix: keep the fallback for an absent label, but log the unknown value when the label is set.

S8. **The reader goroutine's comment understates why it exists** — `rdd/pkg/controllers/mock/logs_passthrough.go:84` [Claude Opus 5]

```go
	// Handle WebSocket control messages
```

The goroutine discards every frame. Its real job is that gorilla only processes control frames from inside a read call, so without it a client-initiated close never reaches the writer, and `writeLogsLoop` exits solely on write failure. The `_ = conn.Close()` on the read error is what actually terminates the loop writer, and that load-bearing detail is invisible from the comment.

Fix: say that the goroutine drains frames so a client close reaches the writer, and that closing the connection is what unblocks `writeLogsLoop`.

S9. **Comment names a log writer that does not exist** — `e2e/containers.e2e.spec.ts:159` [Claude Opus 5]

```ts
    // Navigate to a container using the "count" mock log writer...
```

The container fetched four lines above uses writer `ten`. `count` is the Go function name (`writeLogsCount`), not a writer value. The sibling comment at line 138 correctly names `"labels"`.

Fix: `// Navigate to a container using the "ten" mock log writer...`

S10. **Assertion restates the selector it was fetched by** — `e2e/containers.e2e.spec.ts:149` [Claude Opus 5]

```ts
    expect(container.status?.labels).toHaveProperty(['io.rancherdesktop.mock.logs.writer'], 'labels');
```

`getContainerByLogsWriter('labels')` already selects on exactly this key and value, and fails inside the helper when nothing matches, so this line cannot fail. The next assertion pins the `org.opencontainers.image.vendor` label the terminal check actually depends on.

Fix: delete this line and keep the vendor assertion.

S11. **Leftover `page.reload()` from the docker-era test** — `e2e/containers.e2e.spec.ts:252` [Claude Opus 5]

```ts
    await page.reload();
```

The reload existed because the old test created a container with `docker run` after the page had rendered. The mock containers are present before the suite starts, and every sibling conversion in this file dropped the reload. Keeping it re-mounts the whole renderer for no benefit.

Fix: delete the line.

S12. **Log writers are methods that never touch the receiver** — `rdd/pkg/controllers/mock/logs_passthrough.go:122` [Claude Opus 5]

```go
func (c *controller) writeLogsLabels(write func(string) error, container *v1alpha1.Container) {
```

Neither `writeLogsLabels` nor `writeLogsCount` nor `writeLogsLoop` reads `c`. As plain functions they could live in a package-level dispatch table instead of one rebuilt on every request (see `logs_passthrough.go:105-110`).

Fix: drop the receivers and hoist `logWriterMap` to package scope.

S13. **`writeLogsLoop` cannot be cancelled** — `rdd/pkg/controllers/mock/logs_passthrough.go:151` [Gemini 3.5 Flash]

```go
func (c *controller) writeLogsLoop(write func(string) error, _ *v1alpha1.Container) {
```

The loop terminates only when `write` fails. A client disconnect does end it, which Codex confirmed against a live control plane, but `handleLogs` never passes `r.Context()` down, so nothing stops the goroutine on server shutdown. The passthrough handler lives as long as the daemon, so the leak lasts until the process exits.

Fix: pass the request context in and select on `ctx.Done()` alongside a ticker, if the cost of carrying the context is judged worthwhile for mock-only code.

S14. **Mixed indentation inside the fixture** — `rdd/pkg/controllers/mock/testdata/containers.json:447` [Claude Opus 5]

```json
      "Id": "e9a453cba86bcd4ffa50648fcca76c119d1171a2b4fc3122c8b7b2e66fcaaf40",
```

Measured leading-space widths: the two pre-existing entries step by four (4, 8, 12, 16, 20), the two new ones by two (4, 6, 8, 10, 12). `.editorconfig` sets `indent_size = 2`, so the new entries are the conforming ones and the file now carries both styles.

Fix: reformat the whole file to two-space indentation in a separate mechanical commit.

## Design Observations

### Concerns

- **The writer vocabulary is spelled out in three places** (in-scope) [Claude Opus 5]. The label key and its four values live as Go constants in `logs_passthrough.go`, as string literals in the JSON fixture, and as string literals at four call sites in the spec. The Go constants are used only as keys into a map built in the same file, so today they buy nothing. Validating the writer name when the fixture is unmarshalled would turn a fixture typo into a loud controller-startup failure instead of a silent degradation to the labels writer.
- **The undici interop rests on an undocumented global symbol** (future) [Claude Opus 5]. `setGlobalDispatcher` from the npm package steers Node's built-in `fetch` only because both write `globalThis[Symbol.for('undici.globalDispatcher.1')]`; I read that mechanism in the installed `undici@7.25.0` `lib/global.js`, and the PR pins 8.8.0. That same file installs undici's own `new Agent()` at import time when no dispatcher is set yet, so the value `getRDDConfig` saves and restores may itself be the npm package's agent rather than Node's original. It works at the pinned Node and undici, which the green e2e job demonstrates, but a Node major bump can break it quietly.
- **Three describes stay `.fixme`** (future) [Gemini 3.5 Flash, Claude Opus 5]. The Shell, Info, and Stats tabs still call `tool('docker', …)`, so 15 tests report as skipped. They need mock fixtures of their own before they can come back.

### Strengths

- **Bracketing log lines as `[Line N]`** makes substring matching unambiguous [Claude Opus 5]. `[Line 1]` cannot match `[Line 10]` or `[Line 100]`, which the scrolling test depends on.
- **The status patch overrides Content-Type to `PatchStrategy.MergePatch`** [Claude Opus 5]. The generated `patchNamespaced*` methods otherwise default to `application/json-patch+json`, which would reject this merge-shaped body. Correct and not obvious.
- **Label-selected log writers give deterministic finite, scrolling, and continuous streams** without a real container engine [Codex GPT 5.6 Sol, Gemini 3.1 Pro, Gemini 3.5 Flash].
- **The reader goroutine respects gorilla's single-reader constraint** [Gemini 3.5 Flash, Codex GPT 5.6 Sol], and `Close` is documented as safe to call concurrently with the writer.
- **Moving fixtures into the mock drops the suite's dependency on a running VM and a host `docker`**, which is what lets it run on the Linux-only Playwright runner at all [Claude Opus 5].
- **The conversion fixes a stale call site.** The base file passed a settings object as a second argument to `startSlowerDesktop`, which takes only `testInfo`. Nothing caught it because the describe was `.fixme` and the repo does not run `tsc` over e2e.

## Testing Assessment

The change is itself test work, so this covers what the restored suite leaves uncovered, highest risk first.

1. **Container actions are untested.** `ContainersPage.clickContainerAction` supports start, stop, restart, and delete, but the suite only ever calls `viewContainerInfo`. The mock has no reconciler consuming the `containers.rancherdesktop.io/action` annotation, so covering this needs mock work first.

3. **Log-stream error paths are untested.** The passthrough returns 400 for an invalid container ID and 404 for an unknown one, and `ContainerLogs.vue` exposes an error message element, but nothing drives either.
4. **Nothing asserts that `writeLogsLoop` terminates when the client disconnects.** The suite proves lines arrive; the goroutine's exit is what S13 turns on. A Go test over `handleLogs` with an `httptest` server and a client that closes mid-stream would pin it.
5. **Fifteen tests remain skipped** across the three `.fixme` describes.

Executed during this review: `gofmt -l` and `go vet ./pkg/controllers/mock/` both clean; `jq` confirms the fixture is valid JSON with exactly one writer label per container; CI job 91220529854 at the review SHA shows 10 `Containers` tests passing in 22 seconds and 15 skipped; job 91215737194 at the merge-base establishes the pre-change test-location format; and a two-`--config` Playwright invocation confirms the last flag wins.

## Review Process Notes

### Skill improvements

- When a change alters how a test runner, linter, or build tool reports results, compare the same file's output before and after by pulling the tool's output from a CI run at the merge-base and one at the review SHA. Diff-reading cannot distinguish "the tool now reports differently" from "this file happens to look different", and an author's own acknowledgement of a trade-off is a reason to measure its scope, not to accept the framing.
- Verify a claim about CLI flag precedence by running the CLI with the flags in both orders. A wrapper that appends user arguments after its own hardcoded ones silently depends on last-wins behavior, and reading the wrapper cannot tell you which argument survives.

### Repo context updates

- [repo] The renderer creates the `App` resource with `spec.namespace: 'rancher-desktop'`, matching the `apiNamespace` constant the mock controller writes its `Container`, `Image`, and `Volume` objects into. The CRD's own default for that field is `default`, so a test or tool that reads the namespace from the CRD default rather than from the live `App` resource will look in the wrong place.
- [repo] `supportsNamespaces()` in the container-engine store returns a hardcoded `false`, so the store never sends a `status.namespace` field selector and the Containers, Images, and Volumes lists show every object regardless of its container namespace. Any assertion about which rows appear is insensitive to `status.namespace` until that getter is implemented; flag fixtures that depend on the current behavior.
- [repo] The e2e suite runs Playwright under `tsx` with `PW_DISABLE_TS_ESM=1`, so reported test locations are `file:1:<byte-offset>` rather than source positions. Do not read a location of that shape as a defect in the test file.

**I1. Global dispatcher restore is not guaranteed and the replacement `Agent` is never disposed — `e2e/containers.e2e.spec.ts:40-43`** *(important, regression)*

```ts
  test.afterAll(async({ colorScheme }, testInfo) => {
    await teardown(electronApp, testInfo);
    rddConfigCleanup();
  });
```

`getRDDConfig` replaces the process-wide undici dispatcher (`e2e/utils/TestUtils.ts:424`) and hands back a restore closure (line 425). Line 41 awaits `teardown()` first, and `teardown` has several throwing paths — `context.tracing.stop()` (`TestUtils.ts:164`), `teardownApp`'s `app.close()` race (line 118), and the `expect(...).resolves.toBeUndefined()` on the log-stream close at line 178. Any of those skips line 42. The playwright config sets `workers: 1` (`e2e/config/playwright-config.ts:16`), so the worker process is reused across spec files: every later suite would then run against the CA-injected `Agent` instead of the default dispatcher. Separately, the `Agent` built at `TestUtils.ts:424` is never `close()`d, so its keep-alive socket pool outlives the suite even on the happy path.

Fix:

```diff
   test.afterAll(async({ colorScheme }, testInfo) => {
-    await teardown(electronApp, testInfo);
-    rddConfigCleanup();
+    try {
+      await teardown(electronApp, testInfo);
+    } finally {
+      await rddConfigCleanup();
+    }
   });
```

and in `getRDDConfig`, make the cleanup dispose the agent it created:

```diff
   const dispatcher = getGlobalDispatcher();
-  setGlobalDispatcher(new Agent({ connect: { ca: [...ca, ...rootCertificates] } }));
-  return [config, () => setGlobalDispatcher(dispatcher)];
+  const agent = new Agent({ connect: { ca: [...ca, ...rootCertificates] } });
+  setGlobalDispatcher(agent);
+  return [config, async() => {
+    setGlobalDispatcher(dispatcher);
+    await agent.close();
+  }];
```

(The return type becomes `[KubeConfig, () => Promise<void>]`; update the `rddConfigCleanup` initializer at `e2e/containers.e2e.spec.ts:24` to `async() => {}`.)

The infinite loop in `writeLogsLoop` relies solely on `write()` failing when a client disconnects to terminate. If the manager/server shuts down while a stream is active, the goroutine is not responsive to context cancellation and will sleep for the full second before the next write.

-func (c *controller) writeLogsLoop(write func(string) error, _ *v1alpha1.Container) {
-	for i := 1; ; i++ {
-		err := write(fmt.Sprintf("[Line %d]\n", i))
-		if err != nil {
-			return
-		}
-		time.Sleep(time.Second)
-	}
-}
+func (c *controller) writeLogsLoop(ctx context.Context, write func(string) error, _ *v1alpha1.Container) {
+	ticker := time.NewTicker(time.Second)
+	defer ticker.Stop()
+	for i := 1; ; i++ {
+		if err := write(fmt.Sprintf("[Line %d]\n", i)); err != nil {
+			return
+		}
+		select {
+		case <-ctx.Done():
