## Important Issues

I1. **`ForProfile`'s docstring promises a copy, but an empty profile returns the receiver** — `rdd/pkg/overlay/manifest.go:171-179` [Claude Opus 5]

```go
// ForProfile returns a copy of the manifest holding only the entries that apply
// to profile, which is how distro-overlay builds one profile's image from a
// manifest both share. An entry naming no profile applies to every one. An
// empty profile keeps every entry, so a caller that does not build per profile
// gets the whole manifest back.
func (m *Manifest) ForProfile(profile string) *Manifest {
	if profile == "" {
		return m
	}
```

The first sentence promises a copy. When the profile is empty, line 178 returns `m` itself, so a caller that trusts the docstring and edits the result edits the manifest it passed in. The only caller, `main.go:92`, reassigns `m` and never mutates it, so nothing breaks today. The finding is Important because the comment states something the code contradicts.

The probe edits the result for a lima profile and for an empty one. The lima case leaves the receiver alone; the empty case changes it. Against the patch below the probe still fails, as it should, because it asserts the old promise and the patched comment says an empty profile returns `m` itself.

S2. **Omitting `--profile` builds an image with both profiles' exclusive files** — `rdd/cmd/distro-overlay/main.go:30` [Claude Opus 5]

```go
	profile := flag.String("profile", "", "build profile to overlay for: lima or wsl (default: every entry)")
```

Without the flag, `ForProfile("")` keeps every entry, so lima-only and wsl-only entries both reach the image. Once epic #798 moves the profile-exclusive files in, such an image gets the `network-namespace.conf` drop-ins `config.sh` deletes for lima and the `requires-*.conf` drop-ins it deletes for wsl, and the run succeeds. No build wants that mix, since `config.kiwi` binds each image type to exactly one profile.

The Makefile always passes the flag, so only a manual run is exposed, and the example's usage line (S6) omits it. The `ForProfile` docstring and the README describe the default, and `overlay_test.go:140` pins it.

Fix: when `--profile` is empty and any entry names a profile, refuse the run.

S3. **A profile-limited entry does not keep a tree copy of the same path out of the other profile** — `rdd/cmd/distro-overlay/manifest.example.yaml:69-71` [Claude Opus 5]

```yaml
  - path: /usr/local/lib/systemd/system/lima-init.service.d/requires-network.conf
    source: systemd/requires-network.conf
    profiles: [lima]   # any of lima, wsl
```

The example places this entry under the `/usr/local/lib/systemd/system` tree copy at lines 47-49, which applies to both profiles, after showing that an explicit entry overrides the tree's copy (line 50). A reader following that pattern can expect `profiles: [lima]` to keep the file out of the wsl image. It doesn't.

`Apply` builds its `owned` set from the already filtered manifest (`overlay.go:59`), and `writeTreeFiles` skips only owned paths (`overlay.go:152`), so the wsl build writes the tree's copy whenever the tree source holds that file. Claude's probe confirmed it: a both-profile tree holding a file plus a wsl-only entry for the same path gave the tree's contents under `--profile lima`.

Fix: document in the example that `profiles` limits the entry, not the path, so a profile-exclusive file must stay out of every tree source.

S4. **The Makefile keys the profile on `TARGET_OS`, not on the variant its comment names** — `rdd/Makefile:63-68` [Claude Opus 5, Codex GPT 5.6 Sol]

```make

```

The comment and the commit body say the profile follows the variant, but line 68 repeats line 63's test of `TARGET_OS`. Every supported build pairs them correctly: `make -p` resolves `GOOS=linux` to raw and lima, and `GOOS=windows` to tar and wsl. Overriding the variant alone breaks the pair, though. `make GOOS=linux DISTRO_VARIANT=tar` resolves to tar and lima, and `distro-overlay` does not check the profile against the format it detects. With the fix below, the same override resolves to tar and wsl.

Fix: derive the profile from the variant.

```diff

+DISTRO_PROFILE := $(if $(filter tar,$(DISTRO_VARIANT)),wsl,lima)
```

## Design Observations

### Concerns

- **The profile repeats what the tool detects** (future) [Claude Opus 5]. `config.kiwi` binds `lima` to the raw image and `wsl` to the tarball, and `run` detects the format right after it filters (`main.go:92`, `main.go:96-100`). Deriving the profile from the format would drop the flag, the Makefile variable (S4), the flag check (S5) and the empty default (S2). But #803 asks for a `--profile` flag, and a future profile sharing a format would need it back. The lighter step keeps the flag and has `run` reject a mismatched pair; `TestRunProfileAppliesOnlyItsEntries` pairs `lima` with a tarball (`main_test.go:252`), so it would then need a raw image.
- **Path uniqueness spans profiles** (future) [Claude Opus 5, Codex GPT 5.6 Sol]. `Manifest.validate` rejects one path in two entries even when their profiles don't overlap; both reviewers' probes got `path is already used by entry 0`. The rationale at `manifest.go:100-102` covers one image receiving both entries, which disjoint profiles rule out. None of the profile-exclusive files #803 lists needs different contents per profile at one path. If one ever does, key the check on path and profile.

### Strengths

- **Whole-manifest validation before filtering** (in-scope) [Claude Opus 5, Codex GPT 5.6 Sol, Gemini 3.5 Flash]. `LoadManifest` checks every entry before `ForProfile` drops any, so a typo in a wsl-only entry fails the macOS build too.
- **One filter point** (in-scope) [Claude Opus 5]. `run` filters once, before the format dispatch, so neither backend changed.
- **A target-derived profile** (in-scope) [Codex GPT 5.6 Sol]. The overlay runs on the build host, so selecting by `runtime.GOOS` would pick the host's profile when a Mac builds the Windows image. This answers the first alternative in mook-as's comment on #803.

## Review Process Notes

### Skill improvements

- [ ] When a change filters or subsets an input before handing it to existing code, check every rule in that code that derives state from the input, such as ownership, deduplication, or override sets. The subset changes what those rules see, and an item the filter removed can come back through a broader rule the filter never touched, such as a directory copy, a glob, or a default.

### Repo context updates

- [ ] [repo] In the distro overlay manifest, a per-entry profile limit applies to the entry, not the path: a directory-tree entry with a source still writes a profile-excluded path into the other profile's image. When a PR adds profile-limited entries under a directory that a tree entry also copies, check that the tree's source does not hold the same file.
- [ ] [repo] `rdd/go.mod` declares Go 1.27, whose composite literals may set a promoted field of an embedded struct directly, and `go fix` rewrites nested literals into that form. A tool or editor on the Go 1.26 language version rejects it with "requires go1.27 or later". Flag a PR that re-nests such a literal as reverting `go fix`, and reject any finding that calls the promoted form a compile error.

S1. **Omitting `--profile` builds an image that carries both profiles' exclusive files** — `rdd/cmd/distro-overlay/main.go:30` (suggestion, regression)


S2. **A profile-limited entry inside a shared tree lets the tree's copy reach the other profile** — `rdd/cmd/distro-overlay/manifest.example.yaml:69-71` (suggestion, regression)
