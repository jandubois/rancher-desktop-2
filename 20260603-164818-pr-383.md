## Important Issues

I1. **`service.PID()` rejects a control plane started as `rdd svc serve`** — `pkg/service/cmd/service.go:176` [Codex GPT 5.5]

```go
if err == nil && !process.IsOurProcess(pid, "service", "serve") {
    err = fmt.Errorf("pid %d is not our control plane", pid)
}
```

`svc` aliases `service` (`cmd/rdd/service.go:45`) and `serve` is a normal, non-hidden subcommand, so the daemon can run as `rdd svc serve`, whose command line holds `svc serve`, not `service serve`. `IsOurProcess` requires every substring via `strings.Contains` (`process_windows.go:83`), so the absent `service` returns false and line 181 removes the live daemon's PID file; `Running()` then reports it dead and `svc stop` cannot find it. At merge-base `PID()` accepted any alive PID, making this a regression. The blast radius is narrow: `svc start` self-spawns the canonical `service serve` (`service.go:296`), so the normal path and every BATS test stay unaffected — only a manual `rdd svc serve` triggers it. Unlike Round 2's declined S1 (a transient failure judged near-impossible), this fires deterministically.

Fix: discriminate on `"serve"` alone, since `"service"` does not contain `"serve"`; the image-path match still rejects unrelated rdd processes. Or accept and document it, as with the concurrent-instances limitation at `service.go:162-166`.

## Review Process Notes

**Skill improvement — Correctness dimension: discriminator must survive every launch spelling.** When code identifies a process by matching a substring of its command line — to confirm identity, ownership, or role before a destructive or state-changing action — enumerate every way that process can be launched: command aliases, abbreviated subcommands, a background self-spawn that hard-codes one spelling, and direct foreground invocation. Confirm the discriminator matches each. A guard that matches only the canonical self-spawn spelling silently rejects the same process started through an alias, so a reviewer who verifies only the self-spawn path marks the code clean and misses the gap. Recognize the pattern when a `strings.Contains` or substring check on argv or a command line gates a kill, signal, or PID-file removal.

**[repo] The `service` command is aliased `svc`, and `serve` is directly invocable.** `rdd`'s `service` command registers `svc` as an alias (`cmd/rdd/service.go`), and the `serve` subcommand — the control-plane daemon entry point — is not hidden, so `rdd svc serve` runs the daemon directly. The normal start path self-spawns it as canonical `service serve` (`pkg/service/cmd/service.go`), but a manual `rdd svc serve` produces a daemon whose command line reads `svc serve`. When reviewing code that discriminates the control-plane process by its command line, account for both spellings.

### Verification of the three resolution fixes

**1. `processCommandLine` buffer-sizing fix — `pkg/util/process/process_windows.go:177-193` — correct and complete.**

```go
length := params.CommandLine.Length
if length < 2 || params.CommandLine.Buffer == nil {
    return "", nil
}
buf := make([]uint16, length/2)
if err := readProcessMemory(handle, uintptr(unsafe.Pointer(params.CommandLine.Buffer)),
    unsafe.Pointer(&buf[0]), uintptr(len(buf)*2)); err != nil {
```

Verified against the upstream struct: `golang.org/x/sys/windows@v0.43.0` `types_windows.go:2800-2806` declares `NTUnicodeString.Length` as `uint16` in *bytes* ("should always be even"). The fix holds for every value of `length`:
- `length == 0` or `length == 1` → early return, so `make([]uint16, 0)` and the panicking `&buf[0]` deref are unreachable. (Old `length == 0` guard let `length == 1` through and panicked.)
- `length` even (the only real case) → `len(buf)*2 == length`, exact read.
- `length` odd (contract-impossible) → `len(buf)*2 == length-1 < length`, read stays inside `buf`; `UTF16ToString` consumes only whole units. No partial-unit read, no OOB.
- No overflow: max `length` is 65535, so `len(buf)*2` ≤ 65534.

`GOOS=windows go vet ./pkg/util/process/` passes (test file included). The fix's own comment at lines 178-180 and 184-187 accurately states the invariant.

**2. `service.go` doc-only change — `pkg/service/cmd/service.go:139-178` — accurate.** The added `PID()` docstring (lines 139-142) correctly notes the per-call PEB walk cost on Windows.
