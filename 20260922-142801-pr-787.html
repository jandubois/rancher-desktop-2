the same image ID (one per tag).  If an image without any tags exists, that will

Design Observations ¶

Concerns ¶

  • containerd Images still use a separate always-hash helper (future) Claude Opus 5.5 Codex GPT 6 Astra Gemini 3.5 Flash. Round 1 noted that only two of five kinds used the shared algorithm; four do now. containerdImageMirrorName cannot route through MirrorName as it stands, because its hash puts the namespace first and a valid namespace would pass through unencoded. An always-hash sibling of MirrorName would let the doc state one rule for Images instead of two (I1).
  • The mock controller still uses a third naming scheme (future) Gemini 3.1 Pro Codex GPT 6 Astra Gemini 3.5 Flash. sanitizeKubernetesObjectName (mock/volume_reconciler.go:72, mock/image_reconciler.go:45) replaces only / and :, so a mock Volume named My_Vol_Ume produces an invalid object name. This predates the PR and round 1 recorded it.
  • Tag separation depends on the image ID containing a colon (future) Gemini 3.1 Pro. imageMirrorNames passes the tag as an extra, which MirrorName ignores for a valid input. Docker IDs always include the sha256: algorithm prefix, so this holds today.

Strengths ¶

  • A pass-through name still can never equal a hashed one with extras present, since hashed output always matches <prefix>-<64 hex> and any input of that form is hashed Claude Opus 5.5 Codex GPT 6 Astra Gemini 3.5 Flash.
  • Moby Image mirror names are byte-identical to the merge-base for dangling, single-tag and multi-tag images, so no existing Image mirror is renamed Claude Opus 5.5 Codex GPT 6 Astra.
  • Every containerd container call site (apply, prune, task-start, delete event, resolver scan) passes the namespace as the extra, which avoids the namespace loss round 1 warned a naive swap would cause Claude Opus 5.5 Codex GPT 6 Astra.
