Design Observations ¶

Concerns

  • Substring discrimination is brittle to command-name aliases (in-scope) Codex — IsOurProcess's strings.Contains discriminator (process_windows.go:83) assumes the daemon spells its subcommand one canonical way. The svc/service alias pair breaks that assumption (I1). The docstring already warns about prefix collisions (vm vs vm2); alias spellings are the same class. Matching on the narrowest token that survives every alias (serve), or parsing argv, forecloses the class.

Strengths

  • The hostagent force-stop paths re-check HostAgentPID immediately before each destructive use, including after graceful waits, so a stored PID is never trusted once time has passed. (in-scope) Codex
  • hostAgentPIDFile() is exactly the --pidfile value passed at launch (limavm_lifecycle.go:367,646), an unambiguous per-instance discriminator that cannot match a sibling whose name is a prefix. (in-scope) Claude Codex
  • IsOurProcess is the single PEB-walk implementation in the tree, so the buffer-sizing invariant the Round 2 fix established lives in one place. (in-scope) Claude

Review Process Notes ¶

Skill improvement — Correctness dimension: discriminator must survive every launch spelling. When code identifies a process by matching a substring of its command line — to confirm identity, ownership, or role before a destructive or state-changing action — enumerate every way that process can be launched: command aliases, abbreviated subcommands, a background self-spawn that hard-codes one spelling, and direct foreground invocation. Confirm the discriminator matches each. A guard that matches only the canonical self-spawn spelling silently rejects the same process started through an alias, so a reviewer who verifies only the self-spawn path marks the code clean and misses the gap. Recognize the pattern when a strings.Contains or substring check on argv or a command line gates a kill, signal, or PID-file removal.

[repo] The service command is aliased svc, and serve is directly invocable. rdd's service command registers svc as an alias (cmd/rdd/service.go), and the serve subcommand — the control-plane daemon entry point — is not hidden, so rdd svc serve runs the daemon directly. The normal start path self-spawns it as canonical service serve (pkg/service/cmd/service.go), but a manual rdd svc serve produces a daemon whose command line reads svc serve. When reviewing code that discriminates the control-plane process by its command line, account for both spellings.
