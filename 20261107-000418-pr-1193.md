## Executive Summary

This PR lets a copy or symlink named `rdd-<instance>` select that instance, with `--instance` overriding the name and the name overriding `RDD_INSTANCE`. It routes the service and hostagent re-execs through `instance.Command`, so each child keeps the instance that its parent resolved. The code is correct on every path traced, and the extracted parser behaves like the old one. The Important finding is two comments outside the diff that still say the inherited environment keeps children on one instance.

## Suggestions

S1. **The typed case of an `rdd-<instance>` command decides the instance, so one file can select two instances that share a directory** — `rdd/cmd/rdd/multicall.go:36-39` [Claude Opus 5.5]

```go
	if len(name) < len(prefix) || !strings.EqualFold(name[:len(prefix)], prefix) {
		return ""
	}
	return name[len(prefix):]
```

`instanceFromName` reads `os.Args[0]`, the name as typed, not the file's name. On macOS, one `rdd-dev` copy run as `./rdd-dev` and as `./RDD-DEV` printed `rancher-desktop-dev` and `rancher-desktop-DEV` for `svc paths dir`. A case-insensitive APFS or NTFS volume maps both to one directory, so both names share one PID file. On Windows the interrupt event name (`Local\rdd-<suffix>-…`) differs too, and Microsoft documents event names as case-sensitive (not run here). So on Windows, `RDD-DEV svc status` would fail `IsOurProcess`, delete the PID file (`rdd/pkg/service/cmd/service.go:160-161`), and orphan the `dev` daemon. `RDD_INSTANCE` values that differ only in case already behave this way; the name route reaches it without the user choosing a case.

`rdd/docs/design/README.md:37` says only that the instance name "keeps its case".

Fix: document that the command as typed decides the case. Lowercasing the name's instance would extend case-insensitive matching past the `rdd-` prefix check.

S2. **No unit test checks that `ParseFlag` strips what `Command` prepends, which `lima-controller` depends on** — `rdd/cmd/lima-controller/main.go:24` [Claude Opus 5.5, Gemini 3.5 Flash]

```go
	os.Args = instance.ParseFlag(os.Args)
```

`lima-controller` reaches its `hostagent` branch only when `ParseFlag` strips the `--instance=<suffix>` that `instance.Command` prepends, a dash-led suffix included. No BATS suite runs the standalone binary (bats-lima starts hostagents from the embedded service), and nothing in `rdd/pkg/instance` tests `flag.go`. A regression there fails every hostagent start, so a developer sees it at once. Because the binary is also only a development tool, the test is optional.

Fix: add `rdd/pkg/instance/flag_test.go` with table cases for `ParseFlag` (`--instance=x`, `--instance x`, `--instance=`, a dash-led value) and a case that passes `Command(ctx, "hostagent", "vm").Args` under `RDD_INSTANCE=-x` back through `ParseFlag`, expecting `[<exe> hostagent vm]` with `RDD_INSTANCE` still `-x`.

S3. **`TestInstanceFromName` does not pin the documented cut at the first `.`** — `rdd/cmd/rdd/multicall_test.go:51` [Gemini 3.5 Flash]

```go
		{"instance with extension", "rdd-9.exe", "9"},
```

`rdd/docs/design/README.md:37` says "The instance name ends at the first `.` in the file name", but every case in the table has at most one dot. A switch to trimming `filepath.Ext`, which drops only the last extension, would pass the table and make `rdd-1.2.exe` select `1.2` instead of `1`.

Fix: add `{"instance ends at the first dot", "rdd-1.2.exe", "1"}`.

## Design Observations

### Concerns

- (future) Any binary whose name starts with `rdd-` now selects an instance without saying so. A kept `rdd-old`, or a download saved as `rdd-darwin-arm64`, creates or drives instance `old` or `darwin-arm64`. A debug-level log line naming the instance that the command name chose would make such a mix-up quick to spot. [Claude Opus 5.5]

### Strengths

- (in-scope) `instance.Command` is now the one place where rdd re-executes itself, so the service and every hostagent start on the instance that their parent resolved. Its `--instance=<suffix>` form also passes a dash-led suffix, which the two-argument form rejects. [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.1 Pro, Gemini 3.5 Flash]
- (in-scope) Precedence follows from ordering alone. `main` sets `RDD_INSTANCE` from the name before `ParseFlag` runs, so `--instance` wins without extra logic. [Claude Opus 5.5, Codex GPT 6 Astra]
- (in-scope) `8-instance-name.bats` runs a copy, so it exercises the re-exec on Linux too, where `os.Executable` resolves a symlink back to `bin/rdd`. Because `svc start` waits for this instance's API server, a child on the wrong instance fails the test. [Codex GPT 6 Astra, Gemini 3.1 Pro]

### Skill improvements

- **Prose about a changed mechanism**: when a change alters how a value or decision reaches a component (an inherited environment variable replaced by an explicit argument, a step moved into another process), grep the whole repository, comments outside the diff included, for prose that names the old channel as the reason something works. Such a sentence turns false while none of its lines appears in the diff. This broadens the existing bullet on a changed default or value set.

### Repo context updates

- rdd re-executes itself through `instance.Command`, which puts `--instance=<suffix>` first on the child's command line. An `rdd-<instance>` command name overrides an inherited `RDD_INSTANCE`. On macOS, and for a copy on any OS, `os.Executable` returns the invoked name. So a child started from such a binary without that flag serves the name's instance, not its parent's. Flag any new self-exec (`os.Executable` plus `exec.Command`) that bypasses `instance.Command`.
