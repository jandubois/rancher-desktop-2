Design Observations ¶

Concerns ¶

  • ContainerNamespace mirrors have no steady-state re-apply (future) Codex GPT 5.6 Sol Claude Opus 5. Reconcile's steady-state path processes actions and finalizers only, so a Kubernetes-side delete of a namespace mirror is never repaired until an engine event or a watcher restart. Codex re-raised this at Important after confirming it on a live instance in round 1; it stays a design observation because moby reaches syncContainerNamespace from docker_watcher.go:513 alone and behaves identically, making it a gap rather than a regression. More generally, containerd events repair engine-side change while nothing repairs Kubernetes-side change; a bounded periodic resync closes the class.
  • Containers in a non-DNS1123 namespace are mirrored into a namespace nothing lists (future) Claude Opus 5. applyContainer writes status.namespace: Not_Valid while applyNamespace skips the mirror, so a renderer populating its selector from ContainerNamespace shows those containers nowhere. Giving ContainerNamespace a hashed object name plus a status.name carrying the raw namespace would make every containerd namespace representable and remove the three separate IsDNS1123Subdomain gates.
  • start on a paused container diverges between backends (in-scope) Claude Opus 5. containerd returns nil and records Succeeded (container_actions_containerd.go:169-171) while moby forwards to Docker, which refuses. The inline comment documents the choice, but a UI reading lastAction sees success where nothing changed.
  • A persistently failing event stream restarts the watcher with no backoff (future) Claude Opus 5. defer w.enqueueReconcile() feeds a channel source with no rate limiter, and Reconcile restarts the watcher and returns nil, so each iteration pays a full sync. The moby watcher has the identical shape, so a fix belongs in the reconciler where both backends get it.
  • The Windows containerd pipe name is unscoped (future) Claude Opus 5. instance.ContainerdSocket() returns the well-known \\.\pipe\containerd-containerd. Nothing connects on Windows today, but this is the same hazard as the documented \\.\pipe\docker_engine collision with Docker Desktop, so the socket-bridge work should make it instance-scoped rather than inherit the hazard.

Strengths ¶

  • Subscribing before fullSync (containerd_watcher.go:85-98) is the right order for an event service with no replay, and the comment says why. (in-scope) Claude Opus 5 Codex GPT 5.6 Sol Gemini 3.5 Flash
  • The explicit linuxSignals table is the correct cross-platform direction: moby/sys/signal resolves against the host, and its map is per-GOOS, so the obvious implementation would have shipped a macOS-only bug above SIGTERM. I2 only asks for its range to be completed. (in-scope) Claude Opus 5 Codex GPT 5.6 Sol Gemini 3.5 Flash
  • containerdIOCreator reproduces nerdctl's own reconstruction: cio.TerminalLogURI sets the same Terminal: true config as nerdctl's cio.TerminalBinaryIO for the URIs nerdctl writes, and both refuse a terminal container with no log driver. (in-scope) Claude Opus 5
  • deleteAllOfType strips the finalizer before deleting, so the engine-switch sweep can never forward a delete into the user's containers. (in-scope) Claude Opus 5
  • Every full-sync loop seeds activeNames before the fallible apply, so a transient failure cannot mark a live object stale, done consistently across containers, images and namespaces. (in-scope) Claude Opus 5

Review Process Notes ¶

Skill improvements ¶

  • When a reviewer attaches a reproducer that passes, read what it actually asserts before crediting the finding. A probe that demonstrates something the finding merely assumes (a standard-library behaviour, a third-party function's contract) proves nothing about the code under review, and a green repro block beside a confident finding reads as evidence at a glance. Require the reproducer to fail against the reviewed tree, or to name explicitly which of the finding's steps it does not cover.
  • Treat a probe's result as platform-scoped whenever it calls into a library that selects its data by build tag. A host-run probe against a guest-facing dependency measures the host's variant, so a rejection or acceptance it reports may be an artifact of where it ran rather than what the code does in production.
  • When a reviewer reports that it delegated part of the review to a sub-agent, verify that portion's citations directly rather than accepting the relay. The delegating agent's own verification is one level removed from the tree, and the report attributes the finding to the agent that filed it.

Repo context updates ¶

  • [repo] Deep-review agents run in a fresh worktree where go build ./... fails on pkg/guestagent/guestagent.go's lima-guestagent.gz embed, because that artifact is produced by the build rather than checked in. Treat a claim that "make build passes" from such a worktree as unverified, and scope build verification to go vet/go test on the changed packages or a cross-compiled go test -c.
  • [repo] assert [ … ] is an accepted idiom in this bats suite, used across 32-app-controllers, 33-lima-controllers and 20-service. Do not flag it as a style violation; the project's bats conventions cover run -0, refute_output, piping and variable scoping, and say nothing against it.
  • [repo] moby/sys/signal's SignalMap is per-GOOS, so a signal name resolved on the host is not the number the Linux guest uses, and the darwin map omits the real-time names entirely. Any finding about signal names or numbers must say which side of the host/guest boundary it was measured on; the daemon keeps its own Linux table for exactly this reason.
