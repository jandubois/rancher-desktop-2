S1. cygpath test guard uses is_windows, breaking the PATH test on WSL2 Codex¶
bats/tests/32-app-controllers/kube-context.bats
@test "rdd run prepends the instance bin directory to PATH" {
    # The instance bin directory leads PATH so tools bundled with the
    # instance shadow any global ones for the duration of the command.
    run -0 rdd svc paths short_dir
    bin_dir="${output}/bin"
    if is_windows; then
        # printenv is an MSYS program: its runtime rewrites the inherited
        # PATH into POSIX form, so convert rdd's native path to match.
        run -0 cygpath -u "${bin_dir}"
        bin_dir="${output}"
    fi

    run_e -0 rdd run printenv PATH
    assert_equal "${output%%:*}" "${bin_dir}"

is_windows is true for both MSYS2 and WSL2 (bats/helpers/os.bash), but cygpath is MSYS-only — the helper layer already handles WSL with wslpath (bats/helpers/commands.bash). On a WSL2 runner this new test calls a missing binary before it reaches the PATH assertion. This matches the repo's documented BATS rule: gate an MSYS2-only tool on is_msys, not is_windows.

Fix:

-if is_windows; then
+if is_msys; then
     run -0 cygpath -u "${bin_dir}"
     bin_dir="${output}"
+elif is_windows; then
+    run -0 wslpath -u "${bin_dir}"
+    bin_dir="${output}"
 fi

setupRunEnv sets DOCKER_CONTEXT but leaves DOCKER_CONFIG alone. The daemon writes the rancher-desktop-<instance> context under its own $DOCKER_CONFIG/contexts (docker_context.go:dockerConfigDir), reading the value frozen at daemon-spawn time. So DOCKER_CONFIG=/tmp/isolated rdd run docker ps against a daemon started with the default ~/.docker searches /tmp/isolated and cannot find the context. The common flows (no custom DOCKER_CONFIG, or a consistent one) work; only a mismatch fails.

Fix: optional. Before exec, create or update the instance Docker context in the child's effective DOCKER_CONFIG without changing currentContext, or document that rdd run assumes one DOCKER_CONFIG.

When PATH is unset, os.Getenv("PATH") returns "", leaving a trailing separator (~/.rd2/bin:). POSIX reads an empty segment as the current directory, so the cwd silently enters the executable search path. An unset PATH is rare for an interactive invocation, so this is low risk.

S6. A signal-killed child reports exit 255 instead of 128+signal Claude¶
cmd/rdd/run.go
	command.Stdin = os.Stdin
	command.Stdout = os.Stdout
	command.Stderr = os.Stderr

	err := command.Run()
	var exitErr *exec.ExitError
	if errors.As(err, &exitErr) {
		return &cliexit.Error{Code: exitErr.ExitCode()}
	}
	if err != nil {
		return fmt.Errorf("run %s: %w", args[0], err)
	}
	return nil

When the child dies from a signal, exitErr.ExitCode() returns -1 (the Go os/exec contract), and os.Exit(-1) wraps to 255 on Unix, losing the 128+signal status a shell would propagate. The PR's own comment notes signal handling is not yet wired up, so this is an edge case.

Fix: note the limitation in the existing comment, or on Unix map a signaled exit to 128 + int(ws.Signal()).

Design Observations ¶

Concerns ¶

  • rdd run relies on the App-startup path to publish contexts (future) Codex — both S2 and S3 trace to one root: the one-shot command depends on App startup to publish Docker and Kubernetes contexts into shared config, then reads them back. Building ephemeral configs directly from the instance endpoints would make the command's isolation local and testable and free it from the daemon's frozen DOCKER_CONFIG. Out of scope for this PR.

Strengths ¶

  • The standalone instance kubeconfig is wired symmetrically: writeInstanceKubeConfig sits beside createReplaceKubeContext in manageKubeContext, and removeInstanceKubeConfig beside deleteKubeContext in removeKubeContext, which fires on both the disabled and not-running paths. The file is gone whenever the context entries are. (in-scope) Claude Codex Gemini
  • instanceClusterUser was extracted so the merge path and the standalone-file path share one cluster/user extraction, avoiding duplication. (in-scope) Claude
  • Running the target as a child rather than replacing rdd gives uniform cross-platform exit propagation; the cliexit.Error{Code} plus nil-Err suppression is a minimal way to drop the spurious error line, and run.go:158 is the only nil-Err producer. (in-scope) Claude Codex Gemini
  • DisableFlagParsing with early --help interception and -- escape lets rdd run pass arbitrary flags to the child without absorbing them. (in-scope) Gemini
  • The kubernetes.enabled=true auto-enable resolves through the existing defaulter, keeping one source of truth for the version and retiring the "stable not yet implemented" caveat from #386. (in-scope) Claude

Review Process Notes ¶

Skill improvement: When CLI code wraps or execs a subprocess and propagates its exit status, check the signal-death path. (*exec.ExitError).ExitCode() returns -1 when the child is terminated by a signal, and os.Exit(-1) wraps to 255 on Unix, dropping the shell-conventional 128+signal status. Flag exit-code propagation that forwards ExitCode() directly without handling the signaled case, and recommend mapping a signaled exit to 128 + int(signal) on Unix.

Skill improvement: When code prepends a directory to PATH by concatenating it with the existing value (newDir + sep + os.Getenv("PATH")), check the empty-PATH case. An empty existing value leaves a trailing separator, and POSIX reads an empty PATH segment as the current directory — silently adding the cwd to the executable search path. Flag unconditional PATH concatenation and recommend appending the separator only when the existing value is non-empty.

Repo context update [repo]: go test ./cmd/rdd cannot run in a fresh review worktree: the package embeds pkg/guestagent/lima-guestagent.gz, a build artifact absent from a clean checkout, so the build fails before any test runs. Build the asset (run make) before go test ./cmd/rdd, or verify cmd/rdd logic through the BATS suite and through packages that do not embed the asset (pkg/controllers/... tests run without it).
