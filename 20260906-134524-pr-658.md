- `stopTask`'s two long comments record the alternatives rounds 3 and 4 each re-proposed, the deadline on the post-SIGKILL wait and the early return on `NotFound`, which stops a later reviewer proposing them a third time [Claude Opus 5].
- The `mirrorClient` extraction is a verbatim move. `git show` of `1e9feacb8` and `a314d00b5` shows the four helpers relocated with only the receiver renamed and one "Docker" turned into "the engine" [Claude Opus 5].
- Map-derived status lists are sorted before the apply, ports included, so the apply is stable across reconciles [Gemini 3.5 Flash].

## Review Process Notes

### Skill improvements

- Before launching, run in the lead worktree any verification whose cost scales with the number of commits or files (per-commit builds, a full test suite, a generated-file check), and state the results in the initial prompt with an instruction not to repeat them. Otherwise an agent handed a request to review each commit spends its whole deadline on builds the orchestrator can run once, and a watchdog kill leaves no output at all.
- Run suites and lints from the lead worktree even when the main checkout is at the review SHA when you check. A concurrent session can switch the main checkout's branch mid-run, and the run then reports on a different tree with no error; copy gitignored build inputs into the lead worktree instead. This replaces the current "when the main checkout is clean and sits at the review SHA, run the suite from there".
- Check the merge-base's version of a sentence before filing an intermediate-commit doc inconsistency as a commit-structure finding. Text that predates the series and that a later commit rewrites is inherited staleness, and a finding on it rates the recut for a defect the author did not write.

### Repo context updates

- [repo] UPDATE the entry on `lima-guestagent.gz`: `go build ./...` and `go test ./cmd/rdd` fail in a fresh worktree at `pkg/guestagent/guestagent.go` on the gitignored embed. Copying `rdd/pkg/guestagent/lima-guestagent.gz` from a built checkout makes both pass, and `make lint-rdd` rebuilds it itself, so a full build is available to any agent that copies one file.
- [repo] `make verify-generate` under a Go toolchain newer than `go.mod`'s `go` directive reports 47 added blank-comment lines across nine `containers` applyconfigurations, at `main` too. Run it under `GOTOOLCHAIN=<go directive>` before calling drift the PR's; a PR that claims no drift is judged under the pinned toolchain.
- [repo] UPDATE the BATS entry "Never nest `run` calls": scope the flag to a helper that calls `run` and is invoked under `run` or `try` when the caller then reads `$output` or `$lines`, or when the helper asserts with a bare test instead of a bats-assert primitive. An `assert_*` helper built on `assert_output` and polled by `try` is the convention the next two entries describe, and `try` echoes the captured output and stderr on exhaustion, so the inner diff reaches the log. As written, the entry tells a reviewer to flag the shape the next entry recommends.
- [repo] The containers controller's reconciler writes a default status (`status: unknown`, `path: ""`) to every `Container` it observes, so a mirror another controller creates and then status-applies races that write. The API server rejects a status apply that omits a required field when it arrives first (3 to 5 of 20 back-to-back applies, measured) and accepts it otherwise. ### Design Observations

#### Concerns

1. **Unbuffered log stream return on containerd** `(future)`: Returning a hardcoded 501 (Not Implemented) error for containerd container logs means any UI component depending on WebSocket logs will fail. While marked out-of-scope for this PR, a proxy container log shipper or CRI agent must be scheduled soon to avoid user experience fragmentation.

#### Strengths

1. **Deterministic list sorting for SSA stability**: In `sync_containers_containerd.go:370`, port-mappings are meticulously grouped, and map keys are sorted using `slices.Sorted` before constructing the apply-configuration. This guarantees deterministic order across reconciles, preventing random map iteration from altering `resourceVersion` and triggering infinite reconciler loops.
2. **Subscription before snapshots prevents lost events**: The containerd watcher subscribes to events before running its initial `fullSync` (`containerd_watcher.go:88`). This ensures no events are lost during synchronization, and since the event handlers are fully idempotent, racing events are safely re-applied.

### Testing Assessment

#### Untested Scenarios

1. **Stop timeout label parsing limits and fallbacks**: No automated unit or integration tests exist to verify that the container's stop timeout label (`nerdctl/stop-timeout`) correctly falls back to `defaultStopTimeout` on non-numeric or overflow values. 2. **Container action signal override**: There is no automated test confirming that a custom stop signal specified on the container (e.g., SIGRTMIN+3) is sent instead of SIGTERM during stop actions.
