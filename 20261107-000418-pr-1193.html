Executive Summary ¶

This PR lets a copy or symlink named rdd-<instance> select that instance, with --instance overriding the name and the name overriding RDD_INSTANCE. It routes the service and hostagent re-execs through instance.Command, so each child keeps the instance that its parent resolved. The code is correct on every path traced, and the extracted parser behaves like the old one. The Important finding is two comments outside the diff that still say the inherited environment keeps children on one instance.

S1. The typed case of an rdd-<instance> command decides the instance, so one file can select two instances that share a directory Claude Opus 5.5¶
rdd/cmd/rdd/multicall.go
// or "" when arg0 selects none. The rdd- prefix matches in any letter case, as
// file names do by default on Windows and macOS.
func instanceFromName(arg0 string) string {
	const prefix = "rdd-"
	name := commandName(arg0)
	if len(name) < len(prefix) || !strings.EqualFold(name[:len(prefix)], prefix) {
		return ""
	}
	return name[len(prefix):]
}

// commandName returns argv[0]'s basename cut at the first ".", so rdd-9.exe
// gives rdd-9.
func commandName(arg0 string) string {

instanceFromName reads os.Args[0], the name as typed, not the file's name. On macOS, one rdd-dev copy run as ./rdd-dev and as ./RDD-DEV printed rancher-desktop-dev and rancher-desktop-DEV for svc paths dir. A case-insensitive APFS or NTFS volume maps both to one directory, so both names share one PID file. On Windows the interrupt event name (Local\rdd-<suffix>-…) differs too, and Microsoft documents event names as case-sensitive (not run here). So on Windows, RDD-DEV svc status would fail IsOurProcess, delete the PID file (rdd/pkg/service/cmd/service.go:160-161), and orphan the dev daemon. RDD_INSTANCE values that differ only in case already behave this way; the name route reaches it without the user choosing a case.

rdd/docs/design/README.md:37 says only that the instance name "keeps its case".

rdd/docs/design/README.md

The `RDD_INSTANCE` environment variable (defaults to `2`), the global `--instance` flag, and the command name select the instance. With `RDD_INSTANCE=bats` or `rdd --instance=bats` the service directory becomes `$APPDATA/rancher-desktop-bats` and the short directory becomes `~/.rdbats`. <!-- spellchecker:ignore -->

Similarly the docker and kube contexts (normally `rancher-desktop-2`) become `rancher-desktop-bats`.

Running `rdd` through a symlink or copy named `rdd-<instance>` (`rdd-<instance>.exe` on Windows) works like `RDD_INSTANCE=<instance> rdd`. The `rdd-` prefix matches in any letter case, but the instance name keeps its case. The instance name ends at the first `.` in the file name.

The `--instance` flag takes precedence over the command name, and the command name over the `RDD_INSTANCE` environment variable. So `rdd-3 --instance 2` uses instance `2`, and `RDD_INSTANCE=4 rdd-3` uses instance `3`.

[^profile]: The only exception is the system [deployment profile](profile.md), which applies to all instances.

Fix: document that the command as typed decides the case. Lowercasing the name's instance would extend case-insensitive matching past the rdd- prefix check.

Acknowledged Limitations ¶

Review Process Notes ¶

Skill improvements ¶

  • Prose about a changed mechanism: when a change alters how a value or decision reaches a component (an inherited environment variable replaced by an explicit argument, a step moved into another process), grep the whole repository, comments outside the diff included, for prose that names the old channel as the reason something works. Such a sentence turns false while none of its lines appears in the diff. This broadens the existing bullet on a changed default or value set.

Repo context updates ¶

  • rdd re-executes itself through instance.Command, which puts --instance=<suffix> first on the child's command line. An rdd-<instance> command name overrides an inherited RDD_INSTANCE. On macOS, and for a copy on any OS, os.Executable returns the invoked name. So a child started from such a binary without that flag serves the name's instance, not its parent's. Flag any new self-exec (os.Executable plus exec.Command) that bypasses instance.Command.
