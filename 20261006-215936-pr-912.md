## Executive Summary

Round 2 fixes both round-1 Important findings. The ready mark now waits for the passthrough server, which binds its port before the manager starts, and the reconciler tests index with the production extractor. But the new listener cleanup closes the port when the manager's context ends, before `Shutdown` runs. So nearly every clean stop logs `pass through server failed`, and the manager stops without draining requests in flight. The cross-project membership removal works, but no test pins it.

## Important Issues

I1. **The passthrough listener closes before `Shutdown` runs, so a clean stop logs a server failure and skips the drain** — `rdd/pkg/service/controllers/manager.go:550` [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash]

```go
	context.AfterFunc(listenCtx, func() { listener.Close() })
```

`listenCtx` derives from `mgrCtx` (line 542), so cancelling the manager fires this callback at once. The runnable runs under its runnable group's context instead, which controller-runtime v0.24.1 derives from `context.Background()` (rdd does not set `BaseContext`) and cancels only when `StopAndWait` reaches the LeaderElection group (`pkg/manager/internal.go:578`). By then `Serve` (line 574) has returned `use of closed network connection`, which is not `ErrServerClosed`. The runnable returns an error and skips the wait on `shutdownComplete` (line 577), and the manager finishes stopping while `Shutdown` drains in the background. At the merge-base only `Shutdown` closed the listener.

```go repro
// TestProbePassthroughShutdownLogs counts clean stops that log a server failure.
func TestProbePassthroughShutdownLogs(t *testing.T) {
	const iterations = 50
	logged := 0
	for range iterations {
		var failed atomic.Bool
		logger := funcr.New(func(_, args string) {
			if strings.Contains(args, "pass through server failed") {
				failed.Store(true)
			}
		}, funcr.Options{})
		port, cancel, result := startProbe(t, logger, http.HandlerFunc(func(w http.ResponseWriter, _ *http.Request) {
			_, _ = io.WriteString(w, "ok")
		}))
		resp, err := http.Get(fmt.Sprintf("http://localhost:%d/fake/ep/x", port))
		if err != nil {
			t.Fatal(err)
		}
		_ = resp.Body.Close()
		cancel()
		if err := <-result; err != nil {
			t.Fatalf("mgr.Start returned %v", err)
		}
		if failed.Load() {
			logged++
		}
	}
	t.Logf("%d of %d clean stops logged \"pass through server failed\"", logged, iterations)
}
```

## Design Observations

### Concerns

- **The ready mark now includes a full cache sync, but only when a passthrough controller is registered** (in-scope) [Claude Opus 5.5, Codex GPT 6 Astra]. The passthrough runnable starts in the LeaderElection group, after the Caches, Others and Warmup groups (`internal.go:446-477` in controller-runtime v0.24.1). With the engine, demo or mock controller, ready therefore waits for every informer, including the ComposeProject one that round 1 saw draw a 429 with `Retry-After: 1s`; a lima-only manager marks ready before any cache syncs. Round 1's bind-only patch already made `passthrough.bats` pass 3 of 3, since queued connections wait for `Serve`. Pick one guarantee and state it in the `ReadyAnnotation` doc: drop the wait, or wait for cache sync in every configuration.
- **Membership changes only on observed Container events** (future) [Gemini 3.1 Pro, Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash]. A Docker full sync narrows round 1's concern: it deletes mirrors of containers that no longer exist (`sync_containers.go:62-74`), and those deletes reach this reconciler. What remains is a Container mirror already gone when the reconciler starts, which only the deferred ComposeProject arm can catch by checking stored members against existing Containers. Gemini 3.1 Pro rated it Important; the PR defers that arm, so it stays here.
- **The `com.docker.compose.config-hash` gate excludes the guest's nerdctl** (future) [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash]. `rdd/dependencies.yaml` pins nerdctl v2.1.2, which does not set that label; v2.2.0 adds it. State which engines compose detection supports.

### Repo context updates

- [repo] controller-runtime runs each `manager.Runnable` under its runnable group's context, which derives from `BaseContext` (rdd sets none, so `context.Background()`) and ends only when the stop sequence reaches that group; the LeaderElection group, where a plain `RunnableFunc` goes, stops after Warmup and Others. A resource a runnable owns, such as a listener, must not also be closed by a callback on the context passed to `mgr.Start`, because that context ends first. An error a runnable returns after the stop begins is logged as `error received after stop sequence was engaged` and not returned from `Start`.
- [repo] A Docker full sync deletes every Container mirror whose container no longer exists (`sync_containers.go`), so a container removed while rdd was down produces a delete event at the next start. Code that tracks membership from Container events misses only mirrors already gone before its watch starts.

However, the new passthrough shutdown logic introduces a data race between `context.AfterFunc` and `server.Shutdown`, causing `server.Serve` to return `net.ErrClosed` and abort manager shutdown with an error.

### Findings

#### Critical Issues

None.

#### Important Issues

I1. **`context.AfterFunc` races with `server.Shutdown`, failing manager shutdown** — `rdd/pkg/service/controllers/manager.go:558-575` (important, regression)

```go
	context.AfterFunc(listenCtx, func() { listener.Close() })

	err = mgr.Add(manager.RunnableFunc(func(ctx context.Context) error {
		defer listenCancel()
		defer markReady()
		server := http.Server{
			Addr:     fmt.Sprintf("localhost:%d", scm.passthroughPort),
			Handler:  mux,
			ErrorLog: slog.NewLogLogger(logr.ToSlogHandler(klog.FromContext(ctx)), slog.LevelError),
		}

		shutdownComplete := make(chan struct{})
		go func() {
			defer close(shutdownComplete)
			<-ctx.Done()
			shutdownCtx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
			defer cancel()
			if err := server.Shutdown(shutdownCtx); err != nil {
				log.Error(err, "failed to shutdown pass through server")
			}
		}()

		log.V(2).Info("Starting pass through server", "addr", server.Addr)
		markReady()
		if err := server.Serve(listener); !errors.Is(err, http.ErrServerClosed) {
			return fmt.Errorf("pass through server failed: %w", err)
		}
		<-shutdownComplete

		return nil
	}))
```

When `mgrCtx` cancels during normal manager shutdown, `listenCtx` cancels simultaneously. The `context.AfterFunc` callback runs in an independent goroutine and immediately calls `listener.Close()` (line 558). This races against the shutdown goroutine calling `server.Shutdown(shutdownCtx)` (line 568). If `listener.Close()` closes the socket before `server.Shutdown` sets internal shutdown state, `listener.Accept()` unblocks with `net.ErrClosed` ("use of closed network connection"). Because `server.shuttingDown()` is still false, `server.Serve(listener)` returns `net.ErrClosed`, which does not match `http.ErrServerClosed` (line 573). The runnable returns an error, causing `mgr.Start` to exit with an error and logging failure during clean shutdown (and exiting status 1 in `pkg/external/main.go:121`).

```go repro
// .scratch/test_race.go; run with: go run .scratch/test_race.go
package main

import (
	"context"
	"errors"
	"fmt"
	"net"
	"net/http"
	"time"
)

func runOnce() error {
	ctx, cancel := context.WithCancel(context.Background())
	listenCtx, listenCancel := context.WithCancel(ctx)
	defer listenCancel()

	l, err := (&net.ListenConfig{}).Listen(listenCtx, "tcp", "127.0.0.1:0")
	if err != nil {
		return err
	}
	context.AfterFunc(listenCtx, func() { l.Close() })

	s := &http.Server{}
	errCh := make(chan error, 1)

	go func(runnableCtx context.Context) {
		shutdownComplete := make(chan struct{})
		go func() {
			defer close(shutdownComplete)
			<-runnableCtx.Done()
			sCtx, sCancel := context.WithTimeout(context.Background(), 5*time.Second)
			defer sCancel()
			_ = s.Shutdown(sCtx)
		}()

		err := s.Serve(l)
		if !errors.Is(err, http.ErrServerClosed) {
			errCh <- fmt.Errorf("pass through server failed: %w", err)
			return
		}
		<-shutdownComplete
		errCh <- nil
	}(ctx)

	time.Sleep(10 * time.Millisecond)
	cancel()
	return <-errCh
}

func main() {
	var failures int
	for i := 0; i < 100; i++ {
		if err := runOnce(); err != nil {
			failures++
		}
	}
	fmt.Printf("Failures in 100 runs: %d\n", failures)
}
```

```text repro-output
Failures in 100 runs: 69
```

Fix: Stop the `context.AfterFunc` callback once the runnable starts and takes ownership of `listener`, and allow `net.ErrClosed` alongside `http.ErrServerClosed`.

```diff
-	context.AfterFunc(listenCtx, func() { listener.Close() })
+	stopAfterFunc := context.AfterFunc(listenCtx, func() { listener.Close() })

 	err = mgr.Add(manager.RunnableFunc(func(ctx context.Context) error {
+		stopAfterFunc()
 		defer listenCancel()
 		defer markReady()
...
 		log.V(2).Info("Starting pass through server", "addr", server.Addr)
 		markReady()
-		if err := server.Serve(listener); !errors.Is(err, http.ErrServerClosed) {
+		if err := server.Serve(listener); !errors.Is(err, http.ErrServerClosed) && !errors.Is(err, net.ErrClosed) {
 			return fmt.Errorf("pass through server failed: %w", err)
 		}
```

S1. **`removeComposeMembership` compares membership by UID rather than Name** — `rdd/pkg/controllers/containers/compose/compose_reconciler.go:186-188` (suggestion, regression)

```go
	for _, item := range list.Items {
		if project != nil && item.GetUID() == project.GetUID() {
			continue
		}
```

`removeComposeMembership` checks `item.GetUID() == project.GetUID()` to skip the container's current project. In Kubernetes, `(namespace, name)` uniquely identifies resources; comparing `item.GetName() == project.GetName()` is more direct. Relying on `GetUID()` forced `compose_reconciler_test.go:41-48` to inject synthetic UUIDs into fake client objects. If `item` or `project` lacks a UID (such as unshimmed test clients), `"" == ""` evaluates to true for all items, silently skipping removal from other projects.

Fix: Check `item.GetName() == project.GetName()` (or both name and UID).

```diff
 	for _, item := range list.Items {
-		if project != nil && item.GetUID() == project.GetUID() {
+		if project != nil && (item.GetName() == project.GetName() || item.GetUID() == project.GetUID()) {
 			continue
 		}
```

S2. **Entire reconcileContainer loop wrapped in `retry.RetryOnConflict`** — `rdd/pkg/controllers/containers/compose/compose_reconciler.go:87-172` (suggestion, regression)

```go
func (r *reconciler) reconcileContainer(ctx context.Context, req composeRequest) (ctrl.Result, error) {
	err := retry.RetryOnConflict(retry.DefaultRetry, func() error {
		// Find the object (Container) that triggered the reconcile request.
		var container v1alpha1.Container
		if err := r.Get(ctx, req.NamespacedName, &container); err != nil {
...

		// of, except for the one it is currently associated with.

			return err

			return r.Status().Update(ctx, project)
```

Wrapping the entire function body in `retry.RetryOnConflict` re-executes container reads, project retrieval/creation, and the `removeComposeMembership` listing/updating sequence on every conflict encountered during `r.Status().Update(ctx, project)` (line 170). Only the final `project` read and `Status().Update` need conflict retry.

Fix: Narrow `RetryOnConflict` to wrap only the `Status().Update` call and its preceding `r.Get(ctx, itemKey, project)`.

### Design Observations

#### Concerns

1. **Missing reconciliation on missed container deletions** `(future)`:
   Compose membership updates depend entirely on observing `Container` events (`compose_reconciler.go:277-297`). If a container is deleted while `rdd` is stopped, or if mirror resources are swept (`watch_reconciler.go:449`), no container delete event is dispatched to `compose-reconciler`. Because `ComposeProject` is not swept by `cleanupMirrorResources`, stale container references persist in `Status.Containers` until an active member triggers reconciliation. Periodic reconciliation or checking container existence during `reconcileCompose` would self-heal stale entries.

2. **`com.docker.compose.config-hash` excludes nerdctl projects** `(future)`:
   Line 108 gates project detection on `com.docker.compose.config-hash`. nerdctl did not populate this label until v2.2.0, while the guest environment currently pins nerdctl v2.1.2 (`rdd/dependencies.yaml:56`). Until nerdctl is updated in the guest image, Compose projects started via nerdctl will be ignored.

#### Strengths

1. **Early TCP listener prevents connection-refused races**: Creating the passthrough `net.Listener` prior to `mgr.Start` (`manager.go:554`) allows the kernel backlog to queue connections during the window between CRD establishment and controller cache sync, cleanly resolving the 502/refused errors observed in Round 1.
2. **Idempotent status writes via change tracking**: Calculating `changed` (`compose_reconciler.go:136-162`) before issuing `r.Status().Update` prevents unnecessary status writes and resourceVersion increments on steady-state reconciliation passes.

### Testing Assessment

#### Untested Scenarios

1. **Passthrough server shutdown without error** (Required — *How would a user see it?*: Causes `sharedManager.Start` to return an error on shutdown, leading to process exit code 1 in external controllers and error logs in service daemon):
   `rdd/pkg/service/controllers/manager_test.go:95-136` tests webhook startup order using `probeController`, but `probeController` does not implement `base.PassthroughController`. The passthrough server runnable shutdown path is never exercised in unit tests.
2. **Container project transfer / migration** (Required — *How would a user see it?*: A container re-labeled to a new project could remain duplicated in old projects):
   `compose_reconciler.go:133` calls `removeComposeMembership(ctx, req, project)`. If line 133 is deleted, no test in `compose_reconciler_test.go` fails. A subtest moving a container between projects is required.
3. **`composeConfigFiles` relative path edge case `rel == ".."`** (Optional — *Does the code run only for us?*: Internal path normalization):
   `compose_reconciler_test.go:TestComposeConfigFiles` tests normal relative and absolute paths, but has no test case verifying that a path evaluating to `".."` (e.g. parent directory) remains absolute.
4. **Multi-version selectableField deduplication in `IndexCRDFields`** (Optional — *Does an existing test catch it?*: Informer indexer failure on duplicate registration):
   No test in `field_indexer_test.go` or elsewhere exercises `IndexCRDFields` against a multi-version CRD with identical `selectableFields`.

### Acknowledged Limitations

1. **`HasMembers` condition remains `Unknown/Calculating` after member removal** (`rdd/pkg/controllers/containers/compose/compose_reconciler.go:207-212`):
   When a container member is removed, `HasMembers` is stamped with `Status: Unknown, Reason: Calculating`. The author explicitly defers evaluating whether any members remain to `reconcileCompose` on the WIP branch (`https://github.com/mook-as/rd2/commits/wip/rdd/rdx/compose/v2/`).
2. **Mirror cleanup does not delete `ComposeProject` resources** (`rdd/pkg/controllers/app/engine/controllers/watch_reconciler.go:449`):
   `cleanupMirrorResources` deletes `Containers`, `Volumes`, `Images`, and `ContainerNamespaces`, but leaves `ComposeProject` objects in etcd across engine restarts.
3. **nerdctl compose projects excluded under pinned version** (`rdd/dependencies.yaml:50-61`):
   The gate on `com.docker.compose.config-hash` (`compose_reconciler.go:108`) excludes nerdctl projects until the guest image upgrades nerdctl to v2.2.0+.
