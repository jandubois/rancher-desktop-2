Executive Summary ¶

This PR lets an rdd-<instance> command name select the instance and passes --instance to every re-executed child. Since round 1 it also rejects invalid instance names and every command name except five built-in ones. The round-1 fixes hold. The Important finding follows from the new name check: the standalone rdd that releases publish as rdd.<version>.<platform>.<arch> now exits with an error under that name, and no CI job runs it.

Other ¶

  • multiCallArgs runs before ParseFlag, so kubectl --instance=2 hands the flag to kubectl. The merge-base had the same order; do not re-suggest swapping it in this PR.
  • An empty --instance= is ignored, and rdd falls back to RDD_INSTANCE or 2. The merge-base parser did the same, and 2-instance.bats:34 pins it; do not re-suggest validating the empty value.
  • Do not re-suggest an --instance= pattern in matches_our_instance. Round 1 found that it would make sig_kill_our_leaks kill a service that is still running when a BATS target ends. Separately, is_interesting_process and our_leaked_pids recognize rdd only by the process names rdd and rdd.exe, so they skip the rdd-vampire process that 8-instance-name.bats starts; sig_quit_rdd_service still reaches it through the PID file.
  • Rulings on this PR; do not re-suggest an alternative: reject invalid names rather than lowercase them, on every route; match the rdd- prefix in lowercase only; run only the built-in names, with the dlv debug cost documented; strip only a Windows .exe; document the Linux symlink-target name rather than pass rdd as the child's argv[0]; reject -logs on every OS.

Review Process Notes ¶

Skill improvements ¶

  • Check every producer of a narrowed input: when a change narrows what a program accepts about its own invocation or input (the names it runs under, the extensions it strips, the formats it parses), search the build, packaging and release scripts for every name, path or format that the project itself produces for that program, and run the program under each. A rule tested against the names that a developer types can pass while the file that users download fails.
  • Whole-tree checks see the stage: when the prompt stages dependencies into the agent worktree, name the repo checks that walk the whole working tree, such as license-header or spelling scans, and say that a failure inside the stage says nothing about the change.

Repo context updates ¶

  • UPDATE the entry that says instance.Suffix() returns RDD_INSTANCE with no validation: rdd's main rejects any resolved instance name outside ^[a-z0-9][a-z0-9-]*$ or ending in -logs before a command runs, so a newline, quote or shell metacharacter cannot reach those consumers through the rdd CLI. Suffix() itself still returns the raw value, and the standalone controller binaries do not check it; they fail later, when rdd svc config rejects the name.
  • Releases publish the standalone rdd as rdd.<version>.<platform>.<arch>, plus .exe on Windows (rddArtifactName), and users run it under that name. Flag any change to how rdd reads its own name from argv[0] that would reject it.
  • On Windows, the ~/.rd<n>/bin forwarders (rdd-forwarder) start their target with their own command line unchanged, so the target sees argv[0] exactly as the invoking shell passed it. Any argv[0]-based dispatch on Windows must allow for whatever case and form the shell passes.
