Executive Summary ¶

The PR replaces the Kubernetes error dialog with a general fatal-error dialog that adds a Show Logs button, collapsible details and vertical resizing. Nothing calls it yet; draft #1167 adds the first caller. The new width: max-content in the shared dialog layout widens DenyRoot and UnmetPrerequisites, which ship today. A second, longer message clips the open dialog, because its width stays locked. Nine locales claim to translate "Fatal Error" but still say "Error".

None.

Design Observations ¶

Concerns ¶

  • (in-scope) The page sends its size limits once, from whatever content is laid out at the first dialog/size, so the window's geometry depends on that first layout (I2, S3). Limits recomputed after each dialog/populate and each toggle of the details would follow what the dialog shows. Claude Opus 5.5 Gemini 3.1 Pro Gemini 3.5 Flash
  • (future) Nothing records that the user dismissed an error. Under #1167, each App status change while the FatalError condition holds calls openFatalErrorDialog, so a dialog that the user closed comes back with the next change. Decide whether a closed dialog stays closed before #1167 lands.
  • (future) Troubleshooting.vue:166 sends show-logs, which nothing in the main process handles; the page stays off the nav until the TODO in window/constants.ts:8 restores it. The new error/show-logs handler does that job, so naming its channel show-logs would serve both pages. Claude Opus 5.5

Strengths ¶

  • (in-scope) The page renders the backend's text with v-text, and uses v-clean-html only for the translated version line, which needs &mdash; decoded. Claude Opus 5.5 Codex GPT 6 Astra Gemini 3.5 Flash
  • (in-scope) When the logs folder will not open, the handler logs the error and shows a translated message box that names the folder. Claude Opus 5.5 Codex GPT 6 Astra
  • (in-scope) Returning early when the dialog is open stops a second call from adding another set of openDialog listeners to the same window, which a second call at the merge-base would have done. Gemini 3.1 Pro

Testing Assessment ¶

  • The full Jest suite, run in the lead worktree at the review SHA, passed 60 suites and skipped 1; 555 tests passed and 33 were skipped. FatalError.spec.ts did not print any warnings.
  • No existing test catches I1 or I2, because jsdom does not lay out pages and no e2e spec opens these dialogs. A test would need a rendered Electron harness like the probe in I1, so this review does not ask for one.
  • S1 depends on load state, so it needs a test once #1167 gives the branch a caller. No unit spec mocks BrowserWindow yet, so that test belongs with #1167.
  • The spec's first case asserts placeholders that the user never sees (S2), and its ipcRenderer mock lacks removeListener, so nothing runs setDialogSize. Claude Opus 5.5 Gemini 3.5 Flash
  • No CI job catches I3. CI's Translation Checks job runs i18n-report check --locale=all, which passes, and i18n-report drift reports the stale titles only once the I3 fix restores the @source lines.

Documentation Assessment ¶

  • The layout's header comment (layouts/dialog.vue:1-8) lists the events that a dialog page can use, but not the new dialog/size and dialog/size-constraints. Claude Opus 5.5
  • Every translated messageUnknown drops the final period that the English sentence has. Claude Opus 5.5

Acknowledged Limitations ¶

  • Nothing calls the dialog in this PR, as commit 37726f3b6 says, and #1167 adds the first caller. I2 and S1 through S4 become reachable only then.
  • Do not re-suggest replacing max(size, 100vh - 2.5rem) with min() at FatalError.vue:103. 100vh is the dialog window's own height, not the screen's, and max lets the container fill a window that the user has made taller; the probe in I1 shows the dialog opening at 763x269.

Review Process Notes ¶

Skill improvements ¶

  • When a change's risk shows only once the built UI renders, such as layout, window sizing or CSS in a shared layout, render both revisions in the real runtime with a small harness before launching agents, and put the measurements in the prompt. Agents without the runtime can only reason about layout, and a fix that nobody rendered can break the page that the change was for.

Repo context updates ¶

  • [repo] Dialog windows size themselves from Chromium's preferred size, because openDialog sets enablePreferredSizeMode and resizes the window on preferred-size-changed. Every page with layout: 'dialog' shares the CSS in layouts/dialog.vue, so a sizing rule there changes DenyRoot, UnmetPrerequisites, FirstRun, SudoPrompt, Dialog and the snapshots dialog at once. An intrinsic width on .wrapper removes text wrapping from every page that does not set its own width. Check the rendered size of each page at both revisions.
  • [repo] A locale's # @source must name the English that its value translates. When a change edits en-us.yaml, flag any locale whose @source line changed while its value line did not; that hides the key from i18n-report drift.
  • [repo] UPDATE: the rule that new app-tree .ts, .js and .vue files start with the SPDX header from .ltag/go.txt matched one such file in the tree on 2026-11-06 (pkg/rancher-desktop/main/__tests__/rdd-ctl.spec.ts). Confirm with the maintainers that it is the convention, or drop it.
  • [repo] The repository root's package.json sets "type": "module", so a CommonJS probe saved there, such as an Electron main script, needs the .cjs extension.
