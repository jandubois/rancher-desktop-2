## Executive Summary

The `emits` declaration still fixes the double-fired `change`, and the new unit tests now pin it. But the `parseInt` added this round reopens the `NaNGi` bug by another path. Clearing the field fires `input` with `''`, and `parseInt('')` is `NaN`, which gets past `hasError`, so the store holds `NaNGi` until the next digit. Nothing pins the new `min`/`max`/`step`/`disabled` bindings, and `disabled || isLocked` strips the `locked` style from a locked field.

## Important Issues

I1. **Clearing the number field stores `NaNGi` again** — `pkg/rancher-desktop/components/form/RdSlider.vue:77` [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash]

```vue
        @input="updatedVal(parseInt($event.target.value))"
```

Backspace over the last digit, or a lone `-`, makes Chromium fire `input` with `''`, and `parseInt('')` is `NaN`. `SystemPreferences.hasError` compares with `<` and `>`, so `NaN` passes and `setMemory` stores `'NaNGi'`. The `memoryInGB` computed then throws until the next digit, and a remount in that window (switching tabs and back) fails. The CPU field stores `NaN` the same way.

Round 1's commit passed the raw string, which `'' < 2` sent to the error branch. The merge-base stored `NaNGi` from the same keystrokes on blur, through the double-fired `change`, so against the merge-base the fix is incomplete. `parseInt` also reads `2e1` as 2 and `5.5` as 5.

## Design Observations

### Concerns

- **The error for a typed out-of-range value still reaches nobody** (in-scope) [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.1 Pro, Gemini 3.5 Flash]. The bounds now stop the arrows, but typing `50` into the memory field leaves `8Gi` stored and `50` on screen: `SystemPreferences.updatedVal` emits `error`, and `VirtualMachineHardware.vue:56-57` does not listen. This is the direct-entry half that round 1's I2 left open, and it predates the PR. Routing the emit into the store's `errorStatus`, which `ModalFooter.vue` already renders, would cover it.
- **A malformed quantity still takes down the pane** (future) [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.1 Pro, Gemini 3.5 Flash]. `parseQuantity` throws from the `memoryInGB` computed, and a remount with `NaNGi` stored fails with `Malformed quantity: NaNGi` on Vue 3.5.42. I1's guard closes the known path there; a fallback in the computed would contain the next one.

### Strengths

- **The new tests assert the whole emit list** (in-scope) [Claude Opus 5.5, Codex GPT 6 Astra]. A stray trailing emit cannot hide behind a correct first value, which is how the original bug appeared (`[5]`, then `NaN`).
- **The commit body now names the mechanism** (in-scope) [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.1 Pro, Gemini 3.5 Flash]. The undeclared `change` became a native listener on the component's root, and declaring it removes that listener.

## Review Process Notes

### Skill improvements

- When a round applies a patch that a prior round proposed, review it as new code and read every expression in the receiving component or helper that uses the value the patch changes, not only the attribute or call it targets. A flag that sets one attribute often gates a class or a branch too, and the proposing round verified the patch only against the finding it fixed.
- When the code under review has a test suite that needs installed dependencies, stage them for the agents under `stage/` so they run the suite instead of tracing it. An APFS clone of a 950 MB, 50,000-file `node_modules` took 9 seconds per worktree (measured on this review). First name in the prompt every package script that starts a service or VM. In an earlier review, only the missing dependency tree stopped an agent's run of one.
- Extend the preamble's list of forbidden commands to `git worktree add` (and any other git command that writes to the shared `.git`) and to downloading and running an executable. An agent's worktree shares its `.git` with the user's checkout, and a binary fetched without a checksum runs with the user's privileges.
- Before quoting a full-suite count from the lead worktree, delete the probe files under `.scratch/`. A runner that discovers tests by filename pattern also runs the probes as part of the suite, and they change the totals.

### Repo context updates

- [repo] Jest runs a probe spec saved under a worktree's `.scratch/` with `node --experimental-vm-modules node_modules/jest/bin/jest.js --rootDir . .scratch/<name>.spec.ts`, and a full `jest` run discovers it too, because the config does not exclude dot directories. Keep probes there, outside the tracked tree, and delete them before quoting suite totals.
