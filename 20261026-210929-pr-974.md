## Executive Summary

On Windows, `rdd nerdctl` rewrites host paths through a port of the 1.x stub parser, driven by a table generated from nerdctl's cobra tree. The generator is sound. But the parser rejects or rewrites command lines that #981's pass-through handled: `nerdctl --help`, `-p8080:80`, `top ctr -ef`, `build -f -`, anonymous volumes, and named volumes with a mode. A rooted path such as `\data` still mounts the VM's directory; #504 asked to settle that rule before this PR leaves draft.

I2. **`volumeArgHandler` rejects anonymous volumes and turns named volumes with a mode into bind mounts** — `rdd/pkg/nerdctlstub/translate.go:37-44` [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash]

nerdctl splits a `--volume` spec on `:` (`splitVolumeSpec`). A spec with one part is an anonymous volume at that container path, and a third part is a mode that nerdctl validates itself, warning on options it does not know, such as `z`. The handler instead strips only `:ro` or `:rw` and takes everything before the last colon as the source. So `-v /data` fails. A named volume with any other mode, such as `myvol:/data:z` or `myvol:/data:ro,rshared`, misses the named-volume check, and the container gets a bind mount of `<cwd>/myvol` instead of its volume, without any error. Both forms passed through unchanged under #981.

pflag accepts a value attached to a shorthand, as in `-p8080:80`, `-eFOO=bar` and `-vC:\x:/y`. `parseOption` splits on the first `=` before the lookup, so `-eFOO=bar` becomes the option `-eFOO`, and its bunching loop rejects a value-taking letter anywhere but last. Both paths end in `does not support option`. 1.x has the same bug, but under #981 these commands reached nerdctl unchanged.

The patch also changes how `-namespace=x` parses. The old fallback turned it into `--namespace x`; now it becomes `-n amespace=x`, as it does in pflag.

## Suggestions

S1. **`--build-context` is parsed as a CSV record** — `rdd/pkg/nerdctlstub/translate.go:146-149` [Gemini 3.1 Pro, Codex GPT 6 Astra]

```go
	parts, err := csv.NewReader(strings.NewReader(arg)).Read()
	if err != nil {
		return "", nil, err
	}
```

Each `--build-context` value is one `name=value` pair, which nerdctl splits once at `=` (`parseContextNames` in `pkg/cmd/builder/build.go`). The handler parses it as CSV instead, so `n=C:\a,b` fails with `failed to parse context value "b"`, and the CSV writer can add quotes that nerdctl never removes. Separately, an `oci-layout://` value names a local directory but is in the URN list, so it stays untranslated.

Fix: split once at the first `=`, translate the value without CSV decoding or encoding, and treat the path after `oci-layout://` as a host path.

S2. **Several host-path forms reach the guest untranslated** — `rdd/pkg/nerdctlstub/parse_args.go:354-359` [Codex GPT 6 Astra, Gemini 3.5 Flash, Claude Opus 5.5]

```go

	// restore the 1.x imageImportHandler when a bump brings it back.
	for path, handler := range map[string]commandHandlerType{
		"builder build": builderBuildHandler,
		"container cp":  containerCopyHandler,

```

No positional handler covers `compose cp web:/etc/hosts C:\tmp\hosts`. `run --rootfs C:\rootfs /bin/sh` takes the root filesystem as its first positional. `build --ssh default=C:\key` slips past both path heuristics in `generate/main.go:279-282`, because its usage says "socket or keys". `--cosign-key` is classified as a file path, but nerdctl's usage text also allows a URI, a KMS reference or a Kubernetes secret there, and `--cosign-key=https://example.com/key.pub` becomes `/https:/example.com/key.pub`; #981 passed that through.

Fix: register `containerCopyHandler` for `compose cp`, classify `--ssh` and add `socket` to the usage heuristic, give `--cosign-key` a handler that passes URIs through, and handle `--rootfs` or list it in the doc as unsupported.

S3. **The cleanup code has nothing to clean up** — `rdd/pkg/nerdctlstub/parse_args.go:29-33` [Claude Opus 5.5]

## Design Observations

### Concerns

- **(in-scope)** The parser fails closed. An option missing from the table aborts the command (I1, I3, I5), while #981's pass-through could at worst leave a path untranslated. On an unknown option the stub could instead pass the rest of the command line through unchanged and log it at debug level, which bounds every table gap to "path not rewritten". Stopping at the unknown option, instead of guessing whether it takes a value, keeps the argument shift that the design doc warns about away from later path flags. [Claude Opus 5.5]
- **(in-scope)** `make generate` now needs a container engine on macOS and Windows (`rdd/Makefile:351`), because the generate stage runs only on Linux. The Makefile keeps `generate-typescript` out of `generate` for a similar reason. `generate-nerdctl` could move to `verify-generate`, which CI runs on Linux. [Claude Opus 5.5]
- **(future)** The overlay validation only catches flags whose name or usage text looks like a path, and `--ssh` (S2) slipped past both. A bump could list every value flag that is new since the previous table, so that the classification covers all of them. [Codex GPT 6 Astra]

### Strengths

- Deriving the table from the real cobra tree, with an `extract` stage that fails when nerdctl's `main` package changes shape, removes 1.x's help-text hand patches. [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.1 Pro, Gemini 3.5 Flash]
- The overlay validation works both ways: every entry must name a real flag, and every path-like flag must be classified. `TestTableMatchesGuestNerdctl` ties the table to `dependencies.yaml`. [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash]

Fix: for a single-dash argument, walk its letters. Once a letter maps to a value flag, the rest of the token (minus a leading `=`) is its value, and the next argument is the value only when that rest is empty.

###### Design Observations

###### Concerns

1. **Host path translation decoupled from standard Windows path resolver** (in-scope)
`guestexec.TranslateHostPath` parses paths using string splitting rather than standard Windows path normalization (e.g. `filepath.Abs` or `GetFullPathName`). This causes edge cases like drive-relative paths (`d:foo`) and rooted paths without drive letters (`\data`) to be mishandled or passed through as POSIX paths, diverging from Rancher Desktop 1.x behavior and the design doc.

###### Strengths

1. **AST extraction and reflection generator architecture**
Generating `commandSpecs` by parsing nerdctl's command tree via reflection and AST extraction eliminates fragile help-text scraping and ensures flag classifications stay in sync across nerdctl version upgrades.
2. **Overlay validation gate**
The generator validates that all path-like flags are classified in `pathFlags` or acknowledged in `notPathFlags`, preventing silent regressions when upstream nerdctl introduces new path flags.
