## Executive Summary

The PR replaces the Kubernetes error dialog with a general fatal-error dialog that adds a Show Logs button, collapsible details and vertical resizing. Nothing calls it yet; draft #1167 adds the first caller. The new `width: max-content` in the shared dialog layout widens DenyRoot and UnmetPrerequisites, which ship today. A second, longer message clips the open dialog, because its width stays locked. Nine locales claim to translate "Fatal Error" but still say "Error".

## Important Issues

I1. **The shared dialog layout stops DenyRoot and UnmetPrerequisites from wrapping their text** — `pkg/rancher-desktop/layouts/dialog.vue:66` [Claude Opus 5.5, Gemini 3.5 Flash]

```scss
  min-width: 24rem;
  width: max-content;
  height: fit-content;
```

`openDialog` sizes every dialog window from Chromium's preferred size (`window/index.ts:576`). With `width: max-content` on the shared `.wrapper`, the preferred width becomes the longest unwrapped line, so a dialog page without its own width limit grows until each paragraph fits on one line. DenyRoot and UnmetPrerequisites both have callers in `background.ts` (lines 164 and 233). Dialog, SudoPrompt and FirstRun set their own widths; an earlier run of the same harness, which also opened them, measured each the same at both revisions.

The probe below opens a page from a renderer built at each revision, the way `openDialog` does on macOS. Its stderr lists IPC handlers that the probe does not provide; the output leaves that out.

//   node_modules/.bin/electron probe-dialog-size.cjs dist/app <DenyRoot|UnmetPrerequisites|FatalError|FatalErrorRepopulate>
// It opens the page the way openDialog() in window/index.ts does on macOS and
// prints the settled window size, its maximum width, the number of lines in the
// first paragraph, and where the last button ends.

const os = require('os');
const path = require('path');
const { pathToFileURL } = require('url');

};

protocol.registerSchemesAsPrivileged([{ scheme: 'app', privileges: { secure: true, standard: true } }]);

app.whenReady().then(async() => {
  protocol.handle('app', req => net.fetch(pathToFileURL(path.join(path.resolve(distDir), new URL(req.url).pathname)).toString()));
  const win = new BrowserWindow({
    width: 100, height: 100, show: false, resizable: false, frame: true, ...c.opts,

  win.webContents.on('ipc-message', (_event, channel, arg) => {
    if (channel === 'dialog/load' && c.populate) win.webContents.send('dialog/populate', ...c.populate);
    if (channel === 'dialog/ready') win.show();
    if (channel === 'dialog/size-constraints') { // as openDialog() handles it
      const { width, height } = win.getBounds();
      const pick = (value, current) => (value === 'current' ? current : value);
      if (arg.minSize) win.setMinimumSize(pick(arg.minSize.width, width), pick(arg.minSize.height, height));
      if (arg.maxSize) win.setMaximumSize(pick(arg.maxSize.width, width), pick(arg.maxSize.height, height));
    }
  });
  win.webContents.on('preferred-size-changed', (_event, { width, height }) => {
    win.setContentSize(width, height);
    win.webContents.send('dialog/size', { width, height });
  });

  await win.loadURL(`app://./index.html#${ c.route }`);
  await sleep(2000);
  if (c.repopulate) {
    win.webContents.send('dialog/populate', ...c.repopulate);
    await sleep(2000);
  }
  const layout = await win.webContents.executeJavaScript(`(() => {
    const range = document.createRange();
    range.selectNodeContents(document.querySelector('p'));
    const button = [...document.querySelectorAll('button')].pop().getBoundingClientRect();
    return { lines: range.getClientRects().length, buttonRight: Math.round(button.right), viewport: innerWidth };
  })()`);
  const [width, height] = win.getContentSize();
  const maxWidth = win.getMaximumSize()[0] || 'none';
  console.log(`${ name }: window ${ width }x${ height }, max width ${ maxWidth }, first paragraph ${ layout.lines } line(s), last button ends at x=${ layout.buttonRight } of ${ layout.viewport }`);

});

I2. **A second message leaves the open dialog at the first message's width, clipping its text and buttons** — `pkg/rancher-desktop/pages/FatalError.vue:86` [Claude Opus 5.5, Gemini 3.5 Flash]

```ts
    minSize: { width: 'current', height: 'current' },
    maxSize: { width: 'current', height: 2 ** 30 },
  });
  ipcRenderer.removeListener('dialog/size', setDialogSize);
```

On the first `dialog/size`, the page sets the window's maximum width to its current width and stops listening. When `openFatalErrorDialog` finds the dialog open, it re-sends `dialog/populate` (`window/index.ts:673`). A longer message then needs a wider window, and the maximum width refuses it. The message is cut off, and the Close button ends past the window's right edge, where the user cannot click it. Nothing reaches this branch in this PR, but #1167 calls `openFatalErrorDialog` on every App status change while its condition holds.

I3. **Nine locales claim to translate "Fatal Error" but still say "Error"** — `pkg/rancher-desktop/assets/translations/de.yaml:809-810` [Claude Opus 5.5, Codex GPT 6 Astra]

```yaml
  # @source {appName} Fatal Error
  title: '{appName}-Fehler'
```

The translation commit moved each locale's `@source` for `fatalError.title` to the new English and kept the old value, so the title still means "{appName} Error" in de, es, fr, it, ja, ko, pt-br, vi and zh-hans. `i18n-report drift` compares `@source` with the English, so it reports nothing, and no translation sweep will find the gap.

```bash repro
#!/usr/bin/env bash
# Save as probe-title-drift.sh; run from the repository root: bash probe-title-drift.sh
# Shows that every locale keeps its old "{appName} Error" value under an
# @source that claims "{appName} Fatal Error", and that this silences drift.
set -o errexit -o nounset -o pipefail
dir=pkg/rancher-desktop/assets/translations
echo "English: $(grep -A0 "^  title: '{appName} Fatal Error'" $dir/en-us.yaml)"
for loc in de es fr it ja ko pt-br vi zh-hans; do
  head=$(awk '/^fatalError:/{f=1} f && /^  title:/{print; exit}' $dir/$loc.yaml)
  base=$(git show HEAD~4:$dir/$loc.yaml | awk '/^kubernetesError:/{f=1} f && /^  title:/{print; exit}')
  printf '%-8s head %-32s base %s\n' "$loc" "$head" "$base"
done
echo "--- drift for de with the PR's @source line:"
go -C src/go/i18n-report tool i18n-report drift --locale=de | grep -c fatalError.title || true
cp $dir/de.yaml /tmp/de.yaml.orig
sed -i.bak 's/^  # @source {appName} Fatal Error$/  # @source {appName} Error/' $dir/de.yaml
echo "--- drift for de with @source left at the English it translates:"
go -C src/go/i18n-report tool i18n-report drift --locale=de | grep fatalError.title || true
mv /tmp/de.yaml.orig $dir/de.yaml; rm -f $dir/de.yaml.bak
```

## Suggestions

S1. **Repeat calls to `openFatalErrorDialog` lose an update sent during load, steal focus and pile up listeners** — `pkg/rancher-desktop/window/index.ts:671-675` [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.5 Flash]

```ts
  if (existingWindow) {
    // The dialog is already open; update it, and focus.
    existingWindow.webContents.send('dialog/populate', titlePart, mainMessage, failureDetails);
    restoreWindow(existingWindow);
    return new Promise<void>(resolve => existingWindow.on('closed', resolve));
```

`getWindow` returns the window as soon as `createWindow` registers it, before the page listens. A second call during load sends `populate` to nobody, and the first call's `dialog/load` handler then shows the first message. After load, each call runs `restoreWindow`, which calls `show()` and brings the dialog to the front whenever it lacks focus. Each call also adds a `closed` listener, and Node warns once there are more than ten. Under #1167, every App status change makes such a call.

Fix: keep the latest arguments where the `dialog/load` handler reads them, re-send and refocus only when they change, and share one `closed` promise across calls.

S2. **The "Unknown Error" placeholders never show, and an empty message leaves the dialog blank** — `pkg/rancher-desktop/pages/FatalError.vue:76-80` [Claude Opus 5.5]

```ts
ipcRenderer.on('dialog/populate', (_event, title, message, details) => {
  titlePart.value = title;
  mainMessage.value = message;
  failureDetails.value = details ?? '';
});
```

The window stays hidden until the layout sends `dialog/ready`, and the layout sends it from its own `dialog/populate` handler (`layouts/dialog.vue:37-40`). So the placeholders from lines 66-67 are replaced before anyone sees them, and the spec's first case tests a state that never reaches the screen. A condition with an empty message or no reason, which #1167 could pass, shows an empty message heading over an empty grey box. A probe spec confirmed it. Populated values replace the placeholders, but `populate(undefined, '')` leaves both empty.

Fix: fall back to the placeholders (`title || t.value('fatalError.titleUnknown')`, and likewise for the message), and point the spec's first case at that fallback.

S3. **Opening the details and then shrinking the window hides both buttons** — `pkg/rancher-desktop/pages/FatalError.vue:85` [Gemini 3.1 Pro]

```ts
    minSize: { width: 'current', height: 'current' },
```

The minimum height is the window's height at the first `dialog/size`. Opening "Additional details" grows the window to fit, but the minimum stays put, so the user can drag the window back to its first height. The content no longer fits, and the layout's `overflow: hidden` on `body` (`layouts/dialog.vue:52`) cuts off the bottom. In a probe on macOS, the Close button ended at y=618 in a viewport 285px high.

Fix: let the scroll areas shrink with the window, or raise the minimum height while the details are open; neither approach has been tried.

S4. **On Linux, resizing the dialog moves it back to the top of the main window** — `pkg/rancher-desktop/window/index.ts:578-579` [Claude Opus 5.5]

```ts
    case 'linux':
      resizeWindow(window, width, height);
```

The container's height follows `100vh` (`FatalError.vue:103`), so each resize by the user changes the preferred size and fires `preferred-size-changed`; a probe on macOS saw it fire with the new height. On Linux the handler then calls `resizeWindow`, which puts the window back at the parent's top edge, centred (`window/index.ts:506-509`). FatalError is the first resizable dialog, so no other dialog takes this path. Nobody has run this on Linux.

Fix: for a resizable dialog on Linux, call `setContentSize` instead of `resizeWindow`.

S5. **`RD_OS` and `RD_ARCH` need build-time variables in four files for values that the renderer can compute** — `pkg/rancher-desktop/vue.config.mjs:51-52` [Claude Opus 5.5, Gemini 3.5 Flash]

```js
      'process.env.RD_OS':       JSON.stringify(process.env.RD_OS),
      'process.env.RD_ARCH':     JSON.stringify(process.env.RD_ARCH),
```

Dialog windows run with `nodeIntegration: true` (`window/index.ts:540`), and `pages/Dialog.vue` already imports `os`. So `FatalError.vue` can call `artifactPlatform(os.platform())` and `artifactArch(process.arch)` itself. That removes the edits to `scripts/build.ts`, `scripts/dev.ts` and `scripts/e2e.ts`, and a renderer built some other way no longer compiles `undefined` into the version line.

Fix: compute both values at runtime in `FatalError.vue` and drop the two build-time variables.

S6. **Nothing sends or receives the `kubernetes-errors-details` IPC channel** — `pkg/rancher-desktop/typings/electron-ipc.d.ts:145-148` [Claude Opus 5.5, Gemini 3.5 Flash]

```ts

    titlePart: string,
    mainMessage: string,

```

The entry was already unused at the merge-base. It belongs to the Kubernetes error dialog that this PR retires.

Fix: delete the entry in this PR, which already deletes `KubernetesError.vue`.

S7. **The two new files lack a license header** — `pkg/rancher-desktop/pages/FatalError.vue:1` [Codex GPT 6 Astra]

```vue

```

The review notes for this repository ask new app-tree files to start with the SPDX header in `.ltag/go.txt`, which CI's ltag check does not enforce for `.ts`, `.js` or `.vue` files. Neither `FatalError.vue` nor `pages/__tests__/FatalError.spec.ts` has it. But only one app-tree source file in the tree has it today (`pkg/rancher-desktop/main/__tests__/rdd-ctl.spec.ts`), so confirm the convention with the maintainers before adding it.

Fix: if the convention holds, prepend the three SPDX lines, as `//` comments in the spec and as an HTML comment in the `.vue` file.

S8. **`ipcRenderer.once` would replace the hand-removed listener** — `pkg/rancher-desktop/pages/FatalError.vue:88-90` [Gemini 3.1 Pro]

### Concerns

- **(in-scope)** The page sends its size limits once, from whatever content is laid out at the first `dialog/size`, so the window's geometry depends on that first layout (I2, S3). ### Skill improvements

- When a change's risk shows only once the built UI renders, such as layout, window sizing or CSS in a shared layout, render both revisions in the real runtime with a small harness before launching agents, and put the measurements in the prompt. Agents without the runtime can only reason about layout, and a fix that nobody rendered can break the page that the change was for.

###### Design Observations

###### Concerns

- **Coupled dialog layout styling** `(in-scope)`: Sizing properties like `width: max-content` in `layouts/dialog.vue` affect every dialog globally. Because each dialog page has unique layout requirements (some fixed-width, some dynamic), dialog dimensions and wrapping constraints should be managed by the page components rather than the shared dialog wrapper.

###### Strengths

- **Vue Composition API conversion**: Migrating from the legacy Options API component to `<script setup lang="ts">` simplifies reactive state handling and avoids boilerplate `data()` properties.
- **HTML entity decoding via `v-clean-html`**: Rendering `fatalError.version` through `v-clean-html` properly decodes `&mdash;` without exposing the sink to unescaped injection.
- **Log access button**: Replacing the embedded raw log lines with a dedicated "Show Logs" button invoking `Electron.shell.openPath` prevents user confusion while preserving access to diagnostics.
