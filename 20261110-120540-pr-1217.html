Executive Summary ¶

The PR moves the current-context takeover to the reconcile that turns KubernetesReady True and makes the switch compare inside the write. Both work, and the new tests guard them. But the reachability probe still calls some live clusters dead. It drops tls-server-name, a regression from the merge-base, and ignores environment proxies. It also calls an https server dead when it completes the TLS handshake but fails the request, though #1150 and the PR's own comments count that as alive.

At the merge-base the probe used newProbeHTTPClient, which sets ServerName: cfg.ServerName. reachabilityHTTPClient leaves it out. So a cluster behind an SNI router, addressed by IP with tls-server-name set, now fails the handshake and loses current-context. That part is a regression, since the merge-base probe reached it.

The proxy part predates the PR. Without proxy-url, cfg.Proxy is nil, and an http.Transport with a nil Proxy dials directly. client-go v0.36.4 falls back to http.ProxyFromEnvironment instead (transport/cache.go:142-145), so a cluster that kubectl reaches through HTTPS_PROXY looks dead to the probe.

The reproducer runs client-go and the probe on the same kubeconfig. Without tls-server-name, neither one reaches the SNI router.

// writeKubeconfig makes a one-context kubeconfig current and returns its path.
func writeKubeconfig(t *testing.T, cluster *clientcmdapi.Cluster) string {
	dest := filepath.Join(t.TempDir(), "config")
	cfg := clientcmdapi.NewConfig()
	cfg.Clusters["c"] = cluster
	cfg.AuthInfos["c"] = &clientcmdapi.AuthInfo{}
	cfg.Contexts["c"] = &clientcmdapi.Context{Cluster: "c", AuthInfo: "c"}
	cfg.CurrentContext = "c"
	assert.NilError(t, clientcmd.WriteToFile(*cfg, dest))
	t.Setenv("KUBECONFIG", dest)
	return dest
}

// report compares what kubectl's transport (client-go) and the probe see.
func report(t *testing.T, dest string) {
	restCfg, err := clientcmd.BuildConfigFromFlags("", dest)
	assert.NilError(t, err)
	hc, err := rest.HTTPClientFor(restCfg)
	assert.NilError(t, err)
	resp, err := hc.Get(restCfg.Host + "/healthz")
	if err == nil {
		resp.Body.Close()
	}
	t.Logf("client-go reaches the cluster: %v; probe says reachable: %v",
		err == nil, probeCurrentKubeContext(t.Context(), "c"))
}

func TestReviewProbe_EnvProxy(t *testing.T) {

		w.WriteHeader(http.StatusOK)
	}))
	t.Cleanup(backend.Close)
	// A CONNECT proxy that reaches the cluster, which the host cannot resolve.
	proxy := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		up, err := net.Dial("tcp", backend.Listener.Addr().String())
		if err != nil {
			http.Error(w, err.Error(), http.StatusBadGateway)
			return
		}
		conn, buf, _ := w.(http.Hijacker).Hijack()
		_, _ = conn.Write([]byte("HTTP/1.1 200 Connection established\r\n\r\n"))
		go func() { _, _ = io.Copy(up, bufio.NewReader(buf)); up.Close() }()
		go func() { _, _ = io.Copy(conn, up); conn.Close() }()
	}))
	t.Cleanup(proxy.Close)
	const server = "https://cluster.invalid:6443"

	t.Run("proxy-url", func(t *testing.T) {
		report(t, writeKubeconfig(t, &clientcmdapi.Cluster{Server: server, ProxyURL: proxy.URL, InsecureSkipTLSVerify: true}))
	})
	t.Run("HTTPS_PROXY", func(t *testing.T) {
		t.Setenv("HTTPS_PROXY", proxy.URL)
		report(t, writeKubeconfig(t, &clientcmdapi.Cluster{Server: server, InsecureSkipTLSVerify: true}))
	})
}

func probeServer(t *testing.T, server, proxyURL string) bool {
	destPath := filepath.Join(t.TempDir(), "config")
	t.Setenv("KUBECONFIG", destPath)
	writeContextKubeconfig(t, destPath, "other", server, nil)
	if proxyURL != "" {
		cfg := loadDest(t, destPath)
		cfg.Clusters["other"].ProxyURL = proxyURL
		assert.NilError(t, clientcmd.WriteToFile(*cfg, destPath))
	}
	return probeCurrentKubeContext(t.Context(), "other")
}

func TestReviewProbe_Handshake(t *testing.T) {
	t.Run("live: server demands a client certificate (TLS 1.3)", func(t *testing.T) {
		srv := httptest.NewUnstartedServer(http.HandlerFunc(func(http.ResponseWriter, *http.Request) {}))
		srv.TLS = &tls.Config{ClientAuth: tls.RequireAnyClientCert, MinVersion: tls.VersionTLS13}
		srv.StartTLS()
		t.Cleanup(srv.Close)
		assert.Assert(t, probeServer(t, srv.URL, ""), "a live cluster counted as unreachable")
	})
	t.Run("live: server answers after kubeProbeTimeout", func(t *testing.T) {
		done := make(chan struct{})
		srv := httptest.NewTLSServer(http.HandlerFunc(func(http.ResponseWriter, *http.Request) {
			select {
			case <-done:
			case <-time.After(kubeProbeTimeout + time.Second):
			}
		}))
		t.Cleanup(srv.Close)
		t.Cleanup(func() { close(done) })
		assert.Assert(t, probeServer(t, srv.URL, ""), "a live cluster counted as unreachable")
	})
	t.Run("dead: closed port", func(t *testing.T) {
		srv := httptest.NewTLSServer(http.NotFoundHandler())
		url := srv.URL
		srv.Close()
		assert.Assert(t, !probeServer(t, url, ""), "a dead cluster counted as reachable")
	})
	t.Run("dead: https proxy-url that cannot reach the cluster", func(t *testing.T) {
		proxy := httptest.NewTLSServer(http.HandlerFunc(func(w http.ResponseWriter, _ *http.Request) {
			http.Error(w, "cannot reach upstream", http.StatusBadGateway)
		}))
		t.Cleanup(proxy.Close)
		assert.Assert(t, !probeServer(t, "https://cluster.invalid:6443", proxy.URL), "a dead cluster counted as reachable")
	})
}

Design Observations ¶

Concerns ¶

  • The Docker-context takeover has the overwrite race that this PR fixes for kube (future) Claude Opus 5.5. manageDockerContext (rdd/pkg/controllers/app/engine/controllers/watch_reconciler.go:283-312) reads the current context, probes it, then calls setCurrentDockerContext (docker_context.go:88-96), which overwrites any context except the instance's own. A Docker context that the user picks during the probe is lost. A switchCurrentDockerContext(ctx, expected, name) that compares inside the dockerconfig.Edit callback would apply the same fix.

Strengths ¶

  • Splitting the merge from the check (in-scope) Claude Opus 5.5 Codex GPT 6 Astra Gemini 3.5 Flash. mergeKubeContext runs on every healthy reconcile and checkCurrentKubeContext only on the one that turns KubernetesReady True, so Reconcile shows how often each side effect runs.
  • Comparing inside the write (in-scope) Claude Opus 5.5 Codex GPT 6 Astra Gemini 3.1 Pro Gemini 3.5 Flash. switchCurrentKubeContext checks current-context inside atomicfile.Update, which closes the race with a user's switch without new locking.

Testing Assessment ¶

I ran the package tests at the review SHA in the lead worktree, with a staged module cache, and they passed; go vet is clean. Mutations show that each new unit test guards what it names. Setting InsecureSkipVerify false fails the 401 and unverifiable-certificate subtests; dropping the compare in switchCurrentKubeContext fails Test_CheckCurrentKubeContext_LeavesUserChoiceAlone; calling checkCurrentKubeContext on every healthy reconcile fails Test_Reconcile_AlreadyReady_LeavesCurrentContext.

Two deletions leave the package green. The BATS test "kubernetes controller sets current-context when no healthy context exists" should still catch a removed checkCurrentKubeContext call end to end (reasoned, not run), but nothing catches a removed Proxy: cfg.Proxy (I3).

The new BATS test passed in the BATS (ubuntu-latest, bats-app) job in 20.6s. It would fail at the merge-base, where a refused context was switched within one 15s healthy requeue; that is reasoned from the old code, not run.

The three patches apply in any order, and the package passes under -race with all three applied.

CI on the head: BATS (macos-15-intel, bats-lima) failed at limavm-cli.bats:251 (lima delete --timeout exits with code 4) with client rate limiter Wait returned an error. That is the known rate-limiter flake on the --timeout=1ms tests, in a file this PR does not touch. CodeQL failed (S1). The macOS and Windows bats-app jobs, which run the new BATS test, were still pending when this report was written.

Documentation Assessment ¶

rdd/docs/design/api_app.md:39 says rdd changes the current context only "if it does not exist, or is not working at the time the app is starting". After this PR the check runs whenever Kubernetes becomes ready (enabling it, a version change, a VM restart), and it asks only whether the cluster answers. That sentence could say so. The code comments that disagree with the code are in I2.

Acknowledged Limitations ¶

  • The probe skips certificate verification on purpose. It does not send credentials or read the response body, so a CA that it cannot load must not make a live cluster look dead. Do not suggest restoring CA verification in reachabilityHTTPClient.
  • Internal errors leave current-context alone. probeCurrentKubeContext returns true when it cannot resolve or parse the kubeconfig (kube_reconciler.go:545-547), which errs toward not switching.

Review Process Notes ¶

Repo context updates ¶

  • [repo] CodeQL runs on every PR and reports go/disabled-certificate-check for InsecureSkipVerify: true in non-test code, whatever //nolint:gosec says. CodeQL is not a required check, so its failure does not block a merge, but the alert stays open until a maintainer dismisses it. When a change adds a deliberate skip-verify, check that the PR says the alert will be dismissed and why.
  • [repo] A probe that decides whether the user's own kubeconfig context is reachable must reach the cluster the way kubectl does. That means honoring client-go's proxy-url, its http.ProxyFromEnvironment fallback when proxy-url is unset, and tls-server-name for SNI. Flag a hand-built http.Transport that drops any of them, because each drop makes a live cluster look dead.
