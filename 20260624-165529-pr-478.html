Executive Summary ¶

PR #478 reworks the Playwright startup E2E test to drive a standalone mock controller instead of the deleted JavaScript backend. The daemon runs with all controllers disabled while the mock-controller binary ships every CRD and adds an appReconciler that flips the App's Settled condition to mirror spec.running. No critical issues surfaced; the important findings are latent but cheap to fix.

All three reviewers converged on the mock reconciler and the test-helper rewrite. The two Important findings are real but dormant — one trips only when someone runs rdd set against the mock, the other only when a .fixme suite is re-enabled. Two agent claims were downgraded after verification: a "non-SSA status update" race (no concurrent writer exists in the disabled-controllers mock) and an "endless reconcile loop" (the apiserver dedupes the no-op write), both folded into S1.

beforeExit fires when the event loop empties. A fire-and-forget spawnFile adds a live child handle, refills the loop, and re-arms beforeExit when it drains — an exit-time spin. If the worker exits through process.exit() instead, beforeExit never fires and the handler is dead. Either way the cleanup is unreliable. The test passes, which means the handler is being skipped, not looping — teardownApp does the real cleanup via rdd service delete. Downgraded from the reported Critical: the blast radius is test teardown, and an authoritative cleanup path already exists.

Fix: drop the rdd service stop hook and rely on teardownApp; keep the synchronous controller.kill() under process.on('exit').

Design Observations ¶

Strengths

  • Drives the real status-condition path (in-scope). Codex Claude The mock reconciles the actual App CRD and Settled condition the front end already consumes (store/rdd.ts), rather than the bespoke /v1/backend_state shim the old test polled. The test now exercises production wiring.
  • Generated, single-source CRDs (in-scope). Claude generate-crds.sh writes the mock's crd.yaml from the same controller-gen output as the per-controller copies, marked DO NOT EDIT; the //go:embed keeps the data hand-edit-free. The seen_mock header-once logic is correct.
  • Disabled-controller isolation (in-scope). Codex Running the daemon with --controllers= and then a standalone mock keeps the startup test off real VM and container infrastructure while still driving the RDD API path.

Concerns

  • Literal condition type invites silent drift (future). Codex Claude The mock writes the type string "Settled" and reason "MockController" as literals. A mock-specific reason is fine, but the type should use v1alpha1.AppConditionSettled so a future rename cannot diverge from the set.go and store/rdd.ts consumers. Folds into I1's fix.

Review Process Notes ¶

Repo context updates

  • [repo] In Node-based E2E or test harnesses, flag async work — spawnFile, unawaited promises, any call that adds an event-loop handle — inside a process.on('beforeExit') or process.on('exit') handler. beforeExit re-arms the loop every time that async work drains, producing an exit-time spin, and both hooks are skipped when the runner calls process.exit(). Cleanup that must run belongs in explicit teardown, not a lifecycle hook.
  • [repo] UPDATE the App.Status SSA convention entry: the non-SSA / retry-on-conflict requirement applies only to a controller that runs alongside other App-status writers. A standalone mock started with --controllers= is the sole status writer, so a plain read-modify-write Status().Update is correct there and should not be flagged; a spec-write conflict self-heals through the controller-runtime requeue. Reviewers were flagging the mock under the production-controller rule.
  • [repo] CI lint runs ESLint only (scripts/lint-typescript.ts), not tsc, and Playwright transpiles through esbuild, which strips types without checking them. Type errors that tsc would catch — excess function arguments (TS2554), wrong argument types — ship green and fail silently at runtime. When a function signature changes, grep every caller; do not assume the type checker guards the contract.
