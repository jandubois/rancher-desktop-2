## Important Issues

I1. **Memory conversion crashes on fractional quantities and truncates non-whole-GiB values** — `pkg/rancher-desktop/components/Preferences/VirtualMachineHardware.vue:17-18` [Codex GPT 5.6 Sol, Gemini 3.1 Pro, Claude Opus 4.8]

```ts
  const memoryInBytes = BigInt(quantityToScalar(preferences.value?.virtualMachine?.memory ?? '2Gi'));
  return Number(memoryInBytes / gigaScale);
```

`BigInt()` assumes an integral coefficient. `rdd set virtualMachine.memory=2.5Gi` stores `2.5Gi` verbatim (the CRD pattern at `crd.yaml:133` accepts decimals, and `x-kubernetes-int-or-string` skips canonicalization), so `quantityToScalar('2.5Gi')` reaches `BigInt('2.5')` and throws `SyntaxError`, breaking the whole Preferences render. Codex reproduced this on a live control plane.

Separately, `BigInt` division floors. The defaulter writes `NewQuantity(hostMemory/4, BinarySI)` (`app_defaulter.go:125-132`), so a 10-GiB host defaults to `2560Mi` (2.5 GiB), which line 18 renders as `2`; `availMemoryInGB` (lines 22-23) truncates the same way. The mock's exact 12 GiB hides both paths in CI.

Fix: coerce non-bigint scalars and round the division.

```ts
const scalar = quantityToScalar(preferences.value?.virtualMachine?.memory ?? '2Gi');
const memoryInBytes = typeof scalar === 'bigint' ? scalar : BigInt(Math.round(scalar));
return Math.round(Number(memoryInBytes) / Number(gigaScale));
```

I2. **`transient-preferences.spec.ts` no longer type-checks** — `pkg/rancher-desktop/store/__tests__/transient-preferences.spec.ts:43` [Gemini 3.1 Pro]

```ts
      state.navigation.preferences.application = 'environment';
```

`preferencesNavDefaults` now narrows `navigation.preferences.application` to the literal `'general'` (Application's only uncommented tab), so assigning `'environment'` is a type error. Running the project's own `tsc` reports `error TS2322: Type '"environment"' is not assignable to type '"general"'.` on this line.

It ships green because Jest transpiles without type-checking, `Lint TypeScript` runs eslint rather than `tsc`, and spec files fall outside the `package` build's type-check. No CI job catches it, but the file is red in every contributor's editor and under any future `tsc` gate.

Fix: assign through a widened type, e.g. `(state.navigation.preferences.application as string) = 'environment';`, or exercise a valid tab value.

## Design Observations

**Concerns**

- **The `applicable` platform-filter mechanism is half-built** (future) [Claude Opus 4.8] — `navItemEntry.applicable` is checked by `filterNavItems` (`item.applicable?.() ?? true`), but no live entry sets it, and `navItemResult<T>` types every `T[number]['name']` as present. **Strengths**

- Centralizing nav names, labels, ordering, defaults, and help-key typing in `preferenceConstants.ts` cuts drift between the main and renderer processes. (in-scope) [Codex GPT 5.6 Sol, Claude Opus 4.8]
- The mock reconciler feeds deterministic limits (32 CPUs / 12 GiB), so the e2e asserts real data arriving over the watch rather than element presence alone. (in-scope) [Codex GPT 5.6 Sol, Gemini 3.1 Pro, Claude Opus 4.8]

## Review Process Notes

**Skill improvements**

- When a reconciler watches a resource it also writes, do not flag an unconditional status or spec update as an infinite reconcile loop without checking whether the written content is identical in steady state. The API server suppresses no-op updates (no resourceVersion bump, no watch event), so a reconciler that writes constant values settles once it first converges. Flag the loop only when the written content varies each pass, such as a timestamp, a regenerated field, or unsorted map iteration.

**Repo context updates**

- [repo] The renderer reads Kubernetes Quantity fields from the App spec (for example `virtualMachine.memory`, a `*resource.Quantity` surfaced as `x-kubernetes-int-or-string`) as strings that can carry a decimal coefficient (`2.5Gi`) or a milli-normalized form (`...m`), and `rdd set` stores such strings verbatim. Client code converting a Quantity to a number must handle a non-integer scalar (a bare `BigInt(quantityToScalar(x))` throws on a fractional coefficient) and must not floor the unit division (integer `BigInt` division renders `2560Mi` as `2` GiB). Flag `BigInt()` on a Quantity coefficient and integer-division truncation when reviewing resource-settings UI.
- [repo] UPDATE the "dormant `Body*.vue` nav entries" entry: the Virtual Machine nav item and its Hardware tab are live in `preferenceConstants.ts`, not commented out. Only the Volumes, Network, and Emulation tabs, and the WSL and Container Engine top-level items, remain dormant. Findings in the Virtual Machine Hardware path are live, not latent.

```typescript
const memoryInGB = computed(() => {
  // quantityToScalar will return BigInts in our case; convert it to gigabytes,
  // at which point it should be reasonable for us.

```

If a user manually edits their configuration to set a non-power-of-two fractional memory value like `memory: 4.1Gi`, Kubernetes parses and normalizes this quantity to `"4402341478400m"`. Fix: Safely coerce the value to a `BigInt`.

```diff
-  const memoryInBytes = BigInt(quantityToScalar(preferences.value?.virtualMachine?.memory ?? '2Gi'));
+  const scalar = quantityToScalar(preferences.value?.virtualMachine?.memory ?? '2Gi');
+  const memoryInBytes = typeof scalar === 'bigint' ? scalar : BigInt(Math.round(scalar));
```
(important, gap)

#### Critical Issues

C1. **Nil mutate callback in `controllerutil.CreateOrUpdate` triggers panic** — `rdd/pkg/controllers/mock/hostinfo_reconciler.go:38`

```go
	if _, err := controllerutil.CreateOrUpdate(ctx, r, &hi, nil); err != nil {
		return ctrl.Result{}, err
	}
```

In `hostinfo_reconciler.go:38`, passing `nil` as the `MutateFn` (mutate callback) to `controllerutil.CreateOrUpdate` causes a guaranteed nil pointer dereference and process crash. The `CreateOrUpdate` helper unconditionally executes the callback function to mutate the object before submitting the write to the API server. This panic occurs during any reconciliation attempt where the `HostInfo` resource is processed (both on initial creation and subsequent updates).

**Trace Chain:**
1. Reconcile is triggered: `rdd/pkg/controllers/mock/hostinfo_reconciler.go:28`
2. `CreateOrUpdate` executes: `rdd/pkg/controllers/mock/hostinfo_reconciler.go:38`
3. Callback `f` is called within controller-runtime's `mutate(...)`, dereferencing the `nil` argument and panicking.

```diff
-	if _, err := controllerutil.CreateOrUpdate(ctx, r, &hi, nil); err != nil {
+	if _, err := controllerutil.CreateOrUpdate(ctx, r, &hi, func() error {
+		return nil
+	}); err != nil {
```

#### Important Issues

I1. **Unconditional Status Update causes Infinite Reconcile Loop** — `rdd/pkg/controllers/mock/hostinfo_reconciler.go:43`

```go
	hi.Status.CPUs = 32
	hi.Status.Memory = 12 * 1024 * 1024 * 1024
	if err := r.Status().Update(ctx, &hi); err != nil {
```

In `hostinfo_reconciler.go:43`, `Status().Update` is executed unconditionally. Since the reconciler registers a watch on the `HostInfo` resource (`hostinfo_reconciler.go:54`), updating its status increments its `metadata.resourceVersion` and triggers a new watch event. This causes a loop: each reconcile triggers a status write, which triggers another watch event, resulting in high CPU usage and endless database writes.

**Trace Chain:**
1. `Reconcile` sets status fields: `rdd/pkg/controllers/mock/hostinfo_reconciler.go:40-41`
2. Unconditional write: `rdd/pkg/controllers/mock/hostinfo_reconciler.go:43`
3. Watch triggers: `rdd/pkg/controllers/mock/hostinfo_reconciler.go:54` queues a new request, looping infinitely.

Fix: Guard the status update with a change check.

```diff
-	hi.Status.CPUs = 32
-	hi.Status.Memory = 12 * 1024 * 1024 * 1024
-	if err := r.Status().Update(ctx, &hi); err != nil {
-		logger.Error(err, "Failed to update HostInfo status", "name", hi.Name)
-		return ctrl.Result{}, err
-	}
+	if hi.Status.CPUs != 32 || hi.Status.Memory != 12*1024*1024*1024 {
+		hi.Status.CPUs = 32
+		hi.Status.Memory = 12 * 1024 * 1024 * 1024
+		if err := r.Status().Update(ctx, &hi); err != nil {
+			logger.Error(err, "Failed to update HostInfo status", "name", hi.Name)
+			return ctrl.Result{}, err
+		}
+	}
```

*(important, regression)*

#### Suggestions

S1. **Exclude never-typed fields from PreferenceNavTabDefaults to improve type-safety** — `pkg/rancher-desktop/window/preferenceConstants.ts:72-75`

```typescript
type PreferenceNavTabDefaults = {
  [K in keyof typeof preferencesNavItems as KebabCase<K>]:
  (typeof preferencesNavItems)[K] extends { tabs: readonly ([infer T, string])[] } ? T : never;
};
```

For top-level navigation items that lack sub-tabs (e.g., `"Kubernetes"`), `PreferenceNavTabDefaults` maps the kebab-case key to `never` (yielding `"kubernetes": never`). Because these keys are filtered out of the actual object at runtime, the cast `as PreferenceNavTabDefaults` causes TypeScript to believe that a `"kubernetes"` key exists with a type of `never`. This results in confusing autocomplete and weaker type-checking.

Fix: Exclude keys that evaluate to `never` from the mapped type's keys.

```diff
 type PreferenceNavTabDefaults = {
-  [K in keyof typeof preferencesNavItems as KebabCase<K>]:
+  [K in keyof typeof preferencesNavItems as (typeof preferencesNavItems)[K] extends { tabs: readonly ([infer T, string])[] } ? KebabCase<K> : never]:
   (typeof preferencesNavItems)[K] extends { tabs: readonly ([infer T, string])[] } ? T : never;
 };
```

*(suggestion, enhancement)*
