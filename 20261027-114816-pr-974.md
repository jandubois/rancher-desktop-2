## Review Process Notes

### Skill improvements

- When a change rewrites a command line before another program parses it, test the rewrite against that program's parser on invalid input as well as valid, and flag any input that the program rejected before and accepts after. A front end that reorders tokens or fills in a missing value can turn a rejected command into a different one, and an oracle over valid input alone reports full parity while it happens.

### Repo context updates

- [repo] UPDATE the pending nerdctl-stub parity rule: the stub must also pass on a command line that nerdctl rejects in a form that nerdctl still rejects, because it rebuilds the command line and can turn an error into a different command. Check parser changes against a value flag at the end of the line, a `--` before a dash-led positional, an option whose value is `--`, and invalid command-specific forms such as `cp` between two containers.
