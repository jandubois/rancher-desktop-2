## Design Observations

### Concerns

- **(in-scope) Rejecting a malformed file on removal now leaves our `export PATH` line live, where the merge-base removed it.** [Claude Opus 5.5] With a complete block followed by a stray end marker and `present=false`, the merge-base returned nil and wrote the file without the block; the head returns `ErrMalformedBlock` and leaves the block in place (reproduced at both revisions). This matters most on the paths that never retry. `rdd svc delete` logs a warning (`service.go:546`) and then deletes the bin directory, so the startup file keeps a PATH entry for a directory that is gone. App deletion only logs and releases its finalizer (`reconciler.go:111`). Issue #917 chose rejection on purpose, since stripping around a stray start marker leaves an `export PATH` line live with no marker around it. One alternative keeps both properties. When removing, strip every complete block and still return `ErrMalformedBlock` naming the stray marker. The user is still told, and the next pass returns the same error. Which behavior the unwind paths want is the author's call.
- **(in-scope) The add path loses two fixed points.** [Claude Opus 5.5] Under `front` or `back`, a block followed by a stray end or start marker was stable at the merge-base (nil, no write). It now returns `Malformed` on every pass, so `Settled` stays False until the user edits the file. A nested start was rewritten into a clean block at the merge-base, which also discarded any user lines between the two start markers, so rejecting it is safer. Both follow from the policy #917 asked for, though the issue discusses only removal.

### Strengths

- **(in-scope)** One scan now decides marker pairing for both the managed block and the duplicate collapse. The merge-base used two matchers, `splitByMarkers` and `stripBlocks`, that disagreed about lone markers, which was the root cause of #917. [Claude Opus 5.5, Gemini 3.1 Pro, Gemini 3.5 Flash]
- **(in-scope)** `duplicates: len(blocks) > 1` replaces the indirect `len(after) != len(rest)` comparison. [Claude Opus 5.5]
