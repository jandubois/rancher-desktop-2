## Executive Summary

Preferences now asks before it discards unsaved changes, keeps its shortcuts after a cancelled close, is destroyed on quit, and applies a picked language only on Apply. Those changes work, and tests cover them. One regression remains. The language picker still shows the displayed language, which no longer follows a pick, so after a tab switch it shows English while a Korean pick waits for Apply. The patch binds the picker to the pending preference.

###### Design Observations

###### Concerns

1. **Decoupled locale selection without component model synchronization** `(in-scope)`: Switching the locale on Apply rather than previewing immediately in `store/i18n.ts` is cleaner and eliminates complex window teardown/rollback logic. However, form controls in `components/Preferences/` must bind to `preferences/preferences` rather than global state getters like `i18n/current` (see I1).
2. **Dropping `RD_TEST` e2e bypass in close guard** `(in-scope)`: The old close guard in `window/preferences.ts` explicitly returned early when `(process.env.RD_TEST ?? '').includes('e2e')` was set. Moving `confirmUnload` to `Preferences.vue` dropped this bypass. Current e2e tests do not close dirty Preferences dialogs, but any future e2e test that triggers `page.close()` while changes are dirty will block on `show-message-box`. Consider adding an explicit Playwright e2e test for the discard dialog to validate the flow end-to-end.

###### Strengths

1. Moving discard handling into `Preferences.vue`'s `beforeunload` event handler and delegating to asynchronous `show-message-box` avoids blocking the main-process event loop with `showMessageBoxSync` and confines dirty-state logic to the page that owns it.
2. Destroying Preferences on `mainEvents` `before-quit` mirrors `FirstRun.vue`, preventing cancelled unloads from deadlocking or aborting app shutdown after Steve has already been terminated.
3. Unhooking shortcut registrations on `closed` rather than `close` in `utils/shortcuts.ts` ensures shortcuts remain intact when an unload is prevented by the user.
