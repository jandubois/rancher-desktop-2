## Executive Summary

The PR turns the Container Engine preferences page back on and adds a `currentNamespace` getter that falls back to `default` when nothing is selected. But nothing restarts the resource watches when that fallback changes, so the namespace picker can name one namespace while the list shows another, or all of them. Separately, the Volumes page never watches namespaces, so its picker stays empty on a direct visit, and the PR closes #970, which asks for exactly that.

I1. **The effective namespace changes without restarting the filtered watches** — `pkg/rancher-desktop/store/container-engine.ts:83` [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.5 Flash]

```ts
    if (state.selectedNamespace) {
      return state.selectedNamespace;
    }
    return getters.namespaces.includes('default') ? 'default' : getters.namespaces[0];
```

`resourceFieldSelector` (lines 17-22) reads this getter, and an open watch keeps the selector that it started with (`pkg/rdd-client/cache.ts:207`). Only `setCurrentNamespace` (line 119) and the Kubernetes-namespace plugin (`rddConnection.ts:108`) rewatch. Line 83 now changes the result when the namespace list loads, and an engine switch flips `supportsNamespaces`.

Containers and Images start their watches before namespaces arrive, so on a first visit the list is unfiltered while the picker shows `default`. Picking `default` again does nothing, because the `<select>` does not fire `change` for the option it already shows. At the merge-base the picker was blank, which matched the unfiltered list.

## Suggestions

S1. **A deleted namespace stays selected, and the getter comment is outdated** — `pkg/rancher-desktop/store/container-engine.ts:80` [Gemini 3.1 Pro, Gemini 3.5 Flash, Claude Opus 5.5]

```ts
  /** The currently selected namespace, or undefined if namespaces are not supported */
  currentNamespace(state, getters): string | undefined {
    if (!getters.supportsNamespaces) {
      return undefined;
    }
    if (state.selectedNamespace) {
      return state.selectedNamespace;
    }
```

If the user deletes the selected namespace (`nerdctl namespace rm`), `selectedNamespace` stays set, so the picker goes blank and the lists empty until the user picks another namespace. The merge-base getter returned the stored value unchecked too. The doc comment on line 75 predates the `default` fallback and does not mention it.

Fix: return `selectedNamespace` only while `getters.namespaces` includes it, and update the comment. With I1's plugin, the fallback also rewatches; without it, this fix inherits I1's stale filter.

S2. **Nothing calls `checkSelectedNamespace`** — `pkg/rancher-desktop/pages/Volumes.vue:196-205` [Gemini 3.1 Pro, Claude Opus 5.5, Gemini 3.5 Flash]

```ts
    checkSelectedNamespace() {
      if (!this.supportsNamespaces || !this.namespaces.length) {
        return;

        const defaultNamespace = this.namespaces.includes(K8S_NAMESPACE) ? K8S_NAMESPACE : this.namespaces[0];

```

Nothing calls this method, at the head or the merge-base, yet the PR updates line 203. It prefers `k8s.io`, while the new getter prefers `default`.

Fix: delete the method; the getter now picks the default.

The `currentNamespace` Vuex getter returns a deleted namespace if the user removes it via the CLI, which leaves the UI broken; the getter must validate the selection against the active namespaces.

###### Important Issues

I1. **`currentNamespace` getter skips validation for existing selections** — `pkg/rancher-desktop/store/container-engine.ts:80-82` (important, gap)

```typescript
    if (state.selectedNamespace) {
      return state.selectedNamespace;
    }
```
The `currentNamespace` getter returns `state.selectedNamespace` unconditionally if it is truthy. If a user deletes the currently selected namespace via the CLI (e.g., `nerdctl namespace rm`), the engine reconciler removes the namespace from the system, updating `getters.namespaces`. However, `state.selectedNamespace` retains the deleted value and the getter continues to return it. Pages that rely on `currentNamespace` (Containers, Images, Volumes) will pass this non-existent namespace to their API watches and render empty lists, instead of gracefully falling back to a valid namespace like `default`. 

Fix: Validate the selected namespace against `getters.namespaces` before returning it. 

```diff
   currentNamespace(state, getters): string | undefined {
     if (!getters.supportsNamespaces) {
       return undefined;
     }
-    if (state.selectedNamespace) {
+    if (state.selectedNamespace && getters.namespaces.includes(state.selectedNamespace)) {
       return state.selectedNamespace;
     }
     return getters.namespaces.includes('default') ? 'default' : getters.namespaces[0];
   },
```
*(You will also need to update the `should return selected namespace when available` unit test in `container-engine.spec.ts` to include `namespaces: ['three-per-em']` in its mocked `getters`, as it implicitly tests this broken behavior).*

### [Gemini 3.5 Flash]

###### Executive Summary

PR #1042 restores container engine selection in Preferences, updates radio button margins, and refactors namespace state in the `container-engine` Vuex store. While the UI and preferences binding work well, dynamic namespace fallback in `getters.currentNamespace` fails to trigger `rewatchResources`, causing resource watches to retain stale or empty field selectors. Additionally, `Volumes.vue` does not watch namespaces, leaving its dropdown unpopulated.

---

###### Findings

###### Critical Issues

None.

###### Important Issues

I1. **Resource watchers retain stale `fieldSelector` when `currentNamespace` falls back dynamically** — `pkg/rancher-desktop/store/container-engine.ts:76-84` (important, regression)

```ts
  currentNamespace(state, getters): string | undefined {
    if (!getters.supportsNamespaces) {
      return undefined;
    }
    if (state.selectedNamespace) {
      return state.selectedNamespace;
    }
    return getters.namespaces.includes('default') ? 'default' : getters.namespaces[0];
  },
```

In `store/container-engine.ts:76-84`, `currentNamespace` falls back to `'default'` or `namespaces[0]` when `state.selectedNamespace` is unset. However, `resourceFieldSelector` (`container-engine.ts:17-22`) is evaluated only when a watch starts. On page mount, `watchResources` starts `containers` before `namespaces` finishes loading, so `currentNamespace` evaluates to `undefined`. When `state.namespaces` arrives, `currentNamespace` updates to `'default'`, but `rewatchResources` is never dispatched. The live watch retains `fieldSelector=undefined`, streaming containers across all namespaces despite the UI displaying "default". Similarly, switching engines flips `supportsNamespaces` without restarting active watches.

Fix: Add a Vuex store watch plugin in `store/container-engine.ts` (mirroring `store/rddConnection.ts:111-131`) that observes `getters['container-engine/currentNamespace']` and calls `rewatchResources` whenever the effective namespace changes.

```diff
+export const plugins: Plugin<RootState>[] = [
+  function(store) {
+    let activeNamespace = store.getters['container-engine/currentNamespace'];
+    store.watch(
+      (_state, getters) => getters['container-engine/currentNamespace'],
+      (newNamespace) => {
+        if (newNamespace !== activeNamespace) {
+          activeNamespace = newNamespace;
+          store.dispatch('container-engine/rewatchResources', ['containers', 'images', 'volumes'])
+            .catch(error => console.error('Failed to rewatch resources:', error));
+        }
+      },
+    );
+  },
```

I2. **`Volumes.vue` displays empty namespace selector because it does not watch `namespaces`** — `pkg/rancher-desktop/pages/Volumes.vue:181-191` (important, gap)

```ts
  beforeMount() {
    this.watchResources(['volumes']).catch(error => {
      this.SET_ERROR({ source: 'volumes', error });
    });
  },
```

Unlike `Containers.vue:270` and `Images.vue:76`, `Volumes.vue:182` only watches `['volumes']`. When navigating directly to Volumes without prior visits to Containers or Images, `state.namespaces` is never populated. As a result, `namespaces` (`Volumes.vue:137`) remains empty, leaving the namespace `<select>` dropdown (`Volumes.vue:26-38`) with zero options. Furthermore, `checkSelectedNamespace()` (`Volumes.vue:196-205`), which this PR updated to call `this.setCurrentNamespace`, is dead code that is never invoked from any lifecycle hook or watcher.

Fix: Watch `namespaces` alongside `volumes` in `Volumes.vue` and clean up `checkSelectedNamespace`.

```diff
   beforeMount() {
-    this.watchResources(['volumes']).catch(error => {
+    this.watchResources(['namespaces', 'volumes']).catch(error => {
       this.SET_ERROR({ source: 'volumes', error });
     });
   },
   beforeUnmount() {
-    this.unwatchResources(['volumes']);
+    this.unwatchResources(['namespaces', 'volumes']);
   },
```

I3. **`currentNamespace` getter returns deleted namespace when `selectedNamespace` no longer exists** — `pkg/rancher-desktop/store/container-engine.ts:80-82` (important, regression)

```ts
    if (state.selectedNamespace) {
      return state.selectedNamespace;
    }
    return getters.namespaces.includes('default') ? 'default' : getters.namespaces[0];
```

In `store/container-engine.ts:80-82`, `currentNamespace` returns `state.selectedNamespace` unconditionally without checking whether the namespace still exists in `getters.namespaces`. If a user selects a namespace that is later deleted in containerd, `currentNamespace` continues returning the defunct name. The dropdown in `Containers.vue:30-41` fails to match any option (rendering blank), and `resourceFieldSelector` requests `status.namespace=<deleted>`, keeping resource lists empty until manual user intervention.

Fix: Verify `state.selectedNamespace` exists in `getters.namespaces` before returning it (allowing an exception only while namespaces are loading).

```diff
-    if (state.selectedNamespace) {
+    if (state.selectedNamespace && (!getters.namespaces.length || getters.namespaces.includes(state.selectedNamespace))) {
       return state.selectedNamespace;
     }
```
