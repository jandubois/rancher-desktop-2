I1. **The last commit lists three production CSS changes; the builds show four** — `pkg/rancher-desktop/components/Alert.vue:45-47` [Claude Opus 5.5]

```scss
  .banner-notify {
    margin: 0;
  }
```

Alert puts `banner-notify` on Banner's root, so this rule and Banner's `margin: 15px 0` (`Banner.vue:122`) tie at specificity 0,2,0, and the later rule wins. ## Suggestions

S1. **A shift-click on a row checkbox selects that row alone, not the range** — `pkg/rancher-desktop/components/form/Checkbox.vue:166` [Gemini 3.1 Pro]

```ts
      const click = new CustomEvent('click', customEvent);
```

`clicked()` stops the native click and re-dispatches this event from the checkbox root. `CustomEventInit` has no modifier keys, so `shiftKey` is lost, and SortableTable's `onRowClick` sees `isRange(e)` false (`SortableTable/selection.js:292`). On Images, Containers and Volumes, shift-clicking a row's checkbox toggles that row; shift-clicking elsewhere in the row still selects the range. My jsdom probe saw `CustomEvent shiftKey=undefined` reach the parent, against `MouseEvent shiftKey=true` from a plain element. With `MouseEvent` in place of `CustomEvent`, the probe saw `shiftKey=true`, and the Checkbox and RdCheckbox specs still passed. The code is unchanged from alpha.1 and from upstream master, so this predates the PR; the fork makes it ours to fix.

Fix: dispatch `new MouseEvent('click', customEvent)`, whose init dictionary takes the modifier keys.

**Outcome:** declined for this PR, because the bug predates it, and filed as #932.

S2. **The lint commit leaves ToggleSwitch with a strict-mode type error** — `pkg/rancher-desktop/components/form/ToggleSwitch.vue:33-35` [Claude Opus 5.5]

```ts
  data() {
    return { state: false };
  },
```

`4ea982ec6` dropped the `as StateType` cast, so `state` infers as `boolean`, and `toggle()` assigns it a `StateType` at line 48. Extracted and run through `tsc --strict`, the script block compiles at `af7fe1f3c` and fails at HEAD with `TS2322: Type 'string | boolean | undefined' is not assignable to type 'boolean'`. Nothing type-checks it in CI. The production build did not log a single TypeScript diagnostic, because `happyPackMode` forces ts-loader to transpile only. Editors show the error, though, and a future type check would fail on it.

Fix: annotate the return type, `data(): { state: StateType } {`. It compiles under the same check, and Claude ran eslint on it to confirm it passes the rule that removed the cast.

**Outcome:** fixed as proposed, in `45f5a1ec6`.

S3. **The two composables arrived without their upstream tests** — `pkg/rancher-desktop/composables/useLabeledFormElement.ts` [Claude Opus 5.5]

`af7fe1f3c` imported each component with its tests but took `useCompactInput.ts` and `useLabeledFormElement.ts` without the tag's `useCompactInput.test.ts` (36 lines) and `useLabeledFormElement.test.ts` (135 lines). No RD2 spec exercises `validationMessage`, `requiredField` or `isCompact`. No RD2 caller passes `rules` or `required` today, so the untested paths are also unreached.

**Outcome:** fixed as proposed. `c6a011c1a` adds both tests verbatim, `45f5a1ec6` lints them, and `3cb954131` points their imports at `../` and gives `useLabeledFormElement.spec.ts` the `jest` import from `@jest/globals` that the component specs have.

## Design Observations

### Concerns

- (future) StringList, LabeledInput and TextAreaAutoGrow emit `change`, `blur`, `focus` and `paste` without declaring `emits`, so Vue also binds a parent's listener for those names to the component root, and the listener can fire twice, once for the emit and once for the native event. For StringList's `change` this once corrupted the noproxy setting; `505269b1f` fixed it with an `Array.isArray($event)` guard at each call site (`ContainerEngineAllowedImages.vue:85`, `WslProxy.vue:126`). No caller outside the fork listens for the other events; inside it, only LabeledInput's multiline mode, which RD2 never uses, does. Declaring `emits` in the fork would fix it in one place and let the guards go. [Gemini 3.1 Pro, Gemini 3.5 Flash]
- (future) LabeledSelect validates through `mixins/labeled-form-element.ts` and `mixins/compact-input.ts`, while the imported LabeledInput uses the new composables, so the tree now has two implementations of the same logic. Moving LabeledSelect onto the composables would leave one. [Claude Opus 5.5]
- (future) `cronstrue` and `cron-validator` became direct dependencies only for LabeledInput's `type="cron"` hint, which no RD2 caller uses. Removing cron support from the fork would drop both packages and the Dependabot bumps they will now get. [Consolidator]
- (future) The imported code has defects nothing reaches today. `utils/error.js` exports six names and only `stringify` has a caller. `form/__tests__/Checkbox.spec.ts` imports `Wrapper`, a test-utils v1 type that 2.5.1 no longer exports. TextAreaAutoGrow's border sum is always 0, because `getPropertyValue('borderTopWidth')` needs the kebab-case name and returns `''`. [Claude Opus 5.5, Gemini 3.5 Flash]

**Outcome:** all four declined for this PR, which only imports the components; each is tracked in pending-work.

## Review Process Notes

**Skill improvements**

- When the change's main risk shows only in build output (a production bundle, compiled CSS, generated code), build both revisions in the lead worktree before launch and stage the outputs under `stage/`. Agent worktrees start without installed dependencies, so an agent installs its own, stops short of the build, or reaches outside its sandbox for them.

**Repo context updates**

- [repo] UPDATE the entries saying the production `package` build type-checks bundled files and checks `<script lang="ts">` blocks. `vue.config.mjs` sets ts-loader's `happyPackMode: true`, which forces transpile-only, so the production build does not report TypeScript diagnostics, and a script-block type error ships green. Verify a type claim with `tsc --noEmit` on the extracted script block.
- [repo] Renderer CSS reaches production in two orders. SFC styles compile into `index.css` in webpack module order, while a prebuilt npm bundle using vue-style-loader injects its CSS at startup, after `index.css`; `yarn dev` already uses the compiled order. A change that moves a component's styles from one path to the other (forking or adding a bundled UI dependency) flips every equal-specificity tie between the component's own rule and a parent's override on the component root. Verify by comparing rule order in production builds of both revisions, counting the classes parents pass to a child's root.

### Executive Summary

This change imports the eleven `@rancher/components` components used by the app as a local fork to fix regressions introduced by a stalled upstream package. The imports correctly mirror the `0.3.0-alpha.1` tag and successfully drop the npm dependency. However, pulling these components into the tree exposes pre-existing Vue 3 reactivity and event-handling gaps, most notably missing `emits` declarations that cause native events to double-fire.

### Findings

#### Critical Issues

None.

#### Important Issues

I1. **Undeclared native events cause double-firing** — `pkg/rancher-desktop/components/form/LabeledInput.vue:250-252` (important, gap)

```vue
    onChange(event: Event): void {
      this.$emit('change', event);
    },
```

Vue 3 requires components to declare custom events in `emits`. When an undeclared event shares a name with a native DOM event, Vue attaches the parent's listener as a native event handler on the component's root element. 

In `LabeledInput.vue` and `StringList.vue`, the root element is a `<div>`, and native `change` events from inner `<input>` elements bubble to it. The parent's listener fires once for the bubbled native event, and then a second time when the component explicitly calls `this.$emit('change', ...)`. Similarly, `TextAreaAutoGrow.vue` has a `<textarea>` root element; native `paste`, `focus`, and `blur` events trigger the parent's listeners, which are then fired again by explicit `$emit` calls in the template.

Fix: Add the missing `emits` declarations to each component:
- `LabeledInput.vue`: `emits: ['change', 'update:value', 'blur']`
- `TextAreaAutoGrow.vue`: `emits: ['paste', 'focus', 'blur', 'update:value']`
- `StringList.vue`: `emits: ['change', 'errors', 'type:item']`

#### Suggestions

S1. **CustomEvent discards mouse modifiers** — `pkg/rancher-desktop/components/form/Checkbox.vue:157-166` (suggestion, gap)

```typescript
      const customEvent = {
        bubbles:    true,
        cancelable: false,
        shiftKey:   event.shiftKey,
        altKey:     event.altKey,
        ctrlKey:    event.ctrlKey,
        metaKey:    event.metaKey,
      };

      const click = new CustomEvent('click', customEvent);
```

The standard `CustomEvent` constructor takes a `CustomEventInit` dictionary, which expects a `detail` property. Properties like `shiftKey` and `altKey` belong to `MouseEventInit` and are silently discarded by `CustomEvent`. As a result, the dispatched event loses all modifier key state, breaking any parent listener that checks for them (e.g., for multi-selection).

Fix: Use `MouseEvent` to preserve the modifier keys:
```diff
-      const click = new CustomEvent('click', customEvent);
+      const click = new MouseEvent('click', customEvent);
```

I2. **TextAreaAutoGrow lacks explicit emits declaration, causing duplicate focus and blur triggers** — `pkg/rancher-desktop/components/form/TextAreaAutoGrow.vue:183-186` (important, gap)

```vue
    v-bind="$attrs"
    :spellcheck="spellcheck"
    @paste="$emit('paste', $event)"
    @input="onInput($event)"
    @focus="$emit('focus', $event)"
    @blur="$emit('blur', $event)"
  />
```

`TextAreaAutoGrow.vue` renders a single `<textarea>` root element and sets `inheritAttrs: false`. It emits native DOM event names (`focus`, `blur`, `paste`), but omits an `emits` declaration. In Vue 3, undeclared listeners remain in `$attrs` and are passed to `<textarea v-bind="$attrs">`. When the textarea receives focus or blur, the native DOM event fires the parent listener, and the component's `$emit` fires it a second time. In `LabeledInput.vue:280`, `onBlur` re-emits `blur` on every invocation, propagating duplicate events upstream.

### Design Observations

#### Strengths

- **Clean separation of commits**: Keeping commit `af7fe1f3c` 100% byte-for-byte identical to upstream tag `components-v0.3.0-alpha.1` makes verifying upstream provenance straightforward.
- **Dependency isolation**: Replacing `@rancher/components` CJS bundle with SFC sources allows standard webpack loaders and Sass preprocessing to resolve mixins and variables uniformly with the rest of Rancher Desktop.
- **Cleaned CJS interop**: Replaces hacks like `(Components as any).default ?? Components` in `UpdateStatus.vue` and `LabeledBadge.vue` with direct ES module component imports.

#### Concerns

- **Undeclared emits across forked components** `(in-scope)`: Because `@rancher/components` was originally authored during the Vue 2 to Vue 3 transition and `vue/require-explicit-emits` is disabled in `eslint.config.mts`, multiple forked components (`StringList.vue`, `TextAreaAutoGrow.vue`, `ToggleSwitch.vue`, `Banner.vue`) lack `emits` options. While harmless for custom events like `update:value` or `close`, events matching native DOM event names (`change`, `focus`, `blur`, `paste`) cause Vue 3 to attach duplicate native listeners to root elements (see I1 and I2). Declaring `emits` across all forked components prevents event duplication and state corruption.

### Testing Assessment

- **StringList `@change` listener with native DOM event bubbling**: Required (check 3: user-visible state corruption). An automated test should verify that editing an item in `StringList` emits a `string[]` and does not pass native DOM `Event` objects to the `@change` listener.
- **TextAreaAutoGrow focus/blur event deduplication**: Required (check 3: potential duplicate async triggers). A unit test should verify that triggering focus and blur on `TextAreaAutoGrow` calls parent listeners exactly once.
- All existing 12 test suites (80 tests) across components and modified pages pass cleanly under Jest.

### Documentation Assessment

- No documentation changes required. Commit messages clearly document the forking strategy and the three intentional CSS cascade changes in production builds.

### Commit Structure

- Commits are well structured: `af7fe1f3c` imports upstream sources unmodified, `4ea982ec6` applies repository lint rules, and `bf10ebd67` switches imports over. Keeping the verbatim import commit separate provides clear provenance for future updates.

### Acknowledged Limitations

- **Production CSS cascade changes**: In commit `bf10ebd67`, the author documents that building SFCs from source instead of injecting the npm CJS bundle allows three existing style overrides to take effect in production (Update card text position in `UpdateStatus.vue:202`, snapshot banner margin in `pages/snapshots/create.vue:185`, and table options checkbox label color in `SortableTable/THead.vue:506`). These are intentional and match `yarn dev` behavior.
- **Dependabot configuration divergence**: PR description and prompt confirm that removing `@rancher/components` from `.github/dependabot.yml` intentionally diverges from RD1.
- **Pre-existing LabeledTooltip export bug**: The commit message acknowledges that `LabeledTooltip` was never exported at runtime by `@rancher/components`; importing the SFC directly in `LabeledSelect.vue` fixes this pre-existing gap.
