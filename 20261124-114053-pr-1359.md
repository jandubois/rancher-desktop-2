## Executive Summary

The PR serves `\\.\pipe\docker_engine` through a proxy built on `httputil.ReverseProxy`. The proxy rewrites drive-absolute bind sources in `POST /containers/create` to `/mnt/<drive>` paths, and the shared path helpers now translate `\\?\C:\` paths too. The relay switch broke one thing. An empty create request panics the proxy's handler, so the client gets `EOF` instead of dockerd's 400. And the suite doesn't pin `DisableKeepAlives`, which keeps backend connections from outliving `Serve`. Both come with patches and tests.

I2. **The suite doesn't pin `DisableKeepAlives`, which keeps backend connections from outliving `Serve`** — `rdd/pkg/dockerproxy/proxy.go:85` [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.5 Flash]

With keep-alives on, the Transport keeps an idle connection to dockerd with no timeout, since `IdleConnTimeout` is 0. `Serve`'s shutdown closes only the server, so that connection outlives `Serve`, and each host-switch restart would leave one behind. Setting the flag to false leaves the whole package suite green. The line also lacks a comment, though its neighbour `DisableCompression` has one. If someone deletes the setting, the suite still passes and the proxy doesn't log an error. Only the connections left behind by restarts would show it, so the test is required. ## Suggestions

S1. **Bytes that a client sends before dockerd's 101 never reach dockerd** — `rdd/pkg/dockerproxy/proxy.go:57` [Claude Opus 5.5]

```go
	proxy := &httputil.ReverseProxy{
```

`handleUpgradeResponse` (`reverseproxy.go:841-878` in Go 1.27.4) copies from the hijacked connection and ignores the `bufio.Reader` that `Hijack` returns, so client bytes that net/http had already buffered are lost. RD1's relay forwarded them (`util/reverse_proxy.go:211-224` at `abdf23c74`), and so did the byte bridge. A probe that wrote `early ` right behind an attach request and `late` after the 101 saw the backend echo only `late`, in 3 of 3 runs. The Docker CLI uses moby's Go client, and that client checks for the 101 before it returns the connection (`client/hijack.go:106`, v0.6.3), so the CLI isn't affected.

Fix: add this limit to the package comment, next to the half-close trade-off.

**Outcome:** the `proxy.go` package comment now states this limit (`e94a7993c`).

S2. **The suite doesn't pin `DisableCompression` or the cancelled-context check in `ErrorHandler`** — `rdd/pkg/dockerproxy/proxy.go:92` [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.5 Flash]

```go
		ErrorHandler: func(w http.ResponseWriter, req *http.Request, err error) {
			// net/http cancels the request context when the client goes
			// away or half-closes. The error then only says that the request
			// was cancelled, so it isn't logged.
			if req.Context().Err() == nil {
				logger.Error(err, "Could not forward request to dockerd", "method", req.Method, "path", req.URL.Path)
			}
			http.Error(w, "could not forward the request to dockerd: "+err.Error(), http.StatusBadGateway)
		},
```

Setting `DisableCompression` at line 86 to false, or deleting the context check at line 92, leaves the package suite green. Without the first, the Transport adds `Accept-Encoding: gzip` to a request whose client didn't send one, which changes a response only if dockerd gzips it. Without the second, the proxy logs an error for every client that leaves mid-request. Neither breaks a client, so both tests are optional.

Fix: a backend that asserts the request lacks an `Accept-Encoding` header, and a recording logger in a client-cancellation test.

**Outcome:** `TestServeLeavesAcceptEncodingToClient` pins `DisableCompression` (`e94a7993c`). The cancelled-context check still doesn't have a test, because a test can show that a cancelled request doesn't log an error only by waiting a fixed time first.

S3. **The proxy's server writes panics and accept errors outside logr** — `rdd/pkg/dockerproxy/proxy.go:98-101` [Claude Opus 5.5]
