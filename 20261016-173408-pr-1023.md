## Design Observations

### Concerns

- **(in-scope) A `config.json` that docker loads with a warning now blocks Settled under `front` and `back`.** The plugin edit fails with `ErrMalformed`, and `app_controller.go:721-722` gates on any failure when PATH is managed, so `rdd set --wait` times out until the user repairs a file that docker itself tolerates (`LoadDefaultConfigFile` only warns). At the merge-base, `front` never read `config.json`. Round 2's patch kept this gating on purpose, matching the contract at `app_controller.go:700`. The alternative is to record a permanent plugin-edit failure without gating under every strategy, as `manual` already does. [Claude Opus 5.5]
- **(in-scope) App users still cannot reach the plugin registration.** No code under `pkg/rancher-desktop` writes `application.addPath`, so app installs run `manual`, and `docker compose` stays broken for them on every platform (#899). With the MSI entries restored, standalone `docker-compose` works again on Windows. [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.5 Flash]
- **(future) `rdd svc delete` unwinds with the CLI's `DOCKER_CONFIG`, not the daemon's.** [Claude Opus 5.5, Codex GPT 6 Astra]
- **(future) The shutdown clear can outlast the manager's 10 s grace period**, since `lockTimeout` is 30 s (`service/controllers/manager.go:153`, `dockerconfig.go:29`). [Claude Opus 5.5, Codex GPT 6 Astra]

### Strengths

- **(in-scope)** Classifying by `*fs.PathError` matches docker/cli's `load()`. `load()` wraps open failures with `%w`, read failures reach it through the JSON decoder, and every other error comes from parsing. docker/cli saves through a temp file and a rename (`configfile/file.go:206,242`), so a half-written save cannot look malformed. `config.go` and `configfile/file.go` are byte-identical between docker/cli v29.8.2, which the PR pins, and v29.9.0, which `main` now pins. [Claude Opus 5.5, Codex GPT 6 Astra]
- **(in-scope)** `ErrMalformed` is the only `%w` operand, so `permanentPathError` reads it as one cause, and a malformed `config.json` beside a startup file that fails on I/O stays repairable. [Codex GPT 6 Astra, Claude Opus 5.5]

I2. **Lock wait escapes probe cancellation and blocks shutdown** — `rdd/pkg/controllers/app/engine/controllers/watch_reconciler.go:313`

```go
		if !healthy && probeCtx.Err() == nil {
			if err := setCurrentDockerContext(r.watcherCtx, contextName); err != nil {
				log.Error(err, "Failed to set current Docker context", "context", contextName)
			}
		}
```

The `manageDockerContext` goroutine creates `probeCtx` (via `context.WithCancel(r.watcherCtx)`) so that `removeDockerContext` can interrupt it during shutdown or endpoint changes. However, if the probe finishes and proceeds to write the context, it passes `r.watcherCtx` to `setCurrentDockerContext`. 

Because `dockerconfig.Edit` imposes a 30-second `lockTimeout`, if another instance holds the lock, this call will block for up to 30 seconds. Calling `r.contextProbeCancel()` from `removeDockerContext` cancels `probeCtx` but leaves `r.watcherCtx` untouched, so the lock wait is not interrupted. `removeDockerContext`'s `Wait()` blocks until the 30-second timeout expires, which outlasts the manager's 10-second graceful shutdown and leaks the context.

Fix: Pass `probeCtx` so that the lock wait inherits the cancellation.
```diff
-			if err := setCurrentDockerContext(r.watcherCtx, contextName); err != nil {
+			if err := setCurrentDockerContext(probeCtx, contextName); err != nil {
```
