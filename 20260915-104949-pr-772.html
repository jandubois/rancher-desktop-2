But #651 pairs that name with status.name, which ContainerNamespace still lacks, so a hashed mirror records nothing that names its namespace (I1). Design Observations ¶

Concerns ¶

  • Keep the mirror's object name out of the client contract (in-scope) Claude Opus 5. Clients can reach a mirror only by recomputing cns- plus SHA-256. The new BATS test does; the webhook and the renderer do not (S4). A selectable status.name, as Volume has, lets every consumer query by the engine's name and leaves the naming rule free to change (I1).
  • The commit message overstates the change (in-scope) Claude Opus 5. "Matches the new API where we hash invalid names" covers the naming half of #651's ContainerNamespace contract, not status.name or status.labels. "Fix containerd namespace mirroring" presents a reversal of documented behavior, from skip to hash, as a bug fix, and the doc, field comments and test that described the skip stay in place (I2, I3).

Strengths ¶

  • One helper names the mirror everywhere (in-scope) Claude Opus 5 Codex GPT 5.6 Sol. Apply, remove and the full-sync keying all call containerdNamespaceMirrorName (rdd/pkg/controllers/app/engine/controllers/sync_namespace_containerd.go:43, 75, 88), so apply and prune agree on every name, and removeNamespace drops its validity guard.
  • A name kept verbatim is always admissible (in-scope) Claude Opus 5. The check is the one the API server applies to custom-resource names (NameIsDNSSubdomain in apiextensions-apiserver v0.36.4), and a hashed name is 68 characters.
  • The new test proves the mirror exists before waiting for its deletion (in-scope) Claude Opus 5, which avoids the vacuous wait --for=delete the neighbouring test's comment warns about.
