// StopWithWait sends a shutdown signal to the service. If wait is true, it blocks
// until the process exits or a timeout expires.
func StopWithWait(wait bool) error {
	if !Running() {
		return fmt.Errorf("%q control plane is not running", instance.Name())
	}

	pid := PID()
	// Try graceful shutdown first. On Unix, Kill already sends SIGTERM which
	// triggers the Go signal handler. On Windows, Kill uses TerminateProcess
	// which bypasses all handlers, so we send Interrupt (CTRL_BREAK_EVENT)
	// first to let the service run its shutdown path (shutdownAllHostagents).
	//
	// On Unix, Interrupt (SIGINT) always succeeds for a valid PID, so the
	// Kill fallback never fires. On Windows, Interrupt uses
	// GenerateConsoleCtrlEvent, which fails when caller and target lack a
	// shared console; Kill (TerminateProcess) then bypasses graceful shutdown.
	// Hostagents survive in their own process groups and self-heal on the
	// next service start via killOrphanedHostagent.
	if err := process.Interrupt(pid); err != nil {
		if err := process.Kill(pid); err != nil {
			return fmt.Errorf("failed to stop %q control plane with pid %d: %w", instance.Name(), pid, err)
		}
	}

Running() calls PID() (line 404); StopWithWait then reads PID() again (line 408). The new identity guard makes PID() return PIDNotFound (== 0, line 137) and delete the file whenever IsOurProcess fails. If the service exits or its PID recycles between the two reads, pid is 0, and process.Interrupt(0) runs GenerateConsoleCtrlEvent(CTRL_BREAK, 0) (process_windows.go:36-38) — group 0 signals every process sharing the caller's console, killing the rdd CLI and terminal. The post-crash recycled-PID case is already caught (Running() returns false), so the live trigger is a narrow TOCTOU; the blast radius is the STATUS_CONTROL_C_EXIT this PR exists to prevent.

func (r *LimaVMReconciler) signalHostagent(name string) bool {
	r.instanceStatesMu.RLock()
	state, ok := r.instanceStates[name]
	r.instanceStatesMu.RUnlock()
	if !ok || state.cmd == nil || state.cmd.Process == nil {
		return false
	}
	// Once procExited is closed, cmd.Wait() has released the OS process handle
	// and the PID may be reused; signalling it could deliver CTRL_BREAK to an
	// unrelated console process on Windows. While it is open the handle is
	// normally still held; cmd.Wait() releases it just before closing the
	// channel, leaving a brief window.
	select {
	case <-state.procExited:
		return false
	default:
	}
	return process.Interrupt(state.cmd.Process.Pid) == nil
}

Review Process Notes ¶

Skill improvements ¶

  • When a function signals or terminates a process by numeric PID, check whether the underlying OS primitive treats 0 or a negative value as a broadcast or process-group wildcard rather than a single target. POSIX kill(0, ...) and kill(-1, ...) reach the caller's process group or every permitted process, and Windows GenerateConsoleCtrlEvent(evt, 0) signals every process sharing the caller's console. Trace every path that supplies the PID, including "not found" sentinels: when the sentinel equals 0 (or another wildcard), a lookup miss silently becomes a broadcast that can kill the caller and its console. Flag any signal or kill wrapper that forwards an externally derived PID without rejecting non-positive values.
