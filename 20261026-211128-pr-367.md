## Executive Summary

This round reviews the redesigned resolver, which tries the embedded kubectl, then the cache, then a download of the patch release that `stable-<minor>.txt` names. The download path is sound. Three defects need fixing. The cluster probe ignores kuberc's `credentialPluginPolicy` and runs exec plugins that the user denied. The marker lookup shares the 5-minute download timeout, so a mirror that drops packets adds 30 s to every out-of-skew call. And `cmd_service.md` now calls the kubeconfig the service settings file.

## Critical Issues

C1. **The cluster probe runs exec credential plugins that kuberc denies** — `rdd/pkg/kuberlr/resolver.go:138-142` [Codex GPT 6 Astra]

```go
	cf, err := parseKubeConfigFlags(args)
	if err != nil {
		return nil, err
	}
	return cf.ToRawKubeConfigLoader().ClientConfig()
```

kubectl v1.36.4 reads the user's kuberc by default and applies its `credentialPluginPolicy` (DenyAll or an allowlist) through `ConfigFlags.WrapConfigFn` before it contacts a cluster. The probe builds its config with `ToRawKubeConfigLoader().ClientConfig()`, which skips that wrap, and client-go treats an empty policy as AllowAll (client-go `exec.go:582`). So every cluster-bound `rdd kubectl` runs the kubeconfig's exec plugin before kubectl refuses it. The policy exists to stop a kubeconfig from running arbitrary commands, and a user who set DenyAll for an untrusted kubeconfig loses that protection. At the merge-base only the embedded kubectl ran, and it honors the policy.

## Suggestions

S1. **Attached shorthand values such as `-ojson` set the probe's server** — `rdd/pkg/kuberlr/resolver.go:157-159` [Codex GPT 6 Astra]

```go
	cf := genericclioptions.NewConfigFlags(true)
	cf.AddFlags(fs)
	return cf, fs.Parse(args)
```

The flag set binds only kubectl's connection flags and lets pflag skip unknown ones. For an unknown shorthand with an attached value, pflag skips one character and parses the rest as more shorthands. So `get pods -ojson` sets `-s` (`--server`) to `on`, and `-ojsonpath={.items}` sets it to `onpath={.items}`; I confirmed both by calling `parseKubeConfigFlags`, and `-o json` and `-oyaml` parse correctly. The probe then fails against host `on` and the embedded kubectl runs, so `-ojson`, a common scripting form, never gets a matching kubectl. `isClientOnly` builds the same flag set.

Fix: bind the value-taking shorthands that kubectl commands use (at least `-o`, `-l`, `-f`, `-c`) so pflag consumes their values, or parse with the selected kubectl command's own flags.

S2. **The cache root is classic Rancher Desktop's own directory** — `rdd/pkg/kuberlr/cache.go:51` [Gemini 3.1 Pro, Claude Opus 5.5]

```go
	return filepath.Join(cache, "rancher-desktop")
```

`os.UserCacheDir()/rancher-desktop` is RD1's cache directory on macOS and Linux, and RD1's whole app home on Windows (`%LOCALAPPDATA%\rancher-desktop`), per RD1's `src/go/rdctl/pkg/paths`. An RD1 factory reset or uninstall deletes it, along with this "rdd-wide" root that the doc invites future consumers into. `guestdeps.DefaultCacheDir` avoids the problem. Its comment asks for a directory clear of the app's cache and of every instance directory, and it uses `rancher-desktop.guest-deps`.

Fix: use a dotted name such as `rancher-desktop.cache`, which `instance.Name()` cannot produce either.

## Design Observations

### Concerns

- **The probe runs exec credential plugins, and a cached kubectl runs them again** `(future)` [Claude Opus 5.5] — client-go v0.36.4 starts the plugin with `exec.Command` and hands it stdin when the session is interactive (`exec.go:457-462`), so the 2-second probe timeout does not bound a login prompt. An out-of-skew cluster runs the plugin twice per call, once for the probe and once in the exec'd kubectl. C1's fix keeps the probe inside the user's policy but leaves this cost; setting `StdinUnavailable` on the probe's `ExecProvider` would at least keep prompts out of the probe.
- **The resolver rebuilds part of kubectl's configuration setup** `(in-scope)` [Codex GPT 6 Astra] — C1 (kuberc policy) and S1 (shorthand parsing) both come from re-creating a subset of what kubectl derives from its own command tree. Each fix patches one piece; kuberc aliases and defaults are the next pieces that the probe would miss.
- **Pre-GA servers warn on every call** `(future)` [Claude Opus 5.5] — on 2026-10-26, `stable-1.38.txt` returned 404 while `latest-1.38.txt` named `v1.38.0-alpha.2`. A `latest-` marker goes stale after GA (`latest-1.35.txt` still names `v1.35.0-rc.1`), so it could serve only as a fallback when `stable-` returns 404.
- **Downloads are not retried** `(future)` [Claude Opus 5.5] — `rdd/pkg/guestdeps` and `scripts/lib/download.ts` retry transient network failures; here one reset during the 50 MB transfer exits non-zero. That suits an interactive command, but S4's test then depends on one clean transfer.

### Strengths

- **The redesign closes round 1's vendor-patch concern** `(in-scope)` [Codex GPT 6 Astra] — `latestPatch` works from the server's minor, so a `v1.34.7-gke.500` server resolves through `stable-1.34.txt` to a published patch; Codex ran that case.
- **`rdd ctl` skips the probe** `(in-scope)` [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.1 Pro, Gemini 3.5 Flash] — `ctlAction` calls `SkipResolver()` before `kubectlAction`, so the embedded control plane path stays off the network.
- **Download verification** `(in-scope)` [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash] — streaming sha512 with size limits, a temp-file-then-rename publish, and a check that the marker's major and minor match the server's.
- **The fake mirror logs request paths** `(in-scope)` [Claude Opus 5.5] — the BATS tests assert which URLs the resolver fetched, not only the outcome.

## Review Process Notes

### Skill improvements

- When code re-creates part of a library's or tool's setup instead of calling its constructor (building a client from parsed flags, a config loader, a transport), list what the full setup applies, such as config wrappers, user preferences and policy hooks, and check which of them the partial copy drops. A dropped security policy costs the most, and nothing in the copied code shows its absence.
- When a doc or comment change renames a file or identifier, check what the named target holds, not only that it exists. A reference that resolves to a real file with a different purpose passes a name check and misleads more than a dangling one.

### Repo context updates

- [repo] The pinned kubectl applies kuberc preferences by default (`KUBECTL_KUBERC` gate, beta), including `credentialPluginPolicy`, which it installs through `ConfigFlags.WithWrapConfigFn`. Code that builds a `rest.Config` from `genericclioptions.ConfigFlags` outside kubectl's own command constructor must apply that policy and call `ToRESTConfig()`; `ToRawKubeConfigLoader().ClientConfig()` skips the wrap, and client-go then runs any exec plugin.
- [repo] clientcmd reads a user's auth info, exec credential plugins included, only for TLS servers (`IsConfigTransportTLS`). A test or probe that serves plain HTTP never exercises credential handling, so a fixture for an auth-related claim needs `httptest.NewTLSServer`.
- [repo] `os.UserCacheDir()/rancher-desktop` is classic Rancher Desktop's cache directory on macOS and Linux and its app home on Windows (`%LOCALAPPDATA%\rancher-desktop`), which an RD1 factory reset or uninstall deletes. Flag new rdd paths under it; rdd's own shared caches use a dotted name such as `rancher-desktop.guest-deps`.

###### Design Observations

###### Concerns

- **Hand-rolled version resolver maintenance tail** `(future)`: By re-implementing kuberlr's internal resolver logic in `pkg/kuberlr/` rather than depending on an upstream package (due to kuberlr's internal package layout), RDD assumes ownership of mirror format changes, platform architecture tag mappings, and discovery flags binding. If Kubernetes SIG Release changes marker conventions or binary CDN layouts, `downloader.go` will require maintenance.

###### Strengths

- **Graceful embedded fallback for pre-GA and offline clusters**: Querying `stable-<major>.<minor>.txt` via `latestPatch` and falling back to the embedded kubectl with a user-facing warning allows offline users and pre-GA clusters to function normally without hard errors.
- **`rdd ctl` bypass**: Short-circuiting discovery via `kuberlr.SkipResolver()` ensures commands targeting RDD's embedded apiserver pay zero probe or network latency.
- **Streaming SHA-512 verification with size limits**: `streamGet` and `io.MultiWriter(tmp, h)` compute digests while streaming without loading multi-megabyte binaries into RAM, and `os.Rename` guarantees partial downloads are never published.
- **Discovery flag preservation**: Binding genericclioptions `ConfigFlags` ensures the probe resolves the identical cluster context and auth parameters as kubectl while avoiding interactive stdin credential prompts.

###### Acknowledged Limitations

- **Windows `os.Rename` cache-publish race** (`downloader.go:136`): Two concurrent first-time downloads of the same version can collide on `os.Rename` on Windows if one process holds an open handle. Acknowledged and declined across rounds of PR #348.
- **`CacheRoot` panic on `os.UserCacheDir` failure** (`cache.go:48`): `CacheRoot` panics if the user cache directory cannot be determined. Acknowledged and declined in PR #348.
- **Cache eviction and leaked `.kubectl-*` temp files** (`cache.go:27`): Marked via `TODO(eviction)`; a TTL or LRU cleanup will be needed before the cache footprint expands noticeably.
- **Offline mode toggle** (`downloader.go:47`): Marked via `TODO(offline)` to eventually allow air-gapped users to forbid network fetches entirely.
- **Truncation surfaces as checksum mismatch** (`downloader.go:142`): Exceeding `maxKubectlBytes` (256 MiB) truncates the stream and reports a checksum mismatch rather than an explicit size error.
- **Windows `exec.CommandContext` cancellation hard-kill** (`exec_windows.go:23`): Documented in comments that context cancellation hard-kills kubectl rather than letting Ctrl+C propagate.
- **`local_teardown_file` in `7-kubectl-cache.bats`** (`7-kubectl-cache.bats:99`): Explicitly commented departure from the no-teardown convention to release ephemeral ports held by the mock server.
- **Dependabot scan on `fake-kube`** (`.github/dependabot.yml:143`): Pre-positioning for future dependency additions, acknowledged in round 1 (S4).
