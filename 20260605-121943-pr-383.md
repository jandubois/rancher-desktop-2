## Important Issues

I1. **`service.PID()` rejects a control plane started as `rdd svc serve`** — `pkg/service/cmd/service.go:177` [Claude Opus 4.8, Codex GPT 5.5, Gemini 3.1 Pro]

```go
if err == nil && !process.IsOurProcess(pid, "service", "serve") {
    err = fmt.Errorf("pid %d is not our control plane", pid)
}
```

`service` aliases `svc` (`cmd/rdd/service.go:60`) and `serve` is directly invocable, so a daemon launched as `rdd svc serve` carries the command line `svc serve`, not `service serve`. `IsOurProcess` requires every substring via `strings.Contains` (`process_windows.go:756`), so the missing `service` token reads the live daemon as not-running and removes its PID file (`service.go:182`). The common path is safe — `Run` self-spawns the canonical `service serve` (`service.go:306`) — so only a manual `rdd svc serve` triggers it. Against merge-base `PID()` accepted any live PID, so this is a regression open since Round 3.

Fix: match the `serve` token alone. `service` does not contain `serve`, and the image-path match still rejects unrelated rdd processes.

```diff
- if err == nil && !process.IsOurProcess(pid, "service", "serve") {
+ if err == nil && !process.IsOurProcess(pid, "serve") {
```

## Design Observations

**Concerns**

- **`removeStaleInstance` unregisters a WSL2 distro without terminating it first** `(in-scope)` [Gemini 3.1 Pro] — PR #392's `removeStaleInstance` (`limavm_lifecycle.go:800`) calls `unregisterWSL2Distro`, then `os.RemoveAll`. PR #383's `forceStopForDeletion` (`:683`) terminates the distro before letting Lima's `Delete` unregister it, because a stopped WSL2 distro "can retain kernel state that deadlocks `wsl.exe --unregister`" — a hazard the project's own recovery notes confirm needs `taskkill wslservice.exe`. Recommendation: call `terminateWSL2Distro` before `unregisterWSL2Distro`. The code is PR #392's, so the fix can land here or separately.

- **`Reconcile` now holds three leftover-cleanup paths with uneven WSL2 handling** `(future)` [orchestrator] — the sentinel path removes the directory with a bare `os.RemoveAll` (`limavm_controller.go:205`, no distro unregister), the leftover-instance path force-stops then `Delete`s (PR #383, `:219`), and the stale-directory path runs `removeStaleInstance` (PR #392, `:317`). ## Review Process Notes

**Skill improvement — handle invocation from a git worktree.** When the skill runs from a git worktree rather than the main repo root, the lead helper resolves the `.reviews` directory relative to the worktree, finds no prior reviews, and reports `ROUND=1` even for a re-review; Step 6 would then create or target the wrong `.reviews` path. Resolve the reviews worktree through the main repository — `git rev-parse --git-common-dir` yields the main repo's `.git`, whose parent is the root — instead of `git rev-parse --show-toplevel`. Until the helper is fixed, an orchestrator running from a worktree must verify the round number against the main repo's `.reviews/` and target every Step 6 worktree and commit operation at the main repo root.

**Skill improvement — Correctness dimension: a safety-ordering comment is a codebase-wide invariant.** When changed code documents an ordering or guard required for safety ("terminate before unregister," "clear the PID before the kill," "acquire X before Y to avoid deadlock Z"), treat that ordering as a checkable invariant across the whole codebase, not only at the commenting call site. Enumerate every sibling that performs the same operation — including code introduced by a rebase or in an adjacent package — and confirm each applies the same discipline. A sibling that performs the operation without the documented safeguard is a defect, even when the changed code itself is correct.

**Skill improvement — Correctness dimension: read the callee's error contract before accepting an ignored-error finding.** Before flagging "an ignored error from this call leads to a destructive action," read the called function's documented error contract. Many APIs return "not found" as a sentinel error and surface other failures as data (a populated result with an embedded error list), so an apparently ignored error may be the intended sentinel branch that the destructive path legitimately depends on. A fix that converts the sentinel into a hard return can break the very recovery the code implements. Verify the contract before raising the finding and before proposing the fix.

**[repo] WSL2 teardown order: terminate before unregister.** `wsl.exe --unregister` can deadlock on a stale or stopped Lima distro that retains kernel state, and recovery then requires killing `wslservice.exe`. Lima's own WSL2 `Delete` (`pkg/driver/wsl2/wsl_driver_windows.go`) calls `unregisterVM` directly, without a prior `--terminate`, so RDD adds the terminate step itself (`terminateWSL2Distro` before the unregister). When reviewing any RDD code that unregisters a WSL2 distro, verify it terminates the distro first; flag a direct `--unregister` (or a call to `unregisterWSL2Distro`) that is not preceded by a terminate.

**[repo] Lima `store.Inspect` returns an error only for `os.ErrNotExist`.** `store.Inspect` (`pkg/store/instance.go`) returns a non-nil error only when the instance does not exist (a missing `lima.yaml`) or the name is invalid; every other failure — a parse error or a transient read — returns a non-nil `*limatype.Instance` with `Instance.Errors` populated. Code that branches on `if err == nil && inst != nil` therefore treats a transiently-unreadable but valid instance as present, never as absent. When reviewing a finding that claims an inspect error leads to destructive cleanup, account for this contract before accepting it.

### Executive Summary

This PR adds process identity verification (`process.IsOurProcess`) to Windows process termination to ensure signals and kills do not reach unrelated processes that recycled a stale PID, and ensures hostagent resources are always reclaimed during graceful shutdown. The rebased commits introduce a new sibling concern where `removeStaleInstance` calls `unregisterWSL2Distro` without the required termination guard, risking a deadlock that can trap the reconciler in an infinite timeout loop. 

### Findings

#### Critical Issues
None.

#### Important Issues

**I1. `service.PID()` rejects a control plane started as `rdd svc serve`** — `pkg/service/cmd/service.go:171` (important, regression)

The `IsOurProcess(pid, "service", "serve")` guard checks if the process command line contains both `"service"` and `"serve"`. Because `svc` aliases `service` and `serve` is directly invocable, a daemon launched manually as `rdd svc serve` has a command line containing `svc serve`, not `service serve`. The missing `"service"` token makes the live daemon read as not-running and causes its PID file to be incorrectly removed. (This re-verifies the prior round finding).

Fix: Use `"serve"` as the sole substring. It is specific enough to reliably identify the control plane among `rdd` processes.

```diff
-		if err == nil && !process.IsOurProcess(pid, "service", "serve") {
+		if err == nil && !process.IsOurProcess(pid, "serve") {
 			err = fmt.Errorf("pid %d is not our control plane", pid)
 		}
```

**I2. `removeStaleInstance` risks a `wsl.exe --unregister` deadlock by omitting the `terminate` guard** — `pkg/controllers/lima/limavm/controllers/limavm_lifecycle.go:749` (important, gap)

The new base commit `7bffb23c` introduced `removeStaleInstance`, which calls `unregisterWSL2Distro` to clean up a stale WSL2 distro before removing its directory. However, this PR (#383) correctly documents in `forceStopForDeletion` that a "stopped" WSL2 distro can retain kernel state that deadlocks `wsl.exe --unregister`, and calls `terminateWSL2Distro` first to prevent it. Because `removeStaleInstance` omits this termination, it risks the very deadlock this PR aims to prevent. If the unregister times out after 30 seconds, `os.RemoveAll` will fail (since the VHD is still locked), causing the reconciler to endlessly requeue and timeout again.

Fix: Call `terminateWSL2Distro` before `unregisterWSL2Distro` in `removeStaleInstance`.

```diff
 func removeStaleInstance(ctx context.Context, logger logr.Logger, instName, instanceDir string) error {
 	if runtime.GOOS == "windows" {
+		terminateWSL2Distro(ctx, logger, instName)
 		unregisterWSL2Distro(ctx, logger, instName)
 	}
 	return os.RemoveAll(instanceDir)
 }
```
