## Executive Summary

The PR builds the standalone `rdd.*` download without the `with_dashboard` tag, so it leaves out steve and the dashboard, and `yarn sign` now signs that binary and, on macOS, notarizes it. A manual Package run on the author's fork signed it on macOS arm64 and Windows x86_64. It needs two fixes. A new comment wrongly names `DashboardOpen.vue` as steve's only port reader (I1), and nothing checks that the separately built binary has its package leg's architecture (I2).

S1. **The new CI check reads build tags, so it misses a standalone rdd that links steve** — `.github/workflows/package.yaml:127-133` [Claude Opus 5.5]

```yaml
        tags="$(go version -m dist/rdd.* | grep --extended-regexp -- '-tags=')"
        echo "${tags}"
        echo "${tags}" | grep --extended-regexp -- '-tags=(.*,)?with_distro(,|$)'

          echo "::error::The standalone rdd embeds the dashboard"
          exit 1

```

The step proves that the standalone build left out the `with_dashboard` tag, but not that the binary left out steve. I deleted the `//go:build with_dashboard` line from `rdd/cmd/rdd/steve.go` and built `cmd/rdd` without the tag. The step's dashboard test still passed, and `go version -m` listed `dep github.com/rancher/steve v0.9.23`. An unmutated build without the tag does not list steve at all, so the module line tells the two apart where the tags cannot. It catches a lost build constraint and a new import of `pkg/steve` alike.

Fix: also fail the step when the binary lists steve as a dependency.

S2. **No binary reaches the API-only mode of `pkg/steve` any more** — `rdd/pkg/steve/steve.go:64-69` [Claude Opus 5.5]

```go
	var handler http.Handler = s
	if dashboardFiles == nil {
		logrus.Warn("This binary does not embed the dashboard; serving only the steve API")
	} else if handler, err = newHandler(s, dashboardFiles, port); err != nil {
		return fmt.Errorf("could not set up dashboard handler: %w", err)

```

`rdd/cmd/rdd/steve.go` is the only importer of `pkg/steve`, and it now builds only with `with_dashboard`, the tag that also sets `dashboardFiles` in `dashboard_embed.go`. So no binary runs the nil branch, and no test calls `Run`. The package doc (`steve.go:5-6`), the `Run` doc (`steve.go:36`) and `dashboard.go:22-23` still describe a build that serves steve without the dashboard. Each statement is true of the package, but no binary matches it.

Fix: either drop the branch, so that `Run` returns an error without an embedded dashboard, and trim the three comments, or keep the branch and say in the package doc that only its tests build it without the tag.

S3. **`yarn sign` checks only the file name of the standalone rdd, so a wrong path fails after the app is signed** — `scripts/lib/build-utils.ts:498-504` [Claude Opus 5.5]

```ts
  findStandaloneRdd(files: string[], version: string, platform: NodeJS.Platform): string {
    const expected = rddArtifactName(version, platform, this.arch);
    const rdd = files.find(f => path.basename(f) === expected);

    if (!rdd) {
      throw new Error(`Signing needs the standalone rdd ${ expected }; pass its path along with the archive`);
    }
```

`findStandaloneRdd` runs before any signing, but it compares base names only. So a path to a file that does not exist passes, and the copy fails later. On macOS that happens after the whole app is signed (`sign-macos.ts:139`), and on Windows after `buildWiX` (`sign-win32.ts:125`). The error names the path, so the cost is a rerun.

Separately, `scripts/sign.ts:113` treats every `.zip` as an app archive. On Windows, the GitHub `rdd` artifact zip passed without extracting it looks like the app archive because of the `.exe` inside, so signing fails on a missing `electron-builder.yml`.

Fix: add `|| !fs.existsSync(rdd)` to the guard. Optionally leave `rdd.*.zip` out of `archives` and tell the user to extract it.

S4. **No unit test covers `findStandaloneRdd`** — `scripts/lib/build-utils.ts:498` [Gemini 3.5 Flash]

`scripts/lib/__tests__/build-utils.spec.ts` tests the neighbouring `checkArchiveArch` by stubbing the `arch` getter, and `findStandaloneRdd` can use the same pattern. The test is optional, because the function runs only in our own release signing, and a regression throws an error that names the expected file. Add a case that picks the matching name out of several files and one that throws when it is missing. I2 covers `goArch`.

S5. **`BUILD_RDD` leaves a trailing space in the tags of the standalone build** — `rdd/Makefile:265` [Gemini 3.5 Flash]

```makefile
go$(EXE) build -tags="$(TAGS) with_distro $(2)" -gcflags="all=${GCFLAGS}" -ldflags="$(LDFLAGS)" -o $(1) ./cmd/rdd
```

With an empty second argument the recipe runs `go build -tags="sqlite_omit_load_extension with_distro "`, as the package job logs show. Go ignores the space, and `go version -m` records clean tags, so nothing breaks. `CONTROLLER_TARGETS` in the same file wraps its tags in `$(strip ...)` for the same case.

Fix: write `-tags="$(strip $(TAGS) with_distro $(2))"`.

### Concerns

- (in-scope) **The PR conflicts with #1208 in `docs/development/release-checklist.md`.** Both PRs rewrite the "Sign windows installer" line, so whichever merges second needs a rebase, and the merged line has to name both the arm64 installer and the standalone `rdd.exe`. ### Strengths

- (in-scope) **The notarization helper keeps the password out of errors.** `notarizeFile` catches `SpawnError`, whose `command` holds the password, parses stdout alone, and appends `notarytool log` to the error when Apple rejects a submission. - (in-scope) **The entitlements come from one place.** The standalone `rdd` gets the entitlements that `signing-config-mac.yaml` gives the app's `rdd`, and the `sign-mac` job checks for `com.apple.security.virtualization`. [Claude Opus 5.5, Codex GPT 6 Astra]

## Acknowledged Limitations

- **Notarization first runs at a release.** CI passes `--skip-notarize`, as the PR body says.
- **Builds without a staged dashboard leave out `rdd steve`.** The commit message says so. In BATS, E2E and `yarn dev`, the app spawns `rdd steve` again on every `backend/app-status-changed` event while Kubernetes is ready, logs the failure, and leaves the Dashboard button disabled (`background.ts:342-352`). `e2e/dashboard.e2e.spec.ts` is `describe.fixme`, so no test depends on it.
- **`make lint-rdd` no longer checks `steve.go`,** because it builds without `with_dashboard`, as #1192 records.
- **Do not re-suggest: a stale standalone `rdd` after a `GOARCH` switch.** `download-guest-deps` runs on every build and restages the distro for the new architecture (`rdd/Makefile:166-174`), so the distro image prerequisite rebuilds both `rdd` targets.
- **Do not re-suggest: non-boolean values in `entitlementsPlist`.** The PR moved that mapping unchanged, and every entitlement in `signing-config-mac.yaml` and `macos-entitlements.plist` is a boolean.
- **Do not re-suggest: a type guard on the JSON from notarytool.** `notarytool submit --output-format json` prints an object, and any other value would still fail the signing with a `TypeError`.
- **Do not re-suggest: the signing identifier of the standalone `rdd`.** codesign derives it from the file name, `rdd.<version>.darwin`, while the app's `rdd` gets `rdd-<Mach-O UUID>`, which changes with every build, so neither was ever stable.
