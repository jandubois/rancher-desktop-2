## Executive Summary

PR #478 reworks the Playwright startup E2E test to drive a standalone mock controller instead of the deleted JavaScript backend. The daemon runs with all controllers disabled while the `mock-controller` binary ships every CRD and adds an `appReconciler` that flips the App's `Settled` condition to mirror `spec.running`. No critical issues surfaced; the important findings are latent but cheap to fix.

All three reviewers converged on the mock reconciler and the test-helper rewrite. The two Important findings are real but dormant — one trips only when someone runs `rdd set` against the mock, the other only when a `.fixme` suite is re-enabled. Two agent claims were downgraded after verification: a "non-SSA status update" race (no concurrent writer exists in the disabled-controllers mock) and an "endless reconcile loop" (the apiserver dedupes the no-op write), both folded into S1.

## Important Issues

I1. **Mock `Settled` omits `ObservedGeneration`; `rdd set --wait` hangs against the mock** — `rdd/pkg/controllers/mock/app_reconciler.go:57-62` [Codex GPT 5.5, Claude Opus 4.8]

```go
apimeta.SetStatusCondition(&app.Status.Conditions, metav1.Condition{
    Type:    "Settled",
    Status:  status,
    Reason:  "MockController",
    Message: fmt.Sprintf("app.running set to %v", app.Spec.Running),
})
```

`app_types.go:22-26` states a load-bearing invariant: every App status condition must stamp `ObservedGeneration`. `rdd set` (default `--wait=true`) returns only when `gen >= minGen && status == True` (`set.go:488`), where `minGen` is the post-write generation. The mock leaves `observedGeneration` at 0, so the predicate never holds and the command blocks until timeout. This PR's test sidesteps it with `--wait=false`, and the front end reads status only (`store/rdd.ts:50`), so nothing breaks today — but the next caller who runs `rdd set running=true` against the mock hits the hang. New code, so a fidelity gap rather than a regression.

Fix:

```diff
 apimeta.SetStatusCondition(&app.Status.Conditions, metav1.Condition{
-    Type:    "Settled",
+    Type:               v1alpha1.AppConditionSettled,
     Status:             status,
     Reason:             "MockController",
     Message:            fmt.Sprintf("app.running set to %v", app.Spec.Running),
+    ObservedGeneration: app.Generation,
 })
```

I2. **`startSlowerDesktop` dropped a parameter that five suites still pass** — `e2e/utils/TestUtils.ts:350` [Codex GPT 5.5, Claude Opus 4.8]

```ts
export async function startSlowerDesktop(testInfo: TestInfo): Promise<[ElectronApplication, Page]> {
```

The signature went from `(testInfo, defaultSettings = {})` to one parameter, and the body no longer calls `createDefaultSettings`. Seven call sites still pass a settings object — `containers.e2e.spec.ts:20,318,426`, `dashboard.e2e.spec.ts:12`, `extensions.e2e.spec.ts:65`, `volumes.e2e.spec.ts:16`, `credentials-server.e2e.spec.ts:224`. That is a TS2554 error, but CI lint runs ESLint only (`scripts/lint-typescript.ts`), not `tsc`, and Playwright's esbuild loader strips types — so the argument is dropped silently at runtime. Every affected block is `.fixme`, so the loss is dormant; re-enabling any of them launches with default settings, not the intended ones.

Fix: drop the dead second argument at the call sites, or restore the parameter and forward it to `createDefaultSettings`.

I3. **`beforeExit` cleanup spawns async work** — `e2e/utils/TestUtils.ts:291-296` [Gemini 3.1 Pro]

```ts
process.on('beforeExit', () => {
  spawnFile(
    path.join(topSrcDir, 'rdd', 'bin', exeName('rdd')),
    ['service', 'stop'],
    { env, stdio: ['ignore', rddLogs, rddLogs] });
});
```

`beforeExit` fires when the event loop empties. A fire-and-forget `spawnFile` adds a live child handle, refills the loop, and re-arms `beforeExit` when it drains — an exit-time spin. If the worker exits through `process.exit()` instead, `beforeExit` never fires and the handler is dead. Either way the cleanup is unreliable. The test passes, which means the handler is being skipped, not looping — `teardownApp` does the real cleanup via `rdd service delete`. Downgraded from the reported Critical: the blast radius is test teardown, and an authoritative cleanup path already exists.

Fix: drop the `rdd service stop` hook and rely on `teardownApp`; keep the synchronous `controller.kill()` under `process.on('exit')`.

## Suggestions

S1. **Mock reconciler updates status on every reconcile** — `rdd/pkg/controllers/mock/app_reconciler.go:57-63` [Codex GPT 5.5, Gemini 3.1 Pro, Claude Opus 4.8]

```go
apimeta.SetStatusCondition(&app.Status.Conditions, metav1.Condition{ /* ... */ })
if err := r.Status().Update(ctx, &app); err != nil {
```

The real App controller guards the write with `SetStatusCondition`'s return — `if !changed { return }` (`app_controller.go:533`). The mock discards the bool and always calls `Status().Update`. Two stronger framings were checked and dropped: there is no concurrent App-status writer in the disabled-controllers mock (the convention in `deep-review-context.md:50` targets the real `AppReconciler`/`EngineReconciler`), and the apiserver dedupes the byte-identical no-op write, so no reconcile loop forms. The remaining point is hygiene: mirror the guard to drop one redundant write per reconcile.

Fix:

```diff
-apimeta.SetStatusCondition(&app.Status.Conditions, metav1.Condition{ /* ... */ })
+if !apimeta.SetStatusCondition(&app.Status.Conditions, metav1.Condition{ /* ... */ }) {
+    return ctrl.Result{}, nil
+}
 if err := r.Status().Update(ctx, &app); err != nil {
```

S2. **`waitForAppSettled` leaks its timer and keeps a dead guard** — `e2e/pages/nav-page.ts:60-79` [Gemini 3.1 Pro, Claude Opus 4.8]

```ts
let timedOut = false;
setTimeout(() => { timedOut = true }, 30_000);
```

The 30s timer is never cleared, so on the success path it stays armed and keeps the Node event loop busy until it fires. The loop's only non-`return` exit sets `timedOut` true, making the trailing `if (timedOut) throw` always true. A deadline comparison drops the timer, the eslint-disable, and the redundant guard:

```ts
const deadline = Date.now() + 30_000;
while (Date.now() < deadline) {
  if (await this.isAppSettled()) return;
  await util.promisify(setTimeout)(500);
}
throw new Error('Backend did not settle within 30 seconds');
```

S3. **1 s progress-bar timeout risks CI flakes** — `e2e/main.e2e.spec.ts:58` [Gemini 3.1 Pro]

```ts
await rdd('set', 'running=false', '--wait=false');
await expect(navPage.progressBar).toBeVisible({ timeout: 1_000 });
```

After `--wait=false` the bar reappears only once the reconcile, watch event, IPC hop, and render all complete. One second covers that on a fast machine; a loaded CI runner can miss it. Drop the override to inherit Playwright's default, or raise it to `5_000`.

S4. **Defensive CRD `Get` cannot fire** — `rdd/pkg/controllers/mock/app_reconciler.go:34-40` [Claude Opus 4.8]

The reconciler reads `apps.app.rancherdesktop.io` each pass and errors if it is absent. The controller installs and establishes its CRDs before `mgr.Start`, and a `For(&App{})` reconciler cannot trigger until the App CRD exists — so the read always succeeds. No sibling reconciler does this. Drop the block.

S5. **Doc comment typo and non-idiomatic godoc** — `rdd/pkg/controllers/mock/app_reconciler.go:24` [Claude Opus 4.8]

```go
// type appReconciler reconiles the mock App resource, resulting in the app
```

"reconiles" should read "reconciles", and godoc leads with the bare symbol name: `// appReconciler reconciles the mock App resource...`.

S6. **`appReconciler.Recorder` is assigned but never read** — `rdd/pkg/controllers/mock/app_reconciler.go:28` [Claude Opus 4.8]

`Recorder events.EventRecorder` is wired in `mock_controller.go:108` but unused in `Reconcile`. Sibling reconcilers carry the same dead field; since `appReconciler` is new, drop the field and its `GetEventRecorder` wiring rather than copy the pattern.

S7. **`verifyUserProfile` is now a no-op; `lockedFields` asserts state it no longer sets** — `e2e/utils/ProfileUtils.ts:132-134`, `e2e/lockedFields.e2e.spec.ts:96` [Gemini 3.1 Pro, Claude Opus 4.8]

Removing `setUserProfile` leaves `verifyUserProfile` calling only `clearUserProfile()`, so the name overstates the work. `lockedFields.e2e.spec.ts` still asserts `patterns` equals `['c','d','f']` and the locked-field rejections that `setUserProfile` used to establish. ## Review Process Notes

**Repo context updates**

- `[repo]` In Node-based E2E or test harnesses, flag async work — `spawnFile`, unawaited promises, any call that adds an event-loop handle — inside a `process.on('beforeExit')` or `process.on('exit')` handler. `beforeExit` re-arms the loop every time that async work drains, producing an exit-time spin, and both hooks are skipped when the runner calls `process.exit()`. Cleanup that must run belongs in explicit teardown, not a lifecycle hook.
- `[repo]` UPDATE the App.Status SSA convention entry: the non-SSA / retry-on-conflict requirement applies only to a controller that runs alongside other App-status writers. A standalone mock started with `--controllers=` is the sole status writer, so a plain read-modify-write `Status().Update` is correct there and should not be flagged; a spec-write conflict self-heals through the controller-runtime requeue. Reviewers were flagging the mock under the production-controller rule.
- `[repo]` CI lint runs ESLint only (`scripts/lint-typescript.ts`), not `tsc`, and Playwright transpiles through esbuild, which strips types without checking them. Type errors that `tsc` would catch — excess function arguments (TS2554), wrong argument types — ship green and fail silently at runtime. When a function signature changes, grep every caller; do not assume the type checker guards the contract.

### [Codex] — Codex GPT 5.5

### Executive Summary

The PR moves active E2E startup coverage onto RDD plus the standalone mock controller. The main blocker is in the new mock App reconciler: it writes `Settled` without the App generation and updates status on every reconcile, which breaks generation-aware waits and can self-trigger continuous reconciles.

### Findings

#### Critical Issues

None.

#### Important Issues

I1. **Mock Settled never satisfies generation-aware waits** — `rdd/pkg/controllers/mock/app_reconciler.go:57` (important, regression)

```go
	apimeta.SetStatusCondition(&app.Status.Conditions, metav1.Condition{
		Type:    "Settled",
		Status:  status,
		Reason:  "MockController",
		Message: fmt.Sprintf("app.running set to %v", app.Spec.Running),
	})
```

The condition written at line 57 omits `ObservedGeneration`. The App API contract says every App status condition must stamp the App generation (`rdd/pkg/apis/app/v1alpha1/app_types.go:24`), and `rdd set` only accepts `Settled=True` when `observedGeneration >= minGen` (`rdd/cmd/rdd/set.go:488`). With the mock controller, `conditionInfo` reads the missing generation as `0` (`rdd/cmd/rdd/set.go:604`), so a normal `rdd set running=true` waits until timeout even after the mock marks Settled.

Fix:

```diff

-		Type:    "Settled",
-		Status:  status,
-		Reason:  "MockController",
-		Message: fmt.Sprintf("app.running set to %v", app.Spec.Running),
+		Type:               v1alpha1.AppConditionSettled,
+		Status:             status,
+		Reason:             "MockController",

 	})
```

 		Type:    "Settled",

### [Gemini] — Gemini 3.1 Pro

### Executive Summary

This PR replaces the legacy JavaScript backend E2E tests with updated integration coverage against the new Go-based `rdd` architecture. It shifts the UI tests to use a mock controller that actively drives the App state to "Settled" via a dedicated `appReconciler` and embeds all required CRDs. The headline finding is a critical infinite-loop flaw introduced by `process.on('beforeExit')` executing asynchronous process spawns during test teardown.

### Findings

#### Critical Issues

**C1. `beforeExit` hooks trigger an infinite loop** — `e2e/utils/TestUtils.ts:291-304` (critical, regression)

```typescript
  process.on('beforeExit', () => {
    spawnFile(
      path.join(topSrcDir, 'rdd', 'bin', exeName('rdd')),
      ['service', 'stop'],
      { env, stdio: ['ignore', rddLogs, rddLogs] });
  });
```

Node.js's `beforeExit` is emitted when the event loop is completely empty. If the callback introduces new asynchronous operations (like `spawnFile` awaiting a child process), Node.js resumes the event loop. Once that async work finishes, the event loop empties again, which triggers `beforeExit` again, creating an infinite loop. Additionally, if Playwright exits forcefully (`process.exit()`), `beforeExit` is never emitted. The `teardownApp` function already explicitly runs `rdd service delete`, ensuring safe shutdown.

Fix: Remove the `beforeExit` hook for `spawnFile`. For the mock controller, use `process.on('exit')` which is safely synchronous:

```diff
-  process.on('beforeExit', () => {
-    spawnFile(
-      path.join(topSrcDir, 'rdd', 'bin', exeName('rdd')),
-      ['service', 'stop'],
-      { env, stdio: ['ignore', rddLogs, rddLogs] });
-  });
...
-  process.on('beforeExit', () => {
+  process.on('exit', () => {
     // Stopping RDD should have caused the mock controller to exit; kill it just in case.
     controller.kill();
   });
```

#### Important Issues

**I1. Dangling timeout leaks across tests** — `e2e/pages/nav-page.ts:60-61` (important, regression)

```typescript
    let timedOut = false;
    setTimeout(() => { timedOut = true }, 30_000);
```

The `setTimeout` call is not assigned to a variable and lacks a corresponding `clearTimeout`. If `isAppSettled()` successfully returns `true` before 30 seconds elapse, the unreferenced timer remains active on the Node.js event loop. This dangling timer delays the exit of the test runner and can trigger resource leak warnings.

Fix: Store the timer ID and explicitly clear it in a `finally` block:

```diff
     let timedOut = false;
-    setTimeout(() => { timedOut = true }, 30_000);
+    const timer = setTimeout(() => { timedOut = true }, 30_000);
     const delay = 500; // msec
-    // eslint-disable-next-line no-unmodified-loop-condition -- Flag updated by timer.
-    while (!timedOut) {
-      if (await this.isAppSettled()) {
-        return;
-      }
-      await util.promisify(setTimeout)(delay);
-    }
+    try {
+      // eslint-disable-next-line no-unmodified-loop-condition -- Flag updated by timer.
+      while (!timedOut) {
+        if (await this.isAppSettled()) {
+          return;
+        }
+        await util.promisify(setTimeout)(delay);
+      }
+    } finally {
+      clearTimeout(timer);
+    }
```

**I2. Aggressive UI expectation timeout** — `e2e/main.e2e.spec.ts:58` (important, regression)

```typescript
    await rdd('set', 'running=false', '--wait=false');
    await expect(navPage.progressBar).toBeVisible({ timeout: 1_000 });
```

A 1,000ms timeout for the progress bar to become visible is too aggressive for CI environments. The test relies on a long asynchronous chain: spawning `rdd set`, IPC to the embedded API server, the mock controller's reconcile loop, the Kubernetes watch event propagating to the Electron backend, IPC to the frontend, and finally the React render. This sequence regularly spikes beyond 1 second on constrained test runners.

Fix: Remove the explicit `timeout` to inherit Playwright's safer default, or increase it to at least `5_000`:

```diff
-    await expect(navPage.progressBar).toBeVisible({ timeout: 1_000 });
+    await expect(navPage.progressBar).toBeVisible();
```

**I3. Non-SSA Status Update on App** — `rdd/pkg/controllers/mock/app_reconciler.go:61` (important, regression)

```go
	if err := r.Status().Update(ctx, &app); err != nil {
		log.Error(err, "Failed to update App status", "name", req.NamespacedName)
		return ctrl.Result{}, err
	}
```

The repository conventions explicitly state: *"App.Status.Conditions has multiple concurrent writers... Flag any non-SSA, non-retry-on-conflict Status().Update on the App object."* The mock controller uses a direct read-modify-write `Status().Update` without retry-on-conflict. Mirroring the correct convention in the test harness prevents spurious conflict errors if other mock reconcilers (or background tasks) update the object simultaneously.

Fix: Wrap the update in `retry.RetryOnConflict` with a fresh `Get`:

```diff
-	apimeta.SetStatusCondition(&app.Status.Conditions, metav1.Condition{
-		Type:    "Settled",
-		Status:  status,
-		Reason:  "MockController",
-		Message: fmt.Sprintf("app.running set to %v", app.Spec.Running),
-	})
-	if err := r.Status().Update(ctx, &app); err != nil {
-		log.Error(err, "Failed to update App status", "name", req.NamespacedName)
-		return ctrl.Result{}, err
-	}
+	err := retry.RetryOnConflict(retry.DefaultRetry, func() error {
+		if err := r.Client.Get(ctx, req.NamespacedName, &app); err != nil {
+			return err
+		}
+		apimeta.SetStatusCondition(&app.Status.Conditions, metav1.Condition{
+			Type:    "Settled",
+			Status:  status,
+			Reason:  "MockController",
+			Message: fmt.Sprintf("app.running set to %v", app.Spec.Running),
+		})
+		return r.Status().Update(ctx, &app)
+	})
+	if err != nil {
+		log.Error(err, "Failed to update App status", "name", req.NamespacedName)
+		return ctrl.Result{}, err
+	}
```
