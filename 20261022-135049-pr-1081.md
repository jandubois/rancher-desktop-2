## Suggestions

S1. **The pin is decided from a read that its patch does not check** — `rdd/cmd/rdd/set.go:310-314` [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.1 Pro, Gemini 3.5 Flash] round 1 S1 unaddressed

```go
	if _, named := properties["application.addPath"]; !named {
		if apierrors.IsNotFound(err) || app.Spec.Application.AddPath == appv1alpha1.AddPathUnset {
			coerced["application.addPath"] = string(appv1alpha1.AddPathManual)
		}
	}
```

The pin depends on the `Get` at line 302, but `patchApp` sends a merge patch with no `resourceVersion` (line 464). The `AlreadyExists` branch (lines 383-389) re-reads the App and still reuses the `specMap` built for a missing one. A writer that stores `front` inside that window loses it to `manual`, which the CEL rule allows. Today nothing in the product writes `addPath` concurrently. The GUI will not write it before #1051 lands, so the window takes two CLI commands, one naming `addPath`, within milliseconds of each other.

Fix: when the pin is added, send the `Get`'s `resourceVersion` with the patch, retry on conflict, and recompute the pin after each read, the `AlreadyExists` branch included.

S2. **State `unset` once per document** — `rdd/docs/design/api_app.md:117-121` [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.1 Pro, Gemini 3.5 Flash] round 1 S2 unaddressed

```markdown
  The field defaults to `unset`, so the App can record that nobody has chosen yet. The GUI sends
  `front`/`back`/`manual` when the user opts in. When `rdd set` runs without naming
  `application.addPath` and the App is missing or still `unset`, it also writes
  `application.addPath: manual`, so a CLI-created instance — including one started with
  `rdd set running=true` — leaves `PATH` alone and never gets the first-run dialog.
```

The `unset` bullet at lines 108-112 already gives the default, the CEL rule and the `rdd set` replacement, and this paragraph repeats the default and the replacement.

The field doc's value bullets (`app_types.go:222-224`) leave `unset` out and explain it in prose at lines 225-228, which is copied into both CRDs and the TypeScript client. That prose says `rdd set` replaces `unset` "for a CLI-created instance", but any App still `unset` when `rdd set`, `start`, `stop` or `run` runs gets `manual`, including one the GUI created.

Fix: keep the `rdd set` detail in one place in `api_app.md`. In the field doc, give `unset` its own bullet, drop the "CLI-created" qualifier, and regenerate.

S3. **`bootstrap.md` never says how to turn PATH management on** — `rdd/docs/design/bootstrap.md:70` [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.5 Flash]

The corrected sentence limits automatic PATH edits to `front` and `back`. But the page walks through `rdd start`, which stores `manual` on a new App (`app.go:43` calls `setAction`). So a reader who follows the page does not get a PATH edit and is not told how to opt in.

Fix: add "`rdd start` sets it to `manual`; run `rdd set application.addPath=front` to opt in, or use `rdd run`."

## Design Observations

### Concerns

- **The pin reaches GUI-created Apps through `rdd stop` and `rdd run`** (in-scope) [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash]: raised in round 1 by Claude Opus 5.5. Issue #1052 exists for an app that quits before the user answers the first-run dialog. With the pin in `setAction`, a later `rdd stop` or `rdd run docker ps` also erases that signal, as I1's probe shows. One option makes the pin a `setAction` parameter that `stopAction` and `ensureAppRunning` leave off, which makes the `rdd run` docs true again. The other keeps the behavior and takes I1's patch. The maintainers should choose.

### Strengths

- **One predicate for every PATH decision** (in-scope) [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash]: raised in round 1 by Claude Opus 5.5, Codex GPT 6 Astra and Gemini 3.5 Flash. `IsAdding()` replaced the `!= manual` tests in `applyPosix` and the Settled check, which would have treated `unset` like `front`.
- **The one-way rule holds in the API server** (in-scope) [Claude Opus 5.5, Gemini 3.5 Flash]: raised in round 1 by Claude Opus 5.5 and Codex GPT 6 Astra. The rule is on the field itself, so deleting the field or the whole `application` object is defaulted back to `unset` and rejected.
- **The new bats test creates the App without the CLI** (in-scope) [Codex GPT 6 Astra]: it applies the App through `rdd ctl`, checks `unset`, then runs `rdd set`, so it pins both the CRD default and the existing-`unset` branch.

## Review Process Notes

### Skill improvements

- Before stating a dependency's version in a prompt, read it from the build tool (`go list -m`, the lockfile resolver), not from the manifest's `require` line. A `replace` or override directive can pin the build to another version, and a wrong version in the prompt sends every agent to re-verify behavior against code that the build never compiles.
- When a change adds behavior to a function that several commands or entry points call, read each caller's help text, doc comment and user documentation for promises about what that caller does ("only starts", "never changes"). The new behavior breaks them while none of their lines appear in the diff.
- When a change replaces a condition at several sites with one shared helper, confirm that a test reaches the new value at each site. A test that pins the helper through one caller leaves the other sites free to regress, and a mutation at each site is the cheap check.

### Repo context updates

- [repo] UPDATE the `replace` entry for `github.com/lima-vm/lima/v2`: the `replace` block in `rdd/go.mod` also pins every `k8s.io/*` module to one version, which can sit below the `require` lines that a dependency bump moved. - [repo] `setAction` in `rdd/cmd/rdd/set.go` backs `rdd set`, `rdd start`, `rdd stop` (after its own existence checks) and `rdd run`. Behavior added there reaches all four, so check each command's help text and its `cmd_app.md` section against the change.
