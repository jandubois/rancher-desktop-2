Review Process Notes ¶

Skill improvements ¶

  • [ ] When code compares another component's condition reason, status value or string format, find the producer and confirm it emits that exact value. A test fixture that types the expected value in passes whether or not the producer agrees, so a passing test doesn't settle it.

Repo context updates ¶

  • [ ] [repo] An Image mirror's status.repoTag is the engine's own string. The moby mirror stores Docker's RepoTags, which moby renders in familiar form (foo/bar:latest, with docker.io/ and library/ dropped), while containerd stores the full reference. Code that looks up an Image by a normalized reference must try both forms, and a digest reference needs status.repoDigests.
  • [ ] [repo] Under moby the only ContainerNamespace is moby, and the Docker watcher prunes every other one. The ImagePullRequest webhook rejects any other spec.namespace, so a controller that creates pull requests must take the namespace from the running engine.
  • [ ] [repo] An ImagePullRequest settles with Settled=True and reason ImagePulled or Errored, plus Failed=False or True. The reason constants are unexported in the engine package, so consumers should read the Failed condition.
  • [ ] [repo] controller-runtime's fake client ignores a cancelled context and doesn't run admission webhooks. A status write on a context that the code itself cancels, or a child object a webhook would reject, passes unit tests and fails against the API server; ask for an interceptor that honours ctx.Err() or the envtest harness.
