Executive Summary ¶

PR #831 applies five findings from the last review of #773. It corrects the workingDir wording, moves the spec.name rule into a CRD pattern, switches to api.MirrorName, reads only through the uncached reader, and rejects a workingDir that is not a directory. Each fix does what it should, and the pattern accepts exactly the names compose-go accepted. But no test pins the FIFO guard, and the commit message names a field and a validator the change does not touch.

Skill improvements ¶

  • When a PR says it addresses the review of an earlier PR, fetch that review's report and inline the findings the PR claims, and the ones it leaves unclaimed, as the specification of record. The diff shows what changed, not which finding each change answers, so without the report agents cannot tell a partial fix from a complete one, or an old finding from a new one.

Repo context updates ¶

  • [repo] rdd/.golangci.yml forbids t.Fatal* in tests through forbidigo. A test's timeout or unreachable branch fails with assert.Assert(t, false, msg), as the existing tests do. Check a proposed test patch against this rule before quoting it.
  • [repo] Nothing in CI checks that rdd/go.mod is tidy. go-mod-k8s-sync.yaml runs go mod tidy only on PRs that touch rdd/go.mod, and commits the result to same-repository PR branches. When a diff deletes an import, run go mod tidy -diff in rdd/, since the stale requirement otherwise surfaces in the next unrelated PR that touches go.mod.
