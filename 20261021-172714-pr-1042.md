## Executive Summary

Round 3 reworks the plugin test, which now fails when the plugin is unregistered, and adds a commit that closes watch streams that a rewatch leaves behind. That commit helps only once the stale stream delivers an event. A stream that never delivers one stays open until the apiserver ends it, 30 to 60 minutes later, and the new comment misstates why. Two checks in `ListWatch` close every case. The partial-filter, Volumes-watch and getter-comment gaps remain.

## Important Issues

I1. **Commit 8 closes a stale stream only after a watch event, and its comment misstates why** — `pkg/rancher-desktop/store/rddConnection.ts:635-639` [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.1 Pro, Gemini 3.5 Flash]

```ts
      } else {
        // Stale watcher; destroy it.  It's probably already marked as stopped,
        // but the connection initiated while the marker was still false.
        watcher.stop(errorManuallyStopped);
      }
```

Its comment says the stream connected while `stopped` was still false. But in round 2's S2 case, a rewatch during the first list, `stop()` sets the flag while the list is awaited, and `doneHandler` opens the watch afterwards without checking it again (`pkg/rdd-client/cache.ts:176-209`).

When the list returns items, `addOrUpdateItems` fires `change` before `this.request` exists (`pkg/rdd-client/cache.ts:191`), so this `stop()` aborts nothing. An empty list does not fire `change`, and a `stop()` while the watch connects misses the same way. Each stream then stays open until a watch event arrives or the apiserver's default watch timeout, 30 to 60 minutes, ends it. The leak predates the PR; the comment and body that the code contradicts make this Important.

## Design Observations

### Concerns

- **(in-scope)** On a namespaced page, the first list of containers, images or volumes goes out unfiltered, because `currentNamespace` is `undefined` until `namespaces` loads (`container-engine.ts:83`). The namespace load then changes the getter, and the plugin rewatches while those lists are usually still in flight, which is the window I1 leaks. The merge-base kept the unfiltered rows until the user picked a namespace, so this PR shortens the flash. ### Skill improvements

- When staging installed dependencies for agents from the main checkout, compare the staged versions of the packages that the reviewed manifest pins against that manifest before launching, and install into the stage when they differ. A checkout's `node_modules` lags its own branch after a rebase or a dependency bump, and every agent's test run then exercises other versions without saying so.

### Repo context updates

- [repo] In this repository, eslint run with `node_modules` symlinked into a worktree reports `import-x/order` errors in files that pass CI, untouched files included. Before reporting an import-order or other import-resolution finding, lint with a real install (`yarn install --immutable --mode=skip-build`) or compare against the same run on an untouched file.

Size a leaked renderer watch by that lifetime, not by the next event.

I1. **Ineffective stale watcher cleanup in `Watcher.start`** — `pkg/rancher-desktop/store/rddConnection.ts:635-638` (important, regression)

```ts

      // Only trigger a change if this is the current watcher.
      if (Object.is(watcher, this.#watcher)) {
        this.onChange();
      } else {
        // Stale watcher; destroy it.  It's probably already marked as stopped,
        // but the connection initiated while the marker was still false.
        watcher.stop(errorManuallyStopped);
      }
    });
```

When `Watcher.start()` replaces an active watcher while `listFn()` is in flight, `watcher.stop()` marks `stopped = true` but cannot abort the watch because `this.request` is undefined until line 209 of `pkg/rdd-client/cache.ts`. For empty initial lists, `change` never fires initially, leaving the stream open until a mutation or server close.

###### Design Observations

###### Concerns

- **Retained `selectedNamespace` in state restores deleted namespace without user action** `(in-scope)`: In `pkg/rancher-desktop/store/container-engine.ts:80-82`, `currentNamespace` falls back to `'default'` when `state.selectedNamespace` is deleted. However, `state.selectedNamespace` is never reset. If a namespace with the same name is later recreated in the guest, `getters.namespaces.includes(state.selectedNamespace)` becomes true again, and the UI shifts back to that namespace unexpectedly. Consider clearing or syncing `state.selectedNamespace` when it is no longer present in `getters.namespaces`.
- **Unfiltered initial resource list before namespace list loads** `(in-scope)`: In `pkg/rancher-desktop/store/container-engine.ts:17-22`, `resourceFieldSelector` evaluates `currentNamespace`. When `setupResourceWatch` runs at app startup, `currentNamespace` is `undefined` because `namespaces` is empty `[]`. Consequently, the initial ListWatch for containers, images, and volumes sends no field selector, fetching all objects across all namespaces before re-watching once namespaces load.
- **`BodyContainerEngine.vue` hardcodes tabs rather than deriving from `preferencesNavItemsMap`** `(future)`: While `BodyVirtualMachine.vue:23` computes `tabs` dynamically from `preferencesNavItemsMap['virtual-machine'].tabs`, `BodyContainerEngine.vue:44-58` hardcodes `<tab name="general">` and comments out `allowed-images`. Deriving tabs from `preferencesNavItemsMap` would keep navigation and rendering synchronized.
- **Disabled volume browsing leaves unreachable, broken `/volumes/files/:name` page mapping removed `initialPreferences`** `(future)`: Line 149 of `pkg/rancher-desktop/pages/Volumes.vue` hardcodes `enabled: false` on `browseFiles`. The target page `pages/volumes/files/_name.vue:167` maps `initialPreferences`, which was removed from the preferences store during RDA migration; if ever reached, it throws a TypeError when accessing `this.settings.containerEngine`.

###### Strengths

- **Single reactive getter watch covers all namespace transitions**: Watching the `currentNamespace` getter via Vuex `store.watch` in `container-engine.ts:290-300` cleanly captures user selections, initial namespace list loading, engine switches, and namespace deletions in one centralized handler.
- **Positive reference count check in `rewatchResources`**: `rddConnection.ts:550` checks `watcherInfo.refCount > 0` before restarting watchers, preventing unnecessary requests for inactive resources while the plugin filter (`container-engine.ts:288`) safely excludes `namespaces`.
