Executive Summary ¶

PR 1120 adds a two-stage generator that rebuilds the nerdctl stub's parse table from nerdctl v2.1.2's cobra tree, checks the path overlay against that tree, and joins make verify-generate. It reproduces the checked-in table byte for byte. No Critical or Important finding survived, so this round converged and the suggestions are optional. At the next bump, v2.4.1 adds image import, and nothing flags its host-file argument (S1). The root-flag check also has gaps that no release through v2.4.1 triggers.

Design Observations ¶

Strengths ¶

  • The generator reproduces the shipped table (in-scope) Claude Opus 5.5 Codex GPT 6 Astra: CI's full run on Linux and extract on macOS both leave the checked-in files byte-identical, so the generator matches the table that an earlier PR shipped.
  • The overlay check runs both ways (in-scope) Claude Opus 5.5 Codex GPT 6 Astra Gemini 3.5 Flash: a stale entry fails, an alias key fails with the canonical name, and an unclassified flag that looks like a path fails. nerdctl v2.4.1's new root --log-file, a host path, is the kind of flag it stops on at the next bump.
  • Extract fails loudly on command-list changes (in-scope) Claude Opus 5.5: a new AddCommand argument shape or a package-main constructor that replica.go lacks stops generation.
  • A separate module keeps nerdctl's dependencies out of rdd (in-scope) Codex GPT 6 Astra.

Testing Assessment ¶

The generator module does not have tests, and make test would not run them anyway, because ./... in rdd/ stops at the module boundary (S9). The checks that exist cover the output. I ran these at the review SHA:

  • go run ./extract on macOS rewrote both zz_generated_* files with no diff.
  • GOOS=linux go build . and GOOS=linux go vet ./... of the module passed.
  • go test ./pkg/nerdctlstub/... passed.

CI's Verify generated files job also passed at the review SHA after running the whole generator on Ubuntu. When I finished, 46 checks had passed and 3 were skipped. BATS (windows-latest, bats-app), the only leg that runs the stub's host-path translation, was still running, as was BATS (macos-15-intel, bats-app). These two commits do not change translation code, so that leg matters more to #1119's review. Extract does not have a build tag, so a unit test for collectRootFlags such as the S2 probe would run on any OS once the module has a test target.

Documentation Assessment ¶

  • nerdctl.md:117-119, replica.go:23-25 and extract/main.go:17-18 promise that any root-flag change fails generation. S2 shows two kinds of change that do not. One is a flag registered through a pflag method whose name lacks Flag and that pflagConstructors does not list, and the other is a flag whose type changes.
  • The bump steps at nerdctl.md:143-147 cover flags only (S1).
  • Checked and correct: TestTableMatchesGuestNerdctl exists (parse_args_test.go:299), MAX_VERSION is at scripts/dependencies/nerdctl.ts:21, the tigron pin and its comment are at generate/go.mod:145-148, and nerdctl v2.1.2 leaves container cp and apparmor out of non-Linux builds.

Acknowledged Limitations ¶

Review Process Notes ¶

Skill improvements ¶

  • When the code under review exists to keep working across dependency bumps (a generator, a drift check, a compatibility table), stage the dependency's latest release beside the pinned one and check the code against both. The pinned version alone cannot separate dead code from code written for the next release, and only the next release shows which of the promised failures fire.
  • Before launching agents, search the earlier review reports for the files that the PR changes. When another PR's review already covered the same code, as happens when a branch is recut into a stack, load those reports as prior rounds, with their declined items and do-not-re-suggest notes, even when the PR body does not mention them. A round counter keyed on the PR number misses them, and the agents then re-raise what the earlier rounds settled.
  • When a liveness monitor reports an agent stalled, read its stderr before relaunching it. A CLI that sleeps on a quota retry prints the quota message to stderr once and then goes quiet, so it looks hung, and a relaunch hits the same quota.

Repo context updates ¶

  • [repo] A recipe or script that runs a host Go tool with go run must pin GOOS=$(HOST_OS) GOARCH=$(HOST_ARCH), as rdd/Makefile explains above its download recipe; otherwise a GOOS set on the make command line, or saved with go env -w, builds the tool for another OS. Flag a new host-tool invocation that leaves the pin out.
  • [repo] A nested Go module under rdd/ is outside ./..., so make test and make lint-rdd never reach it. For each such module, check which CI job builds, tests or lints it before calling it covered.
