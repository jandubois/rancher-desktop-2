Review Process Notes ¶

Skill improvements

  • Before trusting the ROUND value the lead helper exports, check the reviews branch for an existing review of the same target (git ls-tree reviews | grep <target>). When a prior review exists but the helper reports ROUND=1, treat this as round N+1 and apply the prior-round gates. The helper's round detection can miss a committed review and silently skip the prior-round reconciliation.
  • When a change replaces a hand-rolled polling loop with a framework poll/retry primitive (Playwright expect.poll, toPass, testing-library waitFor), verify the polled function still tolerates the transient errors the old loop swallowed. Many such primitives retry only when an assertion fails, not when the polled function itself throws, so a function that now throws on a transient error fails immediately. Flag a refactor that drops a try/catch-to-sentinel guard from a function handed to such a primitive.
  • When test cleanup hands a spawned resource's identity (PID, handle, port) from a setup hook to a teardown hook through the test framework's own facilities (attachments, annotations, context), verify the framework shares that state across those hooks. Several frameworks scope per-test state per test, so the setup and teardown hooks see different instances and the handoff silently yields nothing. Prefer module-scoped state for cross-hook resource handles.
  • Cleanup that is the sole owner of a spawned process or resource must not sit behind throwable setup or teardown calls. Verify it runs even when an earlier step throws — a finally block or an unconditional guard. Flag must-run resource cleanup placed after a call that can throw on a partially-initialized fixture.
  • For a review whose assembled prompt embeds a large inlined diff (roughly above 100 KB), budget a longer in-process Claude watchdog than the default 900 s. Thorough review of a large diff routinely exceeds it, and a watchdog kill of a still-progressing agent costs a full retry.
