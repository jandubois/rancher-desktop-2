## Executive Summary

The PR turns the Volumes e2e spec back on, makes the mock volume reconciler keep deleted fixture volumes deleted, and moves three SortableTable row comparisons to key matching. CI ran the restored spec green once. But the mock's deletion tracking races the GUI's concurrent bulk delete. In an envtest probe a deleted volume came back in 6 of 20 rounds, which fails "should support bulk operations". A spec comment also still says the mock always mirrors its fixture.

## Important Issues

I1. **The mock reconciler recreates a volume deleted during a reconcile, and keeps it** — `rdd/pkg/controllers/mock/volume_reconciler.go:175-178` [Claude Opus 5.5, Codex GPT 6 Astra]

```go
		CreateFunc: func(_ context.Context, evt event.TypedCreateEvent[client.Object], q workqueue.TypedRateLimitingInterface[reconcile.Request]) {
			r.deletedMu.Lock()
			delete(r.deleted, evt.Object.GetName())
			r.deletedMu.Unlock()
```

`Volumes.vue:175` sends the requests of a bulk delete concurrently, so the first delete event starts a reconcile while the others are in flight.

When a volume's DELETE reaches the API server after that reconcile has checked `isDeleted` but before it calls `Apply` (`volume_reconciler.go:85-98`), the server-side apply creates the volume again. The watch then delivers Delete and then Create, and the handler above clears the mark, so the volume stays.

The bulk test's API check (`e2e/volumes.e2e.spec.ts:234-236`) then fails. CI has run the spec once, and it passed.

The probe runs the reviewed reconciler against envtest's API server. Concurrent deletes left a volume behind in 6 of 20 rounds, and deletes 300 ms apart left none.

## Suggestions

S1. **`lastMessageBox` waits out the whole test timeout when no dialog opens** — `e2e/volumes.e2e.spec.ts:34-36` [Claude Opus 5.5]

```ts
async function lastMessageBox(electronApp: ElectronApplication) {
  return await electronApp.evaluate(() => (globalThis as any).lastMessageBox);
}
```

The stub's Promise resolves only when `dialog.showMessageBox` runs (line 21), and `expect(...).resolves` at lines 133, 154, 183 and 217 does not have a timeout of its own. If the confirmation ever stops calling `showMessageBox`, the test waiting on it hangs until the Playwright test timeout and fails with "Test timeout exceeded" instead of naming the missing dialog.

`e2e/config/playwright-config.ts:16` sets that timeout to ten minutes times `timeScale`, which is 4 on CI, so each attempt waits 40 minutes.

Fix: store the options as a plain value, cleared when the stub is installed, and assert with `expect.poll(() => lastMessageBox(electronApp)).toMatchObject(...)`, which fails after the expect timeout.

## Design Observations

### Concerns

- **(in-scope)** The mock tracks deletions through watch events while `Reconcile` acts on the API server, so the two disagree whenever events lag a reconcile (I1). Seeding each fixture once and leaving deletion to the API server removes that state, and the I1 patch does so. [Claude Opus 5.5, Codex GPT 6 Astra]

### Strengths
