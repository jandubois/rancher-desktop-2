## Executive Summary

PR 1120 adds a two-stage generator that rebuilds the nerdctl stub's parse table from nerdctl v2.1.2's cobra tree, checks the path overlay against that tree, and joins `make verify-generate`. It reproduces the checked-in table byte for byte. No Critical or Important finding survived, so this round converged and the suggestions are optional. At the next bump, v2.4.1 adds `image import`, and nothing flags its host-file argument (S1). The root-flag check also has gaps that no release through v2.4.1 triggers.

S1. **The next bump adds `image import`, and nothing prompts its positional handler** — `rdd/docs/design/nerdctl.md:143-147` [Claude Opus 5.5]

```markdown
A nerdctl bump therefore takes four steps. Raise `MAX_VERSION` in the
repository's top-level `scripts/dependencies/nerdctl.ts`, so that rddepman
moves `dependencies.yaml`.
Move `generate/go.mod` to the same version, along with the `tigron` pin that

```

The bump steps end with "classify whatever it names", but the generator names only flags. nerdctl v2.4.1, the current release, adds `image import` and a root `import` (`cmd/nerdctl/main.go:320` at v2.4.1). Its usage is `import [OPTIONS] file|URL|- [REPOSITORY[:TAG]]`, and its only flags are `--message` and `--platform`, so the overlay check stays quiet. `parse_args.go:393-394` already says to restore the 1.x `imageImportHandler` when a bump brings the command back, but nothing makes the person bumping read that comment. If they follow the documented steps, the generator and `verify-generate` pass, and `rdd nerdctl import C:\images\app.tar` reaches the guest untranslated.

Fix: add a bump step that checks each command that the regenerated table adds for positional host paths, and name `image import` there as the known case.

S3. **`notPathFlags` calls `--gpg-homedir` guest-side, but the same commands translate `--key`** — `rdd/pkg/nerdctlstub/overlay.go:210-214` [Consolidator]

```go

		"--gpg-homedir", // guest-side
	},
	"image encrypt": {
		"--gpg-homedir", // guest-side
```

`image encrypt` and `image decrypt` read the user's key material through two flags. `pathFlags` translates `--key`, a list of key files, as host paths (`overlay.go:105-110`), but these new entries mark `--gpg-homedir`, the GnuPG directory that holds the keys, as guest-side. A Windows user who names a host GnuPG directory there gets the `C:\...` path passed to the guest unchanged. The project's pending work lists `--gpg-homedir` as a host path that needs a `filePathArg` entry, so the comment records the opposite decision.

Fix: move both entries to `pathFlags` as `filePathArg`, or, if the guest's own keyring is the target, say so in the comment and close the pending item.

S7. **cobra command aliases never reach the alias map** — `rdd/pkg/nerdctlstub/generate/main.go:141-145` [Claude Opus 5.5, Codex GPT 6 Astra]


`walk` records `sub.Name()` but not `sub.Aliases`, so `detectAliases` finds only commands built twice from one constructor. nerdctl v2.1.2 declares eight cobra aliases (`ns`, `namespace list`, `namespace rm`, `network list`, `network remove`, `volume list`, `volume remove`, `apparmor list`), and the stub passes each through unparsed. ## Design Observations

### Strengths

- **The generator reproduces the shipped table** (in-scope) [Claude Opus 5.5, Codex GPT 6 Astra]: CI's full run on Linux and extract on macOS both leave the checked-in files byte-identical, so the generator matches the table that an earlier PR shipped.
- **The overlay check runs both ways** (in-scope) [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash]: a stale entry fails, an alias key fails with the canonical name, and an unclassified flag that looks like a path fails. nerdctl v2.4.1's new root `--log-file`, a host path, is the kind of flag it stops on at the next bump.
- **Extract fails loudly on command-list changes** (in-scope) [Claude Opus 5.5]: a new `AddCommand` argument shape or a package-main constructor that `replica.go` lacks stops generation.
- **A separate module keeps nerdctl's dependencies out of rdd** (in-scope) [Codex GPT 6 Astra].

## Acknowledged Limitations

- **`HiddenPersistentStringArrayFlag` in `helperNameArg`** (`extract/main.go:223`): nerdctl v2.1.2 does not have that helper, but v2.2.0 through v2.4.1 call it three times in `initRootCmdFlags`, with the flag name as argument 1. The entry is ready for the next bump; do not re-suggest deleting it.
- **`--recipient` key files stay untranslated** (`overlay.go:215-217`), as its comment says.
- **Commands from nerdctl's internal packages stay out of the table** and pass through unparsed (`extract/main.go:184-186`).
- **Nothing checks the replica's `version` subcommand** against upstream (`replica.go:25-26`).
- **MSYS2 would rewrite `--workdir` for a native `docker.exe`** (`generate-nerdctl.sh:36`). #974's second round declined this until someone runs the script on Windows, and the project's pending work tracks it. All three reviewers raised it again. The `--volume` mount takes `git rev-parse --show-toplevel`, which Git for Windows prints as `C:/...`, so do not re-suggest a `cygpath` conversion without a Windows run that shows the mount failing.
- **Host paths inside `key=value` values stay untranslated**, such as `--security-opt seccomp=<path>` and `--log-opt log-path=<path>`. The path heuristics read only a flag's name and usage text, so they cannot see these values, and `nerdctl.md:62-63` tells users to write guest paths there. #974's second round declined translating them, and the project's pending work tracks that. Listing these flags in `notPathFlags` belongs to that work.

## Review Process Notes

### Skill improvements

- When the code under review exists to keep working across dependency bumps (a generator, a drift check, a compatibility table), stage the dependency's latest release beside the pinned one and check the code against both. The pinned version alone cannot separate dead code from code written for the next release, and only the next release shows which of the promised failures fire.
- Before launching agents, search the earlier review reports for the files that the PR changes. When another PR's review already covered the same code, as happens when a branch is recut into a stack, load those reports as prior rounds, with their declined items and do-not-re-suggest notes, even when the PR body does not mention them. A round counter keyed on the PR number misses them, and the agents then re-raise what the earlier rounds settled.
- When a liveness monitor reports an agent stalled, read its stderr before relaunching it. A CLI that sleeps on a quota retry prints the quota message to stderr once and then goes quiet, so it looks hung, and a relaunch hits the same quota.

### Repo context updates

###### Design Observations

###### Concerns

- **Two-stage generator split across build constraints** (in-scope):
  The separation into `extract` (AST inspection) and `generate` (runtime Cobra tree walk) is necessitated by nerdctl defining `apparmor` and `container cp` under `//go:build linux` and keeping `newApp` in `package main`. The wrapper container in `generate-nerdctl.sh` bridges this for non-Linux hosts, but requires container execution for non-Linux developers running `verify-generate`. Excluding `generate-nerdctl` from `make generate` avoids requiring Docker for everyday development, though running `make check` on macOS/Windows still triggers `verify-generate`.

###### Strengths

- **AST verification of replica command definitions**:
  Comparing extracted root flags against `replicaRootCmd` via `verifyRootFlags` and checking unresolved `package main` constructors prevents silent drift when upstream nerdctl alters global flags or root commands.
- **Bi-directional overlay validation**:
  Checking both that all overlay entries exist on actual commands and that all path-smelling flags are classified ensures newly added flags in nerdctl bumps cannot be quietly ignored.

###### Testing Assessment

Missing tests:
- **I1** (required, check 3 from Testing #11): A test verifying that `validateOverlay` rejects overlapping entries between `pathFlags` and `notPathFlags`. Without this test, duplicate classifications escape generation and cause unhandled panics at daemon startup.
- **I3** (required, check 3 from Testing #11): A test verifying `nerdctlModuleInfo` handles module directories with spaces.

###### Documentation Assessment

`rdd/docs/design/nerdctl.md:99-148` cleanly documents the two-stage generator design, Linux-only build constraints, container wrapping for non-Linux hosts, and the four-step workflow for nerdctl version bumps.

###### Commit Structure

The commits under review (`b3a13c7c3` and `9959a3e63`) each represent a distinct, self-contained concept:
- `b3a13c7c3`: Introduces the generator module, replica, AST extractor, and overlay classification.
- `9959a3e63`: Integrates the generator into the build system and `make verify-generate`.

Commit messages are descriptive, follow project conventions, and explain technical rationale.

###### Acknowledged Limitations

- **Overlay path heuristics require human classification** (`rdd/docs/design/nerdctl.md:133-148`): The author documents that nerdctl does not annotate path-consuming flags (`cobra.MarkFlagFilename`), requiring suspect flags to be classified in `pathFlags` or `notPathFlags`.
- **Untranslated key-file flags in `image encrypt`** (`rdd/pkg/nerdctlstub/overlay.go:216-220`): `--recipient` takes `prefix:value` where `value` may be a key file; the author documents that such paths remain untranslated.
- **Skipped internal nerdctl commands** (`rdd/pkg/nerdctlstub/generate/extract/main.go:200-205`): Internal commands cannot be imported across Go modules and pass through the parser unmodified.
- **Container engine requirement off Linux** (`rdd/Makefile:341-344` and `rdd/scripts/generate-nerdctl.sh:31-33`): `generate-nerdctl` is omitted from `make generate` to avoid requiring a container engine on macOS/Windows for standard code generation.
