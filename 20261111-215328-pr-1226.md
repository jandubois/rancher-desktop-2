## Suggestions

S1. **The probe's doc comment leaves out the credential and file errors that also keep current-context** — `rdd/pkg/controllers/app/kubernetes/controllers/kube_reconciler.go:540-542` [Claude Opus 5.5]

```go
// If a path lookup or kubeconfig parse fails, or client-go refuses the TLS
// settings, it returns true to leave the user's current-context alone; each
// such path logs the underlying error.
```

`ClientConfig()` at line 574 validates the context's user stanza and every file path in the context, before `reachabilityHTTPClient` looks at the TLS settings. When that validation fails, the probe returns true, though it never sends those credentials. A dead cluster whose user names a client certificate file that no longer exists probes as reachable, while the same cluster without the user stanza probes as unreachable (scratch test at the review SHA). An `exec` stanza with no `apiVersion` behaves the same way, at this head and at the merge-base. The behavior follows how earlier rounds treated a missing client-certificate file. But the rewritten sentence names only TLS settings, one paragraph after the docstring says the probe does not send credentials, so a reader assumes the user stanza cannot matter. Adopting the design concern below would change this sentence again.

Fix: name the wider case.

```go
// If a path lookup or kubeconfig parse fails, or client-go refuses the
// context's settings, such as its TLS settings, a missing file or its user's
// credentials, it returns true to leave the user's current-context alone;
// each such path logs the underlying error.
```

S2. **The live-cluster https-proxy subtest also passes on the merge-base code** — `rdd/pkg/controllers/app/kubernetes/controllers/kube_reconciler_test.go:1149-1154` [Claude Opus 5.5]

```go
		writeClusterKubeconfig(t, destPath, "other", &clientcmdapi.Cluster{
			Server:                cluster.URL,
			ProxyURL:              proxy.URL,
			InsecureSkipTLSVerify: true,
		})
		assert.Assert(t, probeCurrentKubeContext(t.Context(), "other"))
```

On the merge-base code, the probe fails to verify the proxy's certificate and counts that error as reachable, so this subtest passes without the probe ever reaching the cluster. It does not show that `insecure-skip-tls-verify` lets the probe tunnel through the proxy. A `served` flag in the cluster's handler closes that gap, as the flag in the client-certificate subtest already shows that its server answered. With the flag, the subtest passes at the review SHA and fails with the merge-base `kube_reconciler.go` (`kube_reconciler_test.go:1157: assertion failed: expression is false: served.Load()`). I ran both in the lead worktree.

Fix: set `served.Store(true)` in the cluster's handler and add `assert.Assert(t, served.Load())` after the probe call.

## Design Observations

### Concerns

- **The probe validates credentials that it never sends** (future) [Claude Opus 5.5]. `ClientConfig()` checks the context's user stanza, so a broken credential config, such as a client certificate file deleted along with its cluster, keeps a dead context current (S1). Building the REST config from a copy of the context with an empty `AuthInfo` would validate only the cluster settings, and rdd could then switch away from such a context. The maintainer's ruling covered TLS settings that client-go refuses. Earlier rounds treated a missing client-certificate file as the same case without asking for a separate ruling. Whether broken credential settings belong in that case is still the maintainer's question, and the findings and tests in this report do not assume either answer.

### Strengths

- **One transport builder for both probes** (in-scope) [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash]. `probeTransport` replaces two hand-built `tls.Config`s with `rest.TLSConfigFor`, so CA file and data, `insecure-skip-tls-verify` and `tls-server-name` follow kubectl's rules in both probes.
- **`rest.AnonymousClientConfig` before `TLSConfigFor`** (in-scope) [Claude Opus 5.5, Gemini 3.5 Flash]. It drops client certificates, tokens and the exec and auth-provider settings, so the reachability check never builds an authenticator. The subtest "the probe does not send a client certificate" confirms that the server does not receive one.
- **`fakeK3sServer` demands a client certificate** (in-scope) [Claude Opus 5.5, Codex GPT 6 Astra]. A k3s probe that stops presenting the kubeconfig's certificate now fails `Test_Reconcile_KubernetesReady_Ready`.

## Review Process Notes

### Skill improvements

- When a target's earlier reviews happened outside `.reviews/`, such as single-reviewer rounds recorded only in the author's notes, inject every finding that those rounds dropped, with its reason, alongside the maintainer's rulings. Agents re-raise a dropped finding when the prompt lists only the rulings, and the consolidator then has to repeat the earlier round's reasoning.

### Repo context updates

- [repo] The current-context reachability probe (`probeCurrentKubeContext`) leaves current-context alone whenever it cannot judge the cluster: the kubeconfig fails to load, client-go refuses its TLS settings, or a certificate check fails, including one at an https proxy. The bias is deliberate, because a wrong switch takes a live context away from the user, so do not flag a dead context kept current in these cases as a defect.

###### Acknowledged Limitations

- **Certificate errors from HTTPS proxies treated as reachable**: Go checks an HTTPS proxy's TLS certificate using the cluster's TLS settings. When verification fails, the probe cannot reach through the proxy (and neither can `kubectl`), so `rdd` leaves `current-context` untouched (`kube_reconciler.go:602-606`).
- **Rejected TLS settings leave current-context alone**: If client-go refuses the TLS configuration (e.g. `certificate-authority` combined with `insecure-skip-tls-verify`, or unparseable CA data), `reachabilityHTTPClient` returns an error and `probeCurrentKubeContext` returns `true` (`kube_reconciler.go:431-432, 540-542`).
- **Missing CA or client cert files leave current-context alone**: If a referenced certificate file does not exist, `ClientConfig()` validation fails and the probe preserves `current-context`.
- **Plain HTTP probe timeout**: An HTTP cluster must reply within the 3s timeout; an unresponsive server test was omitted deliberately to avoid stalling the test suite (`kube_reconciler.go:537-538`).
