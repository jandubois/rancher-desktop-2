## Executive Summary

Round 1's deadline fix bounds silence only. A peer sending one byte per stall
window keeps `make build-rdd` running forever, which my probe confirms at 20
stall windows and counting. Three mechanisms round 2 added (progress reporting,
the `Retry-After` wiring, the response-header timeout) can each be deleted with
the suite still green. Everything else in the round is correct, and `go test`,
`-race`, `go vet` and `golangci-lint` are all clean at this SHA.

the manifest's dependency key. I dropped the traversal claim after proving

no longer stacked and both commits below are its own work.

## Important Issues

I1. **A peer that trickles keeps the build alive forever** — `rdd/pkg/guestdeps/stage.go:520` [Codex GPT 5.6 Sol, Claude Opus 5]

```go
func (r *progressReader) Read(p []byte) (int, error) {
	n, err := r.body.Read(p)
	r.read += int64(n)
	r.timer.Reset(stallTimeout)
```

Every read restarts the 30-second timer, so the limit falls on the gap between
bytes. Nothing bounds the transfer itself: `httpClient` sets no `Timeout`
(58-62), and `main.go:41` derives its context from `context.Background()` with
no deadline. A server delivering one byte every 29 seconds holds a temporary
file and a build slot indefinitely, which is the failure round 1's I1 named.

I judged this fresh rather than as a narrowed fix, because a trickle is a
different server behaviour from the silence round 1 named; the `progressReader`
comment (486-489) does document the per-gap limit. GitHub's CDN already
throttles this project's distro downloads, so a slow trickle is the likelier
degradation; the new progress lines at least make it visible.

```go repro
// Save as rdd/pkg/guestdeps/probe_trickle_test.go; run:

package guestdeps

import (
	"context"

	"encoding/hex"

// serve starts a server that writes one byte every gap and never finishes, or,
// when gap is zero, sends the headers and then goes silent.
func serve(t *testing.T, gap time.Duration) string {
	done := make(chan struct{})
	srv := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		w.(http.Flusher).Flush()
		for {
			if gap > 0 {
				_, _ = w.Write([]byte("x"))
				w.(http.Flusher).Flush()
			}
			select {
			case <-r.Context().Done():
				return
			case <-done:
				return
			case <-time.After(max(gap, 10*time.Millisecond)):
			}
		}
	}))
	t.Cleanup(srv.Close)
	t.Cleanup(func() { close(done) })
	return srv.URL + "/distro.raw.xz"
}

// stage runs Stage in the background and reports whether it returned within
// patience, plus the error it gave.
func stage(t *testing.T, ctx context.Context, url string) (time.Duration, error, bool) {
	sum := sha256.Sum256([]byte("never served"))
	dep := Dependency{Name: "distro", Version: "0.2.7", Asset: Asset{
		Platform: "linux", Arch: "arm64", Variant: "raw",
		URL: url, Checksum: "sha256:" + hex.EncodeToString(sum[:]),
	}}
	dir := t.TempDir()
	s := &Stager{CacheDir: filepath.Join(dir, "cache")}
	done := make(chan error, 1)
	start := time.Now()
	go func() { done <- s.Stage(ctx, dep, filepath.Join(dir, "embedded", "distro.raw.xz")) }()
	select {
	case err := <-done:
		return time.Since(start), err, true
	case <-time.After(4 * time.Second):
		return time.Since(start), nil, false
	}
}

func TestProbeTrickle(t *testing.T) {
	// Shorten the schedule so 4 seconds of patience is 20 stall windows.
	oldStall, oldDelay, oldMax := stallTimeout, retryDelay, maxRetryDelay
	stallTimeout, retryDelay, maxRetryDelay = 200*time.Millisecond, time.Millisecond, 10*time.Millisecond
	t.Cleanup(func() { stallTimeout, retryDelay, maxRetryDelay = oldStall, oldDelay, oldMax })

	// The case the round-1 fix closes: a peer that goes completely silent.
	d, err, returned := stage(t, t.Context(), serve(t, 0))
	t.Logf("silent peer:  returned=%v after %v: %v", returned, d.Round(time.Millisecond), err)

	// The case it does not: the same peer sending one byte per half-window.
	d, err, returned = stage(t, t.Context(), serve(t, stallTimeout/2))
	t.Logf("trickling peer: returned=%v after %v (%d stall windows): %v",
		returned, d.Round(time.Millisecond), int(d/stallTimeout), err)

	// The proposed fix, applied at the caller: an overall deadline.
	ctx, cancel := context.WithTimeout(t.Context(), time.Second)
	defer cancel()
	d, err, returned = stage(t, ctx, serve(t, stallTimeout/2))
	t.Logf("trickling peer, caller deadline 1s: returned=%v after %v: %v", returned, d.Round(time.Millisecond), err)
}
```

## Suggestions

S1. **A 408 ends the download after one request** — `rdd/pkg/guestdeps/stage.go:365` [Codex GPT 5.6 Sol, Claude Opus 5]

```go
		// A 4xx other than "too many requests" means the manifest names
		// something the server does not have, which a retry cannot conjure up.
		if resp.StatusCode >= 400 && resp.StatusCode < 500 && resp.StatusCode != http.StatusTooManyRequests {
			return 0, &fatalError{err}
		}
```

The comment's reasoning holds for 404 and 410. It does not hold for `408
Request Timeout`, which RFC 9110 defines as a status the client may repeat, so a
transient becomes an immediate build failure with three attempts unspent. The
failure prints `unexpected status 408 Request Timeout` and a re-run recovers,
which keeps this at Suggestion.

Unproven: I cannot make GitHub emit a 408 on demand, so the classification is
read from the code rather than reproduced against the real server.

Fix: exclude `http.StatusRequestTimeout` from the fatal range beside
`StatusTooManyRequests`.

**Resolved: fixed, and widened.** Verification found that a 403 carrying
`Retry-After` was fatal too, which GitHub uses for throttling, so the
`Retry-After` parse now runs before the fatal-4xx test: any status naming a
delay is retried.

S2. **On Windows the cache sits inside the directory `rdd svc delete` removes** — `rdd/pkg/guestdeps/stage.go:82` [Claude Opus 5]

```go
	return filepath.Join(dir, "rancher-desktop-2", "guest-deps"), nil
```

`os.UserCacheDir()` is `%LocalAppData%` on Windows, and `instance.Name()`
defaults to `rancher-desktop-2` (`rdd/pkg/instance/instance.go:17-23`), so this
path is inside `instance.Dir()` (`instance.go:47-62`), which `rdd svc delete`
removes wholesale (`rdd/pkg/service/cmd/service.go:548`). A reset therefore
costs a 217 MB re-download over a CDN this project already gets throttled by.
Bats instances set `RDD_INSTANCE`, so only the default instance collides.

The project memory records this as accepted, at the cost of one re-download. I
raise it only because a sibling directory no `instance.Name()` can produce
escapes it, and also gives `Prune` a tree it owns outright rather than a
subdirectory of the Electron app's own cache. Nothing invokes the tool yet, so
there are no caches to orphan and no test pins the path.

Fix: `filepath.Join(dir, "rancher-desktop-guest-deps")`, or decline again in one
line.

**Resolved: fixed**, with a different name. `rancher-desktop-guest-deps` is
reachable by `RDD_INSTANCE=guest-deps`, and a bare `rancher-desktop` is RD1's
own Windows tree, so the directory is `rancher-desktop.guest-deps`: the dot is
beyond anything `instance.Name()` can build.

The guard's own comment explains itself in terms of "cachePath builds that path

S5. **`touch` refreshes a cache entry it never verified** — `rdd/pkg/guestdeps/stage.go:103` [Claude Opus 5]

```go
	if staged {
		s.logf("%s is up to date", destPath)
		s.touch(cachePath)
		return nil
	}
```

With a valid staged file and a corrupt cache entry, `Stage` returns here having
reset the corrupt entry's mtime. Every later build does the same, so the 7-day
TTL never collects it and 217 MB of unusable bytes stays on disk until the
staged file goes. `Prune`'s comment (139-141) promises to remove "the partial
files a build killed mid-transfer leaves behind", and this is the one such file
it cannot reach.

Fix: touch only when the entry is known good, or say in `touch`'s comment
(129-131) that an unverified entry is refreshed too.

**Resolved: commented.** Verifying on that path would cost the full hash the
path exists to avoid, so `touch`'s comment now records that it refreshes an
unverified entry, and that a corrupt one outlives its TTL.

S6. **Nothing collects a temporary file stranded in the destination directory** — `rdd/pkg/guestdeps/stage.go:412` [round 1 S3 residual]

```go

```

`copyFile` writes its temporary file beside `destPath`, in the build tree.
`Prune` sweeps `CacheDir` alone, and `rdd/Makefile`'s `clean` target removes
only `bin` and the guestagent binaries, so a build killed here strands up to 217
MB that nothing ever removes. `rdd/.gitignore:3` keeps it out of `git status`,
which also keeps it out of sight. Round 1's S3 named this failure and its fix
covered the cache half.

Fix: this belongs with #708's Makefile rule, on the same reasoning that deferred
the `pkg/embedded/` documentation. Either sweep the destination directory for
`.tmp-*` at the start of a run, or add it to `clean`.

**Resolved: declined**, deferred to #708 which adds the Makefile rule and
creates `pkg/embedded`.

S7. **Manifest validation accepts an https URL with no host** — `rdd/pkg/guestdeps/manifest.go:105` [Codex GPT 5.6 Sol]

```go
	if u.Scheme != "https" {
		return fmt.Errorf("asset %s has url %q, want https", a, a.URL)
	}
```

`url.Parse("https:///distro.xz")` returns scheme `https`, host `""` and base
`distro.xz`, so both checks pass and staging fails later with `http: no Host in
request URL` after the full retry schedule. A URL ending in `/` passes too:
`path.Base("https://example.test/dir/")` is `dir`, which then names the
downloaded file. `yarn rddepman` writes neither form, so this only sharpens a
hand-edited manifest's error.

Fix: require `u.Hostname() != ""`, and reject a path ending in `/`.

**Resolved: fixed**, both checks, each with a test that fails without it.

S8. **The vanished-entry fallback can fire on a destination-side ENOENT** — `rdd/pkg/guestdeps/stage.go:117` [Claude Opus 5]

```go
		if err := copyFile(cachePath, destPath); !errors.Is(err, fs.ErrNotExist) {
			return err
		}
```

`copyFile` can produce `fs.ErrNotExist` from `createTemp` (441, 444) and from

**Resolved: fixed**, by the cheaper route: the branch now stats the cache entry
and returns `copyFile`'s own error unless that entry is the file that went.

## Design Observations

### Concerns

- **Concurrent builds do not share the cache** `(future)` [Claude Opus 5]. Eight
  stagers over one cache directory made eight separate downloads in my probe,
  all succeeding, with the right checksum at the destination and no leaked
  temporary files. The goal at lines 71-73, one copy per asset across bats
  worktrees, holds for sequential builds. Two parallel worktrees pull 434 MB.
  Round 1 declined a lock file on this path, so this is a property to know
  rather than a fix to make.
- **`Prune`'s foreign-file heuristic now guards a directory the tool owns**
  `(in-scope)`. `TestPruneLeavesForeignFilesAlone` models `GPUCache`,
  `Cache/data_0` and `updater-longhorn.json`, the Electron cache's neighbours,
  which could only appear inside `CacheDir` under the pre-move layout. After the
  move to `guest-deps/`, nothing else writes there. The heuristic is cheap
  insurance and the tests still pin `isVersionDir`, so I would keep both; the
  comments could say which layout they defend.

### Strengths

- The persistent-state enumeration is thorough [Claude Opus 5, Codex GPT 5.6
  Sol]: temporary-file-then-rename on both write paths, checksums rather than
  timestamps on both files, an explicit fallback for a cache entry pruned
  mid-`Stage`, and `createTemp`'s retry for a directory pruned mid-create.
- Checksumming `destPath` before the cache entry is a real improvement on round
  1's order, and the comment at 94-96 gives the two reasons: offline builds and
  purged caches [Claude Opus 5].
- `TestStagedDepsResolveAgainstTheManifest` resolves all six target tuples
  against the checked-in `rdd/dependencies.yaml`, so a rddepman rename breaks a
  unit test instead of a build [Claude Opus 5].
- `retryAfter` handles both header forms and the `time.Duration` overflow that
  round 1's fix introduced, with a table test naming the wrap [Codex GPT 5.6
  Sol].
- The prune tests use the real neighbours from the app's cache directory rather
  than invented names [Claude Opus 5, Gemini 3.1 Pro].

wants, and the package comment states the problem rather than restating the
name. The `httpClient` comment (55-57) claims a bound `http.DefaultTransport`

at build time" in the present tense while nothing invokes the tool. That file is
outside this PR's diff, and #708 makes the sentence true, so I raise it only as
the sibling of S3.

## Review Process Notes

### Skill improvements

- When a round's fix narrows a prior finding's guarantee, decide whether the
  residual failure is the same server or system behaviour the finding named, or
  a neighbouring one. A fix that closes the named case documents its own reduced
  scope in a comment and is settled; a neighbouring behaviour producing the same
  user-visible failure is a new finding, judged fresh at whatever severity the
  evidence supports. Say in the finding which of the two you decided, so the
  author can see the call rather than the conclusion.
- Before accepting a finding that traces a value into a dangerous sink, find
  where the value is assigned, not where the struct field is declared. A
  constructor that copies a caller's argument into a field of the same name
  looks identical, in the sink's neighbourhood, to one that copies attacker-
  controlled data, and the difference decides the severity.
- Where a finding is that code is untested, prove it by deleting the mechanism
  and running the suite, and include one mutation the suite does catch. A
  coverage percentage names a line count; a surviving mutation names a
  behaviour nobody would notice losing, and the caught control shows the suite
  was capable of noticing.

### Repo context updates

- [repo] `os.UserCacheDir()` on Windows is `%LocalAppData%`, which is also the
  parent of `instance.Dir()` (`rdd/pkg/instance/instance.go`), and `rdd svc
  delete` ends in `os.RemoveAll(instance.Dir())`. Any Go code choosing a cache
  or state directory under `os.UserCacheDir()` on Windows therefore shares a
  tree with the daemon instance and is removed with it. Bats runs set
  `RDD_INSTANCE`, so only the default instance collides. On macOS and Linux the
  same parent is the Electron app's own cache, set from
  `pkg/rancher-desktop/utils/paths.ts`.
- [repo] `rdd/dependencies.yaml` is the guest dependency manifest that
  `yarn rddepman guest` regenerates. `Manifest.Select` takes the dependency name
  from its caller and copies it into `Dependency.Name`; the manifest's own map
  keys never reach a filesystem path. Findings that trace a manifest key into
  `filepath.Join` need a caller that passes one.
- [repo] The `progressInterval` constant, and `httpClient`'s package-init read
  of `stallTimeout`, are the reason `logProgress` and `ResponseHeaderTimeout`
  have no tests in `rdd/pkg/guestdeps`. Sibling knobs in the same file are
  variables with comments saying tests shorten them.

### Notes on what the fixes turned up

Verification overturned four things the review got wrong or left out, each
caught by an adversarial pass over the applied fix:

- **I1 as specified was a regression.** A per-attempt `context.WithTimeout` of
  30 minutes demanded ~145 KB/s sustained for the largest asset, and each
  retry restarts from zero with no `Range` header, so a slow-but-working link
  would have burned two hours and then failed where the old code finished. The
  shipped fix bounds all four attempts together at 2 hours, a 36 KiB/s floor.
- **S1 named only 408.** A 403 carrying `Retry-After` was equally fatal, and
  that is a status GitHub throttles release downloads with. The parse now runs
  before the fatal-4xx test.
- **The progress test passed on every platform I can run.** It would have gone
  red on `windows-latest`, where Go reads the monotonic clock from
  KUSER_SHARED_DATA and it advances on the ~15.6 ms system tick, while a
  test-sized body read finishes in microseconds. Both progress tests now read
  no clock.
- **S2 needed a third directory name.** `rancher-desktop-guest-deps` is
  reachable by `RDD_INSTANCE=guest-deps`, and a bare `rancher-desktop` is RD1's
  own Windows data directory, so the name carries a dot.

Two measurements correct the report: the largest asset is 261,668,428 bytes
(`distro.v0.2.7.amd64.raw.xz`), not the 217 MB quoted throughout, which is the
arm64 asset that happens to sit on the review machine. Coverage of
`pkg/guestdeps` went from 83.3% to 88.6%.
