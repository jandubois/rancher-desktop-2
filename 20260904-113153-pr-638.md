## Important Issues

I1. **Removal reports success over an unbalanced marker, leaving a live `export PATH` line or a permanently unparseable file** — `rdd/pkg/util/managedlines/managedlines.go:145` [Codex GPT 5.6 Sol, Claude Opus 5]

```go
		result = append(result, lines[i])
```

`stripBlocks` keeps an unbalanced marker as ordinary text, and `splitByMarkers` treats the same marker as fatal once no complete pair remains (`managedlines.go:115`). Removing our block flips one state into the other, and `Manage` returns `nil`, so the reconciler writes `PathManagementReady=Applied`. A lone start marker leaves its `export PATH` line active, so `manual` reports a removal that did not happen. A lone end marker leaves a file that every later pass rejects as `Malformed`; under `front`/`back` that pins `Settled` at `False` forever, so `rdd set application.addPath=front --wait` never returns.

```go repro
	// A: complete block + a stray START marker with a live line after it.
	original := startMarker + "\nexport PATH=valid:$PATH\n" + endMarker + "\n" +
		startMarker + "\nexport PATH=stale:$PATH\n"
	// Control: the same file with the second block properly closed.
	// B: complete block + a stray END marker.
	"# user\n" + startMarker + "\nexport PATH=x\n" + endMarker + "\n# leftover\n" + endMarker + "\n"
```

```text repro-output
A stray-START removal:  err=<nil>  file="# TEST BLOCK START\nexport PATH=stale:$PATH\n"
A balanced control:     err=<nil>  file=""                       (both blocks removed)
B stray-END removal:    err=<nil>  file="# user\n# leftover\n# TEST BLOCK END\n"
B next reconcile:       err=...: managed block is malformed: exactly one of the delimiter lines is present
B switch back to front: err=...: managed block is malformed: exactly one of the delimiter lines is present
B control, no stray:    remove err=<nil>, next pass err=<nil>
same two inputs at 3f2f011d3 (round 5): byte-identical results -> gap, not a regression
```

Fix: reject an unbalanced marker with `ErrMalformedBlock` from a single pass over the file, as Codex proposes, so the user is told about the residue. Do not take the narrower patch of dropping unbalanced markers inside `stripBlocks`. I applied it: face B clears, but face A becomes `"export PATH=stale:$PATH\n"`, with the marker gone and the live line still there, unattributable.

I2. **A repairable unwind failure blocks App deletion forever, including for a startup file that never held our block** — `rdd/pkg/controllers/app/pathmanagement/controllers/reconciler.go:98` [Consolidator]

```go
		if err := r.apply(ctx, appv1alpha1.AddPathManual, false); err != nil {
			if !permanentPathError(err) {
				log.Error(err, "Failed to unwind PATH management before App deletion; will retry")
				return ctrl.Result{}, err
			}
```

Round 5's I3 asked the finalizer to stop abandoning removable blocks. The fix requeues instead, with no bound, since controller-runtime backs off to a 1000 s cap and never gives up (`controller-runtime@v0.24.1/pkg/controller/controller.go:252-257`). `applyPosix` reads all eight startup files and joins their errors, so one unreadable file that never held our block makes every unwind repairable, and the App stays in `Terminating` permanently. `rdd ctl delete app` and the `rdd ctl wait --for=delete` in five BATS teardowns never complete. Windows is worse. No code path there produces `ErrMalformedBlock`, so `permanentPathError` is always false and a policy-locked `HKCU\Environment` has no escape.

```go repro
	// Our block is in .zshrc and is perfectly removable.
	// .cshrc is mode 0000 and has NEVER held our block.
	os.WriteFile(filepath.Join(home, ".cshrc"), []byte("# unrelated\n"), 0o000)
	for i := 1; i <= 5; i++ { r.Reconcile(ctx, reconcile.Request{}) }
	os.Chmod(csh, 0o644)                      // counterfactual: nothing else changes
	// Control: the malformed case the fix targets.
```

```text repro-output
unrelated-unreadable  reconcile 1: err=true finalizerHeld=true
unrelated-unreadable  reconcile 5: err=true finalizerHeld=true
after chmod 644       reconcile 6: err=false finalizerHeld=false
malformed control     reconcile 1: err=false finalizerHeld=false
```

Fix: bound the retry by keeping the finalizer for a few attempts, then releasing it and logging, so a permanently unreadable dotfile cannot strand the App. Failing that, scope the unwind's error to files that actually contain our markers, so an unrelated unreadable file cannot hold deletion.

## Suggestions

S1. **`permanentPathError` inverts its own contract under one extra wrap** — `rdd/pkg/controllers/app/pathmanagement/controllers/reconciler.go:214` [Claude Opus 5]

```go
	if joined, ok := err.(interface{ Unwrap() []error }); ok {
```

The direct type assertion holds only while `apply` returns `applyPosix`'s `errors.Join` untouched, which it does today. One `fmt.Errorf("...: %w", err)` anywhere on the way out defeats it; control falls to `errors.Is` at line 226, which walks a joined error and matches if *any* cause does. All-must-be-permanent silently becomes any-is-permanent, which drops the `manual` `Settled` gate and releases the deletion finalizer over a repairable I/O error.

```text repro-output

same join, wrapped   -> true  (want false)
bare all-malformed   -> true  (want true)
```

S2. **Nothing actually stops retrying a permanent failure, which is what the new sentinel promises** — `rdd/pkg/controllers/app/pathmanagement/controllers/reconciler.go:135` [Gemini 3.1 Pro, Codex GPT 5.6 Sol, Claude Opus 5]

```go

```

The retry is defensible, since it is how the controller notices the user repairing the file; nothing at line 135 says so.

Fix: either return `ctrl.Result{}, nil` for the permanent case, or say at line 135 that only a user edit can clear the condition, so the requeue is intended.

## Design Observations

### Concerns

- **The permanent/repairable split has no Windows half** `(in-scope)` [Claude Opus 5, Consolidator]. `ErrMalformedBlock` originates only in `managedlines`, which is `!windows`. I confirmed by grep that no Windows path can produce it, so every Windows failure classifies as repairable. `api_app.md:157` presents `Malformed` as the general permanent case with no platform caveat, and I2 shows the consequence. On Windows the deletion finalizer has no escape. Either document the asymmetry or classify an access-denied registry error as permanent.

- **Cleanup obligations still come from the desired value alone** `(future)` [Codex GPT 5.6 Sol, Claude Opus 5]. Raised in round 5, and I1 sharpens it. The App records what the user wants and never what was last applied, so `Manage` has to infer from file content what it previously wrote. A `status.appliedAddPath` would let removal target what we know we wrote, so it would not have to pattern-match markers a user may have edited.

- **Every App status write drives a full pass over eight files plus a lock acquisition** `(future)` [Claude Opus 5]. `SetupWithManager` watches the App with no generation or status predicate, so each `Settled`, `ContainerEngineReady`, or `KubernetesReady` update wakes this reconciler, takes the cross-process lock, and reads eight dotfiles. It converges and writes nothing, so there is no reconcile loop, only cost. But it is host I/O on every App event for a setting that changes once a year.

### Strengths

- **The cross-process lock is real and correctly placed** [Codex GPT 5.6 Sol, Claude Opus 5, Gemini 3.1 Pro, Gemini 3.5 Flash]. It encloses the whole read-compute-write rather than the rename, and `sharedDataDir()` matches `instance.Dir()`'s parent exactly on all three platforms (I diffed them), so every daemon a user runs serializes on one file. My two-process probe puts the guarantee beyond argument.
- **The `firstOtherIdx`/`lastOtherIdx` anchoring is the right primitive** for the "middle" rule. I probed seven Windows shapes including duplicates at both edges and a duplicated middle entry; every one is a fixed point after a single pass.
- **Marking the first login file `handled` before the write** (`pathmanagement_unix.go:98`) so a failure cannot push the block onto a file bash never sources is a subtle ordering choice, and the comment explains why.

## Review Process Notes

**Skill improvements**

- When a round's fix converts a best-effort failure path into a retrying one, enumerate what the retry now blocks and for how long. Removing an abandonment is only half a fix. A requeue with no bound turns a silent residue into a stalled resource, and the round that asked for the retry rarely names the ceiling. Check whether any caller can still make progress when the underlying condition never clears.
- When a finding rests on an error classifier, check the classifier at every call site rather than in its own unit test. A table test over a helper proves the mapping and not the routing, and a classifier that is right in isolation can be reached with a differently shaped error from one of its callers, or from a platform where its input can never occur.
- When two agents report defects in the same helper, reproduce both before merging them into one finding. Two faces of one asymmetry usually accept the same remedy. But a remedy proposed against one face can worsen the other, and the report recommends whichever patch it quotes.

**Repo context updates**

- `[repo]` Controllers under `pkg/controllers/app/` that register no CRD of their own return `""` from `GetAPIGroup()`. This excludes them from `--controllers=<group>` selection, since `shouldEnableController` matches a selector token against the API group or the controller name. `pkg/external/main.go` panics on a group mismatch, so blank-importing such a controller into a standalone `cmd/*-controller/main.go` aborts startup rather than being ignored. Check both when reviewing a new controller's registration.
- `[repo]` `instance.Dir()` resolves to `~/AppData/Local/<name>` on Windows, `~/.local/share/<name>` on Linux, and `~/Library/Application Support/<name>` on macOS, with `<name>` = `rancher-desktop-$RDD_INSTANCE`. Helpers that recompute this layout instead of calling `instance.Dir()` do so to avoid its `sync.OnceValue` memoization, which makes them track `HOME` changes in tests; verify such a helper against `instance.Dir()` before treating the duplication as drift.
- `[repo]` `instance.Suffix()` returns `RDD_INSTANCE` verbatim with no validation, and it reaches generated shell text, file fence markers, and directory names. When reviewing code that interpolates it, check what a value containing a newline, quote, or shell metacharacter would do to the consumer.

## Design Observations

### Concerns

- **Marker isolation is a content promise, not a concurrency one, and only one of the two now holds across tools.** `managedlines.go:10-12` says "different tools (and different Rancher Desktop instances) can edit the same file without stepping on each other." After round 6 that is true across RD2 daemons, because they share `<sharedDataDir>/rancher-desktop-pathmanagement.lock`. RD1 takes no such lock and does its own read-compute-write on the same `~/.zshrc`, so an RD1 and an RD2 edit that overlap still lose one block. That is acceptable, but the package doc reads as a stronger guarantee than the code delivers. Narrow the sentence to content isolation and let `reconciler.go:188-194` — which correctly scopes the claim to "across daemons" — carry the concurrency story. *(in-scope)*

- **The permanent/repairable split has no Windows half.** `ErrMalformedBlock` originates only in `managedlines`, which is `!windows`. On Windows every failure classifies as repairable (`reconciler.go:226` falls through to `errors.Is` on a plain wrapped registry error), so a genuinely unrecoverable condition — a locked-down or corrupt `HKCU\Environment` — pins `Settled` at `False` under any strategy and holds the App in `Terminating` behind the finalizer indefinitely (`reconciler.go:95-101`). The asymmetry is invisible in `api_app.md`, which describes `Malformed` as the general permanent case. Either say the split is Unix-only, or classify a Windows `ERROR_ACCESS_DENIED` as permanent too. *(future)*

- **Every App status write drives a full pass over eight files plus a lock acquisition.** `SetupWithManager` (`reconciler.go:277-281`) watches the App with no `GenerationChangedPredicate` and no `.status` filter, so each `Settled`, `ContainerEngineReady`, or `KubernetesReady` update wakes this reconciler, which takes the cross-process lock and stats/reads `.bash_profile`, `.bash_login`, `.profile`, `.bashrc`, `.zshrc`, `.cshrc`, `.tcshrc`, and `config.fish`. It converges and writes nothing, so this is cost rather than a loop, but it is real I/O on every App event for a setting that changes once a year. A predicate on `spec.application.addPath` plus generation would cut it to the changes that matter. *(future)*

### Strengths

- The `firstOtherIdx`/`lastOtherIdx` anchoring is the right primitive for the "middle" rule: it makes one pass a fixed point for every shape I probed, including the duplicate-at-both-edges case that a raw front/back test would slide forever.
- `TestApplyConcurrentInstancesKeepBothBlocks`'s 30-round loop with a shared release channel is a genuinely good concurrency regression test — it failed on the first round when I removed the lock, rather than flaking.
- Reusing `atomicfile` gets symlink resolution, mode preservation, and owner preservation for free, so a dotfiles-managed `~/.zshrc` keeps its link and its permissions. That is easy to get wrong and was not.
- Marking the first login file `handled` *before* the write (`pathmanagement_unix.go:98`) so a failure cannot push the block onto a file bash never sources is a subtle ordering choice, and the comment explains why.
