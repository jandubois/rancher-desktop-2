## Executive Summary

The build and `yarn sign` now write the published names themselves, `rancher-desktop-<version>.<platform>.<arch>.<ext>` and `rdd.<version>.<platform>.<arch>[.exe]`, all from one helper module, and the Windows updater picks its installer by architecture. The PR's CI and a fork signing run produce exactly those names. One regression remains. `scripts/install-latest-ci.sh` still requests the old CI artifact names, so every download from an RD2 run fails. Its default repository is RD1, so the fix has to move that default too.

## Code Changed Since This Review

The findings were addressed on 2026-09-21 by amending the naming commit, now `5debf53ec` (reworded). The updater commit is now `2864308d5`, otherwise unchanged. The cited lines in the signing scripts, `scripts/populate-update-server.ts` and the two docs no longer match the branch. Each finding ends with its outcome.

## Suggestions

S1. **`yarn sign` names Windows files by the signing host's architecture** — `scripts/lib/installer-win32.tsx:82` [Claude Opus 5]

```ts
  const outFile = path.join(outDir, appArtifactName(appVersion, 'win32', buildUtils.arch, 'msi'));
```

`buildUtils.arch` is `GOARCH` or the host's `process.arch` (`scripts/lib/build-utils.ts:453-466`), never the archive being signed, and WiX always builds an x64 package (`installer-win32.tsx:105`). `sign-win32.ts:119` names `rdd.exe` the same way. At the merge-base the Windows names had no architecture, so the signing host could not mislabel them. Now signing with `GOARCH=arm64` exported, or with an arm64 Node on Windows on ARM, names an x64 installer `.windows.aarch64.msi`. After #662, signing both architectures' zips on one x64 host without `GOARCH` gives both the `x86_64` names, and the second overwrites the first in `dist/`. `signing.md:127` mentions `GOARCH` for cross-architecture signing only in its macOS section. macOS signing (`sign-macos.ts:166`) depended on the host before this PR.

Fix: Take the architecture from the `win.artifactName` or `mac.artifactName` that `package.ts:180` writes into the packaged `electron-builder.yml`, and refuse to sign when `buildUtils.arch` disagrees. At the least, move the `GOARCH` note into the steps both platforms share.

**Resolution:** fixed in `5debf53ec`. Both signers call `buildUtils.checkArchiveArch` before signing anything; it refuses an archive whose packaged `artifactName` names another architecture and says which `GOARCH` to set. The `GOARCH` note moved to `signing.md` step 3.

S2. **`populate-update-server.ts` overrides names the files already have** — `scripts/populate-update-server.ts:130-132` [Claude Opus 5]

```ts
    msi:    await getChecksum('RD_SETUP_MSI', appArtifactName(version, 'win32', 'x64', 'msi')),
    macx86: await getChecksum('RD_MACX86_ZIP', appArtifactName(version, 'darwin', 'x64', 'zip')),
    macarm: await getChecksum('RD_MACARM_ZIP', appArtifactName(version, 'darwin', 'arm64', 'zip')),
```

`version` (line 128) comes from `buildInfo.extraMetadata.version` (line 257), the same value `package.ts` and `installer-win32.tsx` build the file names from. So each override repeats the downloaded file's own basename, which `getChecksum` already falls back to (line 89). If a leg ever built a different version, the override would publish the file under a name it was not built with, which is the manual renaming #669 set out to remove.

Fix: Call `getChecksum` with the environment variable alone for all three, and drop the `version` line and the `appArtifactName` import.

**Resolution:** fixed in `5debf53ec`, which also removes `getChecksum`'s unused `filenameOverride` parameter.

S3. **The release checklist names no Linux upload** — `docs/development/release-checklist.md:21` [Claude Opus 5]

```markdown
- [ ] Upload mac, win release artifacts on the GitHub draft Release page.
```

`linux-release.yaml:24,36` now fetches `rancher-desktop-<version>.linux.x86_64.zip` from the release by exact name and fails when it is missing, and the smoke test downloads that zip and its `.sha512sum` by the same name (`smoke-test.yaml:71-72`). The checklist this PR edits mentions neither the Linux zip, the `rdd` binaries nor the checksum files; `signing.md` covers only the signed files, and only the PR description says to upload each file under the name the build gave it. The omission predates this PR, but the exact-name fetch is what makes it matter.

Fix: List every upload by source: the signed macOS and Windows files from `yarn sign`'s `dist/`, and the Linux zip and Linux `rdd` from the Package run, each with its `.sha512sum`, all under the names the build gave them.

**Resolution:** fixed in `5debf53ec`. The checklist lists each upload by source and warns that the Package run's copies under the same names are unsigned. The upload step now also comes before the smoke test, which downloads from the draft release.

## Design Observations

### Concerns

- **Unsigned Package-run files now have the release names** (in-scope) [Claude Opus 5]. The Package run's dmg, zip and `rdd.<version>.darwin.<arch>` now have exactly the names `yarn sign` gives the Developer ID signed copies (`sign-macos.ts:166,203`); the CI dmg used to be `Rancher Desktop 2-<version>-arm64.dmg`. `signing.md` says to upload the signed files "as they are", but nothing warns that the Package-run copies under the same names are unsigned. A checklist line naming `yarn sign`'s `dist/` as the only source for macOS and Windows uploads, or a `codesign --verify` and `Get-AuthenticodeSignature` check before upload, would close that route.
- **The updater change is latent** (future) [Claude Opus 5]. `setupUpdate` (`pkg/rancher-desktop/main/update/index.ts:227`) has no production caller, and `app-update.yml` takes its owner and repo from `package.json:17`, which names RD1. So the second commit's case, a Windows machine downloading the other architecture's installer, cannot happen in a shipped build yet. When the updater is wired up, move `repository.url` to `rancher-desktop-2` in the same change: the new suffix match rejects RD1's `Rancher.Desktop.Setup.1.x.msi` and `-mac.<arch>.zip`, which the old filters accepted.

### Strengths

- One module, `pkg/rancher-desktop/utils/releaseArtifacts.ts`, gives the packager, both signers, the WiX builder, the updater and the upgrade-test publisher their names, and it throws on an unknown platform or architecture instead of inventing a name (in-scope) [Claude Opus 5, Codex GPT 5.6 Sol, Gemini 3.5 Flash].
- The names spell arm64 as `aarch64`, so electron-updater 6.8.9's `MacUpdater`, which treats any update URL containing `arm64` as an arm64 build (`MacUpdater.js:31`), never misreads one; the comment on `artifactArch` records why (in-scope) [Gemini 3.5 Flash, Claude Opus 5].
- The new updater test lists the other architecture's MSI first, so it catches the old first-MSI filter. Restoring `endsWith('.msi')` in `findUpdateAsset` fails two tests (in-scope) [Codex GPT 5.6 Sol, Claude Opus 5].
- `curl --fail` in `linux-release.yaml` and the new `*)` error in the `Set GOARCH` step turn a wrong release name or an unknown architecture into a failed job instead of a 404 page uploaded to S3 or a silent amd64 build (in-scope) [Gemini 3.5 Flash, Claude Opus 5].

## Review Process Notes

### Skill improvements

- Forbid running a repository script whose success path installs, deletes or downloads outside the worktree, even to observe an early failure. A probe that relies on a stub, a dummy argument or missing credentials to fail first has no guarantee it will, so read such a script instead, or run it only with every external command replaced through `PATH` and a check that the replacement took effect.

### Repo context updates

- `[repo]` The Electron app's updater is not wired up. `setupUpdate` in `pkg/rancher-desktop/main/update/index.ts` has no production caller, and `app-update.yml` takes its owner and repo from `package.json`'s `repository.url`, which names RD1 (`rancher-sandbox/rancher-desktop`). Rate findings about installed clients failing to find a renamed release asset, or about updater asset selection, as latent until RD2's update channel exists.
- `[repo]` Release artifact names come from `pkg/rancher-desktop/utils/releaseArtifacts.ts`, and the CI artifact names repeat them without the version. The `package.yaml` uploads set these names, and its `trigger-obs` and signing jobs, `upgrade-generate.yaml`, `smoke-test.yaml`, `linux-release.yaml` and `scripts/install-latest-ci.sh` fetch by them. A rename that misses one fails only when that consumer runs (on merge, on publish, or by hand), so grep for every consumer when a name changes.
- `[repo]` GitHub Actions expressions support `case()`, and `package.yaml` uses it; do not flag it as invalid. Inline `${{ matrix.* }}` and `${{ github.* }}` expansions in `run:` scripts are common across the workflows, with no convention of routing them through `env:`; flag an inline expansion only when its value can come from untrusted input such as a PR title or branch name.
