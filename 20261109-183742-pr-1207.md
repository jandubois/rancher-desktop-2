## Executive Summary

Table headers and stored messages now follow a language switch, and the page's half of the Preferences close guard works as described. The defects are in the window's lifecycle. A Cancel on the discard question deletes the window's shortcut registration, so the next open registers every handler twice. Closing the main window destroys Preferences without unloading its page, so a previewed language stays. The main-process guard has no test, and its quit comment gives the wrong reason.

## Important Issues

I1. **A cancelled close makes the next open register every handler twice** — `pkg/rancher-desktop/utils/shortcuts.ts:143-145` [Codex GPT 6 Astra]

```ts
      window.on('close', () => {
        delete this.windows[id];
      });
```

Electron documents `close` as firing before the page's `beforeunload`, and a run of Electron 45.2.1 showed it firing on a close that the page then cancelled. So a Cancel on the new discard question keeps Preferences open but deletes its Shortcuts registration.

The next `openPreferences` call then finds `Shortcuts.isRegistered(window)` false at `window/preferences.ts:46` and registers the shortcuts and the `ipc-message`, `will-prevent-unload` and locale listeners a second time. Each shortcut then runs twice, and the next close asks twice, where a Cancel in the second dialog cannot overrule a Discard in the first. At the merge-base nothing set the dirty flag, so no close was ever cancelled and the deletion did no harm.

I2. **Closing the main window leaves a previewed language in effect** — `pkg/rancher-desktop/pages/Preferences.vue:88` [Consolidator]

```ts
  window.addEventListener('pagehide', restoreLocale);
```

`restoreLocale` runs only when the page unloads.

Preferences opens as a child of the main window (`parent: getWindow('main') ?? undefined` at `window/preferences.ts:38`). When a parent window closes, Electron 45.2.1 destroys its children without running their `beforeunload` or `pagehide`. So closing the main window while Preferences shows an unapplied language neither asks nor switches back. The previewed locale stays in `localStorage` and in the main process, and the tray menu, the application menu and the About panel keep it until a window opens again. That contradicts the PR body's "however the window closes" and #984's "however Preferences closes". A quit does restore the locale, as the probe's `quit` run shows.

```js repro
// Save as unload-probe.cjs; run from the repo root, once per scenario:
// node_modules/.bin/electron unload-probe.cjs close-preferences|close-main|quit
// Mirrors the PR: Preferences is a child of the main window, its page cancels
// beforeunload while dirty and restores the committed locale on pagehide, and
// the main process answers will-prevent-unload with Discard.
const fs = require('fs');
const os = require('os');
const path = require('path');

const { app, BrowserWindow } = require('electron');

const scenario = process.argv.at(-1);
const tmp = fs.mkdtempSync(path.join(os.tmpdir(), 'unload-probe-'));
const page = path.join(tmp, 'preferences.html');

app.setPath('userData', tmp);
app.on('window-all-closed', () => {});
fs.writeFileSync(path.join(tmp, 'reader.html'), '');
fs.writeFileSync(page, `<script>
  localStorage.setItem('locale', 'de'); // the previewed locale
  addEventListener('beforeunload', e => e.preventDefault());
  addEventListener('pagehide', () => localStorage.setItem('locale', 'en-us'));
</script>`);

async function storedLocale() {
  const reader = new BrowserWindow({ show: false });

  await reader.loadFile(path.join(tmp, 'reader.html'));
  const locale = await reader.webContents.executeJavaScript('localStorage.getItem("locale")');

  reader.destroy();

  return locale;
}

app.whenReady().then(async() => {
  const main = new BrowserWindow({ width: 300, height: 200 });
  const preferences = new BrowserWindow({ width: 300, height: 200, parent: main });

  preferences.webContents.on('will-prevent-unload', event => event.preventDefault());
  await main.loadURL('data:text/html,main');
  await preferences.loadFile(page);
  await preferences.webContents.executeJavaScript('1', true); // user activation

  if (scenario === 'quit') {
    let shuttingDown = false;

    app.on('before-quit', (event) => {
      if (!shuttingDown) { // as background.ts does
        event.preventDefault();
        shuttingDown = true;
        setImmediate(() => app.quit());
      }
    });
    app.on('will-quit', async(event) => {
      event.preventDefault();
      console.log(`${ scenario }: stored locale = ${ await storedLocale() }`);
      app.exit(0);
    });
    app.quit();

    return;
  }
  (scenario === 'close-main' ? main : preferences).close();
  await new Promise(resolve => setTimeout(resolve, 1500));
  console.log(`${ scenario }: preferences destroyed = ${ preferences.isDestroyed() }, stored locale = ${ await storedLocale() }`);
  app.exit(0);
});
```

I4. **The quit comment gives the wrong reason for not asking** — `pkg/rancher-desktop/window/preferences.ts:14-18` [Claude Opus 5.5]

```ts
/**
 * Set once the app starts quitting, so the window drops unsaved changes
 * without asking.  By then the app has stopped steve, and this window
 * closes along with the main window, so Cancel could not keep anything.
 */
```

Not asking is right, but this reason holds only while Preferences is the main window's child. The dashboard window has no parent and outlives the main window, and the application menu still offers Preferences, which line 38 then opens without a parent. A Cancel during the quit keeps that window and aborts the quit (`no-main-window` below). ## Design Observations

### Concerns

- **A Cancel can now overrule `preferences-close`** (future) [Claude Opus 5.5]. `layouts/default.vue:99`, `SnapshotCard.vue:69` and `snapshots/create.vue:61` send it to close Preferences before a backend lock or a snapshot. With unsaved changes the user now gets the discard question and can keep Preferences open. Nothing sends `backend-locked` to a renderer yet, so this matters once snapshots land. Outcome: declined for this PR and tracked.
- **Some quit paths never emit `before-quit`** (future) [Claude Opus 5.5]. Electron documents that a Windows session end does not emit it, and that `autoUpdater.quitAndInstall()` emits it only after closing the windows, so the guard can ask on either path. Nobody ran either path, and the updater has no production caller yet. Outcome: declined for this PR and tracked.

### Strengths

- **The page decides from its own store as it unloads** (in-scope) [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash]. The main process does not keep a copy of the dirty state, so nothing can fall out of step.
- **`ipc-message` is registered along with the shortcuts** (in-scope) [Claude Opus 5.5]. Each reopen used to add another listener, as the old `close` handler did. Until I1 is fixed, a cancelled close still lets the next open add a second one.
- **Stored messages keep their translation key and arguments** (in-scope) [Claude Opus 5.5, Codex GPT 6 Astra]. They are translated when shown, so the volume files page, the snapshot dialog and the container details no longer keep a string translated once.

## Testing Assessment

- I ran the ten changed specs at the review SHA (10 suites, 55 tests) and, together with every spec under `components/__tests__`, 22 suites with 167 tests, all passing. CI's Jest Tests job also passed on the head.
- Required: a test for the main-process guard (I3). I1's patch adds it. With both patches applied, the full Jest run passes 74 suites and 639 tests, with 1 suite (33 tests) skipped.
- The seven header tests switch the locale through `switchableT`, a reactive stand-in for the store's `i18n/t` getter. The real getter reads `getters.current` inside the function it returns (`store/i18n.ts:62-63`), so a computed that calls it tracks the locale the same way.

The probes under I2 and I4 ran Electron 45.2.1 outside the app; the e2e suite cannot reach the question while `window/preferences.ts:119` skips it under `RD_TEST`. Outcome: declined, since it needs an Electron-level test rig that the repo lacks.

## Acknowledged Limitations

- Quitting drops unsaved changes without asking. The behavior is deliberate and correct; I4 concerns only the stated reason.
- The main process's startup locale belongs to #1204.
- Do not re-suggest falling back to `i18n.default` in `restoreLocale`. The App CRD defaults `application.locale` to `en-us` (`rdd/pkg/apis/app/v1alpha1/app_types.go:256`), so a loaded App always has one, and before the App loads the fallback would switch a non-English user to English.
- Do not re-suggest resetting `isLoading` on the error paths of `volumes/files/_name.vue`. The template now shows `error` first, and every other reader of `isLoading` also requires `volumeExists`, which those paths leave false.
- Do not re-suggest restoring the `window.close` spy in `Preferences.spec.ts`. Jest gives each test file its own jsdom environment, so the spy cannot reach another suite.

## Review Process Notes

### Skill improvements

- When a change makes a lifecycle event cancellable for the first time (a window close, a navigation, a shutdown), audit every listener on the events that fire before the point of cancellation. Those listeners now run for attempts that do not complete, so any state they tear down is gone while the object lives on.
- When a change relies on page-lifecycle handlers (`beforeunload`, `pagehide`, `unload`) or another teardown hook for cleanup, list every way the owner can go away (closed directly, destroyed with its parent, killed at shutdown) and check which of them run the hook.

### Repo context updates

- [repo] Electron facts that window code relies on, measured on Electron 45.2.1. `BrowserWindow` emits `close` before the page's `beforeunload`, also when the page then cancels the unload. Closing a parent window destroys its child windows without running their `beforeunload` or `pagehide`. During a quit, a window that cancels its unload aborts the quit even after `background.ts` has set `ShuttingDown`. Preferences is a child of the main window whenever one exists. Flag cleanup that a child window's page leaves to its unload handlers, and state that a listener drops on `close` for a window whose unload can be cancelled.

###### Design Observations

###### Strengths

- Leveraging standard DOM `beforeunload` in `Preferences.vue` paired with Electron's `webContents.on('will-prevent-unload')` in `window/preferences.ts` cleanly eliminates the need to synchronize an IPC dirty state flag between processes.
- Gating `will-prevent-unload` on `quitting` (`mainEvents.on('before-quit')`) prevents app quit operations from stalling or hanging on unapplied changes.
- Converting table `headers` across all 7 views to Vue `computed` properties allows column labels to immediately update on language switch without requiring component remounts or full page reloads.
- Creating the reusable `switchableT()` reactive test utility in `pkg/rancher-desktop/utils/testUtils/translations.ts` provides clean, reliable assertions across all table and dialog specs.
