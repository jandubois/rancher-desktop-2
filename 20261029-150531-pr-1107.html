Review Process Notes ¶

Skill improvements ¶

  • When a PR removes or renames an API value, enum member or field, search the repository's open issues for that identifier and inline every issue that specifies behaviour around it. A removal can invalidate a plan that the PR body never mentions, and agents cannot fetch issues themselves.
  • Have each external agent's liveness monitor also scan that agent's stderr for a quota error and report it at once. A CLI that runs out of quota sleeps until the reset, so the stall window of 15 minutes passes with nothing to show.

Repo context updates ¶

  • [repo] The first-run dialog creates the App itself (rdd/ensureAppExists) and shows its window before the App exists. Any control in pages/FirstRun.vue that dispatches preferences/modify must stay disabled until preferences/preferences has keys, as EngineSelector and RdCheckbox do, because a pending change makes that getter non-empty and enables OK with no App to commit to.
  • [repo] CI's Translation Checks job runs i18n-report check --locale=all on every pull request without --strict, so it covers stale keys and validate (placeholders, tags, ICU constructs) but not drift. A green run therefore misses a translation whose English changed in wording only. To see what a change to en-us.yaml leaves the locales, build src/go/i18n-report and run drift --locale=<code> for each locale.
