I1. **No test covers the guard that keeps the app from deleting rdd's logs** — `pkg/rancher-desktop/utils/logging.ts:216-219` [Claude Opus 5.5]

```ts
      if ([paths.stdout_log, paths.stderr_log].includes(fullPath)) {
        // Avoid removing RDD logs, in case we're connecting to an existing one.
        continue;

```

If a key rename or a normalization difference ever split them, the app would unlink the daemon's live logs at startup, and nothing would report it. I2. **No test covers the rewritten guard that keeps the app from deleting rdd's logs** — `pkg/rancher-desktop/utils/logging.ts:214-218` (important, gap)

```ts
const fullPath = path.join(paths.log_dir, entry.name);

if ([paths.stdout_log, paths.stderr_log].includes(fullPath)) {
  // Avoid removing RDD logs, in case we're connecting to an existing one.
  continue;
}
```

The guard used to match on the topic name. It now compares full path strings, and the two sides are built in different languages: Go's `filepath.Join` produces `stdout_log`, while Node's `path.join` builds `fullPath`. If the two strings ever disagree (a key rename, or a normalization difference), the app silently unlinks the daemon's live `rdd.stdout.log` and `rdd.stderr.log` at startup.

```go
func splitLogPath(filePath string) (dir, base string, err error) {
	base, ok := strings.CutSuffix(filepath.Base(filePath), ".log")
	if !ok {
		return "", "", fmt.Errorf("log file path %q does not end in .log", filePath)

}
```

If `filePath` is `".log"` or ends in `"/.log"`, `filepath.Base` is `".log"`, and `strings.CutSuffix` yields `base = ""` with `ok = true`. In `Rotate()`, this empty name compiles a regex matching `^\.(\d+)\.log$` and renames the file to `".1.log"`.

```diff
 func splitLogPath(filePath string) (dir, base string, err error) {
 	base, ok := strings.CutSuffix(filepath.Base(filePath), ".log")
-	if !ok {
+	if !ok || base == "" {
 		return "", "", fmt.Errorf("log file path %q does not end in .log", filePath)
 	}
 	return filepath.Dir(filePath), base, nil
 }
```

### Design Observations

#### Concerns

- **Dual ownership of log pruning between daemon and Electron frontend** `(in-scope)`: `rdd/pkg/util/logfile/logfile.go` implements log rotation with a retention limit of 5 (`retentionCount = 5`) to preserve historical runs. Concurrently, `pkg/rancher-desktop/utils/logging.ts:211–227` inspects `paths.log_dir` and purges any file ending with `.log` whose full path is not exactly `paths.stdout_log` or `paths.stderr_log`. Consequently, rotated files (`rdd.stdout.1.log`) are deleted by the frontend on application startup. Consider either teaching `clearLoggingDirectory()` about rotated suffixes (`/\.\d+\.log$/`) or having the daemon manage its own log lifecycle exclusively.

#### Strengths

- Refactoring `logfile.Create` and `logfile.Rotate` to accept a unified file path eliminates fragile directory-and-bare-name string concatenation across callers.
- Replacing ad-hoc path joins with Lima's `filenames` constants (`filenames.HostAgentStdoutLog`, `filenames.HostAgentStderrLog`, `filenames.SerialLog`) directly aligns RDD with upstream Lima VM conventions.

### Testing Assessment

- `host_path` translation on WSL2 environments: Required per check 3 (opaque harness crash on initialization under WSL2); see I1.
- Unit testing for `instance.SharedDataDir()`, `instance.LimaVMDir()`, and `instance.StdoutLog()` / `instance.StderrLog()`: Optional per check 2 (internal accessors exercised transitively by integration and BATS paths); see S4.
