## Important Issues

I1. **`--regenerate` erases the assets of every non-regenerable dependency** — `scripts/rddepman.ts:334-347` [Codex GPT 5.5]

```ts
for (const dependency of dependencies) {
  if (!dependency.regenerable) {
    console.log(`Skipping ${ dependency.name } (bumped by rddepman, not regenerated).`);
    continue;
  }
  const assets = await dependency.getAssets(await dependency.currentVersion);
  await dependency.updateManifest(version, assets);
}
```

`readDependencyManifest` parses a legacy `checksums` entry into `assets: []` (`scripts/lib/dependencies.ts:197`). Electron sets `regenerable = false` (`scripts/dependencies/electron.ts:37`), so `regenerateAssets` skips it — but every regenerated sibling rewrites the *entire* file through `writeDependencyManifest`, which serializes Electron as `assets: []` and drops its `checksums` map. Nothing repopulates them.

I reproduced this against a legacy fixture: after one sibling write, `electron:` carried `assets: []` and its recorded checksums were gone from the file. This breaks the exact migration the docstring at `scripts/lib/dependencies.ts:175-179` advertises, and `Electron.download` then throws on an undefined recorded checksum (`electron.ts:72-76`).

Codex labeled this a regression. It is not — `--regenerate` is new in this PR, so this is a gap in new functionality.

Fix: preserve the raw entry for skipped dependencies, or regenerate Electron when the manifest version equals `package.json`'s.

I2. **Credential-helper install succeeds silently when no asset matches** — `scripts/dependencies/tools.ts:247-261` [Codex GPT 5.5]

```ts
const assets = selectAssets(context, this.name, { platform: context.goPlatform, arch: context.goArch });

await Promise.all(assets.map((asset) => {
  return download(asset.url, destPath, { expectedChecksum: assetChecksum(asset), codesign });
}));
```

`selectAssets` returns `[]` when nothing matches (`dependencies.ts:321`), and `Promise.all([])` resolves. The old code enumerated the expected helper names and called `lookupChecksum` for each, which threw when a checksum was absent — so this is a genuine fail-loud to fail-silent regression.

Scope: every other install path calls `selectAsset`, which throws "found 0", so a wholly blank manifest still fails through `helm` or `dockerCLI`. Reaching the silent path needs a gap specific to the credential helpers — a hand-edited manifest, a newly added arch, or an upstream helper that stops shipping. The result is a package with no `docker-credential-*` binaries and registry auth broken with no error.

Fix: require exactly one asset per expected helper name for `context.goPlatform`, and throw otherwise.

I3. **Three asset-validation tests never reach the validator they name** — `scripts/lib/__tests__/dependencies.spec.ts:97-106` [Consolidator]

```ts
it.each([
  ['platform', 'helm:\n  version: 1.0\n  assets:\n    - { platform: solaris, ... }'],
  ['arch', 'helm:\n  version: 1.0\n  assets:\n    - { platform: linux, arch: ppc64, ... }'],
  ['checksum', 'helm:\n  version: 1.0\n  assets:\n    - { ... checksum: not-a-sha }'],
])('rejects an asset with an invalid %s', ...)
```

YAML parses `1.0` as the number `1`, so `readDependencyManifest` throws on its version type-check (`dependencies.ts:189-191`) before `parseAsset` ever runs. Each case asserts a bare `rejects.toThrow()` with no matcher, so all three pass while exercising nothing. `parseAsset` — the PR's core new validation function — has no effective test.

I confirmed this by printing the thrown message for each fixture: `Entry helm ... has invalid version 1; expected a string`. Quoting the version yields `has invalid platform "solaris"`, the intended error.

Fix: quote the version (`version: "1.0"`) and assert the message, e.g. `rejects.toThrow(/invalid platform/)`.

## Design Observations

**Concerns**

- **The whole-manifest rewrite can blank sibling assets during an ordinary bump, not just a regenerate** (in-scope) [Claude Opus 4.8]. `updateManifest` rebuilds the entire file from the in-memory model, so if `checkDependencies` ever runs against an un-migrated manifest, the resulting PR carries one dependency's real assets and `assets: []` for every sibling. Post-merge the workflow always reads the migrated `main`, so the exposure is a manual `workflow_dispatch` branching off the old `origin/main`. This is the same mechanism as I1, reached through the bump path rather than `--regenerate`.

  One correction to the original observation: it argued that a bad PR "fails its own postinstall (`selectAsset` 'found 0')". That holds for `helm`, `dockerCLI`, `wix`, and `steve`, but not for the credential helpers, which take the `selectAssets` path and pass — that is exactly I2.

- **`selectAsset` requires the caller to know a dependency's format multiplicity** (future) [Claude Opus 4.8]. `distro` ships four assets (`{amd64,arm64} × {raw,tar}`), so `selectAsset` without a `format` matches two and throws. The planned Go downloader must pass `format`; the contract deserves a note, since the TS side has no consumer yet.

- **`Distro.getAssets` downloads all four distro images concurrently just to hash them** (future) [Consolidator]. `Promise.all(cartesian(ARCHES, FORMATS))` fetches four compressed images to temp files on every guest bump. On a GitHub-hosted runner this is the most disk- and bandwidth-intensive step rddepman performs. Worth watching once the guest workflow runs on a real bump.

**Strengths**

- The self-describing asset schema pairs an immutable, version-pinned `url` with its `checksum`, so install paths no longer re-derive URLs and the manifest is directly consumable by the planned Go downloader. [Gemini 3.1 Pro, Claude Opus 4.8]
- `serializeAsset` fixes key order, keeping YAML diffs clean however the asset object was built. [Claude Opus 4.8]
- `parseAsset` validates platform, arch, and checksum at file-read time with per-field messages. [Claude Opus 4.8]
- `regenerable = false` isolates the one dependency whose version lives in `package.json` rather than the manifest. [Claude Opus 4.8]
- Storing the `sha256:` prefix documents the algorithm for readers while `parseSha256Checksum` normalizes case, so consumers compare hex with `===`. I verified this end to end: `hashFile` emits lowercase, `download()` compares with `===`, and the parser lowercases. [Gemini 3.1 Pro]

## Review Process Notes

**Skill improvements**

- [ ] When a review's changed files include a test file, run the test suite before consolidating, then verify that each new test fails when the behavior it names is broken. A test whose fixture aborts in an earlier validation layer passes while exercising nothing; a bare `rejects.toThrow()` or `expect(fn).toThrow()` with no message matcher cannot distinguish the intended error from an unintended one. Flag any new negative-path test that asserts only that *something* threw.

- [ ] When one agent reports a defect in a code path and another agent reports the same code path as a strength, treat the disagreement as a finding to adjudicate against the code, not as a split verdict to report. Reproduce the mechanism directly before crediting either. Agents that scan a diff without executing it systematically over-trust migration and compatibility shims, whose failure modes appear only when the shim's output is fed back through the writer.

- [ ] Before accepting a finding's "regression" label, confirm the cited construct exists at the merge-base. New subcommands, new flags, and new code paths cannot regress prior behavior; label them gaps. Conversely, a fail-loud to fail-silent change is a regression only if the prior code actually threw — read the removed error path, do not infer it from the diff's shape.

- [ ] Treat `Promise.all(xs.map(...))`, `for (const x of xs)`, and similar iteration over a collection returned by a lookup as a silent-success candidate whenever the lookup can return empty. Compare against sibling call sites: if one lookup helper throws on no-match and another returns an empty collection, every caller of the second needs an explicit arity check. This pattern hides best in refactors that replace per-item lookups with a single filtered query.

**Repo context updates**

- [ ] [repo] Jest in this repo requires the ESM invocation: `npx cross-env BROWSERSLIST_IGNORE_OLD_DATA=1 node --experimental-vm-modules node_modules/jest/bin/jest.js <path>`. A bare `npx jest` fails with `SyntaxError: Cannot use import statement outside a module` on the octokit import, and specs under `scripts/` additionally need the `@jest-environment node` docblock or they fail with `ReferenceError: TextDecoder is not defined`. Do not report either failure as a defect in the code under review.

- [ ] [repo] Agent worktrees created for review have no `node_modules`, so agents cannot run the test suite or `tsc`. Run test-execution checks from the main checkout instead, and read any agent's claim about type-consistency or test outcomes as static tracing rather than verified execution.

- [ ] [repo] `scripts/dependencies/*.ts` classes are registered in `scripts/dependencies/global.ts` (host) and in the `configs` map in `scripts/rddepman.ts`. A dependency class is only installed at postinstall if it also appears in the lists in `scripts/postinstall.ts`. When reviewing a new dependency class, check all three registries: absence from `postinstall.ts` is what makes a `download()` that rejects an unreachable guard rather than a bug.

### Design Observations

**Strengths**
- **Robust Migration Path:** Using `((entry.assets as RawAsset[]) ?? [])` gracefully loads legacy `checksums` manifests as empty asset lists, ensuring `--regenerate` can bridge the old schema to the new one without breaking the parser.
- **Architectural Separation:** Removing the URL-derivation logic from the downloaders and pushing it purely into `getAssets` centralizes upstream knowledge in `rddepman`. Downstream downloaders now only need to match `platform`/`arch`/`format`, making them generic and trivial to implement in Go.

- **Graceful Multi-Tool Orchestration:** Having `rddepman` reset `main` locally in CI before processing the next list ensures `host` and `guest` updates run cleanly in succession without git state collisions, while avoiding destructive checkouts locally when `SKIP_PULL_REQUESTS` is true.
