Executive Summary ¶

Round 3 is the cleanest so far. Every round-2 fix does what it claims, and I found no defect the fixes introduced. Two defects sit elsewhere in the PR. One is a regression against the merge-base: selecting containerd stops removing the instance Docker context. The other is a gap: an image pulled for a platform other than the host's gets no mirror at all, and says so in the log on every sync.

I proved both with probes run against this tree, each including the neighbouring case that behaves correctly. The two Gemini models share a family, so where they agree it counts once; this round they produced one usable suggestion each and no overlap.

func probeBlob(t *testing.T, cs content.Store, mt string, v any) ocispec.Descriptor {
	t.Helper()
	b, err := json.Marshal(v)
	assert.NilError(t, err)
	d := digest.FromBytes(b)
	desc := ocispec.Descriptor{MediaType: mt, Digest: d, Size: int64(len(b))}
	assert.NilError(t, content.WriteBlob(context.Background(), cs, d.String(), bytes.NewReader(b), desc))
	return desc
}

Design Observations ¶

Concerns ¶

  • User-visible mirror fields diverge between the two engines (future) Claude Opus 5. The same image is busybox:latest under moby and docker.io/library/busybox:latest under containerd; status.id is the config digest on one and the manifest digest on the other; and api_containers.md now documents status.size as uncompressed on moby and a compressed-blob sum on containerd. Each is defensible and each is documented, but together they mean a GUI list and any client keying on repoTag behave differently per backend, which is what the repo's parity principle exists to prevent. Worth settling before the renderer is wired up.
  • Windows will serve the well-known containerd pipe name (future) Claude Opus 5. instance.ContainerdSocket() returns \\.\pipe\containerd-containerd on Windows, and app_controller.go:163 writes it into every Lima template regardless of platform or selected engine. Windows containerd is out of scope here, but the name is global rather than instance-scoped, the same collision it would have with Docker Desktop's \\.\pipe\docker_engine. Scoping it before anything serves it is cheaper than after.
  • A mirror kind created only by fullSync can drift permanently (in-scope) Codex GPT 5.6 Sol. S3 is the instance; the general form is that ordinary reconciliation is authoritative for containers, images and volumes but not for namespaces.

Strengths ¶

  • The watcherEngine state machine holds up (in-scope) Claude Opus 5. Putting the backend-switch arm ahead of the liveness arm, keeping watcherEngine alive across stopWatcher, and clearing it only once the sweep owns the work all survive the state enumerations I traced: switch while dead, switch while stopped, and sweep-fails-then-requeue. The alreadyClean skip cannot swallow a switch either, because the spec change that flips the engine name also bumps app.Generation past the stamped ObservedGeneration.
  • Subscribing before fullSync is the right order, and containerd's Exchange.Subscribe buffers into an unbounded queue, so nothing is dropped while the snapshot runs Claude Opus 5.
  • The signal table and the test that pins SIGUSR1 == 10 rather than syscall.SIGUSR1 close a bug class that would otherwise ship silently on developer machines Claude Opus 5 Codex GPT 5.6 Sol.
  • containerdImageRefs puts the digest check ahead of the reference parse and says why, which is exactly the ordering a later refactor would undo Claude Opus 5 Codex GPT 5.6 Sol.
  • The mirrorClient extraction shares the apply and finalizer semantics without forcing backend-specific APIs into a wider interface Codex GPT 5.6 Sol.

Review Process Notes ¶

Skill improvements ¶

  • When a finding proposes a fix, place the reproducer's assertion where it can distinguish the proposed placement from a correct one. A patch that guards a side effect behind a success path passes any probe whose setup reaches that path, and fails one whose setup does not; running the reproducer against the patch is what separates them, and the placement is often the whole finding.
  • A library call that selects data by the running process's platform is a defect candidate wherever the process and the resource it describes are on different machines. Check every default a client library derives from its own host (platform, architecture, path separators, signal numbers, locale) against where the object it is describing actually lives.

Repo context updates ¶

  • [repo] run -0 followed by a ${output} capture is the established form for rdd ctl and rdd svc calls in this bats suite, including inside try predicates; assert_single_mirror, assert_action_consumed and assert_docker_context all use it. Do not flag a nested run inside a retry predicate as a style violation. The separate run_e rule applies to commands with a debug path that writes to stderr, not to every capture.
  • [repo] The daemon builds its containerd client with containerdclient.New(instance.ContainerdSocket()) and no platform option, so the client carries platforms.Default(), which is the host's platform and not the guest's. Any containerd API whose behaviour depends on the client platform (image size, config resolution, manifest selection) therefore asks about the machine the daemon runs on. On an arm64 Mac this happens to match a linux/arm64 guest, which hides the mismatch in ordinary use.
