Executive Summary ¶

On Windows, rdd nerdctl rewrites host paths through a port of the 1.x stub parser, driven by a table generated from nerdctl's cobra tree. The generator is sound. But the parser rejects or rewrites command lines that #981's pass-through handled: nerdctl --help, -p8080:80, top ctr -ef, build -f -, anonymous volumes, and named volumes with a mode. A rooted path such as \data still mounts the VM's directory; #504 asked to settle that rule before this PR leaves draft.

nerdctl splits a --volume spec on : (splitVolumeSpec). A spec with one part is an anonymous volume at that container path, and a third part is a mode that nerdctl validates itself, warning on options it does not know, such as z. The handler instead strips only :ro or :rw and takes everything before the last colon as the source. So -v /data fails. A named volume with any other mode, such as myvol:/data:z or myvol:/data:ro,rshared, misses the named-volume check, and the container gets a bind mount of <cwd>/myvol instead of its volume, without any error. Both forms passed through unchanged under #981.
