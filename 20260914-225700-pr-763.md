## Suggestions

S1. **The xz package comments still argue for the removed fallback** — `rdd/pkg/xz/xz.go:5-6` [Claude Opus 5]

```go
// Package xz decompresses xz streams in-process with a pure-Go decoder, so rdd
// can provision a VM image without a system xz binary on the host.
```

These lines came with the fallback for hosts without xz (`af94fc41e`), which this PR removes. A downloaded `.xz` image now needs xz on the host (`rdd/docs/design/api_lima.md:64`), so "a VM image" claims more than rdd does.

The package's one production caller decodes the embedded image on every host, xz or not, from a `strings.Reader` (`rdd/pkg/controllers/lima/limavm/controllers/limavm_controller.go:441`).

So the `bufSize` comment at `rdd/pkg/xz/xz.go:21-23` fits only a file source. It blames syscalls for the cost of small reads, and no read from that in-memory source reaches one.

Fix: give the embedded image as the reason, and say on `bufSize` that the buffer matters for a file source.

```diff
-// Package xz decompresses xz streams in-process with a pure-Go decoder, so rdd
-// can provision a VM image without a system xz binary on the host.
+// Package xz decompresses xz streams in-process with a pure-Go decoder, so rdd
+// can extract the distro image it embeds on any host, with or without xz.
```

S2. **Three guards on the extraction path cannot fire either** — `rdd/pkg/controllers/lima/limavm/controllers/limavm_controller.go:407-411` [Claude Opus 5]

```go
	if _, err := os.Stat(diskPath); err == nil || !usesEmbeddedImage(inst) {
		return nil
	}

	if _, err := os.Stat(imagePath); err != nil {
```

This round removed `linkWSL2BaseDisk`'s missing-image guard as unreachable. The checks above for an existing `disk` and `image` cannot fire either. Their only caller runs right after Lima's `instance.Create`, which refuses an existing instance directory (pkg/instance/create.go, lines 43-44, in the pinned fork), and the vz, qemu and WSL2 drivers' `Create` write neither file.

Nor can the `basedisk` check at `rdd/pkg/controllers/lima/limavm/controllers/limavm_controller.go:461`, which the subtest "existing basedisk is left untouched" tests.

I would keep all three. The removed guard was dead within its own function, while these depend on the caller, and all three predate the PR (`af94fc41e`).

Fix: state in `extractEmbeddedImage`'s doc comment that it tolerates a partly prepared instance directory, so a later cleanup does not drop the guards one at a time.
