## Executive Summary

This PR replaces Windows' console-event interrupt and PEB/command-line identity check with a per-process named event, `Local\rdd-interrupt-<key>-<pid>`. Delivery no longer needs a shared console, identity becomes a path-independent, recycle-PID-safe `OpenEvent`, and ~200 lines of cross-process memory reading disappear. Both reviewers found no critical issues and converged on one Important regression: the daemon writes its PID file before registering the event, so `PID()` reads it as "not ours" during a startup window the old check never had.

Two reviewers ran (Claude Opus 4.8, Codex GPT 5.5); Gemini was dropped after an authentication failure. Both independently raised the same I1 and agree on severity.

## Important Issues

I1. **Serve registers its interrupt event after writing the PID file, opening a Windows window where the daemon reads as "not ours"** — `rdd/pkg/service/cmd/service.go:703-748` [Claude Opus 4.8, Codex GPT 5.5]

```go
pid := []byte(strconv.Itoa(os.Getpid()))
if err := os.WriteFile(instance.PIDFile(), pid, 0o600); err != nil { ... }   // 703
// ... PrintFlags, LinkBundledBinaries (720), Complete (724), SetupSignalContext ...
if releaseInterrupt, err := process.RegisterInterruptHandler(process.ServeInterruptKey, cancel); ... // 744
```

On Windows, identity is now the interrupt event (`IsOurProcess`, service.go:170). The PID file exists from line 703, the event only from line 744, with `LinkBundledBinaries` (720) and `Complete` (724) between them — hundreds of ms on a cold start. Throughout that window `PID()` returns `PIDNotFound` (`IsAlive` true, `IsOurProcess` false), so `Running()` is false; the old command-line check confirmed identity from process creation. A concurrent `rdd svc start` (it re-checks `Running()` at line 694) double-launches, overwrites the first daemon's PID file, and orphans it — the failure this PR set out to prevent. `rdd svc delete` shares the race before kine locks `state.db`. Codex generalizes the trigger to any live-but-unregistered daemon (pre-fix build, failed registration) — less likely than the window.

Fix: register the interrupt event before writing the PID file.

```go
ctx := genericapiserver.SetupSignalContext()
ctx, cancel := context.WithCancel(ctx)
defer cancel()
if releaseInterrupt, err := process.RegisterInterruptHandler(process.ServeInterruptKey, cancel); err != nil {
	klog.Warningf("Failed to register interrupt handler: %v", err)
} else {
	defer releaseInterrupt()
}
pid := []byte(strconv.Itoa(os.Getpid()))   // now follows registration
```

The reorder shifts `SetupSignalContext` earlier; confirm nothing depends on its current placement.

## Design Observations

### Concerns

- **Identity gated on registration timing** `(in-scope)` [Claude Opus 4.8] — I1 and S2 share one root: identity is proven by an event created partway through startup, not at process creation, as the old command-line check was. Registering the event as the first startup action closes the window for both roles.

### Strengths

- **Named-event mechanism replaces cross-process memory reading** `(in-scope)` [Claude Opus 4.8, Codex GPT 5.5] — the change deletes the entire PEB/`ReadProcessMemory`/image-path path (~200 lines) in favor of one `OpenEvent`. Identity becomes path-independent (any rdd binary is recognised) and recycle-PID-safe, fixing the app-bundle-vs-standalone mismatch the old image-path compare suffered.
- **`Delete` db-first guard** `(in-scope)` [Claude Opus 4.8, Codex GPT 5.5] — removing `db/` before the rest of the directory probes the one resource a live daemon locks. On Windows the lock makes `RemoveAll` fail deterministically and aborts the delete; on Unix the earlier `StopWithWait` already guarantees the daemon is gone. It even catches a live pre-fix daemon that `PID()` cannot confirm.
- **`RegisterInterruptHandler` lifecycle is correct** `(in-scope)` [Claude Opus 4.8] — the manual-reset event latches the signal so the watcher cannot miss a racing `SetEvent`; the release event plus `sync.Once` closure waits on `<-done` before closing handles, so no use-after-close; `onInterrupt` fires only on `WAIT_OBJECT_0`.

## Review Process Notes

### Skill improvements

- When a change moves how a process proves its identity or liveness — from an attribute fixed at process creation (argv, executable path) to a resource created during startup (a registered event or handler, a named object, a bound socket, a lock file) — check the ordering of startup steps. Any interval between the point the process becomes discoverable to peers (writes its PID file, takes a lock) and the point its identity becomes confirmable (creates that resource) is a window in which liveness or identity probes read the process as absent or not-ours. Flag a discoverability step that precedes the identity-establishing step, and recommend establishing identity first.

### Repo context updates

- [repo] On Windows, a process proves its identity and receives graceful-interrupt requests through a per-process named event, `Local\rdd-interrupt-<key>-<pid>`, created by `process.RegisterInterruptHandler` at startup. `process.Interrupt`, `process.IsOurProcess`, and `process.IsAlive` (`pkg/util/process`) are the canonical primitives, and `Interrupt`/`IsOurProcess`/`RegisterInterruptHandler` take a role key (`ServeInterruptKey`, `HostagentInterruptKey`). The earlier PEB/command-line/image-path identity check (`IsOurProcessWithArg`) was removed. When reviewing Windows process-lifecycle code, expect identity via the named event, not via image-path or command-line comparison, and check that any process which can be an `Interrupt` target registers its event before it writes its PID file.

### Executive Summary

The PR replaces Windows console CTRL_BREAK shutdown with keyed named events and removes path-based process identity checks. The main issue is that live-but-unregistered PIDs are collapsed into “not running,” so later start/cleanup paths can overwrite or skip the very live processes this PR is trying to preserve.

### Findings

#### Critical Issues

None.

#### Important Issues

I1. **Live unregistered PIDs are treated as safely absent** — `rdd/pkg/service/cmd/service.go:170` (important, regression)

```go
if !process.IsOurProcess(process.ServeInterruptKey, pid) {
	return PIDNotFound
}
return pid
```

`PID()` returns `PIDNotFound` for a live daemon that lacks the Windows event at line 170. `Start()` relies only on `Running()` at `rdd/pkg/service/cmd/service.go:275`, so the next `serve` process can overwrite `rdd.pid` at `rdd/pkg/service/cmd/service.go:704`, orphaning a pre-fix daemon or a daemon whose event registration failed. Fix: expose a distinct “live but unconfirmed” PID state. `Start()`/autostart should refuse or require explicit recovery for that state, and daemon/hostagent startup should register the event before publishing the PID file and fail startup if registration fails.

None.
