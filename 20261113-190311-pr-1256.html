Executive Summary ¶

Preferences now asks before it discards unsaved changes, keeps its shortcuts after a cancelled close, is destroyed on quit, and applies a picked language only on Apply. Those changes work, and tests cover them. One regression remains. The language picker still shows the displayed language, which no longer follows a pick, so after a tab switch it shows English while a Korean pick waits for Apply. The patch binds the picker to the pending preference.

export const plugins: Plugin<RootState>[] = [
  // Follow the App's locale, so a locale picked in Preferences takes effect
  // on Apply.
  function(store) {
    store.watch(
      (state, getters) => getters['preferences/committed']?.application?.locale,

      },

Repo context updates ¶

  • [repo] Preferences controls should read preferences/preferences, the committed App spec with the pending changes applied. A control bound to another getter, such as i18n/current, shows a stale value once a tab switch remounts it while a change is pending. When a PR changes what a store plugin watches, check every component that reads the getter that the plugin drives.
  • [repo] screenshots/screenshots.e2e.spec.ts runs only through workflow_dispatch, so CI never runs it. It makes a Preferences change to enable Apply and then closes the window with runBeforeUnload: true. Check it whenever a PR changes what happens when Preferences unloads.
