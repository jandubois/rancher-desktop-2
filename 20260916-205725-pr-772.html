// MirrorName returns the mirrored name for a given container resource.  The
// prefix is prepended to the mirrored name with a dash if the input is not a
// valid Kubernetes object name.
func MirrorName(prefix, input string) string {
	if len(validation.IsDNS1123Subdomain(input)) < 1 {
		return input
	}
	return fmt.Sprintf("%s-%x", prefix, sha256.Sum256([]byte(input)))
}

Design Observations ¶

Concerns ¶

  • The IsNotFound branch fires after the mirror it would skip has already been created (in-scope) Claude Opus 5. applyNamespace applies the object at line 80 and only then calls Labels (line 86), so the branch the author kept as future-proofing returns after re-creating a mirror for a namespace containerd says is gone. Fetching the labels first, or deleting the mirror in that branch, makes the guard do what its comment describes. This is about the ordering, not the reachability the author declined.
  • applyNamespace now costs three round trips on every container and image create (future) Claude Opus 5. Each call is an object apply, a containerd Labels call, and a status apply, all on the single event-loop goroutine (containerd_watcher.go:195,236). A k3s startup burst in k8s.io multiplies that by the number of containers, where the merge-base paid one no-op apply. Unmeasured.
  • resourceFieldSelector is evaluated when a watch is established, not when its inputs change (in-scope) Codex GPT 5.6 Sol. currentNamespace depends on another store module, and the only automatic rewatch watches the Kubernetes namespace. That is the mechanism behind I2's engine-switch case, and it will bite any future selector built the same way.

Strengths ¶

  • The selectable field reached every artifact it needed to (in-scope) Codex GPT 5.6 Sol. status.name is wired through the API type, both CRD copies, the apply configuration, the deepcopy, the TypeScript model, the serializer and the status API methods, and make verify-generate agrees.
  • activeNames survived the reroute (in-scope) Claude Opus 5 Codex GPT 5.6 Sol. sync_namespace_containerd.go:41-44 still records the mirror name outside the apply's error branch, so a failed apply cannot make the prune loop classify a live mirror as stale.
  • Dropping the existence check from ValidateUpdate is the right narrowing (in-scope) Gemini 3.1 Pro Claude Opus 5. spec.namespace is immutable, so re-checking on update only blocked controllers during the windows where mirrors do not exist. The retained comment says so.
  • The BATS test now covers the whole encoded-name round trip (in-scope) Gemini 3.1 Pro Gemini 3.5 Flash: the hashed name, both status fields through wait_for_resource_status, a label update through the new NamespaceUpdate path, the container inside the namespace, and the reaping.

Skill improvements ¶

  • When a change edits an error branch that feeds a server-side apply, check what the apply sends on that branch, not only what the branch computes. A generated apply-configuration setter that ignores an empty or nil value leaves the field out of the request, and an apply that omits a field the manager previously owned deletes it. A comment saying the branch "does not update" that field then describes the opposite of what happens, and no test catches it because the change is silent.
  • When a change flips a capability flag from a constant to a live value, enumerate every branch guarded by that flag and review each as new code. The diff shows one line; the behavior change is every if, v-if, and default that the constant had been pinning. Check in particular whether anything initializes the state those branches now depend on, and whether the flag can go false again while that state persists.
  • When a PR contains a commit that regenerates client code from the source in a sibling commit, diff the regenerated output against the source of record rather than treating it as machine-produced and therefore correct. A regeneration run before the last amendment to the schema produces output that is internally inconsistent, and a verification target that covers only one language will not see it.

Repo context updates ¶

  • [repo] REMOVE the entry saying supportsNamespaces() in the container-engine store returns a hardcoded false, that the namespace picker is dead code, and that renderer-side namespace defects should be rated as latent. The getter reads app.status.supportsNamespaces from the rdd/app root getter, so it is true whenever the container engine is containerd and the ContainerEngineReady reason is not NotApplicable — including while the VM is stopped. Rate renderer namespace defects as live.
  • [repo] UPDATE the entry saying a new CRD field missing from the generated TypeScript is expected follow-up work. That still holds for a PR that adds a field without regenerating, but when a PR contains its own rdd-client: regenerate commit the generated tree is in scope, and the regeneration can predate the commit it sits on. Compare the generated descriptions against the CRDs the same PR ships.
  • [repo] @typescript-eslint/no-unused-vars is off for the whole repository: the rancher-desktop-compatibility block in eslint.config.mts has no files restriction and turns it off globally, so an unused import or variable never fails yarn lint:typescript:nofix despite --max-warnings=0. Flag dead imports and bindings by reading, because the lint will not.
  • [repo] The renderer's resource watches take their field selector when the watch is established. rewatchResources is dispatched from exactly two places: the setCurrentNamespace action, and a Vuex plugin that watches the Kubernetes namespace in rddConnection.ts. Any state a fieldSelector callback reads must therefore be changed through an action that rewatches, or the live watch keeps the stale selector until the page remounts.
  • [repo] The Playwright mock control plane's App reconciler writes only the Settled condition. Any renderer behavior gated on another App.status field is unreachable from the e2e suite until the mock sets that field, whatever fixtures the mock creates for the resources underneath.
