Design Observations ¶

Concerns ¶

  • Rollback ownership sits with the wrong call (in-scope) Codex GPT 5.6 Sol Claude Opus 4.8 — state.changes carries both dialog edits and in-flight immediate writes, so one request's cleanup can mutate another's entry. That single overload produces I1. Giving each immediate write a request identity, or holding pending immediate values in their own per-key overlay, would let the preferences getter merge committed, staged, and pending values while keeping rollback the writer's own business.
  • SFC prop types go unchecked at call sites (future) Claude Opus 4.8 — typings/shims-vue.d.ts types every *.vue as DefineComponent<object, object, any>, so the RecursiveLeafKeysOfType<AppSpec, boolean | undefined> constraint on RdCheckbox.vue:19 binds inside the component only. A misspelled preference at ApplicationGeneral.vue or General.vue compiles and fails at runtime as a checkbox stuck on false. Moving the type-check step to vue-tsc would close the class. This compounds the CI type-checking gaps already recorded in repo context.
  • Two windows, two state.changes (future) Claude Opus 4.8 — the module-level pendingCommit, modifySerializer, and commitSerializer singletons all assume one store, as does the writeNow comment at line 177. The author has committed to fixing this architecturally. Noting it because that root and I1 are the same root.

Review Process Notes ¶

Skill improvements ¶

Run the project's real test suite when a checkout at the review SHA is available, and say so in the report. Agent worktrees routinely lack installed dependencies, which turns every test and type claim into a static trace. When the main checkout is clean and sits at the review SHA, run the suite from there, and for any finding that a fix is test-pinned, revert the fix and confirm the test goes red before crediting it. Executed results outrank four agents agreeing from inspection, and the revert step is the only way to tell a test that pins a fix from one that passes either way.

Treat a reviewer's stated run result as a claim about its own environment. Before repeating a pass count, a green suite, or a built binary, confirm the reporting agent could have produced it. An agent that cannot install dependencies cannot have run the suite, and a confident "checks are green" from such an agent is inference presented as measurement. Verify it independently or label it unverified; never pass it through.

On a round where the author reports fixes, diff the review SHAs and scope attention to what changed. Comparing the prior review's SHA against the current one names the exact files the round touched, which separates code that must be re-read end to end from code the prior round already cleared. This also catches a rewritten branch, where the prior SHA is no longer an ancestor and commit-by-commit reasoning silently breaks.
