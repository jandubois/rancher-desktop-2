## Executive Summary

The PR mirrors containers with `docker compose` labels into `ComposeProject` objects and adds a client-side JSONPath index helper. The mirroring logic holds up. But registering the index before the manager starts holds back every embedded runnable until the ComposeProject cache syncs, so the passthrough server starts after the control plane reports ready, and `bats-app` fails. The reconciler tests also swap in a hand-written index, so a broken JSONPath would pass them.

## Suggestions

S1. **Each member event sends a `Create` and a status write, and the message changes with every member** — `rdd/pkg/controllers/containers/compose/compose_reconciler.go:145-151` [Claude Opus 5.5, Gemini 3.1 Pro, Gemini 3.5 Flash]

```go

			Status:  metav1.ConditionTrue,
			Reason:  v1alpha1.ComposeHasMembersReasonFound,

```

Every event on a labelled container sends a `Create`, which fails with AlreadyExists once the project exists (line 115), then writes the status whether or not it changed. With several members, the message names whichever container fired last, so the API server cannot drop the write as a no-op, and each write enqueues a ComposeProject reconcile. `removeComposeMembership` (line 185) also writes when its UID guard removed nothing.

The spy's doc (`compose_reconciler_test.go:27-31`) says it exists to catch redundant writes, yet the idempotency subtest asserts two of them. Gemini 3.1 Pro and Gemini 3.5 Flash rated this Important; it costs writes and converges, so it stays a Suggestion.

Fix: `Get` first and `Create` only on NotFound, use a message that does not name the member, and skip `Status().Update` when the status is semantically unchanged.

## Design Observations

### Concerns

- **Membership changes only on observed Container events** (in-scope) [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash]. If rdd stops while delete events are queued (stopping the App deletes every Container through `cleanupMirrorResources`, `watch_reconciler.go:454`), the restart replays only the containers that still exist, so the deleted ones stay members. A containerd label change that moves a container to another project leaves it in both. The WIP branch resolves `HasMembers` from the member count alone, so a stale member keeps a project from ever reaching `False/Deleted` and being reaped. A level-triggered check in the ComposeProject arm, dropping members whose Container is gone, has another UID, or names another project, covers all three cases.
- **The config-hash gate decides which engine's projects appear** (in-scope) [Claude Opus 5.5]. nerdctl v2.1.2, which `rdd/dependencies.yaml:50-62` ships in the guest, labels compose containers with only `com.docker.compose.project` and `com.docker.compose.service` (`pkg/composer/up_service.go:188-189` at that tag); `com.docker.compose.config-hash` first appears in v2.2.0. So containerd projects never mirror today. That fits a design that removes projects with `docker compose down`, but a nerdctl bump will start mirroring them with no code change. Say which engines compose supports, in the design doc or at the gate.
- **Engine cleanup leaves ComposeProjects behind** (future) [Gemini 3.1 Pro, Claude Opus 5.5]. `cleanupMirrorResources` removes Containers, Volumes, Images and ContainerNamespaces (`watch_reconciler.go:454-463`), but not ComposeProjects. After an engine switch, a project's `status.namespace` can name a namespace that no longer exists, and the reaper on the WIP branch has to handle that.

### Strengths

- The request key includes the UID, and `reconcileContainer` re-reads the Container by name, so a mirror that a full sync deletes and recreates keeps its membership under the new UID. [Claude Opus 5.5, Codex GPT 6 Astra]
- `IndexField` and `IndexFields` separate the indexes the API server can serve from client-only ones, and the doc comment says why. [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.1 Pro]

## Review Process Notes

### Skill improvements

- Put the head commit's failing checks in the prompt. When a check is red, include each failing job's name and its first failure lines, and ask reviewers to explain the failure from the diff. A reviewer who sees only the tree assumes CI is green and never looks for a change in startup or ordering that only an integration suite exercises.
- When a change adds work that runs before a component reports ready (an informer, an index, an init hook, a migration), check what the ready signal waits for, and whether anything clients use after that signal now starts later.

### Repo context updates

- [repo] In `SharedControllerManager`, controller-runtime starts every controller and every plain `manager.RunnableFunc` only after each informer created before `mgr.Start` has synced, and `MarkControlPlaneReady` waits only for the webhook server. A controller that calls `base.IndexFields`, `base.IndexField` or `GetInformer` while registering adds an informer to that wait; on a CRD established moments earlier, its first watch draws a 429 with `Retry-After: 1s`. Check that nothing a client uses after the ready annotation depends on a runnable that waits for that sync.
- [repo] The guest's nerdctl (version in `rdd/dependencies.yaml`) labels `nerdctl compose` containers with only `com.docker.compose.project` and `com.docker.compose.service` before v2.2.0, which adds `com.docker.compose.config-hash`. Code that keys compose membership on any other label excludes nerdctl projects, and a nerdctl bump changes which projects it sees.

If a container's label is changed from `project-a` to `project-b`, the container is added to `project-b`, but lines 98–104 do not clear its membership from `project-a`. Querying the container index and removing the container from any `ComposeProject` where `status.name != projectName` would prevent stale memberships.

2. **`composeConfigFiles` assumes host path separators for container labels** `(future)`:
   `composeConfigFiles` (line 209) uses `filepath.Separator`. When running on Windows with WSL2 or Linux containers, container labels might record POSIX paths (`/home/...`) while the daemon evaluates them using Windows path rules (`\` and drive letters). A cross-platform path cleaner or using `path/filepath` normalization would improve compatibility.
