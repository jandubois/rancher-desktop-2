## Suggestions

S1. **`cygpath` test guard uses `is_windows`, breaking the PATH test on WSL2** — `bats/tests/32-app-controllers/kube-context.bats:128-131` [Codex GPT 5.5]

```bash
if is_windows; then
    run -0 cygpath -u "${bin_dir}"
    bin_dir="${output}"
fi
```

`is_windows` is true for both MSYS2 and WSL2 (`bats/helpers/os.bash`), but `cygpath` is MSYS-only — the helper layer already handles WSL with `wslpath` (`bats/helpers/commands.bash`). On a WSL2 runner this new test calls a missing binary before it reaches the PATH assertion. This matches the repo's documented BATS rule: gate an MSYS2-only tool on `is_msys`, not `is_windows`.

Fix:

```diff
-if is_windows; then
+if is_msys; then
     run -0 cygpath -u "${bin_dir}"
     bin_dir="${output}"
+elif is_windows; then
+    run -0 wslpath -u "${bin_dir}"
+    bin_dir="${output}"
 fi
```

S2. **A `DOCKER_CONFIG` that differs from the daemon's spawn-time value breaks the context lookup** — `cmd/rdd/run.go:124-127` [Codex GPT 5.5]

```go
{"DOCKER_CONTEXT", instance.Name()},
{"KUBECONFIG", instance.KubeConfig()},
```

`setupRunEnv` sets `DOCKER_CONTEXT` but leaves `DOCKER_CONFIG` alone. The daemon writes the `rancher-desktop-<instance>` context under its own `$DOCKER_CONFIG/contexts` (`docker_context.go:dockerConfigDir`), reading the value frozen at daemon-spawn time. So `DOCKER_CONFIG=/tmp/isolated rdd run docker ps` against a daemon started with the default `~/.docker` searches `/tmp/isolated` and cannot find the context. The common flows (no custom `DOCKER_CONFIG`, or a consistent one) work; only a mismatch fails.

Fix: optional. Before exec, create or update the instance Docker context in the child's effective `DOCKER_CONFIG` without changing `currentContext`, or document that `rdd run` assumes one `DOCKER_CONFIG`.

S3. **Help and design text overstate current-context preservation** — `cmd/rdd/run.go:42-44`, `docs/design/cmd_app.md:77` [Codex GPT 5.5, Claude Opus 4.8]

Both the help and `cmd_app.md` say the current context in `~/.kube/config` (and the selected Docker context) "stay as they are." Startup still switches the current context when the existing one is absent or unhealthy: `manageKubeContext` launches a probe that calls `setCurrentKubeContext` (`kube_reconciler.go:411-414`), and the engine reconciler does the same for Docker. The BATS suite asserts both switches (`kube-context.bats:139-145`, `engine-docker.bats:851-867`).

This is pre-existing App-startup behavior, documented at `api_app.md:42` ("only change the current context if it does not exist, or is not working"), not a code regression — the PR-introduced gap is the missing caveat.

Fix: add the absent/unhealthy caveat to the help and `cmd_app.md`, cross-referencing `api_app.md`.

S4. **An unset `PATH` leaves a trailing separator, adding the cwd to the search path** — `cmd/rdd/run.go:125` [Gemini 3.1 Pro]

```go
{"PATH", binDir + string(os.PathListSeparator) + os.Getenv("PATH")},
```

When `PATH` is unset, `os.Getenv("PATH")` returns `""`, leaving a trailing separator (`~/.rd2/bin:`). POSIX reads an empty segment as the current directory, so the cwd silently enters the executable search path. An unset `PATH` is rare for an interactive invocation, so this is low risk.

Fix: append the separator and the existing `PATH` only when it is non-empty.

S5. **Redundant `len(args) > 0` guard after `args[0]` was already indexed** — `cmd/rdd/run.go:69` [Claude Opus 4.8]

```go
if args[0] == "-h" || args[0] == "--help" {   // line 65: indexes args[0]
    return cmd.Help()
}
if len(args) > 0 && args[0] == "--" {          // line 69: len > 0 already guaranteed
    args = args[1:]
}
```

`cobra.MinimumNArgs(1)` runs even under `DisableFlagParsing`, so `runAction` is never reached with empty `args`, and line 65 already dereferences `args[0]`. The `len(args) > 0` clause at line 69 can never be false. The post-strip `len(args) == 0` check at line 72 is the one that matters (it catches `rdd run --`).

Fix: drop the `len(args) > 0 &&` clause at line 69.

S6. **A signal-killed child reports exit 255 instead of `128+signal`** — `cmd/rdd/run.go:156-158` [Claude Opus 4.8]

```go
var exitErr *exec.ExitError
if errors.As(err, &exitErr) {
    return &cliexit.Error{Code: exitErr.ExitCode()}
}
```

When the child dies from a signal, `exitErr.ExitCode()` returns `-1` (the Go `os/exec` contract), and `os.Exit(-1)` wraps to 255 on Unix, losing the `128+signal` status a shell would propagate. The PR's own comment notes signal handling is not yet wired up, so this is an edge case.

Fix: note the limitation in the existing comment, or on Unix map a signaled exit to `128 + int(ws.Signal())`.

## Review Process Notes

**Skill improvement:** When CLI code wraps or execs a subprocess and propagates its exit status, check the signal-death path. `(*exec.ExitError).ExitCode()` returns `-1` when the child is terminated by a signal, and `os.Exit(-1)` wraps to 255 on Unix, dropping the shell-conventional `128+signal` status. Flag exit-code propagation that forwards `ExitCode()` directly without handling the signaled case, and recommend mapping a signaled exit to `128 + int(signal)` on Unix.

**Skill improvement:** When code prepends a directory to `PATH` by concatenating it with the existing value (`newDir + sep + os.Getenv("PATH")`), check the empty-`PATH` case. An empty existing value leaves a trailing separator, and POSIX reads an empty `PATH` segment as the current directory — silently adding the cwd to the executable search path. Flag unconditional `PATH` concatenation and recommend appending the separator only when the existing value is non-empty.

**Repo context update [repo]:** `go test ./cmd/rdd` cannot run in a fresh review worktree: the package embeds `pkg/guestagent/lima-guestagent.gz`, a build artifact absent from a clean checkout, so the build fails before any test runs. Build the asset (run `make`) before `go test ./cmd/rdd`, or verify `cmd/rdd` logic through the BATS suite and through packages that do not embed the asset (`pkg/controllers/...` tests run without it).

The named context is written by the daemon under the daemon’s own `$DOCKER_CONFIG` at `pkg/controllers/app/engine/controllers/docker_context.go:31` and `pkg/controllers/app/engine/controllers/docker_context.go:61-72`; the daemon inherits that environment at start because `pkg/service/cmd/service.go:295` sets no `cmd.Env`. #### Suggestions

S1. **Trailing PATH separator when `PATH` is unset** — `cmd/rdd/run.go:124` (suggestion, gap)

```go
		{"PATH", binDir + string(os.PathListSeparator) + os.Getenv("PATH")},
```

If the `PATH` environment variable is completely unset, this assignment leaves a trailing path separator (e.g., `~/.rd2/bin:`). On POSIX systems, an empty segment in `PATH` (such as a trailing colon) is interpreted as the current working directory (`.`). While an empty `PATH` is rare, this accidentally elevates the current directory into the executable search path.

Fix: conditionally append the separator and the current `PATH`.

```diff
-		{"PATH", binDir + string(os.PathListSeparator) + os.Getenv("PATH")},
+		{"PATH", appendPath(binDir, os.Getenv("PATH"))},
```
Where `appendPath` handles the empty case:
```go
func appendPath(newDir, current string) string {
	if current == "" {
		return newDir
	}
	return newDir + string(os.PathListSeparator) + current
}
```

**Strengths**
- **Robust CLI Flag Handling:** Disabling flag parsing for `rdd run` (`DisableFlagParsing: true`) while cleanly intercepting `--help` and escaping with `--` natively supports executing arbitrary child commands without inadvertently absorbing global `rdd` flags that follow the subcommand.
