Executive Summary ¶

This PR adds an ImagePullRequest reconciler, a validating webhook, progress status fields, and a moby-backed pullImage, alongside a Complete→Settled condition rename and a reconciler split. The state machine is careful and unusually well unit-tested. Five Important defects survived verification: the bulk reconcile path discards every requeue, two documented failure reasons are unreachable, a stale progress callback writes onto a recreated request, the refactor lost workqueue coalescing, and progress writes are unthrottled.

Four reviewers ran. Codex timed out without emitting a review, but the probe tests it left in .scratch/ were recovered, executed, and contributed two findings no other reviewer raised (I3, S2). Findings marked reproduced below come with a failing test written and run against the review SHA; go build and go test -race are otherwise clean on every changed package.

Design Observations ¶

Concerns ¶

The webhook makes the reconciler's "engine not ready" path nearly unreachable (in-scope) Claude Opus 5. imagePullRequestValidator.validate rejects a request whose spec.namespace names a ContainerNamespace that does not exist, and ContainerNamespace/moby is created by the engine controller's fullSync and swept by cleanupMirrorResources when the app stops. So a client cannot queue a pull while the engine is down — yet reconcileImagePullRequest:91-95 is built around exactly that case, and the whole req.UID == "" bulk-scan branch exists to serve it. The two mechanisms encode opposite assumptions about who waits. Worth settling explicitly: either relax the webhook so requests can be queued ahead of the engine, or drop the queue-for-later machinery.

A daemon restart mid-pull surfaces as PullTimeout, never a resume (future) Claude Opus 5. Once Settled=False/Pulling is persisted, nothing re-enters e.pullImage for that object; the reconciler only waits out the clock and settles as timed out. After a restart the pull is provably dead, so the wait buys nothing and the reason misleads. Treating a Pulling request with no in-memory state as orphaned and restarting it would be both faster and more accurate.

Failed=False, Reason=Succeeded is an awkward encoding (future) Claude Opus 5. A condition named Failed carrying the reason Succeeded reads oddly in kubectl output and in the BATS test name. Settled already distinguishes ImagePulled from Errored, so Failed is redundant on the success path.

No private-registry authentication (future) Gemini 3.5 Flash. ImagePullRequestSpec carries only repoTag, with no credential or secret reference, so only public images can be pulled. Worth stating as a known limitation in the design doc rather than leaving it implicit.

Strengths ¶

Cancel-cause plumbing Claude Opus 5. Making imagePullRequestReason an error so it can ride context.CancelCauseFunc, then testing it with errors.AsType in onComplete, cleanly separates "we already decided the outcome" from "something else cancelled us."

Settled re-checks inside the retry closure Claude Opus 5. Every status write re-checks IsStatusConditionTrue(Settled) inside its RetryOnConflict body, so a late progress callback cannot resurrect a settled request even if it wins the initial read — the conflict forces a re-read that sees the terminal state.

Refactor ordering and mechanics Claude Opus 5. Splitting watch_reconciler.go out before adding the second reconcile path is the right sequence, and a function-set diff against the merge-base confirms the move is mechanical apart from the reconcileWatcher extraction and the watcher→engine rename.

newDockerWatcher takes a plain enqueue func() Claude Opus 5. Replacing the chan<- event.GenericEvent parameter puts the buffering policy with the reconciler that owns the channel.

Referential-integrity webhook Gemini 3.5 Flash. Validating that the referenced ContainerNamespace exists before admission prevents a class of invalid requests reaching the reconciler at all — see the first concern for the tension this creates.

  2. Delete/recreate under the same name (I3). No test covers a progress or completion callback outliving its object; the UID guard that exists at line 320 has no counterpart test.

Review Process Notes ¶

Skill improvements ¶

  • [ ] When an agent hits its deadline without emitting a review, inspect its .scratch/ directory before recording it as failed. An agent that spends its budget writing and running probe programs leaves reproductions behind that are stronger evidence than the prose review would have been; execute them against the lead worktree and attribute the resulting findings to that agent. Only after that comes up empty should the retry budget be spent.
  • [ ] When a finding asserts that an external system emits events at some rate, locate the emitter's own throttling before accepting the rate. Producers of progress or event streams commonly rate-limit at the source, so a claim of "unthrottled" or "N per second" usually rests on the reviewer's intuition rather than the emitter's code; the corrected bound often changes the severity without changing the underlying concern.
  • [ ] When a finding says a value returned by an inner call is discarded, check whether any other path can supply that value before rating it. A dropped error is usually cosmetic because the operation retries, but a dropped scheduling or continuation token often has no alternative producer, which turns a tidiness nit into stranded state — and the difference is only visible by looking for the second producer.
  • [ ] When a guard against a hazard appears at one call site, grep for the other call sites that share the hazard. A comment explaining why a check exists is evidence the author knew about the failure mode; its absence at a sibling site is more likely an oversight than a deliberate exemption, and this asymmetry localises real bugs faster than reading either site alone.

Repo context updates ¶

  • [ ] [repo] On Windows this repo runs its BATS suite under MSYS2, not inside WSL: CI invokes C:\msys64\usr\bin\bash.exe, so uname reports MINGW*/MSYS*. Running BATS inside WSL is unsupported because restarting WSL kills the test process. The WSL-detection branch in rdd/bats/helpers/os.bash is therefore latent — treat defects in it as latent rather than as live regressions.
  • [ ] [repo] The engine reconciler is a cluster-scoped singleton whose reconcileWatcher pass is object-independent and issues several List calls per invocation. When reviewing changes to its event handlers, check whether mirror-resource events still map to a single constant workqueue key: giving each object its own key defeats the workqueue's dedup and turns a fullSync burst from O(N) into O(N²).
  • [ ] [repo] *Request CRDs in this repo use paired Settled and Failed conditions, where Settled=True marks any terminal state and Failed distinguishes the outcome; a successful request carries Failed=False, Reason=Succeeded. Only ImagePullRequest has a controller — the other *Request types exist as CRD schema with no reconciler, so a finding that one of them "does nothing" is expected, not a defect.
