Executive Summary ¶

The PR logs named startup timing points and shows a static, sandboxed splash from Electron's ready until the first app window is visible. The design is sound. The one Important finding: the "Incompatible RDD Service" box, the startup error that #463 describes, comes up over the still-spinning splash, and the obvious fix of closing the splash first deactivates the box on macOS. Hiding the splash fixes both. The five suggestions are optional.

Only the first window that createWindow() builds can close the splash, and only when that window shows or finishes loading. If that window's page fails to load, or the user closes the main window before its page finishes loading, no later window takes over. The splash then stays on screen until the app quits, and the timing line never reaches the log. A harness that loads the real modules against a stand-in Electron reproduced the second case. A reopened main window finished loading with the splash still open. A packaged build loads a local app:// page, so both triggers are rare.

Fix: also close the splash from the first window's closed event and from a main-frame did-fail-load (check isMainFrame).

Outcome: fixed in b891a8bba. The first window's closed ends startup for any first window. A main-frame did-fail-load or a render-process-gone ends it only for the visible main window, because closing the splash when a hidden dialog's page fails would leave nothing on screen. window/__tests__/index.spec.ts covers each trigger.

Acknowledged Limitations ¶

  • Code comment, splash.ts:63-64: "e2e tests (including the screenshot specs) call electronApp.firstWindow(), which would return the splash instead of the first app window." So the e2e specs don't cover the splash.
  • Code comment, window/index.ts:93-95: "The main window starts visible, so its first page load is the closest event." Accepted; S1 covers the case where that load never finishes.
  • Settled design, do not re-suggest: the four hardcoded theme colours; the static data-URL page, because nothing may delay the splash; a native launcher in place of the Electron splash; the queued rewording of the startupTiming.ts import comment. #463's error half and the #1327 race stay out of scope.
  • Checked and dropped, do not re-suggest: a <title> for the splash, because a window without one takes app.name ("Rancher Desktop 2") as its title (measured); a default for createWindow()'s options, because its type makes the parameter required; closable: false, since a user who closes the splash loses only the splash.

Repo context updates ¶

  • [repo] Two native error boxes can appear during startup. Only the before-quit failure path reaches showErrorDialog in background.ts. The "Incompatible RDD Service" box in main/rdd-ctl.ts can appear before any app window opens, because setupNetworking() fires rdd/kube-config without waiting for it. A change that must act before "a startup error", such as removing a window or flushing a log, has to cover the second one.
  • [repo] Destroying or closing the app's last open window fires window-all-closed synchronously, and the handler in background.ts hides the macOS dock icon, which deactivates the app. A native box shown next comes up inactive, with a grey button that Return doesn't press. Until the first app window opens, any early window such as a splash is the last one, so code that removes it before a dialog should hide it.
  • [repo] A BrowserWindow whose page lacks a <title>, and that doesn't set the title option, takes app.name as its title, which is "Rancher Desktop 2" in dev and packaged builds. Do not flag a missing title as showing "Electron" or the page URL.
