## Executive Summary

On Windows, a bundled rdd publishes each tool as a hardlink to one user-owned forwarder plus a `.shim` naming the real binary. PR #940, now in the base, builds and signs the forwarder, which resolves round 1's Critical; every check passes. But no test runs the real forwarder, so a re-sync from upstream that drops the `argv[0]` passthrough would break Windows `kubectl` with every suite green. Two comments that this round added also overstate the code.

## Suggestions

S1. **The standalone prune deletes a forwarder on any stat error** — `rdd/pkg/binlinks/forwarders.go:174-177` [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.1 Pro, Gemini 3.5 Flash]

```go
		if _, err := os.Stat(target); err == nil {
			continue
		}
		dropForwarder(binDir, strings.TrimSuffix(name, shimSuffix)+".exe")
```

Round 1 S1, unaddressed. A permission error, an unready drive or an offline share deletes the forwarder and its shim although the target exists, and restoring access does not bring them back. A probe with an unreadable target directory lost the forwarder, while the readable case kept it. `pruneDanglingLinks` skips and warns on the same error (`rdd/pkg/binlinks/binlinks.go:185-189`). It stays a Suggestion because only a standalone start reaches it, and the next bundle start republishes every forwarder.

Fix: skip and warn unless `os.IsNotExist(err)`, as `pruneDanglingLinks` does.

S2. **`dropForwarder` deletes the shim first, so a forwarder that it cannot remove is never found again** — `rdd/pkg/binlinks/forwarders.go:199-207` [Claude Opus 5.5]

```go
	if err := os.Remove(shimPath(binDir, tool)); err != nil && !os.IsNotExist(err) {
		klog.Warningf("Failed to remove shim for %q: %v", tool, err)
	}
	forwarder := filepath.Join(binDir, tool)
	if err := os.Remove(forwarder); err != nil && !os.IsNotExist(err) {
		if asideErr := renameAside(forwarder); asideErr != nil {
			klog.Warningf("Failed to remove forwarder %q: %v", tool, err)
		}
	}
```

Both reconcile passes find forwarders through their `.shim` files. When the removal and the rename aside both fail, as when the tool runs and its `.old` name is busy (S4), the forwarder stays on PATH with nothing left to find it until `rdd svc delete`. A probe that blocked both operations, cleared the blocker and ran again kept the orphan. At the merge-base, `RemoveAll` swept such an entry on the next start.

Fix: remove the forwarder first and keep the shim when that fails, so the next start retries; log `asideErr`, which also fixes S8.

S3. **Every start rewrites each shim in place** — `rdd/pkg/binlinks/forwarders.go:85-89` [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.1 Pro, Gemini 3.5 Flash]

```go
	for tool, target := range want {
		if err := os.WriteFile(shimPath(binDir, tool), shimContent(target), 0o644); err != nil {
			klog.Warningf("Failed to write shim for %q, skipping: %v", tool, err)
			continue
		}
```

Round 1 S2, unaddressed. Go opens the file with `FILE_SHARE_READ | FILE_SHARE_WRITE`, and the forwarder opens it with `GENERIC_READ, FILE_SHARE_READ` (`rdd/src/rdd-forwarder/shim.cpp:545`). So neither side reads a half-written shim; when the two overlap, one of them fails. Either rdd skips relinking that tool for this start, or the forwarder exits with "Cannot open shim file for read". Reasoned from source, unverified on Windows.

Fix: write through `atomicfile.Write` (`rdd/pkg/util/atomicfile/atomicfile.go:70`), which skips identical content, so a start with an unchanged bundle writes nothing.

S4. **A fixed `.old` name can block the forwarder refresh** — `rdd/pkg/binlinks/forwarders.go:217-219` [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.1 Pro, Gemini 3.5 Flash]

```go
	aside := path + ".old"
	_ = os.Remove(aside)
	return os.Rename(path, aside)
```

Round 1 S3, unaddressed. While a process started from an earlier forwarder copy still runs, `os.Remove(aside)` fails and the rename cannot replace the running `.old` file. For the master copy, `linkForwarders` then returns before it writes any shim (lines 81-83). It takes a long-lived process that spans two forwarder updates, and it clears once that process exits. Unverified on Windows.

Fix: give each aside file a unique name; `sweepAside` already matches by suffix.

S5. **A bundled file without a lower-case `.exe` gets a forwarder but loses its shim** — `rdd/pkg/binlinks/forwarders.go:147` [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.5 Flash]

```go
		tool := strings.TrimSuffix(name, shimSuffix) + ".exe"
```

Round 1 S4, unaddressed and still latent. This line appends `.exe` to every shim name, so `removeStaleForwarders` deletes the shim that line 86 just wrote for `UPPER.EXE` or `LICENSE`. The forwarder also derives its shim name by overwriting the last three characters of its own (`rdd/src/rdd-forwarder/shim.cpp:539`). A packaged bundle holds only lower-case `.exe` files today.

Fix: skip bundle entries whose extension is not `.exe`, compared case-insensitively.

S6. **An upgrade from the alpha link layout keeps tools that the bundle dropped** — `rdd/pkg/binlinks/forwarders.go:143-151` [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.5 Flash]


Round 1 S5, unaddressed. `removeStaleForwarders` walks only `.shim` files, and links from the merge-base layout have none, so a dropped tool's old hardlink stays on PATH. That layout shipped in `v2.0.0-alpha.1` and `v2.0.0-alpha.2`. Round 1's fix would now break `TestLinkForwardersPreservesOtherFiles`, which keeps unrelated files on purpose.

Fix: in bundle mode, also drop any `.exe` that is neither a wanted tool nor the master copy.

S7. **The master copy is on PATH and outlives an uninstall** — `rdd/pkg/binlinks/forwarders.go:80-83` [Claude Opus 5.5, Gemini 3.5 Flash]

## Design Observations

### Concerns

- **The MSI still puts the bundle's bin directory on PATH** (future) [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.5 Flash]: `build/wix/main.wxs:91` and `:116` add `resources\windows\bin\`. Since #940 that directory also holds `rdd-forwarder.exe`, a second shim-less forwarder on PATH. Issue #448 plans to remove both entries.
- **AppLocker's default rules would block the forwarders** (future) [Claude Opus 5.5]: Microsoft's documented default executable rules let a standard user run binaries only from `%ProgramFiles%` and `%WinDir%`, so forwarders under `%USERPROFILE%\.rd2\bin` would not run where AppLocker enforces them. The MSI's PATH entry hides that today. Not tested here.

### Strengths

- **The vendored forwarder keeps all three contract invariants** (in-scope) [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.1 Pro, Gemini 3.5 Flash]: it reads `<own name>.shim` (`rdd/src/rdd-forwarder/shim.cpp:539-545`), splits `path = ` on the ` = ` separator (`:56`), and launches the target with its own command line (`:738`, `:752`), so `rdd/cmd/rdd/multicall.go` sees `kubectl`.
- **The daemon outlives the `rdd.exe` forwarder** (in-scope) [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.1 Pro, Gemini 3.5 Flash]: the vendored `shim.cpp:836` still sets `JOB_OBJECT_LIMIT_SILENT_BREAKAWAY_OK`, so the daemon that `rdd svc start` spawns leaves the job.
- **A normal start renames nothing** (in-scope) [Claude Opus 5.5, Codex GPT 6 Astra]: an unchanged forwarder keeps its file identity, which `TestLinkForwardersReconciles` pins.

## Acknowledged Limitations

- **`.old` files can outlive a start.** `sweepAside` skips aside files still in use, and the next bundle start removes them. A standalone start never sweeps (S7).
- **rdd owns the bin directory.** Each start manages the tool names and the `.shim` and `.old` files there, so guarding user-placed binaries stays declined; do not re-suggest it. Round 1 gave the reason as "rdd rewrites that directory on every bundle start", which no longer holds on Windows, where the bundle path reconciles in place.
- **`shimTarget` reads only what rdd writes.** `shimContent` is the only writer, so a general parser stays declined. `TestShimTarget` accepts `path=/usr/bin/rdd`, which the forwarder rejects for lacking ` = `; rdd never writes that form.

In `forwarders.go:221`, `renameAside` appends a fixed `.old` suffix. If an earlier process is still holding `path.old` open, `os.Remove(aside)` will fail on Windows because running executables cannot be deleted. ###### Design Observations

###### Strengths

1. **In-place reconciliation prevents executable locks**: Reconciling in place rather than wiping `binDir` via `os.RemoveAll` allows `rdd svc start` to run through its own forwarder (`~/.rd<n>/bin/rdd.exe`) without triggering `ERROR_ACCESS_DENIED` on active binaries.
2. **Space-efficient hardlinked forwarder architecture**: Publishing a single master copy of `rdd-forwarder.exe` (~140KB) hardlinked to each tool name alongside `.shim` descriptors allows non-privileged standard users to access bundled utilities without requiring symlink privileges or multi-megabyte binary copies.
3. **Multicall preservation via `argv[0]` pass-through**: In `rdd/src/rdd-forwarder/shim.cpp:752`, passing `GetCommandLineW()` to `CreateProcessW` preserves the invocation command name (`argv[0]`), enabling `rdd`'s multicall dispatcher (`rdd/cmd/rdd/multicall.go`) to distinguish `kubectl` from `rdd` seamlessly.
4. **Daemon breakaway from job objects**: `shim.cpp:836` sets `JOB_OBJECT_LIMIT_SILENT_BREAKAWAY_OK` on the job object, ensuring background processes spawned by `rdd svc start` break away cleanly and outlive the forwarder shim.

###### Concerns

1. **Unconditional shim truncation on startup** *(in-scope)*: Calling `os.WriteFile` unconditionally on every tool's `.shim` file on every service start exposes running CLI processes to transient 0-byte reads and file sharing violations. Adding an equality check before writing removes this window.
2. **Static `.old` rename target** *(in-scope)*: Relying on a fixed `.old` file name causes `renameAside` to fail if an earlier process is still running from that `.old` file. Using a unique temporary suffix eliminates rename collisions.
3. **MSI PATH duplication** *(future)*: `build/wix/main.wxs:91, 116` continues to place `[APPLICATIONFOLDER]resources\windows\bin\` directly on the system and user PATH. Issue #448 plans to remove these entries once the forwarder scheme is fully established so PATH routes exclusively through `~/.rd<n>/bin`.

###### Acknowledged Limitations

- **`.old` files outliving a start** (`forwarders.go:227-234`):
  `sweepAside` skips `.old` files that are currently held open by running processes, deferring removal to the next startup. This intentional trade-off prevents startup blocking and avoids unsafe termination of running tools.
- **`rdd` ownership of `binDir`** (`binlinks.go:10-12`):
  Inside the application bundle, `rdd` owns the instance bin directory. While Windows reconciles in place to preserve running executables (tested by `TestLinkForwardersPreservesOtherFiles`), user-placed files shadowing bundled tools are not supported.
- **`shimTarget` reads only what `rdd` writes** (`forwarders.go:189-201`):
  `shimTarget` parses the single `path = <target>` line generated by `shimContent`. A general INI/key-value parser was intentionally declined because `rdd` only reads its own generated shims.
