## Executive Summary

The PR adds a kuberlr-style resolver under `pkg/kuberlr/`: it probes the cluster's version and, when the embedded kubectl is more than ±1 minor out of skew, downloads an sha512-verified match from dl.k8s.io and execs it. The implementation is careful, well-commented, and well-tested. The one user-facing gap is that a cache-miss download runs silently at the default `warn` log level, so the command appears to hang.

Claude carried the review with the only Important finding and the sharpest design observations; Codex contributed one unique real finding and shared another; Gemini produced two "Critical" findings that were both hallucinations against code that reads correctly — verified and dropped. The remaining findings are four low-risk suggestions. No correctness defect blocks the merge.

## Important Issues

I1. **Cache-miss download runs silently at the default log level** — `pkg/kuberlr/downloader.go:78` [Claude Opus 4.8]

```go
logrus.Infof("downloading kubectl v%d.%d.%d from %s", want.Major, want.Minor, want.Patch, mirrorURL())
```

The only feedback before a multi-megabyte fetch (bounded by a 5-minute timeout) is an `Info` log. Outside developer mode the level defaults to `warn` (`cmd/rdd/main.go:99-101`), so an end user running a packaged `rdd kubectl get pods` against an out-of-skew cluster sees nothing while the command appears to hang.

The BATS suite cannot catch this: it runs `bin/rdd` from the source tree, where `developer.Mode()` returns true (it keys on `../cmd/rdd/main.go` beside the executable) and the level is `debug`, so the line shows in tests but not in production. I confirmed both facts against the code.

Fix: print the notice to stderr unconditionally, so it shows at any log level — user-facing progress, consistent with the repo's interactive-UX principle.

```go
fmt.Fprintf(os.Stderr, "Downloading kubectl v%d.%d.%d from %s ...\n", want.Major, want.Minor, want.Patch, mirrorURL())
```

## Suggestions

S1. **Resolver discards known-flag parse errors and probes the default cluster** — `pkg/kuberlr/resolver.go:179-188` [Codex GPT 5.5]

```go
_ = fs.Parse(args)
return cf
```

`parseKubeConfigFlags` ignores `fs.Parse`'s error, so a malformed known flag — `rdd kubectl get pods --kubeconfig` with no value — leaves the connection overrides unset. `loadClientConfig` (resolver.go:154) then builds a client from the default kubeconfig and probes that cluster; if it is reachable and out of skew, the resolver downloads a kubectl for a cluster the user never named, before kubectl reports the flag error.

The trigger is narrow (a typo plus a reachable, out-of-skew default cluster) and self-correcting, so this consolidates to a Suggestion rather than the Important Codex assigned. The fix also aligns this path with `isClientOnly`, which already treats a parse failure conservatively.

Fix: return `fs.Parse`'s error from `parseKubeConfigFlags`; `serverVersion` already falls through on any `loadClientConfig` error.

## Design Observations

### Concerns

- **Exact-patch download can 404 for vendor clusters** `(future)` [Claude Opus 4.8] — `Resolve` passes the server's exact parsed version to `ensureCached`, so a server reporting `v1.32.7-gke.500` downloads `kubectl-v1.32.7` (`downloader.go:99`). Skew compatibility is a minor-level guarantee, yet the resolver pins the patch. A vendor build whose patch number is not published on dl.k8s.io would hard-fail every kubectl call against that cluster, per the loud-error policy. Upstream patches usually exist, so this is rare; resolving the latest published patch of the server's minor would remove the risk. `TODO(offline)` already flags follow-up nearby.
- **Hand-rolled kuberlr reimplementation owns upstream's maintenance tail** `(future)` [Claude Opus 4.8] — the package reimplements flavio/kuberlr inline because its logic lives under `internal/`. The right call given the constraint; flagged so the ownership of dl.k8s.io URL drift, checksum-format variants, and cache eviction (`TODO(eviction)`) is explicit and revisited if upstream ever exports the resolver.

### Strengths

- **`rdd ctl` skips the probe** `(in-scope)` [Codex GPT 5.5, Claude Opus 4.8] — `ctlAction` calls `SkipResolver()` before `kubectlAction`, keeping the embedded-control-plane path off the network; the embedded apiserver and kubectl share a module entry and cannot drift.
- **Hardened download path** `(in-scope)` [Codex GPT 5.5, Claude Opus 4.8, Gemini 3.1 Pro] — streaming sha512 verification with body-size caps, an atomic temp-file-then-rename publish, and a per-request 5-minute timeout.
- **Probe reuses kubectl's `genericclioptions.ConfigFlags` loader** `(in-scope)` [Claude Opus 4.8] — the probe targets the same cluster the kubectl child will contact, with correct `KUBECONFIG`/`--kubeconfig` precedence, avoiding the config-file-only-default class of bug.
- **Unbound basic-auth flags** `(in-scope)` [Gemini 3.1 Pro] — leaving `--username`/`--password` unbound stops `ToRawKubeConfigLoader` from launching an interactive stdin prompt during the background probe.
- **`compatible` casts to int64 before subtracting** `(in-scope)` [Claude Opus 4.8] — avoids unsigned-minor underflow when the client minor is below the server minor.

## Acknowledged Limitations

Declined in prior rounds (PR #348, carried forward in the repo-context file):

- **Windows `os.Rename` cache-publish race** (`downloader.go:128`) — two concurrent first-time downloads of the same version can both reach `os.Rename`; on Windows the second fails. Declined rounds 1–8. This PR adds a second `CacheRoot`/`CacheDir` consumer (`rdd svc paths`), but that path never downloads, so the race surface is unchanged.
- **`CacheRoot` panics if `os.UserCacheDir` fails** (`cache.go:52`) — declined rounds 1, 2, 3, 5, 7, 8. `service_paths.go:33` adds a call site reached by `rdd svc paths`, which the BATS harness sources on every test, so a failure would now also crash the test bootstrap. Likelihood stays near zero (it needs `$HOME`/`$XDG_CACHE_HOME`/`%LocalAppData%` all unset), so per the decline history this stays noted, not re-raised.

Documented in code as intended follow-ups:

- Cache eviction and leaked `.kubectl-*` temp files on SIGKILL (`cache.go:33`).
- Offline fallback when a download fails against a reachable out-of-skew cluster (`resolver.go:64`).
- `maxKubectlBytes` truncation surfacing as a checksum mismatch if kubectl ever exceeds 256 MiB (`downloader.go:138`).
- Windows child-process exec hard-killing on context cancel (`exec_windows.go:27`); the cobra context is never canceled today.
- `local_teardown_file()` in `7-kubectl-cache.bats` deviates from the no-teardown convention; the author documents the exception (an ephemeral-port HTTP server leaks ports if left running). Reasonable.

### Executive Summary
The PR implements an automatic, out-of-skew version resolver for `rdd kubectl` that downloads compatible binaries from upstream Kubernetes mirrors, sharing them across instances. The Go implementation is robust, well-abstracted, and elegantly integrated into the CLI without regressions. ### Findings

#### Critical Issues

C1. **BATS test syntax corrupted by global replace** — `bats/tests/10-cli/7-kubectl-cache.bats:134`, `bats/tests/10-cli/5-paths.bats:42`

```bash
 @pkg/util/tail/tail_test.go 'rdd kubectl downloads a version-matched kubectl on cache miss' {
```

A search-and-replace error replaced the BATS `@test` block syntax with `@pkg/util/tail/tail_test.go` throughout the new `7-kubectl-cache.bats` file and in one test in `5-paths.bats`. Because BATS ignores blocks that do not start with `@test`, the entire caching test suite is silently skipped during execution, resulting in a false-green CI run.

Fix: Revert `@pkg/util/tail/tail_test.go` back to `@test` on all test block definitions. (critical, regression)

C2. **Malformed parameter expansion in test helper** — `bats/tests/10-cli/7-kubectl-cache.bats:105`

```diff
-        rdd "$ @"
+        rdd "$@"
```

The `rdd_env` test wrapper uses `"$ @"` (with a space) instead of `"$@"`. In Bash, `"$ @"` does not expand the positional parameters; instead, it evaluates to the literal string `$ @` and drops the actual arguments (`kubectl get pods`). When C1 is fixed and the tests execute, this will cause the `rdd` CLI to fail with an unknown command error.

Fix: Remove the space to correctly expand the passed arguments as `"$@"`. (critical, regression)
