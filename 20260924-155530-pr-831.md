## Review Process Notes

I2 cites commit `1bfad4f42` because its subject is the commit message. The citation lint reports it as unresolved; that warning is expected.

### Skill improvements

- When a PR says it addresses the review of an earlier PR, fetch that review's
  report and inline the findings the PR claims, and the ones it leaves
  unclaimed, as the specification of record. The diff shows what changed, not
  which finding each change answers, so without the report agents cannot tell
  a partial fix from a complete one, or an old finding from a new one.

### Repo context updates

- [repo] `rdd/.golangci.yml` forbids `t.Fatal*` in tests through `forbidigo`. A
  test's timeout or unreachable branch fails with `assert.Assert(t, false, msg)`,
  as the existing tests do. Check a proposed test patch against this rule before
  quoting it.
- [repo] Nothing in CI checks that `rdd/go.mod` is tidy. `go-mod-k8s-sync.yaml`
  runs `go mod tidy` only on PRs that touch `rdd/go.mod`, and commits the result
  to same-repository PR branches. When a diff deletes an import, run
  `go mod tidy -diff` in `rdd/`, since the stale requirement otherwise surfaces
  in the next unrelated PR that touches `go.mod`.

### Design Observations

#### Concerns

- **Orphaned Go dependencies on refactors** `(in-scope)`: When refactoring code to drop heavyweight dependencies (such as `compose-go`), omitting `go mod tidy` leaves unused modules in `go.mod` and `go.sum`. Adding a CI check (e.g., `go mod tidy -diff`) or running it during `make check` prevents dependency bloat from accumulating silently across PRs.

#### Strengths

- Moving `spec.name` validation to the declarative CRD schema pattern `^[a-z0-9][a-z0-9_-]*$` eliminates runtime dependency on `compose-go`'s `NormalizeProjectName` while maintaining 100% behavioral equivalence.
- Checking `os.Stat(request.Spec.WorkingDir)` and asserting `stat.IsDir()` before `os.OpenRoot` cleanly eliminates the potential goroutine leak/hang on FIFOs without altering directory resolution semantics.
