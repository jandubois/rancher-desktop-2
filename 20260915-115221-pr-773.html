Executive Summary ¶

This PR adds the ComposeProject and ComposeUpRequest API types, a webhook that checks request names, and a context parameter on RegisterWithManager. The fields and naming rule follow the design doc, and the build, lint, generated-file, and race checks pass. A probe shows the new context stays live after the manager fails. Three API comments, which kubectl explain prints, contradict the code or the spec, and the naming test takes its expected value from the function it tests.

Four reviewers ran. Gemini 3.1 Pro's first run stopped mid-review, and its one retry completed. I ran a reproducer for every Important finding in the lead worktree, two of them envtest probes against a real kube-apiserver, and each fix comes with a patch I tested. The findings fall into four groups: the context contract (I1), API text that the code or the spec contradicts (I2, I4, I5), the naming test (I3), and admission gaps (S1 to S3).

rdd/docs/design/api_containers.md
express state.  `Settled` will become `True` when the request object has reached
a terminal state (it will not produce any more actions).  Once a request object
has reached such a terminal state, unless it has an owning reference set, it
will be automatically removed after some timeout.  This will be at least one
minute (so the caller can read any data), but the precise timing is unspecified.
If the `Settled` condition is set to `True` but it is not successful, then the
`Failed` condition will exist and set to `True`, with the reason and message
describing what the error is.

This API is mainly for use by the Rancher Desktop front end; all other users are
strongly urged to use the relevant CLI or other API instead.

Design Observations ¶

Concerns ¶

  • The tree already has a manager-lifetime context that ends on every stop path (in-scope) Claude Opus 5. The engine reconciler derives watcherCtx from context.Background() and cancels it from a manager.RunnableFunc (rdd/pkg/controllers/app/engine/controllers/engine_reconciler.go:209-225), and ImagePullRequest runs its long pulls under it (image_pull_request_reconciler.go:257). controller-runtime cancels a Runnable's context whenever the manager stops, and waits up to the 10 s GracefulShutdownTimeout for it to return. A compose reconciler could use the same pattern, which would make 011117602's parameter unnecessary. Of its 17 implementors, 16 ignore it, and the 17th, the mock, uses it only during setup. If the parameter stays, apply I1's fix.
  • Deterministic request names allow one ComposeUpRequest per project at a time (future) Claude Opus 5. A settled request stays for at least a minute (api_containers.md:36-38), so a second up in that window fails with AlreadyExists, and an update with an unchanged spec bumps no generation. The spec should say how a client runs up again.
  • Reaping can run docker compose down on containers the user never deleted (future) Claude Opus 5. cleanupMirrorResources deletes every Container mirror when the App stops (watch_reconciler.go:449-466), so every ComposeProject will fall to HasMembers=False and be reaped. Deleting a project runs docker compose down --remove-orphans, which "may be retried later" (api_containers.md:720-731); a retry after the next start removes the project's containers. The spec should say that a project deleted while HasMembers=False drops its finalizer without running down.

Strengths ¶

  • The name rule is in a webhook because CEL cannot hash (in-scope) Claude Opus 5 Codex GPT 5.6 Sol Gemini 3.5 Flash. CEL transition rules keep spec.namespace and spec.name immutable, so the name stays consistent with the spec across updates.
  • +listType=map keyed on name (in-scope) Claude Opus 5 makes the API server enforce the spec's rule that each status.containers name is unique.
  • The validator does not require the ContainerNamespace to exist (in-scope) Claude Opus 5, so it avoids the boot-window rejections the ImagePullRequest webhook produces.
  • Both binaries register the compose controller (in-scope) Claude Opus 5 Codex GPT 5.6 Sol. The containers aggregator's blank import pulls it into cmd/containers-controller and the embedded service.

Review Process Notes ¶

Skill improvements

  • Quote the liveness monitor's glob. The Monitor tool runs its command in the user's shell, and zsh expands an unquoted $HOME/.gemini/tmp/review-gemini-pass-1-*/chats/*.jsonl once, at launch. When stale session directories from earlier reviews match the pattern, the list holds only their files, the new session never counts, and a Gemini run longer than one interval reports STALLED. Single-quote the pattern in Step 4's command and table so agent-liveness.sh expands it on every sample, as its header comment assumes.
  • Treat a review that lacks its Coverage Summary, or that ends inside a finding, as truncated even when all three severity headings are present. Read the last record of the agent's session log; an empty or zero-token final message is a dropped stream, and the transient-error retry applies.
  • Check each agent's executed commands with a parser for its session format (Claude's tool_use input.command, Codex's function and custom tool-call arguments, and Gemini's toolCalls[].args.command). A regex over the raw JSONL misses commands with escaped quotes and matches the prompt's own text, so a zero count from it proves nothing.
  • When a change adds a mechanism (a parameter, hook, context, or registry entry) for a feature a later change will build, search the tree for an existing mechanism that serves the same need and compare the two on every exit path, failure paths included. The existing reuse dimension names only the stdlib and installed dependencies.

Repo context updates

  • [repo] UPDATE: the "Live verification setup" section and the live-verification bullet under "Build, test environment, and CI" invite review agents to build rdd and run rdd svc start. The engine reconciler derives watcherCtx from context.Background() and cancels it from a manager.RunnableFunc, which controller-runtime stops on every manager exit. A context taken from the caller of SharedControllerManager.Start stays live when the manager exits on an error, so flag long-running work started under one.
  • [repo] Every other containers API type states the ContainerNamespace relationship conditionally. An object of the same name exists only when the engine's name is a valid object name. Flag a type comment or doc that promises the object unconditionally. The design doc's "the status.name of a ContainerNamespace" names a field the type does not have.
